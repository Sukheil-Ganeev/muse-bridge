# Phase 3: EXECUTE — Выполнение реструктуризации

> **Вход:** Одобренный пользователем план из Phase 2 (mapping old → new, новая структура папок)
> **Выход:** Файлы перемещены, ссылки обновлены, лог изменений создан

---

## Шаг 1: Подготовка

Перед любыми изменениями убедиться, что рабочая директория чистая:

```bash
git status
# Если есть незакоммиченные изменения — закоммитить или stash
git stash push -m "before-refactor-$(date +%Y%m%d)"
```

Создать ветку для рефакторинга:

```bash
git checkout -b refactor/restructure-$(date +%Y%m%d)
```

## Шаг 2: Создать новые папки

Создать всю целевую структуру директорий из одобренного плана:

```bash
mkdir -p src/components src/utils src/services docs/guides tests/unit tests/integration
```

Правило: создавать ВСЕ папки до начала перемещений. Не создавать по одной в процессе.

## Шаг 3: Переместить файлы по маппингу

Переместить каждый файл согласно маппингу `old → new` из Phase 2:

```bash
# Перемещение с сохранением структуры
mv "old/path/file.ts" "new/path/file.ts"
```

**Правила перемещения:**
- Один файл за раз — не использовать wildcards (`mv *.ts`)
- При конфликте имён (файл уже существует) — ОСТАНОВИТЬСЯ и спросить пользователя
- Логировать каждое перемещение в `move_log.md` (формат ниже)

## Шаг 4: Обновить ссылки во ВСЕХ файлах

После перемещения — найти и обновить все ссылки на старые пути:

**HTML** — атрибуты `src`, `href`:
```bash
grep -rn 'src="old/path' --include="*.html"
grep -rn 'href="old/path' --include="*.html"
```

**CSS** — `url()` пути:
```bash
grep -rn 'url(.*old/path' --include="*.css"
```

**Markdown** — ссылки `[text](path)`:
```bash
grep -rn '](old/path' --include="*.md"
```

**Python** — `import` и `Path()`:
```bash
grep -rn 'from old.path' --include="*.py"
grep -rn "Path('old/path" --include="*.py"
```

**CLAUDE.md и конфигурации** — пути в таблицах и описаниях:
```bash
grep -rn 'old/path' CLAUDE.md README.md .github/ docs/
```

Заменить каждый найденный путь на новый. Использовать `Edit` tool — не sed с регулярками (опасно для сложных путей).

## Шаг 5: Удалить дубликаты

**ТОЛЬКО с явного подтверждения пользователя.**

Показать список файлов к удалению:
```
Следующие файлы стали пустыми/дублирующими после перемещения:
- old/path/file.ts (перемещён в new/path/file.ts)
- old/empty-dir/ (пустая директория)

Удалить? (да/нет)
```

Удалять ТОЛЬКО после ответа "да". Пустые директории удалять через `rmdir` (не `rm -rf`).

## Шаг 6: Обновить .dsp/ граф (если используется)

Если проект использует `.dsp/` для графа зависимостей:

```bash
# Для каждого перемещённого файла
# move-entity обновляет граф без потери связей
```

Если `.dsp/` нет — пропустить.

## Шаг 7: Создать лог изменений

Создать файл `move_log.md` в корне проекта:

```markdown
# Move Log — Restructure [YYYY-MM-DD]

## Summary
- Files moved: N
- References updated: N
- Directories created: N
- Directories removed: N

## Moves

| # | Old Path | New Path | Status |
|---|----------|----------|--------|
| 1 | old/path/file.ts | new/path/file.ts | OK |
| 2 | old/path/utils.ts | new/path/utils.ts | OK |

## Reference Updates

| File | Old Reference | New Reference |
|------|---------------|---------------|
| index.html | src="old/path" | src="new/path" |
| CLAUDE.md | `old/path/` | `new/path/` |

## Git Branch
`refactor/restructure-YYYYMMDD`
```

---

## Правила безопасности

1. **НИКОГДА не удалять без подтверждения пользователя** — даже пустые папки
2. **Логировать ВСЁ** — каждое перемещение записывать в `move_log.md` сразу, не в конце
3. **При конфликте имён** — остановиться и спросить (не перезаписывать, не добавлять суффикс)
4. **Git: НЕ коммитить автоматически** — дать пользователю проверить `git diff` и `git status`
5. **Инкрементально** — перемещать файлы группами по 5-10, проверять что ничего не сломалось

## Rollback — Откат изменений

### Вариант A: через Git (рекомендуется)

Если всё сделано в отдельной ветке:

```bash
# Вернуться на основную ветку, отменив все изменения
git checkout main
git branch -D refactor/restructure-YYYYMMDD
```

Если изменения были в текущей ветке:

```bash
# Откатить все незакоммиченные изменения
git checkout -- .
# Или если был stash
git stash pop
```

### Вариант B: через move_log.md (если Git недоступен)

Прочитать `move_log.md` и выполнить обратные перемещения:

```bash
# Для каждой строки в таблице Moves — поменять old и new местами
mv "new/path/file.ts" "old/path/file.ts"
```

Порядок отката: обратный порядку перемещений (последний перемещённый — первым возвращается).
