# Phase 4: SYNC — Documentation Synchronization

**Цель:** После рефакторинга кода (Phases 1-3) документация гарантированно отражает новую структуру. Ни одного устаревшего пути, ни одного дубля, ни одного мёртвого файла.

**Источники методологии:** doc-ops (audit/clean/score), docs-optimizer (anti-patterns, tier-таблица, DUP-коды)

---

## Принципы

1. **CLAUDE.md = навигационный хаб, не энциклопедия** — ссылки вместо содержимого
2. **Свежесть > Полнота** — 50 актуальных строк лучше 500 устаревших
3. **Archive != Delete** — перемещать в `docs/archive/`, не удалять; журналы (CHANGELOG, ISSUES) растут всегда
4. **Cache-optimized** — статическое вверху CLAUDE.md, динамическое внизу
5. **SSOT** — каждый факт живёт в ОДНОМ файле, остальные ссылаются

---

## Пошаговый workflow

### Шаг 1. Пересканировать все .md файлы

После Phase 3 пути могли измениться. Полное пересканирование:

```
1. Найти все .md файлы: корень, docs/, .claude/, подпроекты
2. Для каждого файла: строки, ~токены (строк * 4), дата последнего изменения (git log)
3. Построить parent CLAUDE.md chain (вверх по дереву до ~/.claude/)
4. Определить стадию проекта: INIT / ACTIVE / STABLE / MAINTENANCE
```

### Шаг 2. Проверить 20 anti-patterns

Прогнать все документы через 20 анти-паттернов:

| Приоритет | ID | Что искать |
|-----------|-----|-----------|
| Critical | AP-01 | CLAUDE.md > 4K токенов (context stuffing) |
| Critical | AP-07 | Нет experience/ или lessons learned |
| Critical | AP-12 | Нет стадии проекта (INIT/ACTIVE/STABLE) |
| Critical | AP-16 | Один факт в 3+ файлах (cross-file duplication) |
| High | AP-02 | Инструкции для удалённых файлов (stale docs) |
| High | AP-03 | MD файлы без ссылок ниоткуда (orphan docs) |
| High | AP-04 | Динамика вверху CLAUDE.md (cache-hostile order) |
| High | AP-09 | Документация описывает несуществующий код (code-doc drift) |
| High | AP-10, AP-11, AP-13, AP-17-20 | Monolithic status, duplicate commands, flat hierarchy, etc. |
| Medium/Low | AP-05, AP-06, AP-08, AP-14, AP-15 | Instruction overload, missing rules, emphasis, quick start |

**Особое внимание после рефакторинга:** AP-02 (stale docs) и AP-09 (code-doc drift) — пути файлов и функций изменились в Phases 1-3.

### Шаг 3. Найти дублирование -> DUP-XX коды

Каждое дублирование кодируется обязательно:

```
DUP-XX | [файл A] <-> [файл B] | [что дублируется] | Severity: HIGH/MEDIUM/LOW
```

Примеры:
```
DUP-01 | CLAUDE.md <-> docs/DEPLOY.md | Deploy params (IP, zone) | Severity: HIGH
DUP-02 | CLAUDE.md <-> MEMORY.md | Стек технологий | Severity: MEDIUM
DUP-03 | README.md <-> CLAUDE.md | Quick Start команды | Severity: HIGH
```

**Правило:** одинаковая строка (>10 слов) в 2+ файлах = SSOT violation.

### Шаг 4. Создать tier-таблицу

Классифицировать ВСЕ значимые .md файлы:

| Tier | Описание | Токены | Действие |
|------|----------|--------|----------|
| **Essential** | Загружается каждую сессию | ~800 | Оставить в CLAUDE.md, сжать |
| **On-demand** | По запросу при работе с темой | ~500 каждый | Вынести в docs/, добавить ссылку |
| **Archive** | Устаревшее, orphan docs | 0 | В docs/archive/ + .claudeignore |

**Правило AP-03:** orphan docs (нет ссылок ниоткуда) ВСЕГДА -> Archive.

Пример tier-таблицы:
```
| Tier       | File                    | Reason                              |
|------------|-------------------------|-------------------------------------|
| Essential  | CLAUDE.md               | Навигационный хаб                   |
| Essential  | ISSUES.md               | Актуальный список проблем           |
| On-demand  | docs/ARCHITECTURE.md    | Читать при изменениях архитектуры    |
| On-demand  | docs/DEPLOY.md          | Читать при деплое                   |
| Archive    | docs/old_plan.md        | Superseded by new plan              |
| Archive    | docs/setup_v1.md        | Orphan: нет ссылок                  |
```

### Шаг 5. Оптимизировать CLAUDE.md

Целевая структура (cache-optimized: статическое вверху, динамическое внизу):

| # | Секция | Тип | Содержимое |
|---|--------|-----|-----------|
| 1 | Project Name + стек/git/деплой | СТАТИЧЕСКОЕ | Шапка проекта |
| 2 | Quick Start (5 шагов) | СТАТИЧЕСКОЕ | Быстрый старт |
| 3 | Команды | СТАТИЧЕСКОЕ | Таблица команд |
| 4 | Структура проекта | ПОЛУ-СТАТ | Дерево, макс 40 строк |
| 5 | Принципы и правила | ПОЛУ-СТАТ | Ссылки на docs/ |
| 6 | Навигация по docs | ПОЛУ-СТАТ | Файл -> когда читать |
| 7 | Текущий статус | ДИНАМИЧЕСКОЕ | Таблица: фаза, прогресс |
| 8 | Открытые проблемы | ДИНАМИЧЕСКОЕ | Ссылка на ISSUES.md |
| 9 | Что дальше | ДИНАМИЧЕСКОЕ | Список приоритетов |

**Действия:**
- Убрать дубли (по DUP-XX кодам из Шага 3)
- Обновить все пути файлов после Phase 3 перемещений
- Сжать до целевого размера: **200-250 строк, ~1K-1.2K токенов**
- Вынести On-demand контент в docs/ со ссылками

### Шаг 6. Обновить служебные файлы

| Файл | Что обновить |
|------|-------------|
| INDEX.md | Пути, статусы после рефакторинга |
| CHANGELOG.md | Запись о Phase 4 SYNC (формат Keep a Changelog) |
| ISSUES.md | Закрыть решённые issues, обновить stale статусы |
| .claudeignore | Добавить Archive-тир файлы |

### Шаг 7. Drift check: код <-> документация

**Критический шаг после рефакторинга.** Проверить:

1. **Пути в документации** -> файлы реально существуют (`glob`/`grep` верификация)
2. **Описанные функции/классы** -> существуют в коде
3. **Версии в тексте** -> совпадают с текущей версией проекта
4. **Freshness проблемы** кодировать как AP-F0X:

```
AP-F01 | [файл] | Не обновлялся N дней | Severity: HIGH/MEDIUM/LOW
AP-F02 | [файл] | Версия в тексте расходится с текущей | Severity: HIGH
AP-F03 | [файл] | URL/путь не существует | Severity: MEDIUM
AP-F04 | [файл] | Описан удалённый модуль/функция | Severity: HIGH
```

### Шаг 8. Рассчитать Health Score

Формула:
```
Score = (Completeness * 0.3) + (Efficiency * 0.3) + (Freshness * 0.2) + (Structure * 0.2)
```

| Компонент | Что оценивает |
|-----------|--------------|
| Completeness | Все критичные секции присутствуют |
| Efficiency | Токены CLAUDE.md / полезная информация |
| Freshness | % файлов обновлённых за 30 дней |
| Structure | Cache ordering + tiering + no duplication |

**Пороги:**

| Score | Условие |
|-------|---------|
| 5/5 | CLAUDE.md <250 строк И <2.5K токенов, 0 дублей, 0 stale |
| 4/5 | CLAUDE.md <300 строк, 1-3 дубля, <20% stale |
| 3/5 | CLAUDE.md <400 строк, 3-5 дублей, <30% stale |
| 2/5 | CLAUDE.md >400 строк ИЛИ >4K токенов, >5 дублей |
| 1/5 | Значительный drift, >50% stale, >500 строк |

**Если score < 3/5** -> повторить Шаги 5-7 до достижения минимум 3/5.

## Что НЕЛЬЗЯ делать в Phase 4

- **Удалять** CHANGELOG.md, WHY-LOG.md, ISSUES.md — журналы растут всегда
- **Удалять** dormant docs — спросить владельца, пометить `// DORMANT`
- **Применять** изменения без показа diff и подтверждения владельца
- **Сжимать** архивные журналы — только перемещать старое в docs/archive/
- **Игнорировать** parent CLAUDE.md chain при подсчёте токенов
