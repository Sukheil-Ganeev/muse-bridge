# Опыт скилла readme-проекты

## Критические уроки (топ-5)

### 1. Делай ДВЕ версии README
- **v1 (базовая, ~530 строк):** badges, features, architecture, quick start, commands, tech stack, roadmap
- **v2 (расширенная, ~925 строк):** всё из v1 + Table of Contents, Demo, Why This Bot?, Performance, FAQ, Before/After, ER Diagram, Team
- Пользователь сам выбирает какую использовать. v1 для GitHub, v2 для полной документации

### 2. ASCII-demo вместо скриншотов
- Скриншоты требуют записи экрана, обрезки, загрузки
- ASCII-mockup создаётся за минуту и выглядит стильно
- Добавь пометку: "Replace with actual screenshots"
- Пример: нарисовать чат-бабл с ответом бота в ASCII

### 3. "Why This Bot?" — самая ценная секция
- Таблица "Проблема → Старый подход → Наше решение"
- Сразу показывает ценность проекта
- Пользователь сказал "АХРИНЕТЬ!" именно после этой секции + demo

### 4. Обновляй README вместе с кодом
- README создан на v5.0.1, но за сессию добавили v5.1 и v5.2
- Пришлось запускать 3 субагента для обновления README + CLAUDE.md + CHANGELOG.md
- Урок: после добавления фич сразу обновлять все 3 файла документации

### 5. Mermaid sequence diagram > flowchart для пайплайнов
- Flowchart хорош для архитектуры (модули и связи)
- Sequence diagram лучше для процессов (голосовое → STT → коррекция → резюме)
- Используй ОБА: flowchart в Architecture, sequence в Performance
