# Tilda -- Troubleshooting (12 проблем)

---

## 1. Форма не отправляет данные

**Симптомы:** клик на кнопку отправки ничего не делает или показывает ошибку.

**Решения:**
- Проверьте что приёмник активирован: Site Settings -> Forms -> нужный сервис -> статус "Active"
- В блоке формы Content Panel -> убедитесь что выбран приёмник (Email/Telegram/Webhook)
- Страница **опубликована** после настройки формы (Preview не работает для форм)
- Проверьте обязательные поля -- все ли заполнены корректно
- Email приёмник: подтвердите адрес через письмо-верификацию от Tilda

---

## 2. CSS стили не применяются

**Симптомы:** стили в T123 блоке не работают, элементы выглядят по-старому.

**Решения:**
- Добавьте `!important` к стилям: `.t-btn { border-radius: 30px !important; }`
- Проверьте специфичность селектора -- Tilda использует длинные CSS-цепочки
- Используйте ID блока для точного таргетинга: `#rec123456789 .t-title { color: red !important; }`
- Очистите кеш браузера (Ctrl+Shift+R)
- Проверьте что T123 блок расположен **после** целевого блока на странице

---

## 3. JavaScript не работает

**Симптомы:** скрипт в T123 блоке не выполняется, ошибки в консоли.

**Решения:**
- Оберните код в `t_onReady()`: Tilda загружает контент динамически
  ```javascript
  t_onReady(function() {
    // Ваш код здесь
  });
  ```
- Проверьте консоль браузера (F12 -> Console) на ошибки
- jQuery доступен как `$` -- не нужно подключать дополнительно
- Скрипты в T123 выполняются при загрузке страницы, не в Preview
- Если используете `document.getElementById` -- убедитесь что ID уникален

---

## 4. Страница грузится медленно

**Симптомы:** PageSpeed Insights < 60, пользователи жалуются на скорость.

**Решения:**
- Сжать изображения: TinyPNG/Squoosh, WebP формат, до 200-300 КБ каждое
- Убрать тяжёлые видео -- заменить на YouTube/Vimeo embed
- Уменьшить количество блоков (максимум 15-20 на странице)
- Убрать неиспользуемые T123 блоки с JavaScript
- Проверить что Lazy Loading работает (встроено по умолчанию)
- Использовать не более 2 кастомных шрифтов

---

## 5. Мобильная версия выглядит криво

**Симптомы:** текст выходит за экран, блоки накладываются, кнопки мелкие.

**Решения:**
- Tilda автоматически адаптирует стандартные блоки -- проверьте предпросмотр на разных устройствах
- В Zero Block: настройте каждый breakpoint отдельно (1200, 960, 640, 480, 320)
- Проверьте CSS в T123 -- добавьте media queries:
  ```css
  @media (max-width: 640px) {
    .custom-element { font-size: 14px; padding: 10px; }
  }
  ```
- Если блок не нужен на мобильном: Settings блока -> Visibility -> скрыть на Mobile
- Протестируйте на реальном устройстве, не только в эмуляторе

## 6. Telegram webhook не приходит

**Симптомы:** форма отправляется, но сообщения в Telegram не появляются.

**Решения:**
- Проверьте API Key и Secret Key: напишите @TildaFormsBot заново и нажмите /start
- API Key для групп может быть отрицательным (с минусом) -- это нормально
- @TildaFormsBot **добавлен** в группу и имеет права на отправку сообщений
- В группе написали /start после добавления бота
- В Site Settings -> Forms -> Telegram: статус "Active", зелёная галочка
- В блоке формы Content Panel: Telegram выбран как приёмник данных
- Страница **переопубликована** после настройки

## 7. Оплата не проходит (Stripe/PayPal)

**Симптомы:** клиент не может оплатить, ошибка на странице оплаты.

**Решения:**
- Проверьте что используете **live** ключи, не test (начинаются с `pk_live_`, `sk_live_`)
- Валюта в Tilda совпадает с валютой в Stripe (AED)
- Stripe аккаунт полностью активирован (KYC пройден, ОАЭ поддерживается)
- Проверьте Stripe Dashboard -> Logs -> ищите ошибки
- PayPal: аккаунт должен быть Business, привязан к ОАЭ
- Тестовая оплата: используйте test-режим Stripe (карта 4242 4242 4242 4242)

## 8. SEO: страница не индексируется Google

**Симптомы:** страница не появляется в Google через 2+ недели.

**Решения:**
- Проверьте robots.txt: не заблокирована ли страница (Site Settings -> SEO)
- Добавьте страницу в Google Search Console: URL Inspection -> Request Indexing
- Заполните Title и Description для страницы (Page Settings)
- Проверьте что страница **опубликована** (не черновик)
- Подключите свой домен -- tilda.ws-поддомены индексируются хуже
- Включите HTTPS (Site Settings -> SEO -> HTTPS)
- Добавьте sitemap в Google Search Console: `yourdomain.com/sitemap.xml`

## 9. Домен не подключается

**Симптомы:** после настройки DNS сайт не открывается по домену.

**Решения:**
- DNS обновляется до 24 часов -- подождите
- Проверьте A-запись: Host = `@`, Value = IP Tilda (указан в Site Settings -> Domain)
- Для www: добавьте CNAME запись: Host = `www`, Value = `cname.tilda.ws`
- Проверьте DNS через whatsmydns.net -- записи видны глобально?
- В Tilda: Site Settings -> Domain -> домен введён без http/https
- Если используете Cloudflare: отключите прокси (серая иконка облака, не оранжевая)

## 10. API возвращает ошибку 429 (Too Many Requests)

**Симптомы:** API-запросы возвращают ошибку после нескольких вызовов.

**Решения:**
- Tilda API лимит: **150 запросов/час** -- это жёсткий лимит
- Кешируйте ответы API на своём сервере (Redis/файловый кеш)
- Используйте webhook при публикации для синхронизации (вместо polling)
- Объединяйте запросы: `getpagefull` вместо `getpage` + дополнительные запросы
- Если нужно больше -- экспортируйте код (Site Settings -> Export) вместо API

## 11. RTL (арабский) текст отображается неправильно

**Симптомы:** арабский текст идёт слева направо, выравнивание сломано.

**Решения:**
- Добавьте CSS через T123 блок:
  ```css
  body { direction: rtl; }
  .t-text, .t-title, .t-descr { text-align: right; }
  ```
- Исключите элементы, которые должны оставаться LTR (номера, email):
  ```css
  .t-input, .t-btn, .phone-number { direction: ltr; }
  ```
- Zero Block: установите направление текста вправо для каждого текстового элемента
- Тестируйте на реальном устройстве -- эмуляторы могут показывать неточно
- Используйте Google Fonts с поддержкой арабского (Cairo, Noto Sans Arabic)

## 12. Pop-up не появляется

**Симптомы:** настроен pop-up (форма, корзина), но не отображается.

**Решения:**
- Pop-up блоки должны быть **на той же странице**, что и триггер
- Проверьте ссылку-триггер: формат `#popup:blockID` (например, `#popup:rec123456789`)
- Для корзины (ST100): блок должен быть на каждой странице, где есть товары
- AdBlock и расширения браузера могут блокировать pop-up -- тестируйте в Incognito
- Убедитесь что страница переопубликована после добавления pop-up блока
- В Preview режиме pop-up может не работать -- проверяйте на опубликованной странице
