# Анализ рекламы конкурентов

Скилл для систематического анализа рекламных кампаний конкурентов в туристическом бизнесе ОАЭ. Охватывает 4 платформы: Meta (Facebook/Instagram), Google Ads/YouTube, ВКонтакте, Яндекс.Директ.

## Команды

| Команда | Описание |
|---------|---------|
| `/adspy meta [конкурент]` | Анализ рекламы в Facebook/Instagram через Ad Library |
| `/adspy google [конкурент]` | Анализ рекламы в Google/YouTube через Transparency Center |
| `/adspy vk [конкурент]` | Анализ рекламы и контента ВКонтакте |
| `/adspy yandex [ключевое слово]` | Анализ рекламы в Яндекс.Директ + Wordstat |
| `/adspy all [конкурент]` | Полный анализ по всем 4 платформам |
| `/adspy compare [конкурент1, конкурент2, ...]` | Сравнительный анализ нескольких конкурентов |

## Контекст бизнеса

- **Компания:** VIP DXB RUS (Сухейль)
- **Услуги:** экскурсии, билеты в парки, сафари, яхты, трансферы (ОАЭ)
- **Преимущество:** цены ниже кассы и конкурентов
- **Клиенты:** СНГ (Россия, Казахстан, Узбекистан)
- **Языки:** RU, EN
- **Партнёры:** Марсель (аренда авто, трансферы), Муфамад (Paramount Yachts, 300+ яхт)

Полный контекст: `references/uae-tourism.md`

## Архитектура

### 4 субагента (параллельная работа)

| Субагент | Файл | Платформа | Метод | Покрытие |
|----------|------|-----------|-------|----------|
| Meta Spy | `agents/meta-spy.md` | Facebook, Instagram | MCP: facebook-ads-library-mcp (без токена) | Полное -- все активные объявления |
| Google Spy | `agents/google-spy.md` | Google Ads, YouTube | Ads Transparency Center + WebSearch | Полное -- все объявления рекламодателя |
| VK Spy | `agents/vk-spy.md` | ВКонтакте | WebSearch + WebFetch (ручной) | Частичное -- публичные посты и промо |
| Yandex Spy | `agents/yandex-spy.md` | Яндекс.Директ, Карты | Wordstat + WebSearch (ручной) | Частичное -- выдача + частотность |

### MCP-серверы

| MCP | Для чего | Токен | Установка |
|-----|----------|-------|-----------|
| `facebook-ads-library-mcp` (trypeggy, 191 stars) | Meta Ad Library -- все объявления любой страницы | НЕ нужен | `npx facebook-ads-library-mcp` |
| `google-ads-transparency` (talknerdytome) | Google Transparency Center | НЕ нужен | Опциональный |

### Общие инструменты

- **WebSearch** -- поиск объявлений и страниц конкурентов
- **WebFetch** -- загрузка страниц для парсинга (VK, Яндекс выдача, лендинги)

## Workflow

```
Ввод: пользователь указывает конкурентов (название / домен / FB-страница / VK-группа)
  │
  ├─→ [meta-spy]   ── Meta Ad Library ──→ объявления FB/IG
  ├─→ [google-spy]  ── Transparency Center ──→ объявления Google/YouTube
  ├─→ [vk-spy]      ── WebSearch/WebFetch ──→ промо-посты VK
  └─→ [yandex-spy]  ── Wordstat + выдача ──→ объявления Директа
       │
       ▼
  Объединение результатов → Сравнительный анализ → Финальный отчёт
```

**Правила параллелизма:**
- При `/adspy all` или `/adspy compare` -- все 4 субагента запускаются **параллельно**
- При `/adspy [платформа]` -- запускается только 1 субагент
- Каждый субагент работает **независимо** и возвращает структурированный результат
- Диспетчер объединяет результаты по шаблону `references/report-template.md`

## Быстрый старт

### Пример 1: Анализ конкретного конкурента по всем платформам
```
/adspy all Rayna Tours
```
Запускает 4 субагента параллельно. Результат: полный отчёт со сравнительной таблицей и рекомендациями.

### Пример 2: Только Meta (Facebook/Instagram)
```
/adspy meta GetYourGuide
```
Ищет страницу GetYourGuide в Meta Ad Library, собирает все активные объявления, анализирует креативы, тексты, CTA.

### Пример 3: Яндекс по ключевым словам
```
/adspy yandex "экскурсии в дубае"
```
Проверяет Wordstat (частотность, сезонность), собирает объявления Директа по запросу, анализирует лендинги конкурентов.

### Пример 4: Сравнение нескольких конкурентов
```
/adspy compare Rayna Tours, GetYourGuide, Arabian Adventures
```
Анализирует каждого конкурента по всем платформам, генерирует сравнительную таблицу, карту рынка и gap-анализ.

### Пример 5: VK для русскоязычных конкурентов
```
/adspy vk "экскурсии дубай"
```
Ищет VK-сообщества по теме, анализирует промо-посты, вовлечённость, контент-стратегию.

## Фазы анализа (каждый субагент)

Каждый субагент проходит 5 фаз (адаптированных под свою платформу):

| Фаза | Что делается | Результат |
|------|-------------|-----------|
| 1. Сбор данных | Поиск и загрузка объявлений/постов конкурента | Сырые данные |
| 2. Анализ форматов | Классификация по типам (видео/фото/текст/карусель) | Распределение форматов |
| 3. Анализ messaging | УТП, CTA, цены, эмоциональные триггеры, языки | Позиционирование |
| 4. Паттерны | A/B тесты, сезонность, частота, тренды | Стратегия конкурента |
| 5. Рекомендации | Сравнение, gap-анализ, конкретные действия | Actionable insights |

Детали по каждому субагенту -- в соответствующем файле `agents/*.md`.

## Формат вывода

Финальный отчёт сохраняется в файл:
```
D:/Downloads/Chats/_база/md/competitor-ads-analysis-YYYY-MM-DD.md
```

Структура отчёта (из `references/report-template.md`):
1. **Executive Summary** -- 3-5 ключевых выводов
2. **Детальный анализ по конкурентам** -- для каждого: активность, офферы, креативы, сильные/слабые стороны
3. **Сравнительная таблица** -- все конкуренты vs наш бизнес
4. **Карта рынка** -- позиционирование (цена vs сервис)
5. **Пробелы рынка** -- что НЕ делают конкуренты
6. **Рекомендации** -- Quick Wins, что избегать, незанятые ниши, приоритеты по платформам

## Важные правила

1. **Сохранять отчёт в файл с датой** -- всегда `*-YYYY-MM-DD.md`, чтобы отслеживать динамику
2. **Параллельные субагенты** -- при анализе нескольких конкурентов или платформ запускать субагентов параллельно для экономии времени
3. **Использовать references/** -- перед началом анализа загрузить `uae-tourism.md` для контекста бизнеса
4. **Финальный отчёт по шаблону** -- всегда использовать `report-template.md` как основу
5. **Не угадывать данные** -- если платформа недоступна или данные не найдены, явно указать "не обнаружено"
6. **Цены в объявлениях** -- фиксировать в оригинальной валюте (AED, USD, RUB) без конвертации
7. **Дата через MCP** -- при создании отчёта получить точную дату/время через MCP Time Server (Asia/Dubai)
8. **Повторные анализы** -- рекомендовать пользователю периодичность (раз в 2-4 недели) для отслеживания изменений
