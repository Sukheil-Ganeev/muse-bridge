# Роутер навыков (Skill Bridge)

На этой машине 9014 навыков в 9 библиотеках. Держать их все в голове
нельзя, а описания всех навыков в контекст не влезают — часть каталога
поэтому не видна. Этот роутер ищет навык по смыслу и возвращает 1–3 точных
попадания.

## Проверка при старте (делать один раз в начале сессии)

```bash
python "C:\Users\londo\.agents\skill-bridge\refresh.py" --quiet
```

За пару секунд проверит, не устарел ли индекс навыков и графы, и пересоберёт
их только если нужно. Ничего не удаляет. Если всё актуально — одна строка и
выход. Флаг `--json` даёт машинный ответ, `--strict` возвращает код 2, когда
что-то не починилось.

## Как вызвать

```bash
"C:\Users\londo\.agents\skill-bridge\bin\skill.cmd" --agent claude --query "что нужно сделать"
```

Полезные флаги:

| Флаг | Зачем |
|---|---|
| `--limit N` | сколько результатов вернуть (по умолчанию 5) |
| `--format json` | машинный вывод, если нужно разобрать программно |
| `--format paths` | только пути к папкам навыков |
| `--explain` | показать, по каким словам совпало |
| `--variants` | показать другие версии навыка с тем же именем |
| `--lib <id>` | искать только в одной библиотеке |
| `--archive` | искать **только** в холодном архиве (бэкап `.agents`) |
| `--strict` | не выдавать результат, если индекс устарел |
| `--rerank off` | выключить уточнение через Jev для одного запроса |

**Холодный архив.** Бэкап `.agents` остаётся на диске и **не изменяется**, но в
обычной выдаче его навыков не видно — включая **923 навыка, которых больше нигде
нет**. Они находятся только по явному `--archive`. Так убраны дубли из
ежедневных ответов, но ничего не потеряно. Внутри индекса это пометка записи
(`archive`), а не отдельный файл: вынос архива из статистики IDF стоил бы
2 запроса из 22.

Проверка состояния роутера:

```bash

"C:\Users\londo\.agents\skill-bridge\bin\skill.cmd" list-agents
```

## Перед любой правкой поиска — замер

Правило проекта: изменение остаётся в коде, только если оно **улучшает Top-1 и
не ломает ни один запрос**. На глаз тут не решается — три раза подряд очевидная
идея оказывалась хуже.

```bash
cd C:\Users\londo\.agents\skill-bridge

# 22 реальных запроса владельца: Top-1 / Top-3
"python" eval_search.py --save after.json
"python" eval_search.py --compare before.json after.json

# полнота извлечения: отделяет «не нашёл» от «не отсортировал»
"python" eval_search.py --recall

# пары «должен / не должен»: ловит ложное срабатывание
"python" eval_search.py --negatives

# сколько РАЗНЫХ навыков видит владелец (копии съедают места)
"python" eval_search.py --distinct

# перебор инженерных приёмов одной таблицей
"python" eval_search.py --sweep-features

# почему конкретный запрос не нашёл навык — по шагам
"python" diag_failures.py --query "..." --expected <имя>
```

Ориентир на 2026-09-21: Top-1 15/22 (с Jev 20/22), Top-3 17/22, полнота 100 %
на глубине 10, ложных срабатываний 0/13, разных навыков 4.5 из 5.

## Ловушки (проверено на себе)

1. **Мост требует корень от 3 букв.** Для корня из 3 букв разница не больше 2
   («цен» → «цена/цены», но не «центр»). Иначе короткие корни молча мертвы —
   так лежали `баз`, `код`, `суд`, `цен`, `яхт`. Проверка:
   `"python" -c "import search_skills as ss; print(ss.glossary_health())"` —
   мёртвых должно быть 0.
2. **Сворачивать копии только по `canonical_sha256`.** `body_sha256` у копий
   одного навыка разный (различается оформление шапки), и по нему 7 копий
   `client-report` давали 1 вариант в выдаче из 5.
3. **В словаре моста не должно быть глаголов действия.** `create` встречается в
   11.9 % навыков; мост для «сделать» уронил верный ответ с 1-го места на 4-е.
   Мост несёт тему, а не действие.
4. **Отклонено замером, не повторять:** биграммы (11/22), вес покрытия (любое
   значение хуже нуля), два файла индекса вместо пометки архива.
5. **Детерминизм.** При расхождении цифр между запусками проверять
   `PYTHONHASHSEED`: один запрос давал разный ответ из-за `break` по `set`.
6. **Добавил файл в роутер — добавь его в `deploy/deploy_to_servers.sh`.**
   `ru_en_bridge_extra.json` сначала не попал в набор, и серверы молча остались
   бы со старым словарём на 218 корней: отсутствующий файл моста подмешивается
   без ошибки.

## Уточнение через Jev (включено по умолчанию)

Когда запрос сформулирован расплывчато («разобраться с клиентом»), ключевой
поиск даёт несколько близких кандидатов, и порядок между ними — угадайка.
Jev решает именно такую задачу: выбрать один вариант из заданного набора.
Замер на 22 реальных запросах: точность первого места выросла с 55 до 73
(русские запросы — с 50 до 70). Поэтому шаг включён по умолчанию.

**Правила использования — не нарушать:**

- Jev **только переставляет** кандидатов и подписывает вероятности. Он
  **никогда не удаляет** кандидата и **никогда не является гейтом**: его
  измеренная точность ~73 % с уверенными ошибками. Смотри на список целиком,
  а не только на выбор Jev.
- В опросе всегда есть вариант «ни один не подходит». Без него Jev отвечает
  уверенно даже на случайных символах.
- Ключ берётся из `TYPESAFE_API_KEY` или `~/.typesafe/credentials.env`.
  **Никогда не печатать его в логи, отчёты и артефакты.**
- **Если ключа на машине нет — это не поломка.** Шаг просто пропускается,
  поиск работает полностью. Наличие ключа видно в `"C:\Users\londo\.agents\skill-bridge\bin\skill.cmd" doctor`.
- Выключить уточнение насовсем: `--rerank off` в вызове.

Проверить разбор ответа без сети: `python "C:\Users\londo\.agents\skill-bridge\rerank_jev.py" --selftest`

## Выключить роутер на этой машине

У роутера есть переключатель, который работает **отсюда**, без захода на
другие машины и без правки кода:

```bash
"C:\Users\londo\.agents\skill-bridge\bin\skill-toggle.cmd" status        # что сейчас
"C:\Users\londo\.agents\skill-bridge\bin\skill-toggle.cmd" off           # выключить
"C:\Users\londo\.agents\skill-bridge\bin\skill-toggle.cmd" off "причина" # выключить и записать причину
"C:\Users\londo\.agents\skill-bridge\bin\skill-toggle.cmd" on            # включить обратно
```

Пока роутер выключен, он не ищет навыки и говорит об этом; команды `doctor`
и `list-agents` продолжают работать, чтобы состояние было видно. Выключение
и включение мгновенные и полностью обратимые: ничего не удаляется, файлы
правил не трогаются.

Собирает страницу `C:\Users\londo\.agents\skill-bridge\graphs\skill-graphs.html` — что видно на ней:

Графы только читают индекс, файлы навыков не трогают.

## Что этот агент видит своим

Свои библиотеки: **claude**. Навыки из них ищутся первыми.
Навык из чужой библиотеки помечается стрелкой `->`, и роутер печатает
готовую команду копирования в твою папку навыков: C:\Users\londo\.claude\skills

Пока навык не скопирован, он **не загрузится** — просто найти путь мало.

## Когда использовать

- Задача сформулирована словами, а не именем навыка («сделать инвойс»,
  «собрать цены», «почистить таблицу»).
- Кажется, что нужного навыка нет — возможно, он просто не виден.
- Нужно понять, есть ли вообще навык под такую задачу, прежде чем писать
  свой.

## Когда НЕ использовать

- Имя навыка уже известно точно — вызывай его напрямую.
- Задача про конкретный проект — там свои правила в его `AGENTS.md`.

## Если индекс устарел

Роутер сам предупредит. Пересобрать:

```bash
python "C:\Users\londo\.agents\skill-bridge\build_index.py"
```

Индекс пересобирать нужно после установки или удаления навыков — иначе новые
навыки в поиске не появятся.
