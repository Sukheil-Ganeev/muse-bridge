# NocoDB -- Troubleshooting (Решение проблем)

> ДАННЫЕ АКТУАЛЬНЫ НА: 2026-02-15

---

### 1. HTTP 429 Too Many Requests

**Симптом:** API возвращает 429.
**Причина:** Превышен rate limit (5 req/sec на пользователя).
**Решение:** Подождать 30 секунд. Добавить задержку между запросами. Для bulk-операций использовать массивы вместо отдельных запросов.

### 2. Docker контейнер не стартует

**Симптом:** Контейнер падает сразу после запуска.
**Решение:**
- Проверить логи: `docker logs nocodb`
- Проверить порт: `docker ps` (не занят ли 8080)
- Проверить volume permissions
- Проверить `NC_DB` -- корректная строка подключения?
- Убедиться что PostgreSQL запущен и healthcheck пройден

### 3. Ошибка подключения к PostgreSQL

**Симптом:** `connection refused` или `FATAL: password authentication failed`.
**Решение:**
- Проверить `NC_DB` формат: `pg://host:5432?u=user&p=password&d=database`
- Проверить что PostgreSQL слушает на правильном порте
- Проверить `pg_hba.conf` (разрешен ли доступ с хоста NocoDB)
- В docker-compose: использовать имя сервиса (`db`) как host, не `localhost`

### 4. Формула не работает

**Симптом:** Поле формулы показывает ошибку или пустое значение.
**Решение:**
- Имена полей должны быть в `{}`: `{Цена продажи}`
- Правильное название: `DATETIME_DIFF` (не DATEDIFF)
- `COUNTLINKS` не существует -- используйте Links field + Rollup COUNT
- Проверить типы данных: числовые операции только с числами
- Строки в двойных кавычках: `"text"`

### 5. Webhook не срабатывает

**Симптом:** Webhook создан, но внешний сервис не получает данные.
**Решение:**
- Проверить что webhook активирован (toggle = ON)
- Проверить URL доступность (тест из NocoDB UI)
- Self-hosted: `NC_ALLOW_LOCAL_HOOKS=true` если webhook на localhost
- Проверить условия (Conditions) -- webhook срабатывает только при переходе false->true
- Проверить версию: Webhook v3 с 2025.06.0
- Проверить логи webhook (платные планы)

### 6. SDK ошибка авторизации

**Симптом:** `401 Unauthorized` или `403 Forbidden`.
**Решение:**
- Проверить заголовок: `xc-token` (не `xc-auth`)
- Проверить что токен не удален в Settings
- Проверить `baseURL` -- включает протокол и порт
- SSO-enforced workspace: пересоздать токен после SSO

### 7. Данные пропали после перезапуска Docker

**Симптом:** База пустая после `docker stop/start`.
**Решение:**
- Обязательно монтировать volume: `-v nc_data:/usr/app/data`
- Установить `NC_DB` для внешней БД (PostgreSQL)
- Без volume и без `NC_DB` -- данные теряются при удалении контейнера
- Данные хранятся в `/usr/app/data/` (с v0.10.6)

### 8. Пагинация -- не все записи возвращаются

**Симптом:** API возвращает только часть записей.
**Решение:**
- По умолчанию limit=25. Максимум 1000.
- Используйте `offset` для итерации: `?offset=0&limit=100`, затем `?offset=100&limit=100`
- Проверяйте `pageInfo.isLastPage` в ответе
- Для всех записей: цикл пока `isLastPage != true`

### 9. Связанные записи не отображаются в API

**Симптом:** Links field возвращает только count, не данные.
**Решение:**
- В API v2: используйте отдельный endpoint для links:
  `GET /api/v2/tables/{tableId}/links/{linkFieldId}/records/{recordId}`
- В API v3 (beta): inline linked records в основном GET запросе

### 10. Миграция из SQLite в PostgreSQL

**Симптом:** NocoDB тормозит на большом количестве записей.
**Решение:**
1. Экспортировать данные (CSV)
2. Создать новый инстанс с `NC_DB=pg://...`
3. Импортировать данные
4. Пересоздать связи между таблицами

### 11. Обновление версии -- ошибка миграции

**Симптом:** Ошибки `nc_013_sync_source`, `nc_054_id_length` при обновлении.
**Решение:**
- ВСЕГДА делать бэкап перед обновлением
- Не пропускать много версий -- обновлять последовательно
- Проверить GitHub Issues для конкретной ошибки
- Откатиться из бэкапа если необходимо
- Фиксировать версию: `nocodb/nocodb:0.301.2` вместо `latest`

### 12. JWT токены перестали работать

**Симптом:** Все пользователи разлогинены после обновления.
**Решение:**
- `NC_AUTH_JWT_SECRET` НЕЛЬЗЯ менять -- все токены станут невалидными
- Зафиксировать секрет в `.env` файле
- Если секрет утерян -- все пользователи должны перелогиниться

### 13. Вложения не загружаются

**Симптом:** Upload файлов не работает.
**Решение:**
- Проверить `NC_ATTACHMENT_FIELD_SIZE` (по умолчанию 20 МБ)
- Проверить `NC_MAX_ATTACHMENTS_ALLOWED` (по умолчанию 10 на ячейку)
- Для S3: проверить `NC_S3_BUCKET_NAME`, `NC_S3_ACCESS_KEY`, `NC_S3_ACCESS_SECRET`
- Проверить свободное место на диске (volume)

### 14. Slow queries на больших таблицах

**Симптом:** Медленные API-запросы при >100K записей.
**Решение:**
- Добавить Redis: `NC_REDIS_URL=redis://redis:6379`
- Использовать PostgreSQL (не SQLite)
- Ограничить `fields` в запросах -- не запрашивать все поля
- Использовать `limit` и `offset` вместо загрузки всех записей
- PostgreSQL: создать индексы на часто фильтруемые поля

### 15. n8n NocoDB node -- ошибка "Trigger not found"

**Симптом:** Поиск "NocoDB Trigger" в n8n ничего не находит.
**Причина:** n8n НЕ имеет NocoDB Trigger node. Только action node.
**Решение:** Используйте:
- n8n Webhook trigger + NocoDB Webhook
- n8n Schedule trigger + NocoDB action node (Get Many)

### 16. Form View не принимает заявки

**Симптом:** Форма отображается, но при отправке ошибка.
**Решение:**
- Проверить обязательные поля (красная звездочка)
- Проверить валидацию (Cloud: лимиты символов, типы файлов)
- Убедиться что shared view включен
- Проверить что пароль (если установлен) верный

### 17. Make.com не подключается к NocoDB

**Симптом:** Ошибка при создании подключения в Make.com.
**Решение:**
- Использовать нативный модуль NocoDB (обновлен в 2025.11.0)
- Base URL: полный URL с протоколом (https://app.nocodb.com)
- API Token: корректный, не удаленный
- Self-hosted: убедиться что URL доступен извне

### 18. Диск заполнен -- NocoDB упал

**Симптом:** Контейнер останавливается, ошибки записи в логах.
**Решение:**
- Настроить log rotation: `logging: { driver: json-file, options: { max-size: "10m", max-file: "3" } }`
- Удалить старые бэкапы: `find /backups -name "nocodb-*" -mtime +30 -delete`
- Перенести вложения на S3/Minio
- Увеличить диск сервера
