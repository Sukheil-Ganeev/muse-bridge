## Что НЕ делать

НЕ писать "проект устарел" или "не рекомендуется" без деталей.

## Почему

Пользователи не понимают СТЕПЕНЬ устаревания и продолжают использовать deprecated-инструменты. Фраза "не рекомендуется" не объясняет, что произойдёт при использовании.

## Правильный способ

Для deprecated-инструментов ВСЕГДА указывать 3 параметра:
1. **Дата** прекращения поддержки
2. **Версия**, с которой несовместим
3. **Конкретные альтернативы** (имена проектов, не абстрактные)

## Пример

Правильно:
- **Watchtower:** archived декабрь 2025, несовместим Docker 28+, альтернативы: WUD, DIUN
- **docker-compose v1:** мёртв июнь 2023, удалён из Docker Desktop 4.30+, альтернатива: `docker compose` (v2/v5)
- **DCT (Docker Content Trust):** удалён из CLI Engine v29, собирается как плагин, альтернативы: cosign, Notation

Неправильно:
- "Watchtower устарел, не используйте"
- "docker-compose больше не поддерживается"

## Урок

Три параметра (дата, версия, альтернативы) -- минимум для deprecated-записи в справочнике. Без них пользователь не может оценить риск.
