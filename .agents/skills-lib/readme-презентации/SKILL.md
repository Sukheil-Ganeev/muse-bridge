# README для презентаций — Скилл

## Триггеры активации

Активируй этот скилл когда:
- Нужно создать README.md для HTML-презентации
- Нужно создать README для нескольких презентаций (batch)
- Нужно обновить существующий README презентации
- Пользователь спрашивает о структуре README для презентации

## Обязательный протокол: Анализ → План → Генерация → QA

НИКОГДА не создавай README без предварительного анализа. Всегда следуй 4 фазам.

---

## ФАЗА 1: АНАЛИЗ

### 1.1 Анализ файлов в папке

Для каждой папки-презентации определи:

| Что проверять | Как |
|--------------|-----|
| Какие файлы есть | `ls -la` папки |
| Размер файлов | HTML, backup, PDF, дополнительные файлы (PNG и т.д.) |
| Есть ли backup | `presentation_backup_v1.html` и т.д. |
| Есть ли output/PDF | Папка `output/` |
| Есть ли уже README | `README.md` в папке |

### 1.2 Анализ контента (читай HTML)

Прочитай `presentation.html` и определи:

| Что извлечь | Где искать |
|------------|-----------|
| Технология | Маркеры технологии (см. Детекция технологий) |
| Количество слайдов | Считай `div.slide` или `section` (reveal.js) |
| Заголовки слайдов | `.slide-title`, `h1`, `.hero-title` |
| Тема дизайна | CSS comments, `:root` variables |
| Бренды и модели | Контент слайдов |
| Ценовые диапазоны | Таблицы, карточки с ценами |
| Целевая аудитория | Контент, уровень сложности материала |

### 1.3 Анализ контекста (соседние папки)

| Что проверять | Зачем |
|--------------|-------|
| Есть ли README в соседних папках | Как образец формата |
| INDEX.md в родительской папке | Категория, общая структура |
| Тематические группы | Для секции "Связи и зависимости" |
| Общая структура Skill_Presentations/ | Понять категоризацию |

### 1.4 Детекция технологий

Определи технологию презентации автоматически:

**Custom HTML/CSS (Digital Ink и подобные):**
```
Маркеры: <div class="slide">, нет reveal.js импортов
CSS: :root с --bg-page, --accent-1 и т.д.
Формат: @page { size: 1920px 1080px; }
Навигация: scroll-based, slide-number
```

**Reveal.js:**
```
Маркеры: <div class="reveal">, <div class="slides">, <section>
Импорт: reveal.js/dist/reveal.css, reveal.js/plugin/
Формат: обычно 960x700 или кастомный
Навигация: стрелки, пробел, слайд-индикатор
```

**Другие технологии:**
```
Impress.js: <div id="impress">, data-x, data-y атрибуты
Deck.js: class="deck-container", deck.core.js
Shower: <div class="shower">, shower.js
Slidev: frontmatter, vue-компоненты
```

Если технология не определена — укажи "Неизвестная" и опиши найденные маркеры.

## ФАЗА 2: ПЛАНИРОВАНИЕ

### 2.1 Одиночный режим (1 презентация)

Если нужен README для одной презентации:
1. Выбери шаблон из `references/cheatsheet.md`
2. Адаптируй секции под найденную технологию
3. Определи какие секции заполнять (если нет цен — укажи "не указаны")
4. Приступай к Фазе 3

### 2.2 Batch-режим (несколько презентаций)

Если нужны README для нескольких презентаций:

**Формула распределения по агентам:**

| Правило | Значение |
|---------|----------|
| Максимум файлов на агента | 3 (при размере до 160KB каждый) |
| Файлы >500KB | Отдельный агент |
| Combined/сводные файлы | Через агрегацию (НЕ чтение оригинала) |
| Минимум агентов | ceil(количество_файлов / 3) |
| QA-агент | Всегда 1 дополнительный |

**Архитектура команды (2 волны):**

Волна 1 — Worker-агенты (параллельно):
- subagent_type: "general-purpose"
- mode: "bypassPermissions"
- run_in_background: true
- Каждый обрабатывает файлы ПОСЛЕДОВАТЕЛЬНО (read → write → next)

Волна 2 — QA-агент (после завершения Волны 1):
- Читает все созданные README
- Проверяет консистентность (чеклист из references/qa-checklist.md)
- Создаёт README для combined/сводных файлов через агрегацию
- Исправляет мелкие проблемы на месте

**Правила для worker-агентов:**
- Заверши запись README ПЕРЕД чтением следующего файла
- Один файл в контексте за раз
- Используй `ls -la` для реальных размеров файлов
- Отмечай задачу completed через TaskUpdate после завершения
- Сообщи team lead о результатах

**Правила для team lead (главного окна):**
- НЕ читай HTML файлы в главном окне
- Главное окно = диспетчер
- Shutdown агентов сразу после завершения
- TeamDelete после последнего агента

## ФАЗА 3: ГЕНЕРАЦИЯ

### Шаблон README (14 секций)

Используй шаблон из `references/cheatsheet.md`. Каждый README содержит:

1. **Заголовок + описание** — название и 1-2 предложения
2. **Метаданные** — категория, тема, технология, слайдов, статус, даты
3. **Целевая аудитория** — для кого, уровень сложности
4. **Файлы** — таблица с реальными размерами (ls -la)
5. **Технические инструкции** — открытие, конвертация HTML→PDF, редактирование, CSS-селекторы, размер в токенах
6. **Содержание по слайдам** — таблица: номер, заголовок, описание
7. **Краткое саммари** — 3-5 абзацев о ключевых темах
8. **Бренды и модели** — все упомянутые продукты
9. **Бюджетные диапазоны** — ценовые категории (если есть)
10. **Ключевые слова и теги** — для поиска и каталогизации
11. **Связи и зависимости** — перекрёстные ссылки, тематические группы
12. **Сценарии использования** — как агент/клиент использует справочник
13. **Проблемы и ограничения** — что не покрыто, что устарело
14. **История изменений** — changelog

### Правила заполнения

- Все данные — из РЕАЛЬНОГО контента HTML, не выдумывай
- Размеры файлов — через `ls -la`, не приблизительно
- Количество слайдов — считай `div.slide` или `section`
- Бренды — только те, что реально упомянуты
- Цены — только если явно указаны в презентации
- Токены — формула: размер_KB × 300
- Перекрёстные ссылки — на основе тематических групп и реальных пересечений
- Если данных нет — честно пиши "Не указано в презентации"

### Адаптация под технологию

Секция "Технические инструкции" адаптируется:

**Custom HTML/CSS:**
```
Как открыть: браузер, сервер не нужен
Конвертация: Playwright pdf --width=1920 --height=1080
CSS-селекторы: .slide, .slide-title, .content, .slide-number
```

**Reveal.js:**
```
Как открыть: нужен локальный сервер (npm start или python -m http.server)
Конвертация: ?print-pdf → браузер → Print → PDF
CSS-селекторы: .reveal .slides section, section h1/h2
```

## ФАЗА 4: QA-ПРОВЕРКА

### Обязательна для batch-режима, рекомендуется для одиночного

Используй чеклист из `references/qa-checklist.md`:

1. **Структура:** все 14 секций присутствуют
2. **Форматирование:** таблицы корректны, markdown валиден
3. **Данные:** размеры файлов реальные, количество слайдов верное
4. **Связи:** перекрёстные ссылки двусторонние
5. **Группы:** тематические группы корректны и единообразны
6. **Консистентность:** единый стиль во всех README (для batch)

### Если найдены проблемы

- Мелкие (форматирование, опечатки) — исправь на месте
- Серьёзные (неверные данные, пропущенные секции) — перечитай HTML и перегенерируй секцию

## Быстрый старт

### Одиночный README:
1. Прочитай `presentation.html`
2. Определи технологию (Custom HTML/Reveal.js/другое)
3. `ls -la` для размеров файлов
4. Заполни шаблон из `references/cheatsheet.md`
5. Проверь по `references/qa-checklist.md`
6. Запиши `README.md`

### Batch README (много презентаций):
1. Определи количество презентаций
2. Проанализируй файлы и контекст
3. Рассчитай количество агентов: ceil(N / 3) workers + 1 QA
4. Создай команду (TeamCreate)
5. Создай задачи с зависимостями
6. Запусти Волну 1 (workers параллельно)
7. Запусти Волну 2 (QA после завершения)
8. Shutdown + TeamDelete

### Пример промпта для worker-агента:
Смотри `references/example-readme.md` для образца результата.
