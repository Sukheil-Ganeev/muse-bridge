# Опыт скилла: README для презентаций

## Критические уроки (топ-5)

### 1. Batch-генерация: 5 workers + 1 QA = оптимальная архитектура
**Дата:** 2026-02-14
**Контекст:** Генерация 15 README для PC-hardware справочников
**Урок:** Формула ceil(N/3) workers + 1 QA работает идеально. 5 workers параллельно, каждый по 3 файла последовательно. QA после всех. Результат: 0 проблем.

### 2. Файлы >500KB — через агрегацию, не чтение
**Дата:** 2026-02-14
**Контекст:** pc-guides-combined (1.1MB, 218 слайдов)
**Урок:** НЕ читай огромные файлы. QA-агент создал README для combined из данных 14 индивидуальных README. Быстрее и надёжнее.

### 3. Заверши запись ПЕРЕД чтением следующего файла
**Дата:** 2026-02-14
**Контекст:** Workers обрабатывали по 3 файла
**Урок:** Если агент читает следующий HTML до записи README предыдущего — контекст забивается. Строгий порядок: read → extract → write → NEXT.

### 4. ls -la для реальных размеров, не приблизительных
**Дата:** 2026-02-14
**Контекст:** Секция "Файлы" в README
**Урок:** Никаких "~150KB". Только точные размеры через ls -la. Агенты часто ленятся и пишут примерные значения.

### 5. 14 секций — минимум, не максимум
**Дата:** 2026-02-14
**Контекст:** Brainstorming шаблона README
**Урок:** Все 14 секций оказались нужными. QA подтвердил: ни одна секция не была лишней. Если данных нет — пиши "не указано", но секцию сохраняй.
