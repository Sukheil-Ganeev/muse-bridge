## Контекст

За 20+ презентаций 1920x1080 накоплен список повторяющихся ошибок, которые портят визуальное качество. Каждая ошибка была совершена минимум один раз и исправлена по замечаниям пользователя. Этот файл -- список "что НЕ делать".

## Описание

### 1. "Детские анимации" -- пульсирующие кружки, стрелки в кругах

**Проблема:** Пульсирующие кружки (`pulse-ring`), анимированные стрелки в кругах, вертикальные светящиеся линии воспринимаются как непрофессиональные и "детские" на серьёзных бизнес-слайдах.

**Что НЕ делать:**
```css
/* Пульсирующие кольца */
@keyframes pulse-ring { 0% { transform: scale(0.8); opacity: 1; } 100% { transform: scale(1.5); opacity: 0; } }
.pulse-ring { animation: pulse-ring 2s infinite; }

/* Стрелки в кругах */
.arrow-circle { border-radius: 50%; animation: bounce 1s infinite; }
```

**Что делать вместо:** Статичные декоративные элементы -- gradient-divider (1px height), тонкие border-left на карточках, ambient glow blobs (filter: blur). Они добавляют визуальную глубину без "детского" восприятия.

---

### 2. Emoji в карточках вместо реальных фото/SVG

**Проблема:** Emoji-иконки (desert, city, ship) в product-card карточках каталога выглядят непрофессионально в PDF-презентации для бизнеса.

**Что НЕ делать:**
```html
<div class="product-icon">🏜</div>
<div class="product-icon">🏙</div>
<div class="product-icon">🚢</div>  <!-- МОРСКОЙ КРУИЗ != Аренда яхты! -->
```

**Что делать вместо:**
- Реальные фото из Яндекс Диска через MCP (EXP-052)
- Inline SVG иконки (5-10 строк, масштабируемые, стилизуемые)
- CSS-only декоративные элементы (gradient backgrounds, geometric shapes)

---

### 3. Accent-divider без единообразия на слайде

**Проблема:** Когда accent-divider стоит на 2 из 6 карточек, а на остальных 4 его нет -- создаётся визуальный дисбаланс. Глаз "спотыкается".

**Правило:** Accent-divider (или любой декоративный элемент внутри карточки) -- либо на ВСЕХ карточках слайда, либо ни на одной (EXP-047).

---

### 4. Переусердствие с фиксами

**Проблема:** Пользователь просит "чуть подправить" (например, margin побольше), а в ответ переписывается весь блок CSS с множеством изменений. Результат -- новые баги и необходимость откатываться.

**Правило:** Если просят "чуть подправить" -- менять РОВНО 1 параметр:
```css
/* Запрос: "увеличь отступ" */

/* Правильно: */
margin: 16px;  -->  margin: 20px;  /* Только 1 параметр */

/* Неправильно: */
margin: 16px;  -->  margin: 24px;
padding: 20px; -->  padding: 28px;   /* Зачем? Не просили */
font-size: 15px; --> font-size: 17px; /* Зачем? Не просили */
gap: 16px; --> gap: 24px;            /* Зачем? Не просили */
```

---

### 5. Удаление визуальных эффектов при отладке артефактов

**Проблема:** При обнаружении визуального артефакта (например, светящиеся линии от backdrop-filter) начинается последовательное удаление эффектов -- каждое удаление ухудшает презентацию. После 6 итераций файл становится "голым" и приходится пересобирать с нуля.

**Правило:** После 3+ итераций правок -- пересборка с нуля из исходных материалов (план + дизайн-бриф) даёт чистый результат за 1 агента. Пересборка > патчинг.

---

### 6. SVG noise-текстуры через feTurbulence

**Проблема:** SVG `feTurbulence` на каждом слайде раздувает PDF с 7 MB до 17 MB (x2.5). Chromium растеризует SVG filter на полный 1920x1080 для КАЖДОГО слайда (EXP-030).

**Что НЕ делать:**
```css
.slide::after {
    background: url("data:image/svg+xml,...feTurbulence...");
}
```

**Что делать вместо:** CSS ambient glow (`filter: blur(160px)` на div) -- визуально похожий эффект, 0 impact на размер PDF.

---

### 7. CSS gradients на карточках и code-blocks

**Проблема:** `linear-gradient()` на `.card` и `.code-block` раздувает PDF с 3.7 MB до 11 MB (x3). Каждый gradient = отдельный shading-объект в PDF (EXP-038).

**Что делать вместо:**
```css
/* Solid bg + цветной border-top */
.card { background: var(--bg-card); border-top: 2px solid rgba(74,222,128,0.3); }
.code-block { background: #0d1f14; border-left: 3px solid var(--accent-2); }
```

---

### 8. Тёмные терминалы на светлой теме

**Проблема:** Тёмные терминалы (#1E1E2E) на светлом фоне (#FAFAF8) -- визуальный шок. Терминалы доминируют и забирают всё внимание (EXP-029).

**Правило:** На светлой теме -- light terminals (bg: #FDFCF9, border: rgba(0,0,0,0.13), text: #1B1B1B). Терминал = часть темы, не контраст.

---

### 9. box-shadow на тёмном фоне

**Проблема:** На тёмном фоне (#08081a) `box-shadow` создаёт "грязный" вид -- тяжёлый, давящий дизайн (EXP-033).

**Что делать вместо:**
```css
.card {
    border: 1px solid rgba(255,255,255,0.06);  /* тонкий нейтральный бордер */
    /* box-shadow: УБРАТЬ */
}
```

---

### 10. card-fill + three-columns = пустоты

**Проблема:** `.card-fill` (justify-content: space-between) в `.three-columns` с карточками разного объёма -- заголовок вверху, контент внизу, 50% пустоты между (EXP-049).

**Что делать вместо:**
```css
.three-columns.stretch { align-items: stretch; }
.card { /* БЕЗ justify-content: space-between */ }
```

## Когда применять

Перед созданием каждой новой презентации -- прочитать этот список как чек-лист "чего избегать". Особенно актуально при:
- Запросе "улучши" -- не добавлять анти-паттерны ради "красоты"
- Отладке визуальных проблем -- не удалять эффекты, пересобирать
- Оптимизации размера PDF -- проверять gradients, SVG filters, glow
