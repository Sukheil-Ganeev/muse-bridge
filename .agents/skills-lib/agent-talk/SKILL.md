# Agent Talk — Естественное общение между AI-агентами

Пользователь пишет обычным языком. Claude переводит в tmux-bridge команды.

---

## Распознавание триггеров

### Паттерны (любой из них = активация)

### Категория 1 — Прямое обращение (имя + двоеточие или @)

```
codex: проверь auth.ts          gemini: сделай ревью           claude: напиши тесты
@codex проверь auth.ts          @gemini сделай ревью           @claude напиши тесты
кодекс: исправь баг             джемини: проанализируй         клод: объясни код
```

### Категория 2 — Глагол + агент + задача

Любой из этих глаголов + имя ЛЮБОГО агента в любом падеже:

| Глагол | Codex | Gemini | Claude |
|--------|-------|--------|--------|
| напиши | напиши кодексу проверь auth.ts | напиши джемини сделать ревью | напиши клоду написать тесты |
| скажи | скажи кодексу запустить тесты | скажи джемини проанализировать | скажи клоду исправить баг |
| спроси | спроси кодекс что с покрытием | спроси джемини какие баги | спроси клод что с деплоем |
| попроси | попроси кодекс сделать ревью | попроси джемини оптимизировать | попроси клода рефакторинг |
| передай | передай кодексу эту задачу | передай джемини файл | передай клоду контекст |
| отправь | отправь кодексу на проверку | отправь джемини на ревью | отправь клоду задачу |
| делегируй | делегируй кодексу рефакторинг | делегируй джемини тесты | делегируй клоду документацию |
| поручи | поручи кодексу линтинг | поручи джемини написать тесты | поручи клоду ревью PR |
| кинь/скинь | кинь кодексу задачу | скинь джемини это | кинь клоду на проверку |
| перешли | перешли это кодексу | перешли джемини | перешли клоду |

### Категория 3 — "Пусть" / "должен" / "задача для"

```
пусть кодекс проверит тесты         пусть джемини сделает ревью        пусть клод напишет доку
кодексу задача: рефакторинг          джемини задача: тесты              клоду задача: ревью
это задача для кодекса               это задача для джемини             это задача для клода
отдай это кодексу                    отдай это джемини                  отдай это клоду
кодекс должен исправить баг          джемини должен написать тесты      клод должен сделать ревью
кодексу нужно оптимизировать         джемини нужно проанализировать     клоду нужно документировать
```

### Категория 4 — Контекстные (через / в)

```
в кодексе запусти тесты              в джемини запусти анализ           в клоде запусти ревью
через кодекс проверь код             через джемини проверь тесты        через клода проверь PR
сделай через кодекс ревью            сделай через джемини оптимизацию   сделай через клода рефакторинг
```

### Категория 5 — Статус и управление

**Статус (работает для любого агента — подставь имя):**
```
что делает кодекс / джемини / клод?
как там кодекс / джемини / клод?
статус кодекса / джемини / клода
чем занят кодекс / джемини / клод?
занят ли кодекс / джемини / клод?
проверь кодекс / джемини / клод      (без задачи = запрос статуса)
покажи что у кодекса / джемини / клода
```

**Управление:**
```
стоп кодекс / стоп джемини / стоп клод
останови кодекс / останови джемини / останови клод
стопни кодекс / стопни джемини / стопни клод
выруби кодекс / выруби джемини / выруби клод
перезапусти кодекс / перезапусти джемини / перезапусти клод
```

### Категория 6 — Мульти-агент

```
напиши всем: проверьте тесты
скажи обоим запустить линтер
раздай: кодексу код, джемини тесты, клоду ревью
спроси кодекс и джемини что с прогрессом
напиши кодексу и клоду проверить код
пусть джемини и клод оба посмотрят
```

### Категория 7 — English (все три агента)

```
codex: review auth.ts               gemini: analyze test coverage       claude: write documentation
tell codex to fix the bug            tell gemini to run tests            tell claude to review PR
ask codex about coverage             ask gemini about performance        ask claude about architecture
send to codex: refactor auth         send to gemini: write tests         send to claude: review this
codex should handle deployment       gemini should optimize this         claude should document the API
what is codex doing?                 what is gemini doing?               what is claude doing?
stop codex                           stop gemini                         stop claude
```

### Имена агентов (распознавать ВСЕ варианты написания)

| Агент | Варианты написания |
|-------|-------------------|
| Codex | codex, кодекс, кодексу, кодексом, кодекса |
| Gemini | gemini, джемини, джемину, джеминей, гемини |
| Claude | claude, клод, клоду, клодом, клода |
| Любой | имя панели из `tmux-bridge list` |

**Главное правило:** если в сообщении пользователя упоминается имя агента + есть задача или вопрос → это триггер для agent-talk.

## Алгоритм отправки

Когда распознан триггер, выполни ШАГ ЗА ШАГОМ:

### Шаг 1 — Проверить доступность tmux

```bash
tmux-bridge list 2>/dev/null
```

Если ошибка → сообщить пользователю: "tmux не запущен. Запусти `bash ~/start-agents.sh`"

### Шаг 2 — Найти панель получателя

Из вывода `tmux-bridge list` найти панель с нужным LABEL.
Если панель не найдена → сообщить: "[агент] не найден в tmux. Доступные панели: [список]"

### Шаг 3 — Прочитать панель

```bash
tmux-bridge read <target> 20
```

Кратко сообщить пользователю текущее состояние панели (1 строка):
"Codex сейчас: [свободен / выполняет задачу / ждёт ввода]"

### Шаг 4 — Отправить сообщение

```bash
tmux-bridge message <target> "<сообщение>"
```

### Шаг 5 — Проверить доставку

```bash
tmux-bridge read <target> 5
```

Убедиться что текст появился в панели.

### Шаг 6 — Нажать Enter

```bash
tmux-bridge keys <target> Enter
```

### Шаг 7 — Отчёт пользователю

Сообщить кратко:
"Отправлено в codex: [сообщение]. Ответ придёт в эту панель."

## Приём ответов

Когда в панели Claude появляется сообщение вида:
```
[tmux-bridge from:codex pane:%N at:...] текст ответа
```

Claude должен:
1. Распознать это как ответ от агента
2. Показать пользователю: "Codex ответил: [текст]"
3. Спросить нужно ли ответить

---

## Проверка статуса

Паттерны: "что делает codex", "статус codex", "как там codex", "codex занят?"

Выполнить:
```bash
tmux-bridge read <target> 30
```

Интерпретировать вывод и сообщить понятным языком.

---

## Важные правила

1. **НЕ жди ответа.** После отправки — НЕ читать панель получателя в цикле. Ответ придёт сам.
2. **НЕ отправляй сырые tmux-bridge команды пользователю.** Он не программист. Делай всё сам за кулисами.
3. **Подтверждай доставку.** Всегда говори "Отправлено" или "Ошибка".
4. **Переводи сообщение в контекст.** Если пользователь сказал "спроси кодекс что с тестами" — отправь осмысленное сообщение, не дословную фразу. Например: "Check the test coverage status and report any failures."
5. **Язык сообщений между агентами — English.** Codex и Gemini лучше понимают английский. Переводи русские запросы на английский перед отправкой.

## Мультиагент (3+ панели)

Если tmux-bridge list показывает 3+ панели с агентами:

- `напиши всем: [сообщение]` → отправить каждому по очереди
- `спроси кодекс и джемини: [вопрос]` → отправить обоим
- `делегируй кодексу код, джемини тесты` → разные задачи разным агентам

## Быстрые команды — полная таблица (все 3 агента)

### Задачи → Codex

| Ты пишешь | Отправляется |
|---|---|
| `codex: проверь auth.ts` | "Review auth.ts and report issues" |
| `напиши кодексу сделай ревью` | "Do a code review of recent changes" |
| `@codex исправь баг в app.ts строка 42` | "Fix the bug in app.ts at line 42" |
| `скажи кодексу написать тесты` | "Write tests for the current module" |
| `кинь кодексу рефакторинг auth` | "Refactor the auth module" |
| `пусть кодекс займётся деплоем` | "Handle the deployment process" |
| `кодексу задача: линтинг` | "Run the linter and fix all warnings" |
