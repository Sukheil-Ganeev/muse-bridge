# EXP-139: Mass Data Update Workflow for Existing Presentations

**Тип:** PATTERN
**Дата:** 2026-02-28
**Проект:** AI Models Comparison 2026
**Контекст:** Обновление 16-слайдовой презентации с данными за 10 дней (18→28 фев)

## Ситуация
Существующая презентация (93KB, 16 слайдов, Neural Grid тема) содержала данные до 18 февраля. Нужно было обновить до 28 февраля — добавить новые модели, бенчмарки, события по 6 AI-компаниям.

## Решение: Параллельный research → sequential update

### Фаза 1: Параллельный сбор данных (6 агентов одновременно)
1. Агент чтения текущего файла (структура, что уже есть)
2. Агент по Perplexity AI
3. Агент по OpenAI
4. Агент по Google/DeepMind
5. Агент по Anthropic/Claude
6. Агент по xAI/Meta/Mistral/DeepSeek/Cohere

**Важно:** Каждому агенту — чёткие search queries + формат отчёта (дата, фичи, цены, API pricing).

### Фаза 2: Обновление MD-документа (1 агент)
- Все данные от 6 агентов собраны в один промпт
- Детальные инструкции: какие секции обновить, что добавить, что НЕ трогать
- Результат: 923→1497 строк (+574 строк)

### Фаза 3: Обновление HTML-презентации (1 агент)
- Инструкции per-slide: что менять на каждом слайде
- Чёткое указание CSS-классов и паттернов для consistency
- Результат: обновлены 12 из 16 слайдов

### Фаза 4: Конвертация в PDF (1 агент)
- Создание print-ready копии (без анимаций/навигации)
- Playwright конвертация
- Результат: 3.33 MB, 16 страниц

## Метрики
- Общее время: ~30 мин
- Агентов использовано: 9 (6 параллельно + 3 последовательно)
- Токенов: ~500K суммарно

## Урок
Для mass-update лучше всего работает pipeline:
**parallel research → single MD update → single HTML update → PDF convert**

НЕ пытаться обновлять HTML параллельно — один агент должен видеть всю картину для consistency.
