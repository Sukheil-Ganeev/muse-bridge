# EXP-077: Параллельный дизайн командой агентов

## Паттерн
Для массового редизайна нескольких презентаций — использовать команду из специализированных агентов.

## Структура команды (проверено на VIP-DXB, 10 файлов)

### Состав: 6 агентов
1. **researcher** — веб-поиск дизайн-трендов, сбор CSS-техник
2. **designer-alpha** — batch 1 (3 файла)
3. **designer-beta** — batch 2 (3 файла)
4. **designer-gamma** — batch 3 (3 файла)
5. **designer-combined** — 1 большой файл (208 слайдов)
6. **qa-tester** — тестирование всех 10 файлов

### Порядок работы
1. Researcher + все designers запускаются ПАРАЛЛЕЛЬНО
2. Researcher завершается первым, бриф рассылается через broadcast
3. Designers работают автономно (каждый ищет вдохновение + анализирует тему + делает дизайн)
4. QA запускается ПОСЛЕ всех designers (blockedBy)

### Распределение файлов
- Файлы >50KB: max 3 файла на агента (с Grep-based чтением секций)
- Файлы >200KB: 1 файл на агента
- Каждый designer получает конкретное дизайн-направление per file

### Координация
- broadcast: только для критических данных (research brief)
- message: для точечных инструкций конкретному агенту
- TaskUpdate: для отслеживания прогресса
- shutdown_request: после завершения задачи

### Результат VIP-DXB
- 10 уникальных TOC-дизайнов за ~15 минут
- 0 ошибок на QA
- 0 конфликтов при параллельном редактировании (разные файлы)

### Риски
- Два агента могут отредактировать ОДИН файл (как designer-alpha и designer-gamma оба взяли FORM_TICKETS)
- Решение: чёткое распределение файлов, blockedBy зависимости
