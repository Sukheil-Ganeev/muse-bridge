# 09. Группы, каналы, модерация

## Подключение канала/группы как ресурса

Ресурс -- это канал или группа Telegram, подключённая к боту для управления через PuzzleBot.

### Пошаговая инструкция

1. Открыть настройки канала/группы в Telegram > **Администраторы** > **Добавить администратора**
2. Найти привязанного бота, выдать ему **ВСЕ** права администратора
3. Обязательно включить **последний переключатель** (необходим для приглашения юзер-бота)
4. Сохранить изменения
5. **Написать любое сообщение** в ресурс (можно сразу удалить) -- без этого ресурс не появится в списке
6. В личном кабинете PuzzleBot: выбрать бота > **Добавить ресурс** > выбрать появившийся ресурс

### Важные нюансы

- Бот автоматически выйдет из неподтверждённых ресурсов через **20 минут**
- Последний переключатель прав критически важен -- без него юзер-бот не подключится
- Процедура одинакова для каналов и групп
- Зелёный индикатор у ресурса = всё подключено верно, красный = проблема с правами

## Проверка подписки на канал (простая)

Простейший способ -- через блок **Условия** с проверкой **Наличие подписки**.

### Шаги

1. Добавить канал как ресурс (см. выше)
2. Создать команду **Приветствие** с текстом-призывом и инлайн-кнопкой со ссылкой на канал + кнопка **Проверить подписку**
3. Создать **Условие** > проверка **Наличие подписки** > отметить нужный ресурс
4. В действии условия (подписан): переход к команде выдачи контента
5. В **Исключающем правиле** (не подписан): переход к команде "Не подписался" с повторным предложением
6. Кнопку **Проверить подписку** направить на созданное условие

### Через кнопку-условие

Более продвинутый вариант -- кнопка типа **Условия** в инлайн-клавиатуре:

1. Создать кнопку типа **Условия**
2. Проверка: **Наличие подписки** на ресурс
3. Если подписан -- показать кнопку с переходом к контенту
4. Если не подписан -- скрыть кнопку (или показать другой текст)

Кнопка-условие динамически меняет интерфейс: скрывает/показывает элементы в зависимости от статуса подписки.

## Проверка подписки на несколько каналов

Можно проверять подписку на 2, 5, 10 и более ресурсов **одновременно** в одном условии.

### Шаги

1. Подготовить все каналы/чаты: в каждом добавить бота администратором со всеми правами, отправить сообщение
2. Добавить все ресурсы в PuzzleBot
3. Создать команду **Приветствие** с инлайн-кнопками (ссылки на каждый канал) + кнопка **Подписался**
4. Создать **Условие** > проверка **Наличие подписки** > **отметить все нужные ресурсы**
5. В действии (подписан на все): переход к команде **Готово** (подарок/контент)
6. В исключающем правиле: переход к команде **Не подписался** (повторное предложение с зацикливанием)
7. Кнопку **Подписался** направить на условие

Если пользователь подписался только на один из каналов -- проверка НЕ пройдёт. Нужна подписка на **все** отмеченные ресурсы.

## Капча для защиты от спама

Капча проверяет пользователя перед одобрением заявки на вступление в канал/группу.

### Элементы

- **Категория модерации** "Доступ" -- флаг прохождения капчи
- **Пригласительная ссылка** с включённым тумблером **Заявка на вступление**
- **Группа обычных команд** с несколькими вариантами капч
- Действие **Отправить случайную команду из группы**
- **Форма ввода** тип Тестирование с случайным порядком вариантов

### Шаги

1. В **Модерации** создать категорию **Доступ**
2. В Telegram: создать пригласительную ссылку > включить **Заявка на вступление**
3. Создать 4 **инлайн-команды**: Приветствие, Правила, Отправка случайной капчи, Успешное прохождение
4. Создать **группу обычных команд** для капч; внутри -- несколько команд с разными вопросами
5. Каждая капча: форма ввода (изображение) + тип **Тестирование** + варианты (верные/неверные) + **случайный порядок** + поп-ап при ошибке + переход к случайной капче при неверном ответе
6. При верном ответе: отправить команду **Успешное прохождение**; включить **Удалить текущую команду после вызова следующей**
7. Инлайн-команда Успех: кнопка-ссылка на пригласительную ссылку + действие **Изменить категорию** (добавить **Доступ**)

### Настройка событий ресурса

В ресурсе > **События** > **Заявка на вступление**:
- Реакция 1: **Принять заявку** (допнастройки: категория **Доступ** активна)
- Реакция 2: **Отклонить заявку** + отправить стартовую команду + деактивировать категорию

При отклонении категория деактивируется -- пользователь может попробовать заново.

## Приветственные сообщения и триггеры

### Приветствие новых участников

1. Выбрать бота, перейти к подключённому чату
2. Раздел **События** > включить **Приветствие новых пользователей**
3. Нажать **Настроить** > включить реакцию > изменить текст приветствия > сохранить

### Триггеры по ключевым словам

1. Вкладка **Триггеры** > **Добавить триггер**
2. Раскрыть настройки, вписать фразу-условие
3. Тип условия: **Сообщение содержит** (частичное совпадение -- сработает на любое сообщение, содержащее указанную фразу)
4. Тип действия: **Текстовое сообщение** (или **Отправить команду**)
5. Сохранить

Триггеры могут запускать команды бота, изменять переменные, ставить реакции и выполнять другие действия.

## Auto-accept join requests (автоодобрение заявок)

Для автоматического принятия/отклонения заявок по условию:

1. Создать пригласительную ссылку с включённым **Заявки на вступление**
2. В ресурсе > **События** > **Заявка на вступление**
3. Тип действия: **Команда/Условия** > указать команду или условие
4. Для платного доступа: действие **Принять заявку на вступление** с допнастройками -- проверка наличия категории (например, **Активная подписка**)
5. Для бесплатного: действие **Принять заявку** без дополнительных условий

Пользователь переходит по ссылке > подаёт заявку > бот проверяет условие > одобряет или отклоняет автоматически.

## Бизнес-аккаунт (автообработка сообщений)

Бот может отвечать от имени владельца бизнес-аккаунта Telegram.

### Подключение

1. В **BotFather**: MyBots > выбрать бота > **Settings** > **Business Mode** > активировать
2. В настройках Telegram аккаунта > **Telegram для бизнеса** > **Чат-боты** > вставить username бота
3. Обязательно активировать **Ответы на сообщения**
4. В личном кабинете PuzzleBot: добавить появившийся бизнес-аккаунт как ресурс

### Особенности

- Бот отвечает **от имени владельца аккаунта**
- **Ограничение 24 часа**: бот может отвечать только в течение 24 часов с последнего сообщения пользователя
- Команда **Start** отправляется при **первом контакте** (можно изменить через вкладку **События**)
- Бота можно отключить в конкретном диалоге через настройки
- Требуется подписка **Telegram Premium** (Business входит в Premium)

### Настройка триггеров

Триггеры в бизнес-аккаунте настраиваются так же: тип условия **Сообщение содержит** > фразы > действие (отправить прайс, каталог и т.д.).

## Реакции на бусты (Voices)

Бусты (голоса) -- это поддержка, которую подписчики оказывают ресурсам в Telegram.

### Настройка событий

1. Перейти к ресурсу > **События**
2. Настроить реакцию на буст: текстовое сообщение, включить реакцию
3. Настроить реакцию на **забранный голос** / **истечение срока**: текстовое сообщение

### Условие проверки бустов

1. Создать **Условие** > тип проверки **Голос для ресурсов**
2. Выбрать ресурс, указать минимальное количество бустов
3. Основное действие: переход к контенту для бустеров
4. **Исключающее правило**: уведомление + ссылка на буст для мотивации

Ссылка на буст в инлайн-кнопке мотивирует пользователей поддержать ресурс.

## Бот ставит emoji-реакции (3 метода)

### Метод 1: Триггер в ресурсе

1. Перейти к ресурсу > **Триггеры** > **Добавить триггер**
2. Тип сообщения: **Текст**, тип условия: **Сообщение содержит**, добавить ключевые слова
3. Тип действия: **Поставить реакцию** > выбрать эмодзи

### Метод 2: Действие в команде конструктора

1. В любой команде конструктора добавить действие **Поставить реакцию**
2. Выбрать эмодзи
3. Реакция ставится на сообщение пользователя, вызвавшее команду

Пример: в стартовой команде добавить действие **Поставить реакцию** -- бот поставит эмодзи на команду /start.

### Метод 3: Реакция на ответ формы ввода

1. Создать команду с **формой ввода**
2. В настройках формы ввода: добавить **Реакцию на ответ**
3. Выбрать блок **Реакция** > выбрать эмодзи

Реакция ставится на ответ пользователя после заполнения формы.

## Ограничение комментариев только для подписчиков

Используется связка категорий модерации и прав доступа:

1. В **Модерации** чата: категория по умолчанию -- **запретить отправку сообщений**
2. Создать платную категорию -- **разрешить отправку сообщений**
3. При оплате / проверке подписки: присвоить пользователю платную категорию
4. Сценарий для автоматического истечения прав (тип **Через** > вернуть в категорию без прав)

Также можно использовать проверку подписки на канал через группу команд с проверкой подписки на ресурс.

## Модерация заявок через группу (одобрение/отклонение)

### Через мини-приложение с NoCode-таблицей

1. Создать **мини-приложение** для просмотра заявок с переменными из NoCode
2. Добавить **фиксированную клавиатуру**: кнопки **Принять** (зелёный) и **Отклонить** (красный)
3. Создать команды **уведомлений**: одобрение и отказ (текст для пользователя)
4. Создать мини-приложение для пустого состояния (заявок нет)
5. **Условие** "Следующая заявка": проверка наличия переменной > приложение с заявкой / пустое
6. **Условие** "Одобрить": без проверки > отправить команду одобрения другому пользователю (по ID из переменной) > удалить строку из NoCode > перейти к "Следующая заявка"
7. Аналогичное условие **Отклонить**

### Через группу-форум с уведомлениями

1. Создать группу Telegram, включить темы (преобразовать в форум)
2. Создать тему **Новые заявки**
3. В команде уведомления: текст с переменными + инлайн-кнопки (ссылка на диалог, ссылка на ЛС)
4. **Изменить место отправки** > ресурс > выбрать топик
5. Администратор получает уведомления в форум и принимает решения

## Навигация по ресурсам и модерации (из OCR)

### Точные пути навигации

```
Страница бота (dashboard):
├── Тут группа или канал
│   └── Как добавить?
├── Задать вопрос в Поддержку
└── Сообщений: День | Команд: День | Топ пользователей: День | Топ команд: День
```

**Левое меню ресурса (после подключения):**
```
[Имя ресурса]
├── События              (Заявка на вступление, Подписался, Отписался, Новый пост)
├── Триггеры             (Добавить триггер)
├── Модерация            (Категории, пользователи)
└── Постинг              (Посты в ресурс)
```

**Элементы триггера (из OCR):**
- Тип сообщения: `Все` / `Текст`
- Тип условия: `Сообщение содержит`
- Тип действия: `Текстовое сообщение` / `Поставить реакцию` / `Удалить сообщение` / `Отправить команду`
- Параметр: `Для категории` (исключение категорий)
- Подпись: `Любое сообщение` (тип события при настройке подписки)

## Вкладка Модерация (обзор)

Вкладка **Модерация** содержит:

- **Категории пользователей** -- создание, присвоение (вручную или автоматически)
- **Список пользователей** с фильтрацией по категориям (навести на текущую категорию вверху страницы и выбрать нужную)
- **Ручное присвоение**: навести на пользователя > столбец Категория > выбрать
- **Автоматическое присвоение**: через действие **Изменить категории** в команде
- **Замена vs Изменение**: замена заменяет ВСЕ категории, изменение -- только указанные
- **Права доступа** для категорий в ресурсах (разрешение/запрет отправки сообщений)

## Лид-магнит (подарок за подписку)

Лид-магнит привлекает пользователей в канал через подарок за подписку.

### Полная схема

1. Добавить канал как ресурс в PuzzleBot
2. Создать команду **Приветствие**: текст-призыв + инлайн-кнопка со ссылкой на канал
3. Загрузить изображение через бота (команда `/sp`), скопировать **File ID**
4. Создать команду **Подарок**: блок изображения (вставить File ID) или блок документов (PDF)
5. Создать команду с текстом + **тайм-аут** 2 секунды (индикатор печати) + действие перехода к проверке
6. Создать **Условие**: проверка **Наличие подписки** на канал
7. При подписке: отправить команду **Подарок**
8. В **Исключающем правиле**: отправить команду **Не подписан** (повторное предложение)
9. В **стартовой команде**: действие перехода к условию

### Событие подписки на канал

В настройках ресурса (канала) активировать событие **Пользователь подписался на канал** > переход к команде проверки.

Важно: событие подписки сработает **только если пользователь уже запускал бота ранее**.

### Отслеживание трафика для лид-магнита

1. Создать категорию **Просмотр лид-магнит** во вкладке Модерация
2. Во вкладке **Вход** создать **многоразовую ссылку** с привязкой этой категории
3. Создать переменную **Source** для записи источника
4. Условие: проверка наличия категории > запись Source = "Лид-магнит" > переход к проверке подписки

Это позволяет отделять пользователей, пришедших за подарком, от обычных и направлять их по разным воронкам.
