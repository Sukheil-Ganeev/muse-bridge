# 02 -- Формы ввода

Справочный модуль: все типы полей, маски, валидация, регистрация, квизы, уведомления, загрузка файлов.

---

## 1. Создание формы ввода -- базовые шаги

1. Откройте команду в Конструкторе
2. Нажмите **"+"** для добавления блока
3. Выберите **"Форма ввода"**
4. Заполните:
   - **Текст вопроса** -- что увидит пользователь
   - **Название для статистики** -- внутреннее имя (не видно пользователю)
   - **Тип ввода** -- способ получения данных
5. Настройте дополнительные параметры
6. Опубликуйте

---

## 2. Все типы полей

### Отправка сообщения (текст)

Пользователь вводит произвольный текст.

- Применяется для: имени, email, комментария, адреса
- Поддерживает **маски ввода** для валидации
- Переменная формы автоматически сохраняет ответ
- Можно добавить **реакцию на ответ** с подстановкой переменной

### Запрос контакта

Пользователь нажимает кнопку **"Поделиться контактом"** -- бот получает телефон.

- Текст кнопки можно изменить
- Телефон берётся из профиля Telegram
- Самый надёжный способ получить реальный номер

### Тестирование (варианты ответов)

Пользователь выбирает из предложенных вариантов.

- Указываются правильные и неправильные варианты
- Работает в связке с блоком **"Результат"** для подсчёта баллов
- Каждый вариант может вести к **отдельной команде** (действие "Переход к команде")
- Галочка **"Не записывать ответ"** -- для кнопок выхода (чтобы не получать уведомление)

### Опрос

Пользователь выбирает один или несколько вариантов без правильного ответа.

- Используется для сбора предпочтений, обратной связи
- Результаты видны в разделе **Статистика -> Формы ввода**

### Дата

Пользователь вводит дату.

- Формат проверяется автоматически
- Сохраняется в переменную для дальнейших вычислений (AddDate, DaysBetween)

### Время

Пользователь вводит время.

- Формат проверяется автоматически

### Загрузка файла (изображение)

Маска ввода **"Изображение"** -- пользователь отправляет фото.

- ID файла сохраняется в переменную
- Переменную можно использовать в блоке "Изображение" (поле ID файла)
- Применяется для: аватаров, фото документов, фото товаров

### Валюта

Пользователь вводит сумму.

- Автоматическая валидация числового формата

### Адрес / Геолокация

Пользователь отправляет геопозицию или текстовый адрес.

## 3. Маски ввода

Маски ограничивают формат ответа. Если ввод не соответствует маске, пользователь получает **текст ошибки**.

| Маска | Что принимает | Пример |
|-------|--------------|--------|
| **Число** | Только цифры | `250`, `1000` |
| **Телефон** | Номер телефона | `+7999123456` |
| **Email** | Электронная почта | `user@mail.ru` |
| **Ссылка** | URL-адрес | `https://example.com` |
| **Изображение** | Фото/картинка | (файл) |
| **Крипто-кошелёк** | Адрес кошелька | (зависит от сети) |

### Настройка текста ошибки

1. В форме ввода включите маску
2. В поле **"Текст ошибки"** напишите сообщение, которое увидит пользователь при неправильном формате
3. Пример: `"Пожалуйста, введите корректный email-адрес"`

---

## 4. Регулярные выражения для валидации

Для сложной валидации используйте регулярные выражения в маске ввода.

### Примеры regex-масок

```
# Только кириллица (имя)
/^[а-яА-ЯёЁ\s]+$/u

# Телефон в формате +7XXXXXXXXXX
/^\+7\d{10}$/

# Email
/^[\w.-]+@[\w.-]+\.\w+$/

# Число от 1 до 100
/^([1-9]|[1-9]\d|100)$/

# Ровно 6 цифр (пин-код)
/^\d{6}$/
```

### Применение regex к ответам (формулы)

Для разбиения ответа на части после получения:
```
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 0) -- первое совпадение
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 1) -- второе совпадение
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 2) -- третье совпадение
```

## 5. Формы регистрации (многошаговые)

### Простая регистрация (имя + телефон)

1. В команде **Start** добавьте текстовый блок с приветствием
2. Добавьте **форму ввода имени**:
   - Текст: "Как вас зовут?"
   - Название для статистики: "Имя пользователя"
   - Тип: "Отправка сообщения"
   - Реакция на ответ: `"Приятно познакомиться, {{переменная формы}}!"`
3. Добавьте **форму ввода телефона**:
   - Тип: "Запрос контакта"
   - Измените текст кнопки (например: "Отправить номер")
4. Добавьте **завершающий текстовый блок**
5. Между формами добавьте **таймауты** (1-2 сек) для комфортного UX

### Защита от повторного прохождения

В **дополнительных настройках** первой формы ввода:
1. Включите **"Отключить повторное прохождение"**
2. Укажите **команду перенаправления** (например, "Главное меню")
3. При повторном запуске бота пользователь сразу попадёт в меню

### Расширенная регистрация (бот такси)

Цепочка форм для водителя:
1. Ввести имя (текст)
2. Марка авто (текст)
3. Цвет авто (текст)
4. Госномер (текст, в скобках -- пример формата)
5. Телефон (запрос контакта)
6. Фото авто (маска "Изображение")
7. Итоговое сообщение с подтверждением: блок **"Изображение"** с ID из переменной + текст со всеми переменными
8. Действие **"Создать строку"** в Google Sheets

### Проверка регистрации

Создайте условие перед регистрацией:
- **Проверка:** значение переменной `name` НЕ пустое
- **Если заполнено** -> перенаправить в личный кабинет
- **Если пустое (исключающее правило)** -> перенаправить на регистрацию

## 6. Редактирование ответов (исправление ошибок)

### Способ 1: Проверка после каждого ответа

Каждая форма ввода в **отдельной команде**. После ответа -- показ результата + кнопка **"Редактировать"** (ведёт обратно на ту же форму).

### Способ 2: Проверка в конце

1. После всех форм -- вывод всех ответов через переменные
2. Две кнопки: **"Отправить"** и **"Редактировать"**
3. По "Редактировать" -- вопрос "Что исправить?"
4. Каждая кнопка ведёт на свою форму ввода

---

## 7. Квиз / тесты через формы

### Простой тест с подсчётом баллов

1. Создайте 3+ формы ввода с типом **"Тестирование"**
2. В каждой -- вопрос, варианты (правильные/неправильные)
3. Включите **"Удаление формы после ответа"** для чистоты чата
4. Добавьте блок **"Результат"**:
   - Выберите формы для подсчёта
   - Условие 1: сумма от 0 -> "Ошибка" (перенаправление)
   - Условие 2: сумма от 3 -> "Все правильно" (перенаправление)
5. Вставьте **переменную из блока "Результат"** в текст: `"Правильных ответов: {{результат}}"`

> **Важно:** Порядок условий имеет значение. Условие с большим значением (все правильно) должно быть ниже.

### Вариативный квиз (ветвление)

Каждый вариант ответа ведёт к **отдельной команде** с новыми подвариантами:

1. Форма ввода: "Какой тип авто?" -> варианты: Седан, Кроссовер, Спорт
2. Каждый вариант -> **действие "Переход к команде"** -> новая команда с подвариантами
3. Конечные формы -> переход к общей завершающей команде
4. Кнопка "Выход" -- галочка **"Не записывать ответ"**

### Объединение уведомлений (тип "Сложный")

При вариативном квизе пользователь отвечает не на все формы. Чтобы получать одно общее уведомление:

1. Перейдите в **Настройки -> Формы ввода**
2. Создайте правило -> тип **"Сложный"**
3. Укажите **завершающие формы** (после ответа на любую из них квиз считается пройденным)
4. Укажите остальные участвующие формы
5. Вместо отдельных уведомлений на каждую форму придёт одно общее

---

## 8. Тесты через переменные (сложная система)

Для тестов со 100+ вариантами и множеством сфер:

1. Создайте числовую переменную `{{otvet}}` и текстовые `{{sfera1}}`, `{{sfera2}}`
2. В каждую кнопку ответа встройте действие **"Изменить переменную"**
3. В итоговом блоке используйте формулу:
```
{{=if {{otvet}} > 5 ; {{sfera1}} ; {{sfera2}} }}
```

Для очень большого количества вариантов -- вынесите данные в **NocoDB или Google Таблицы**.

## 9. Формы в мини-приложениях (WebApp)

### Форма ввода "Список" из NocoDB

1. В настройках формы ввода **"Список"** выберите:
   - Какой столбец **отображается** пользователю (1)
   - Какой столбец **записывается** в переменную (2)
2. При выборе строки из (1) в переменную записывается значение из (2)
3. Новая интегрированная переменная подтягивает нужные данные, фильтруя по записанной переменной

### Особенность действий "До" в мини-приложениях

Действия "До" выполняются не строго "до", а "между". Если интегрированная переменная не загружается с первого раза:
- Используйте **промежуточное приложение** для изменения переменной и переадресации
- Или получайте данные **скриптом напрямую**, без интегрированной переменной

## 10. Уведомления по ответам формы

### Простой способ (шаблонное уведомление)

1. Перейдите в **Настройки -> Уведомления**
2. Создайте **правило дублирования**
3. Выберите ресурс (группу/канал) для получения уведомлений
4. Формат уведомления -- стандартный, нередактируемый

### Продвинутый способ (кастомное уведомление)

1. Создайте **отдельную команду** для уведомления
2. В команде добавьте текстовый блок с переменными:
   ```
   Новая заявка!
   Имя: {{FIRST_NAME_TEXT}}
   Ответ: {{переменная_формы_ввода}}
   ```
3. Вернитесь в команду с формой ввода
4. В разделе **"Действия"** добавьте **"Отправить команду или условия"**
5. Выберите команду уведомления
6. Поставьте галочку **"Изменить места отправки"**
7. В параметре **"Ресурс"** выберите нужную группу -> **"Добавить"**

> Продвинутый способ позволяет полностью настроить формат: форматирование, кнопки, любые переменные.

### Уведомления в Telegram

Стандартные уведомления об ответах приходят:
- В **Telegram** (push-уведомление)
- На **email**
- В **личный кабинет** PuzzleBot

## 11. Загрузка файлов через /cp

Для загрузки файлов, превышающих лимит ЛК:

1. Откройте вашего бота в Telegram
2. Отправьте `/cp`
3. Выберите **"Загрузить файл"**
4. Отправьте файл (до 2 ГБ)
5. Скопируйте полученный **ID файла**
6. Вставьте ID в блок в личном кабинете

> **Важно:** ID файлов уникальны для каждого бота!

## Элементы интерфейса форм (из OCR)

### Кнопки и тексты в интерфейсе

| Элемент | Контекст |
|---------|----------|
| `Форма: [Название]` | Заголовок формы в уведомлении (например: `Форма: Имя`, `Форма: Телефон`, `Форма: Какую марку предпочитаете?`) |
| `Ответ: [Значение]` | Ответ пользователя в уведомлении |
| `#Форма` | Хештег в уведомлениях о формах |
| `Ответы записаны! Мы свяжемся с вами в ближайшее время!` | Типичный текст подтверждения |
| `Пропустить` | Кнопка пропуска необязательной формы |
| `Посмотреть ответ` | Кнопка в уведомлении для просмотра ответа |
| `Перейти в личный кабинет` | Ссылка в уведомлении |
| `Перейти в меню` | Кнопка возврата в главное меню |

### Навигация: Формы ввода -> Уведомления (из OCR)

Путь настройки уведомлений:
```
Настройки бота → Формы ввода → Создать правило
  Тип: Простой / Сложный
  Указать команды с завершающими формами
  Указать участвующие формы
  → Одно общее уведомление вместо отдельных
```

## 12. Просмотр и управление ответами

### Статистика форм ввода

1. Перейдите на вкладку **"Статистика"**
2. Раздел **"Формы ввода"**
3. Выберите команду с формами
4. Просматривайте все ответы пользователей

### Удаление тестовых ответов

При тестировании бота накапливаются тестовые данные:
1. Вкладка **Статистика** -> **Формы ввода**
2. **Удалить ответы** на нужные формы

## 13. Дополнительные настройки форм

| Настройка | Описание |
|-----------|----------|
| **Возможность пропустить** | Пользователь может не отвечать на вопрос |
| **Отключить повторное прохождение** | При повторном входе -- перенаправление на команду |
| **Удаление формы после ответа** | Форма исчезает из чата (чистота UX) |
| **Реакция на ответ** | Текст, который бот отправляет после ответа (поддерживает переменные) |
| **Текст ошибки** | Сообщение при несоответствии маске ввода |
| **Таймаут** | Задержка перед следующим блоком |
| **Переход к команде** | Автоматический переход после ответа |
| **Ограничение времени** | Минимум 5 сек -- для циклических форм |

## Типичные ошибки

1. **Забыли название для статистики** -- без него невозможно найти ответы в статистике
2. **Не поставили маску** -- пользователь может ввести что угодно
3. **Не отключили повторное прохождение** -- пользователь каждый раз проходит регистрацию заново
4. **Форма ввода на "Неизвестную команду"** -- нельзя напрямую. Используйте прокладку: неизвестная команда -> текст "Попробуйте ещё раз" -> форма ввода в следующей команде
5. **Кнопки формы удаляются после нажатия** -- если нужны постоянные кнопки, используйте обычный блок с инлайн-кнопками, каждая из которых ведёт на команду с формой
