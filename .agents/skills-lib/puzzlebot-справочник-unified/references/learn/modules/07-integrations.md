# 07. Интеграции

## Обзор

PuzzleBot интегрируется с Google Sheets, NocoDB, AmoCRM, Bitrix24, Tilda, ChatGPT, Webhooks и Make (Integromat). Каждая интеграция подключается через **Настройки -> Интеграция**.

---

## Google Sheets

### Подключение

1. Настройки бота -> **Интеграция** -> **Google Sheets**
2. Нажать кнопку авторизации
3. Выбрать Google-аккаунт
4. **Обязательно поставить ВСЕ галочки** при выдаче разрешений
5. Можно подключить несколько Google-аккаунтов

### Подготовка таблицы

- Первая строка -- **заголовки колонок** (обязательно заполнить заранее)
- Создать нужные листы (например: Заявки, Клиенты, Водители)

### Действие "Создать строку"

1. В Конструкторе добавить действие **"Создать строку" (Spreadsheets)**
2. Выбрать таблицу и лист
3. Маппинг колонок к переменным:
   - Колонка "Telegram User ID" -> `{{USER_ID_TEXT}}`
   - Колонка "Username" -> `{{USERNAME_TEXT}}`
   - Колонка "Имя" -> `{{FIRST_NAME_TEXT}}`
   - Колонка "Фамилия" -> `{{LAST_NAME_TEXT}}`
   - Колонка "Дата" -> `{{JOIN_DATE}}`
4. Формат **"Переменный текст"** -- для кликабельных ссылок в таблице

### Действие "Обновить строку"

1. Добавить действие **"Обновить строку"**
2. Указать критерий поиска (столбец + значение переменной)
3. Заполнить поля для обновления
4. Если значение для ячейки не задано -- оно **не изменяется**
5. Операция "Прибавить" -- для накопления сумм

### Условие "Проверить строку"

Проверка наличия записи в таблице:

1. Создать условие -> добавить правило **"Проверка строки"**
2. Выбрать таблицу, лист, столбец для поиска
3. Тип совпадения: **полное совпадение** -> значение `{{USER_ID_TEXT}}`
4. Если найдено -> отправить одну команду
5. **Исключающее правило**: если не найдено -> отправить другую команду

Паттерн "если найдено / если не найдено" -- стандартный для проверки регистрации.

### Интегрированные переменные из Google Sheets

1. Вкладка **Переменные** -> создать переменную
2. Тип значения: **Интегрированное** -> Google Sheets
3. Выбрать таблицу, лист, столбец для поиска, столбец для вывода
4. Настроить фильтры и сортировку
5. **Кэширование** -- обязательно включить при массовых запросах

### Блок "Слайдер" (тип Google Sheets)

Вывод данных из таблицы с фильтрацией:

1. В команде добавить блок **Слайдер** -> тип **Google Sheets**
2. Выбрать таблицу и лист
3. Настроить фильтрацию по столбцу (например, номер = `{{random_number}}`)
4. Настроить отображение (изображение, описание)

### Лимит: 60 запросов в минуту

- Google Sheets допускает **максимум 60 запросов в минуту**
- При массовых рассылках ставить **большое кэширование** везде
- При превышении -- запросы будут отклонены
- Для высокой нагрузки рекомендуется переход на **NocoDB**

## NocoDB

### Обзор

NocoDB -- альтернатива Google Sheets с более высокой скоростью (10 запросов/сек) и хранением данных на собственных серверах PuzzleBot.

**Важно:** Интеграция работает ТОЛЬКО с таблицами на `nocodb.puzzlebot.top` (собственный сервис PuzzleBot), а не с обычным NocoDB.

### Подключение

1. Настройки бота -> **Интеграция** -> **NocoDB**
2. Перейти на `nocodb.puzzlebot.top`, зарегистрироваться
3. Создать базу данных и таблицу с нужными столбцами
4. В настройках аккаунта NocoDB -> **Токены** -> создать и скопировать API-токен
5. Вставить токен в настройках интеграции бота, сохранить

### Типы полей таблицы

- **Число** -- для User ID, сумм, счётчиков
- **Текст** -- для имён, описаний
- **Длинный текст** -- для развёрнутых описаний

### CRUD операции

#### Создать строку

1. Действие **"Создать строку"** в кнопке или команде
2. Выбрать базу и таблицу
3. Заполнить столбцы переменными через `{{переменная}}`

#### Обновить строку

1. Действие **"Обновить строку"**
2. Поиск по столбцу (например, User ID)
3. Заполнить обновляемые поля
4. Операция "Прибавить" -- для накопления сумм

#### Удалить строку

1. Действие **"Удалить строку"**
2. Поиск по критерию (столбец + значение)

#### Проверить строку (условие)

1. Создать условие с правилом "Проверка строки"
2. Выбрать базу, таблицу, столбец, тип совпадения
3. Фильтры: полное совпадение User ID + числовое сравнение (>=, <=)

### Интегрированные переменные из NocoDB

1. Создать переменную -> тип **Интегрированное** -> NocoDB
2. Выбрать базу, таблицу, столбец для вывода
3. Настроить сортировку (по убыванию для топов)
4. Шаблон вывода с переменными
5. Разделитель: `<br>` для HTML или перенос строки для текста
6. Лимит записей

Пример топа участников:
```
Тип: глобальный
Интеграция: NocoDB
Сортировка: по убыванию (баллы)
Лимит: 3
Шаблон: {{имя}} - {{баллы}} баллов
Разделитель: перенос строки
```

### Форма ввода "Список" из NocoDB

В мини-приложении:

1. Форма ввода -> тип **"Список"**
2. Источник: **NocoDB**
3. Настроить: какой столбец **отображается** (1) и какой **записывается** (2)
4. При выборе строки из (1) в переменную записывается значение из (2)

### NocoDB vs Google Sheets

| Параметр | NocoDB | Google Sheets |
|----------|--------|---------------|
| Скорость | Почти моментально | Ограничена |
| Лимит | 10 запросов/сек | 60 запросов/мин |
| Данные | На серверах PuzzleBot | На серверах Google |
| Стоимость | Бесплатно (в рамках PuzzleBot) | Бесплатно |
| Удобство | Базовые таблицы | Формулы, графики |

## AmoCRM

### Подключение

1. Скопировать ссылку на личный кабинет AmoCRM
2. Настройки бота -> Интеграция -> **AmoCRM** -> "Настроить интеграцию"
3. Вставить ссылку, сохранить
4. Нажать **"Авторизоваться через AmoCRM"**, разрешить доступ
5. Настроить поля и переменные (первая строка -- Telegram User ID лиду, вторая -- контакту)

### Синхронизация контактов

- Вкладка **"Контакты"**: включить синхронизацию
- Добавить связки переменных: PuzzleBot <-> AmoCRM
- Двусторонняя синхронизация (исключение -- связки со стрелками = односторонние)
- Несуществующие поля в AmoCRM создаются автоматически

### Лиды (сделки)

Вкладка **"Лиды"**:
- Финальный статус -- когда сделка считается закрытой
- Разрешение нескольких лидов -- один пользователь может иметь несколько сделок
- Игнорирование лидов в финальном статусе
- Уведомления при смене этапа

### Проверки в Конструкторе

| Проверка | Описание |
|----------|----------|
| Наличие лида | Есть ли у пользователя активный лид |
| Статус лида | На каком этапе воронки |
| Значение поля лида | Конкретное значение в поле сделки |
| Наличие контакта | Есть ли контакт в CRM |
| Значение поля контакта | Конкретное значение в поле контакта |

### Действия в Конструкторе

| Действие | Описание |
|----------|----------|
| Создать лид | Новая сделка (воронка, этап, поля) |
| Изменить статус лида | Перевести на другой этап |
| Изменить поля лида | Обновить данные сделки |
| Создать контакт | Новый контакт в CRM |
| Удалить контакт | Удалить контакт |

### Порядок действий

Первым всегда: **создать контакт**, затем -- создать лид, изменить статус, изменить поля.

### Важно

Все действия основаны на **Telegram User ID**. При изменении этого поля в AmoCRM -- действия не выполнятся.

## Bitrix24

### Подключение

1. Настройки бота -> Интеграция -> **Битрикс24** -> "Настроить интеграцию"
2. Создать/войти в аккаунт Битрикс24
3. Скопировать адрес и вставить в PuzzleBot
4. Установить приложение **PuzzleBot** из маркета Битрикс24 (кнопка "Перейти в маркет")
5. Указать поля: Telegram User ID и имя
6. Нажать **"Подключить интеграцию"**

### Синхронизация контактов

- Активировать во вкладке **"Контакты"**
- Пользователи бота отображаются как клиенты CRM

### Создание сделки

1. В Конструкторе добавить действие **"Действие со сделкой"**
2. Тип: **Создать сделку**
3. Выбрать воронку и этап (например, "Общее" -> "Новое")
4. Добавить поля с переменными из форм ввода

### Дополнительные поля

- В Битрикс24 создать дополнительное поле в сделке (тип "строка")
- Данные из форм ввода бота записываются в это поле

## Tilda (мини-приложение)

### Принцип

Открытие сайта Tilda **внутри** мини-приложения Telegram + обработка нажатий кнопок на сайте.

### Подключение

1. Создать сайт на Tilda, скопировать URL страницы
2. В Конструкторе: добавить **ОБЫЧНУЮ клавиатуру** (не инлайн!)
3. Действие кнопки: **"Ссылка в мини-приложении"** -> вставить URL сайта
4. Создать обычные команды с **латинскими** названиями

**Важно:** Используется именно ОБЫЧНАЯ клавиатура. Инлайн-клавиатура не подходит для обработки нажатий на сайте.

### HTML-скрипт для Tilda

1. В Tilda: **Все блоки -> Другое -> HTML-код**
2. Вставить специальный скрипт (из документации PuzzleBot)
3. На кнопках Tilda в поле "Ссылка" вписать:
   ```
   #pbt_cmd название_команды
   ```
4. Названия команд -- **только латиницей**
5. Опубликовать изменения в Tilda

Формат: решётка, pbt, нижнее подчёркивание, cmd, пробел, название команды.

Способ применим к **любому** сайту, не только Tilda.

## ChatGPT

### Подключение через ChatGPT PuzzleBot

1. Настройки бота -> Интеграции -> **Входящие запросы** -> сгенерировать **API-токен**, скопировать
2. Запустить бот **ChatGPT PuzzleBot** в Telegram
3. Нажать "Подключить свой бот к ИИ", вставить API-ключ
4. Скопировать ссылку от бота
5. Настройки -> **Подписки на события** -> Добавить -> вставить адрес
6. Тип события: **"Любое сообщение"**, активировать
7. Во вкладке События **отключить** реакцию на неизвестную команду (временно)

### Система промптов

В ChatGPT PuzzleBot -> настроить **роль бота** (системный промпт):
- Из готовых примеров
- Или написать свой промпт

### Тройная система лимитов

| Лимит | Тип | Описание |
|-------|-----|----------|
| Суточный персональный | Персональная переменная (число, по умолчанию 50) | Запросы одного пользователя в день |
| Суточный глобальный | Глобальная переменная (число) | Общее количество запросов всех пользователей |
| Временной | Блок Timeout + категория | Минимум 1 минута между запросами |

### Реализация лимитов

1. Создать переменные (персональный лимит, глобальный лимит)
2. Создать 3 категории модерации (флаги блокировки)
3. Создать 3 команды-уведомления: "минута не прошла", "лимит исчерпан", "общий лимит закончился"
4. Команда обработки должна называться строго **"gpt if"** (для ChatGPT) или **"mj if"** (для MidJourney)
5. В команде: блок Timeout (время между запросами) + действия с категориями
6. Условие с 4 правилами:
   - Если лимит > 0 -> отправить команду ИИ + активировать категории + уменьшить лимиты
   - Если лимит <= 0 -> мьют + сообщение
   - Проверка частых запросов
   - Проверка глобального лимита
7. В События -> Неизвестная команда -> отправить на условие

## Webhooks

- Метод: GET / POST
- URL endpoint
- Заголовки (Headers)
- Тело запроса с переменными

1. Настройки -> Интеграции -> **Входящие запросы**
2. Сгенерировать API-токен

### Подписки на события

1. Настройки -> **Подписки на события** -> Добавить
2. Указать URL webhook-адрес
3. Выбрать тип события (любое сообщение, определённое событие)
4. Активировать

## Make (Integromat)

### Обзор

Make (ранее Integromat) -- платформа для автоматизации, связывающая PuzzleBot с сотнями сервисов.

### Возможности

- Автоматизация бизнес-процессов
- Генерация QR-кодов
- Интеграция с CRM, таблицами, почтой
- Реакция на события бота
- Минимальный интервал: 15 минут на бесплатном тарифе

### Подключение

Через Webhook:
1. В Make создать сценарий с модулем "Webhook"
2. Скопировать URL вебхука
3. В PuzzleBot: действие "Отправить запрос" с URL вебхука
4. Или: Подписки на события с адресом вебхука

### Альтернативы Make

| Сервис | Минимальный интервал |
|--------|---------------------|
| n8n | 1 минута |
| Google Apps Script | По триггеру или времени |
| Make (Integromat) | 15 минут (бесплатно) |
| Apix-Drive | Простая интеграция без кода |

## Реферальная система

### Архитектура

1. Вкладка **Вход** -> Добавить ссылку -> **Реферальная система**
2. Настроить переменную для генерации уникальной ссылки
3. Скопировать переменную -> вставить в текстовый блок команды

### Переменные реферальной системы

- Переменная реферальной ссылки -- генерирует уникальный URL для каждого пользователя
- Юзернейм создателя последней активированной реферальной ссылки -- глобальная переменная
- Таблица переходов: кто пригласил, кого и когда

### Ограничения

- Количество генераций на пользователя
- Запрет генерации без использования предыдущей
- Ссылки каждый раз генерируются разные (если не ограничено)

### Реализация бонусов за рефералов

1. Создать переменные: баланс без рефералов + баланс за рефералов
2. Условие: проверка -- набрал ли реферал N бонусов
3. Если набрал: действие "Отправить другому юзеру" (по юзернейму создателя ссылки)
4. В новой команде: изменить переменную бонусов реферера

### startPayload (альтернатива)

- Данные после `start=` в ссылке бота: `https://t.me/BotName?start=реферал_123`
- Переменная `{{startPayload}}` содержит "реферал_123"
- Функция `match(startPayload, "PB(.*)")` -- извлечение данных из ссылки
- Используется для UTM-меток, промокодов, реферальных ID

## Навигация по интеграциям (из OCR)

### Точные пути в интерфейсе

```
Настройки бота → Интеграция
├── Google Sheets         (авторизация Google-аккаунта, все галочки)
├── NocoDB               (nocodb.puzzlebot.top, API-токен)
├── AmoCRM               (ссылка на ЛК AmoCRM)
├── Битрикс24            (адрес + установка приложения из маркета)

└── Подписки на события   (URL webhook + тип события)
```

**Текст кнопки в интерфейсе (из OCR):** `Интеграция Puzzle` -- заголовок раздела интеграций.

**Подписки на события -- типы (из OCR):**
- `Форма ввода команд` -- при ответе на форму
- `Любое сообщение` -- все сообщения (для ChatGPT)
- `Вызовы команды или условия` -- при вызове конкретной команды

## Общие принципы интеграций

### Интегрированные переменные

- Тип значения: **Интегрированное** (вместо обычного)
- Источники: HTTP-запрос, Google Sheets, NocoDB
- Формат: JSON для HTTP, столбец для таблиц
- **Кэширование** -- критически важно при массовых запросах
- Проблема: в мини-приложениях действия "До" выполняются не совсем "До", а "Между"
- Решение: переход через промежуточное приложение или получение данных скриптом

### Формат "Переменный текст"

При записи в Google Sheets для кликабельных ссылок (профиль пользователя) используйте формат **"Переменный текст"**.

### Последовательность выполнения

- **До** -- действие выполняется до отправки блоков (рекомендуется для изменения переменных перед запросом)
- **После** -- действие выполняется после отправки блоков

### Рекомендации

- Для высокой нагрузки используйте NocoDB вместо Google Sheets
- Всегда включайте кэширование для интегрированных переменных
- Переменные для интеграции должны быть в **текстовом** формате
- User ID -- неизменный идентификатор, используйте его для всех интеграций
