# FAQ — prompt-engineering-patterns

## Q1: Chain-of-Thought (CoT) vs Zero-shot — когда что использовать?
**Zero-shot** (без примеров) — для простых задач: классификация, извлечение данных, перевод. Модель справляется без наводки. **Few-shot** (с примерами) — когда нужен конкретный формат вывода или задача нестандартная. **Chain-of-Thought** — для задач с рассуждением: математика, логика, многошаговый анализ. Добавьте "Let's think step by step" (zero-shot CoT) или покажите примеры рассуждений (few-shot CoT). CoT увеличивает токены, но значительно повышает точность на сложных задачах.

## Q2: Сколько примеров давать в few-shot?
Оптимально 3-5 примеров. Меньше 3 — модель может не уловить паттерн. Больше 5 — убывающая отдача + расход контекстного окна. Исключения: 1-2 примера достаточно для простого форматирования; 6-10 нужно для сложных задач с множеством edge cases. Примеры должны быть разнообразными (покрывать разные кейсы) и последовательными (одинаковый формат).

## Q3: Как заставить LLM строго следовать JSON-формату?
Комбинация техник:
1. Явная инструкция: "Respond ONLY with valid JSON, no other text"
2. JSON-схема в промпте: покажите точную структуру
3. Few-shot примеры с JSON-выводом
4. Structured output (если API поддерживает): `response_format: { type: "json_object" }` (OpenAI) или `tool_use` (Anthropic)
5. Post-processing: парсинг + валидация + retry при ошибке

## Q4: System prompt vs User prompt — куда что класть?
**System prompt:** роль/персона модели, глобальные правила, ограничения, формат вывода, контекст (знания, факты). Устанавливается один раз, действует на всю сессию. **User prompt:** конкретная задача, входные данные, вопрос. Меняется с каждым запросом. Правило: если инструкция не меняется между запросами — system prompt. Если специфична для запроса — user prompt.

## Q5: Как уменьшить галлюцинации?
1. **Grounding:** предоставьте факты в контексте, скажите "Answer based ONLY on the provided context"
2. **Citation:** попросите ссылаться на конкретные части контекста
3. **Uncertainty:** "If you're not sure, say 'I don't know'"
4. **Verification:** попросите модель проверить свой ответ: "Verify each claim against the source"
5. **Temperature:** снизьте до 0-0.3 для фактологических задач
6. **RAG:** подтягивайте релевантные документы перед генерацией

## Q6: Как работать с длинными контекстами (>100K токенов)?
- Размещайте ключевую информацию в начале и конце промпта (эффект "lost in the middle")
- Используйте XML-теги для структурирования: `<context>`, `<instructions>`, `<examples>`
- Для поиска по документу: дайте явную инструкцию "Find in the document above..."
- Разбивайте на чанки + map-reduce для аналитических задач
- Не полагайтесь на запоминание деталей из середины длинного контекста
