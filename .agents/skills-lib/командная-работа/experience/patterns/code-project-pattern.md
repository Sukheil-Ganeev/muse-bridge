# Code Project Wave Pattern (EXP-CMD-029)

> Паттерн организации команды агентов для кодовых проектов (боты, сервисы, библиотеки).
> Подтверждён: ContentFactory Волны 1-3 (33 агента суммарно, 63 .py файла, 338 тестов, 0 сбоев).

## Когда использовать

- Проект = написание кода (Python, JS, etc.)
- Файлы создаются с нуля или расширяются
- Есть тестовый фреймворк (pytest, jest, etc.)
- НЕ подходит для: справочников, исследований, презентаций, контент-миграции

## Структура волн

```
Wave A: Параллельные impl-агенты (независимые модули)
  ├── Агент 1 → module_a.py
  ├── Агент 2 → module_b.py
  ├── Агент 3 → module_c.py
  └── ПРАВИЛО: 1 файл = 1 агент (никогда 2 агента → 1 файл)

Wave B: Зависимые impl-агенты (ждут Wave A)
  ├── Агент 4 → module_d.py (зависит от module_a)
  └── Агент 5 → module_e.py (зависит от module_b)

Wave C: Параллельно
  ├── Wiring-агент → main.py + __init__.py + imports
  └── Test-агент → test_module_a.py, test_module_b.py, ...

Wave D: Verification
  └── Test-агент сам запускает pytest (или отдельный агент если >7 файлов)
```

## Ключевые правила

### 1. НЕ нужные роли
- research (код пишется по спецификации, не по исследованию)
- critic / advocate (тесты заменяют верификацию)
- technical-writer (документация = отдельная задача)
- presentation (код не презентуется)

### 2. Один файл = один агент
Если 2 задачи модифицируют ОДИН файл → объединить в одного агента.

**Пример ContentFactory Волна 2:**
- Photo→Text нужен `ai_adapter.py`
- AI Generator нужен `ai_adapter.py`
- Решение: объединить в одного агента "photo-text-ai-gen"

### 3. Wiring-агент отдельно
Impl-агенты НЕ трогают:
- `main.py`
- `__init__.py`
- Файлы конфигурации (routes, routers, etc.)

Один wiring-агент:
- Читает ВСЕ новые модули
- Подключает их в main.py / __init__.py
- Обеспечивает единый стиль импортов
- Проверяет совместимость

### 4. Тест-агент = верификатор
- Для кодовых проектов pytest/jest = верификация
- Отдельный verification-агент НЕ нужен
- Тест-агент сам пишет тесты И запускает pytest

**Лимиты одного тест-агента:**
| Параметр | Лимит |
|----------|-------|
| Тестовых файлов | 7 |
| Тестов | ~109 |
| Токенов | ~165K |
| Tool calls | ~57 |
| Время | ~711 сек |

Если больше → разделять на 2 тест-агентов.

### 5. Naming collision в БД
В промпте каждого агента, который создаёт таблицы:
> "Прочитай database.py и проверь существующие таблицы ПЕРЕД созданием своих. Если имя занято, добавь префикс (publication_metrics вместо metrics)."

### 6. Graceful degradation обязателен
В промпте каждого агента:
> "Graceful degradation обязателен: try/except + return None/[] + logging.warning. Если API ключ пуст → warning, не exception."

### 7. Конфиг передавать явно
В промпте агента, создающего main.py:
> "Используй config.GEMINI_API_KEY явно, не надейся что конструктор догадается."

## Промпт-шаблон для impl-агента

```
Создай файл {module_name}.py в {path}/.

Требования:
1. [Конкретная функциональность]
2. Прочитай {dependencies} для понимания интерфейсов
3. НЕ модифицируй main.py или __init__.py
4. Graceful degradation: try/except + return None/[] + logging.warning
5. Если нужна таблица в БД → прочитай database.py, проверь существующие имена
6. Сохрани файл через Write tool

Используй паттерн из {reference_file} как образец.
```

## Промпт-шаблон для wiring-агента

```
Подключи новые модули в проект.

Прочитай ВСЕ файлы в {new_modules_path}:
- {module_1}.py
- {module_2}.py
- ...

Модифицируй:
1. main.py — добавь импорты и инициализацию
2. __init__.py — добавь экспорты
3. Проверь совместимость импортов
4. Используй config.{KEY} явно

НЕ меняй логику существующих модулей, только подключение.
```

## Промпт-шаблон для тест-агента

```
Напиши тесты для новых модулей:
- {module_1}.py → test_{module_1}.py
- {module_2}.py → test_{module_2}.py
- ...

Правила:
1. pytest + unittest.mock (patch, AsyncMock)
2. Каждый модуль = отдельный тестовый файл
3. Минимум 10 тестов на модуль (happy path + edge cases + error handling)
4. Все тесты должны быть изолированными (не зависеть от реальных API)
5. После написания — запусти pytest и убедись что ВСЕ тесты проходят

Запуск: python -m pytest tests/ -v
```
