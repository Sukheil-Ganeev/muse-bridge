# Паттерн оптимизации существующего скилла (Skill Optimization Pipeline)

> Подтверждён в проекте: Docker-справочник 20% -> 100%

## Контекст

Оптимизация существующего скилла -- это НЕ создание с нуля. Контент уже есть, структура уже есть. Задача: довести качество от текущего уровня до 100%. Требует другого pipeline'а, чем создание справочника с нуля.

## Метрики проекта Docker-справочника

| Параметр | Значение |
|----------|----------|
| Агентов | 9 |
| Фаз | 3 (P0 / P1 / P2) |
| Quality Gates | 3 |
| Сбоев | 0 |
| Retry | 0 |
| Контент | ~200KB, 50+ файлов |
| Тип агентов | Обычные субагенты (без team_name), bypassPermissions, run_in_background |
| Успех обычных субагентов | 5/5 проектов подряд = 100% |

## Ключевые инновации

### 1. ПРОМТЫ_АГЕНТОВ.md -- промты в отдельном файле

**Проблема:** Team lead передаёт промпты каждому агенту из главного окна. При 9 агентах промпты занимают огромную часть контекста главного окна.

**Решение:** Создать файл `ПРОМТЫ_АГЕНТОВ.md` с промптами всех агентов. Каждый агент получает только:
- Путь к файлу промтов
- Номер/название своего промпта
- Агент сам читает свой промпт и выполняет задачу

**Результат:** Главное окно остаётся чистым. Team lead тратит ~50 слов на агента вместо ~500.

**Когда использовать:** Проекты с подготовленным планом, где промпты заранее написаны. НЕ подходит для ad-hoc задач.

### 2. Предварительный анализ (analysis-*.md)

**Проблема:** Агенты тратят время и контекст на самостоятельное исследование текущего состояния скилла.

**Решение:** 3 файла анализа создаются ПЕРЕД запуском агентов:
- `analysis-skill-md.md` -- анализ текущего SKILL.md (что есть, чего не хватает)
- `analysis-references-gaps.md` -- пробелы в references/ (какие файлы нужны, какие устарели)
- `analysis-experience-bestpractices.md` -- лучшие практики из experience/ для применения

**Результат:** Агенты сразу знают что делать, не тратят 30-60% контекста на исследование.

### 3. Фазы P0/P1/P2 вместо волн

**Отличие от волн:** Волны (Wave 1, Wave 2...) организованы по ТИПУ работы (исследование, верификация, написание). Фазы P0/P1/P2 организованы по ПРИОРИТЕТУ (критическое, важное, улучшения).

| Фаза | Приоритет | Пример задач |
|------|-----------|--------------|
| P0 | Критическое | Исправления SKILL.md, заполнение пустых references/ |
| P1 | Важное | Дополнения контента, расширение примеров |
| P2 | Улучшения | Полировка experience/, оптимизация формулировок |

**Когда использовать:** Когда базовая структура скилла уже создана и нужно довести до полноты.

### 4. Quality Gates через Explore-агентов

**Проблема:** Quality Gates требуют чтения файлов, что засоряет контекст главного окна.

**Решение:** Запустить Explore-агента (обычный субагент) который:
1. Читает все созданные/изменённые файлы
2. Проверяет по чеклисту (размер, структура, полнота)
3. Сохраняет структурированный отчёт в файл
4. Team lead читает только краткий отчёт (не сами файлы)

**Результат:** Быстро (30-60 сек), не засоряет контекст, даёт GO/NO-GO решение.

### 5. Оптимизация ≠ Создание с нуля

| Аспект | Создание с нуля | Оптимизация |
|--------|-----------------|-------------|
| Волны/Фазы | Wave 1-5 (по типу) | P0/P1/P2 (по приоритету) |
| WebSearch | Да (7 рисерчеров) | Нет (контент из плана) |
| Critic/Advocate | Да (Волна 2) | Нет (Quality Gates достаточно) |
| Маппинг | Волна 0 | Предварительный анализ |
| Промпты | В главном окне | ПРОМТЫ_АГЕНТОВ.md |
| Верификация | Отдельная волна | Explore-агенты на каждом gate |

## Pipeline: Skill Optimization

```
Подготовка:
  1. Предварительный анализ (3 файла analysis-*.md)
  2. Создание ПРОМТЫ_АГЕНТОВ.md

Фаза P0 (критическое):
  3. Запуск агентов P0 (2-3 параллельно)
  4. Quality Gate G1 (Explore-агент)

Фаза P1 (важное):
  5. Запуск агентов P1 (2-3 параллельно)
  6. Quality Gate G2 (Explore-агент)

Фаза P2 (улучшения):
  7. Запуск агентов P2 (2-3 параллельно)
  8. Quality Gate G3 (финальная верификация)
```

## Что НЕ нужно при оптимизации

- WebSearch (контент генерируется из плана/анализа)
- Critic + Advocate (нет спорного контента из интернета)
- Маппинг источник->цель (это не миграция)
- Presentation (это не новый справочник)
- Отдельная волна верификации (Quality Gates достаточно)
