# EXP-CMD-017: DAG-оркестрация исследовательских проектов с презентациями

**Дата:** 2026-02-18
**Проект:** Credit Cards Research (ОАЭ vs Россия)
**Контекст:** 3 MD-документа (ОАЭ, Россия, Сравнение) + 3 HTML→PDF презентации (Gold Vault, Frost Finance, Dual Bridge). 7 агентов: 2 исследователя, 1 аналитик-сравнение, 3 дизайнера презентаций + lead.

## Проблема / Ситуация

В проекте с несколькими исследовательскими документами и презентациями нужно определить оптимальный порядок выполнения задач. Наивный подход: последовательно (исследование ОАЭ → исследование РФ → сравнение → презентация ОАЭ → презентация РФ → презентация сравнения) тратит ~100% больше времени, чем нужно. Полностью параллельный подход невозможен из-за зависимостей (сравнение требует ОБОИХ исследований).

## Решение / Паттерн

### DAG-архитектура зависимостей

```
Исследование ОАЭ ──┬──> Сравнительный документ ──> Презентация "Dual Bridge"
                    │
Исследование РФ  ──┘
       │
       ├──> Презентация "Gold Vault" (ОАЭ) -- блокируется ТОЛЬКО исследованием ОАЭ
       └──> Презентация "Frost Finance" (РФ) -- блокируется ТОЛЬКО исследованием РФ
```

### Ключевые правила

1. **Исследования (веб-поиск + генерация MD) запускать ПАРАЛЛЕЛЬНО** -- нет зависимостей между ними
2. **Сравнительный документ блокируется ОБОИМИ исследованиями** -- addBlockedBy: [task_uae, task_ru]
3. **Презентации блокируются СВОИМ документом, не всеми** -- Gold Vault зависит от исследования ОАЭ, не от РФ
4. Это позволяет **запускать презентацию ОАЭ ДО завершения исследования России**
5. Экономия **~30% времени** vs полностью последовательное выполнение

### Правильный порядок (Brainstorm → Plan → Team)

1. **Сначала brainstorming** для определения структуры и аудитории
2. **AskUserQuestion** для уточнения (аудитория, фокус, опыт, дизайн)
3. **Только после согласования плана** -- создание команды и задач
4. Задачи с зависимостями (addBlockedBy) СРАЗУ при создании

## Результат

- 7 агентов, 3 волны фактического исполнения
- Презентации ОАЭ и РФ начали работу раньше, чем завершился сравнительный документ
- Сравнительная презентация начала работу последней, когда все данные готовы
- 0 конфликтов, 0 простоев, 0 retry

## Правило на будущее

Для исследовательских проектов с N темами:
- Исследования: ВСЕ параллельно (N агентов)
- Перекрёстные документы (сравнения): addBlockedBy на ВСЕ исследования, от которых зависят
- Презентации/отчёты: addBlockedBy ТОЛЬКО на СВОЙ документ
- Порядок: Brainstorm → AskUser → Plan → Create Team + Tasks с DAG
- Оптимальный размер: 1 агент = 1 исследовательская тема, 1 агент = 1 презентация
