# EXP-CMD-027: Analyst -> Builder -> QA = идеальный redesign pipeline

**Дата:** 2026-02-18
**Проект:** AI Models Comparison 2026 -- Neural Grid v2
**Результат:** 38/38 QA PASS, 0 исправлений на этапе QA, файл 92KB

## Контекст

Улучшение HTML-презентации "Neural Grid" (16 слайдов, AI Models & Pricing 2026):
- Русификация всех текстов
- Добавление glassmorphism-эффектов
- Градиентные заливки и анимации
- Исправление отступов и визуальных проблем

Команда: 3 последовательных субагента (analyst -> redesigner -> qa-polisher).

## Архитектура pipeline

```
Волна 1: Analyst (Explore-агент)
  └── Читает текущий HTML
  └── Создаёт _improvement_plan.md:
        - CSS-правки по каждому компоненту
        - Переводы для каждого слайда
        - Список проблем с отступами
        - Рекомендации по glassmorphism + анимациям

Волна 2: Redesigner (general-purpose)
  └── Получает HTML + _improvement_plan.md
  └── Пересобирает файл ЦЕЛИКОМ (не патчит!)
  └── Результат: 92KB HTML

Волна 3: QA-polisher (general-purpose)
  └── Проверяет результат по 38 критериям
  └── Итог: 38/38 PASS, 0 исправлений
```

## Уроки

### 1. Пересборка презентации эффективнее патчинга

Redesigner получил текущий HTML + план улучшений и пересобрал файл целиком.
Результат: 0 ошибок на QA.

**Подтверждает EXP-064:** пересборка > патчинг после 3+ итераций.
Но в данном случае пересборка использована сразу (не после неудачных итераций), что ещё лучше -- предотвращает CSS-мусор с самого начала.

### 2. Analyst перед redesigner = качественный handoff

Отдельный агент-аналитик создал `_improvement_plan.md` с:
- Конкретными CSS-правками (какие свойства менять, какие добавить)
- Переводами по каждому слайду (точные строки RU)
- Списком проблем отступов (где и что исправить)
- Спецификациями glassmorphism и анимаций

Redesigner получил ТОЧНЫЕ инструкции, не тратил контекст на анализ.

### 3. Три волны = оптимальный минимум для redesign

| Волн | Проблема |
|------|----------|
| 1 | Нет плана и нет проверки -- всё на одном агенте |
| 2 | Либо нет плана, либо нет QA -- один из этапов страдает |
| **3** | **Analyst (план) -> Builder (реализация) -> QA (проверка) -- идеальный баланс** |
| 4+ | Избыточно для задачи улучшения одного файла |

Формула идеального результата:

- Опытный builder (со скиллом pdf-презентации, знание glassmorphism)

### 6. Glassmorphism + анимации + PDF совместимость

Проблема: CSS-анимации ломают PDF-экспорт (Playwright).
Решение:
```css
@media print {
  * {
    animation: none !important;
    transition: none !important;
  }
}
```
Анимации работают в браузере, чисто печатаются в PDF.

## Рекомендации

### Для будущих redesign-проектов

1. **Всегда начинай с Analyst** -- даже для "простых" задач. Детальный план окупает 5 минут анализа нулевым количеством ошибок на QA.

2. **Пересборка по умолчанию** -- не патчить существующий файл, а пересобирать целиком. Особенно если:
   - Нужны изменения в CSS-переменных
   - Правки затрагивают >50% слайдов
   - Добавляются новые компоненты (glassmorphism, анимации)

3. **3 волны = стандарт** -- не сокращать до 2 (без QA) и не раздувать до 4+ (избыточно для 1 файла).

4. **@media print в каждую презентацию** -- если есть анимации, всегда добавлять print media query для отключения.

5. **Обычные субагенты** -- продолжать использовать без team_name. 8/8 проектов = стабильный стандарт.

### Формула промпта для Redesigner

```
Контекст: [что за файл, сколько слайдов, текущий размер]
Задача: пересобери файл ЦЕЛИКОМ по плану из _improvement_plan.md
Важно:
- НЕ патчи -- пересобирай с нуля
- Сохрани все существующие элементы, которые не требуют изменений
- Glassmorphism: backdrop-filter + gradient bg + border
- Анимации: @keyframes + @media print { animation: none }
- Переводы: точные строки из плана
```
