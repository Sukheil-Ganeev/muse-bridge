# EXP-CMD-022: Валидация паттернов на зеркальном проекте Debit Cards

**Дата:** 2026-02-18
**Проект:** Debit Cards Research (ОАЭ vs Россия)
**Контекст:** Второй проект сессии — дебетовые карты. Зеркальная копия первого (кредитные карты), но с новыми темами (СБП, Jaywan, овердрафт vs грейс-период) и новыми палитрами.

---

## Урок 1: DAG-паттерн подтверждён как стабильный и воспроизводимый

### Проблема / Ситуация
DAG-паттерн (EXP-CMD-017) был применён впервые в Credit Cards Research. Нужно было подтвердить, что это не разовый успех, а воспроизводимый паттерн.

### Решение / Паттерн
Тот же DAG-паттерн применён второй раз подряд без модификаций:
- 7 агентов (2 исследователя + 1 аналитик + 3 дизайнера + lead)
- Параллельные фазы с зависимостями (addBlockedBy)
- Исследования параллельно, сравнение блокировано обоими, презентации блокированы ТОЛЬКО своим документом

### Результат
- 0 retry в обоих проектах
- Время от запуска до завершения — примерно одинаковое в обоих проектах
- Паттерн подтверждён как **стабильный и воспроизводимый** (2/2 проекта)

### Правило на будущее
DAG-паттерн из EXP-CMD-017 — проверенный стандарт для проектов "исследование + сравнение + презентации". Использовать без модификаций при повторных проектах аналогичной структуры.

## Урок 2: Размер PDF зависит от количества glow-элементов

### Проблема / Ситуация
Размеры PDF-файлов презентаций сильно различались при одинаковом количестве слайдов (14):
- UAE credit: 5.6 MB, Russia credit: 5.4 MB (богатые glow-эффекты)
- UAE debit: 5.0 MB, Russia debit: 1.8 MB
- Comparison debit: 894 KB — подозрительно мало для 14 слайдов

### Решение / Паттерн
Возможные причины разброса:
- Количество и радиус `blur()` в CSS
- Количество inline SVG
- Плотность контента и количество декоративных элементов
- Ambient glow с большим радиусом = больше пикселей при растеризации

### Результат
Выявлена корреляция: больше glow-элементов = больше PDF. Comparison debit (894 KB) — вероятно потерял часть визуальных элементов при конвертации.

### Правило на будущее
**ПРАВИЛО:** После конвертации HTML→PDF ВСЕГДА проверять размер PDF:
- < 1 MB для 14 слайдов с glow = вероятно что-то потерялось, нужна визуальная проверка
- Ожидаемый диапазон для 14 слайдов: 1.5-6 MB (зависит от количества glow)
- Если размер подозрительно мал — открыть PDF и визуально сравнить с HTML

## Урок 3: Зеркальные проекты — шаблонизация промптов ускоряет в 3x

### Проблема / Ситуация
Первый проект (кредитные карты) потребовал полное проектирование промптов для всех 7 агентов с нуля: структура документа, палитры, запреты CSS, Playwright скрипт и т.д.

### Решение / Паттерн
Для второго проекта (дебетовые карты) промпты скопированы и изменены только:
- **Тема** (содержание: дебетовые вместо кредитных)
- **Палитра** (CSS :root — Emerald/Arctic Steel/Twin Streams вместо Gold/Frost/Dual Bridge)
- **Специфичные разделы** (СБП, Jaywan, овердрафт вместо грейс-период, cashback программы)

Всё остальное (структура промпта, запреты CSS, Playwright скрипт, формат документа) — без изменений.

### Результат
Второй проект запустился в **3x быстрее** первого. Время на проектирование промптов сократилось с ~15 минут до ~5 минут.

### Правило на будущее
**ПРАВИЛО:** При серии похожих проектов — копировать промпт предыдущего агента и менять ТОЛЬКО специфику:
1. Тема (содержание)
2. Палитра (CSS :root)
3. Специфичные разделы (уникальные для темы)

Не переписывать с нуля: структуру слайдов, запреты CSS, Playwright скрипт, формат документа, DAG-зависимости.

## Бонус: Серия из 6 тема-палитр

За одну сессию создано 6 уникальных тема-палитр:
| Проект | ОАЭ | Россия | Сравнение |
|--------|-----|--------|-----------|
| Credit Cards | Gold Vault (тёплое золото) | Frost Finance (холодный синий) | Dual Bridge (градиент обоих) |
| Debit Cards | Emerald Banking (изумрудный) | Arctic Steel (стальной) | Twin Streams (два потока) |

**Принцип:** для ОАЭ — тёплые тона (золото, изумруд), для России — холодные (синий, стальной), для сравнения — градиент обоих. Все zero-dependency, одна CSS `:root` на тему.
