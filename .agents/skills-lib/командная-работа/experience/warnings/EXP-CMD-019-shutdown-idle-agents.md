# EXP-CMD-019: Завершение агентов -- не забывать shutdown

**Дата:** 2026-02-18
**Проект:** Credit Cards Research (ОАЭ vs Россия)
**Контекст:** 7 агентов задействовано в проекте. Исследователи завершают работу раньше презентационных агентов.

## Проблема / Ситуация

После завершения задачи агент переходит в idle состояние и продолжает занимать ресурсы (API лимиты, контекст). Team lead получает idle_notification и иногда путает это с ошибкой или пытается "разбудить" агента. Результат: лишний расход контекста диспетчера на обработку idle-уведомлений + занятые слоты API.

## Решение / Паттерн

### Правила shutdown

1. **Как только задача выполнена → shutdown_request** -- не ждать "пока всё закончится"
2. **idle_notification -- это нормальное поведение**, НЕ реагировать на него
3. **Порядок shutdown:**
   - Исследователи: shutdown после создания MD-документа (Gate G1)
   - Аналитик-сравнение: shutdown после создания сравнительного документа
   - Презентационные агенты: shutdown после создания HTML + PDF
4. **TeamDelete только после завершения ВСЕХ агентов**

### Антипаттерны

- НЕ пытаться "разбудить" idle агента сообщением -- он просто ждёт
- НЕ оставлять агента в idle "на всякий случай" -- ресурсы конечны
- НЕ делать TeamDelete пока есть активные агенты

## Результат

- Исследователи завершены сразу после Gate G1 -- освободили 2 слота
- Аналитик завершён после Gate G2 -- освободил 1 слот
- Презентационные агенты завершены по мере готовности PDF
- Контекст диспетчера не засорён лишними idle-уведомлениями

## Правило на будущее

Shutdown по gate-правилу:
- Агент исследования: shutdown после Gate "документ создан"
- Агент аналитики: shutdown после Gate "сравнение создано"
- Агент презентации: shutdown после Gate "PDF создан"
- TeamDelete: только когда ВСЕ агенты завершены
- idle_notification: ИГНОРИРОВАТЬ (это норма, не ошибка)
