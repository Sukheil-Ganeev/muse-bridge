# API командной работы
> Актуально на: 2026-02-21

## TeamCreate
TeamCreate -> team_name: "название"

## TaskCreate
TaskCreate:
  subject: "Краткое описание"
  description: "Полное описание задачи"
  activeForm: "Выполняет задачу..."  # в процессе (present continuous)

## TaskUpdate (зависимости)
TaskUpdate:
  taskId: "1"
  addBlockedBy: ["2", "3"]  # эта задача ждёт задачи 2 и 3

## TaskUpdate (статус)
TaskUpdate:
  taskId: "1"
  status: "in_progress"  # или "completed"
  owner: "имя-агента"

## Запуск тиммейта
Task:
  subagent_type: "general-purpose"
  team_name: "название-проекта"
  name: "имя-роли"
  mode: "bypassPermissions"
  run_in_background: true
  prompt: "Детальный промпт..."

## Сообщение тиммейту
SendMessage:
  type: "message"
  recipient: "имя-роли"
  content: "Текст сообщения"
  summary: "Краткое описание"

## Broadcast (ОСТОРОЖНО -- дорого!)
SendMessage:
  type: "broadcast"
  content: "Критическое сообщение всем"
  summary: "Описание"

## Shutdown
SendMessage:
  type: "shutdown_request"
  recipient: "имя-роли"
  content: "Задача завершена"

## TeamDelete (после всех shutdown)
TeamDelete

## TaskList (мониторинг)
TaskList -- показывает статус всех задач команды.
Используй для проверки прогресса и gate checks.

## TaskOutput (получение результата)
TaskOutput:
  taskId: "1"
  timeout: 300  # секунд (300-600 для тяжёлых задач, 120 по умолчанию)

## Команды тим-лида

### Полный цикл управления командой

| Этап | Команда | Когда |
|------|---------|-------|
| 1. Создание команды | TeamCreate | В начале проекта |
| 2. Создание задач | TaskCreate x N | Перед запуском Волны 1 |
| 3. Настройка зависимостей | TaskUpdate addBlockedBy | После создания всех задач |
| 4. Запуск агентов | Task (run_in_background: true) | Начало каждой волны |
| 5. Мониторинг | TaskList + TaskOutput | В процессе волны |
| 6. Коммуникация | SendMessage | По необходимости |
| 7. Gate check | Explore-агент для проверки файлов | Между волнами |
| 8. Shutdown | SendMessage shutdown_request | После Quality Gate |
| 9. Финализация | TeamDelete | После всех shutdown |

### Создание задач: волна за волной

**Задачи Волны 1 -- создай СРАЗУ (до запуска агентов):**
```
TaskCreate: subject: "architect: structure-plan.md"
TaskCreate: subject: "researcher-1: разделы 1-3"
TaskCreate: subject: "researcher-2: разделы 4-6"
...
```

**Задачи Волн 2-5 -- создай каркас, уточни после architect:**
```
TaskCreate: subject: "critic: проверка исследований"
TaskCreate: subject: "advocate: верификация critic"
TaskCreate: subject: "writer: создание SKILL.md"
...
TaskUpdate: taskId: "critic", addBlockedBy: ["researcher-1", "researcher-2", ...]
```

### Handoff между волнами

Каждый промпт следующей волны ДОЛЖЕН содержать точные пути:

| Откуда | Куда | Что передать | Важно |
|--------|------|-------------|----------|
| Волна 1 | Волна 2 (critic) | Пути к файлам _research/ | "Ищи ПРОТИВОРЕЧИЯ между файлами" |
| Волна 2 (critic) | Волна 2 (advocate) | critic-report.md | "Верифицируй ТОЛЬКО критические и средние" |
| Волна 2 | Волна 3 | ВСЕ файлы + исправления | "Используй ИСПРАВЛЕННЫЕ данные, НЕ исходные!" |
| Волна 3 | Волна 4 | SKILL.md + проектная папка | "Создай презентацию ПО этим файлам" |
| Волна 3 | Волна 5 (qa) | Все файлы скилла | "Проверь ВСЁ" |

**Анти-паттерн handoff:**
- ПЛОХО: "Прочитай все файлы проекта" -- слишком широко
- ХОРОШО: "Прочитай 3 конкретных файла: [путь1], [путь2], [путь3]" -- точно

## Протоколы коммуникации

### Правила коммуникации

1. ВСЕГДА указывай номер задачи (#{ID})
2. ВСЕГДА указывай путь к файлу (полный)
3. summary в SendMessage: 5-10 слов, информативно
4. НЕ отправляй содержимое файлов в сообщениях -- только пути
5. Для broadcast: ТОЛЬКО критические ситуации (gate fail, session shutdown)

### Приоритеты доступа к ресурсам

При конкуренции за ресурсы (API, файл на запись, MCP):

| Приоритет | Кто | Почему |
|-----------|-----|--------|
| ВЫСШИЙ | advocate | Верификация, дорогие вызовы |
| СРЕДНИЙ | critic | Перепроверка |
| НИЗШИЙ | researcher | Основной сбор данных |

### Типы конфликтов и решения

| Ресурс | Пример | Решение |
|--------|--------|---------|
| API с лимитами | Google Maps 15 вызовов | Очередь по приоритету |
| Один файл на запись | SKILL.md | Только 1 агент пишет, остальные читают |
| Один файл на чтение | experience/_index.md | Все могут читать параллельно |
| MCP сервер | Chrome DevTools | Один агент за раз |

## Шаблоны сообщений между агентами

### Отчёт о завершении задачи (teammate -> лидер)

```
Задача #{ID} завершена.
Файл: {ПУТЬ}
Размер: {SIZE} KB
Качество: {самооценка}/10
Проблемы: {нет / список}
```

### Запрос данных (teammate -> teammate)

```
Нужны данные для моей задачи #{ID}.
Что нужно: {описание}
Из какого файла: {путь}
Формат: {таблица / текст / список}
```

### Отчёт об ошибке (teammate -> лидер)

```
Проблема в задаче #{ID}.
Тип: {API error / пустой результат / неполные данные}
Попытка: {1/2/3} из {max}
Действие: {retry / жду указаний / пропускаю}
Детали: {описание}
```

### Подтверждение gate (лидер -> broadcast)

```
Gate G{N} пройден. Запускаю Волну {N+1}.
Файлы для следующей волны: {список путей}
```

### Запрос на shutdown (лидер -> teammate)

```
Задача #{ID} завершена и проверена.
Gate G{N} пройден.
Можешь завершаться. Спасибо!
```

### Эскалация (лидер -> пользователь)

```
Проблема: {описание}
Retry budget исчерпан для {роль}.
Варианты:
1. Продолжить с частичным результатом
2. Запустить в новой сессии
3. Отменить эту часть
```

## Шаблоны промптов для агентов

### Researcher (Волна 1)

```
Ты researcher-{N} в команде "{team_name}".
Задача #{ID}: Исследуй разделы {список}.

Для каждого раздела:
1. WebSearch: "{тема} {раздел} {год}"
2. Минимум 3 источника на раздел
3. Пометь [ТРЕБУЕТ ПРОВЕРКИ] если данные сомнительные

Сохрани: {PROJECT_PATH}/_research/research-{N}.md
Формат: ## Раздел -> ### Подраздел -> текст + источники
Размер: 3-5 KB на раздел

После завершения: SendMessage лидеру с путём и размером файла.
```

### Critic (Волна 2)

```
Ты critic в команде "{team_name}".
Задача #{ID}: Проверь файлы исследований.

Прочитай файлы: {список путей}
Ищи: ПРОТИВОРЕЧИЯ между файлами, устаревшие данные, пропущенные темы.

Для каждой ошибки:
- Уровень: КРИТИЧЕСКАЯ / СРЕДНЯЯ / НИЗКАЯ
- Файл и строка
- Что не так
- Как исправить

Сохрани: {PROJECT_PATH}/_research/critic-report.md
```

### Advocate (Волна 2)

```
Ты advocate в команде "{team_name}".
Задача #{ID}: Верифицируй critic-report.

Прочитай: {PROJECT_PATH}/_research/critic-report.md
Верифицируй ТОЛЬКО критические и средние ошибки.
Для каждой: ПОДТВЕРДИТЬ / ОПРОВЕРГНУТЬ + обоснование.

Сохрани: {PROJECT_PATH}/_research/advocate-verification.md
```

### Technical Writer (Волна 3)

```
Ты technical-writer в команде "{team_name}".
Задача #{ID}: Создай SKILL.md из проверенных исследований.

Прочитай ВСЕ файлы: {список путей}
ИСПОЛЬЗУЙ ИСПРАВЛЕННЫЕ данные из advocate, НЕ исходные!

Сохрани: {PROJECT_PATH}/SKILL.md
Формат: YAML frontmatter + разделы по structure-plan.md
Размер: ~5000 слов
```
