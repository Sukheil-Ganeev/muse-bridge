# Часто задаваемые вопросы
> Актуально на: 2026-02-21

## Quick Start (7 шагов)

1. **TeamCreate** -> team_name
2. **Создать папки** (mkdir _research/, _qa/)
3. **TaskCreate x N** (все задачи волны 1 + каркас волн 2-5)
4. **TaskUpdate addBlockedBy** (зависимости между волнами)
5. **Task x N** (запуск Волны 1, run_in_background: true)
6. **Мониторинг** -> Quality Gate -> Shutdown -> Следующая волна
7. **TeamDelete** после всех shutdown

### Параметры запуска агента

```
subagent_type: "general-purpose"
team_name: "проект"
mode: "bypassPermissions"
run_in_background: true
name: "роль"
```

### Зависимости (пример)

```
Волна 1: tasks 1-7 -> нет blockedBy
Волна 2: task 8 -> blockedBy [1-7], task 9 -> blockedBy [8]
Волна 3: task 10 -> blockedBy [9]
```

## Sizing: Как определить размер команды?

Используй калькулятор из SKILL.md:

### Формула

```
pre_research = 2 if complexity in [medium, high] else 0
researchers = ceil(sections / 2.5)
architect = 1 (всегда)
critic = 1 if verification in [basic, full] else 0
advocate = 1 if verification == full else 0
writer = 1 (всегда)
presentation = 4 if presentation == yes else 0
qa = 1 if verification in [basic, full] else 0
diagrams = 1 if complexity in [medium, high] else 0
templates = 1 if complexity in [medium, high] else 0
interactive = 1 if presentation == yes else 0

TOTAL = pre_research + researchers + architect + critic + advocate + writer +
        presentation + qa + diagrams + templates + interactive
BUFFER = ceil(TOTAL * 0.15)  # 15% запас на фиксы
```

### Входные данные

| Параметр | Вопрос | Варианты |
|----------|--------|----------|
| sections | Сколько разделов? | 6-16 |
| verification | Уровень верификации? | none / basic / full |
| presentation | Нужна презентация? | yes / no |
| complexity | Сложность темы? | low / medium / high |

### Быстрая таблица

| Разделов | Верификация | Презентация | Сложность | Pre-research | Итого агентов |
|----------|-------------|-------------|-----------|-------------|---------------|
| 6 | basic | no | low | 0 | 7 |
| 10 | basic | no | medium | 2 | 11 |
| 10 | full | yes | medium | 2 | 18 |
| 14 | full | yes | high | 2 | 20 |
| 14 | full | yes (слияние) | high | 2 | 18 (как Битрикс24) |
| 16 | full | yes | high | 2 | 24 |

### Размеры команд (кратко)

| Проект | Агентов | Волн |
|--------|---------|------|
| Малый | 3-5 | 2-3 |
| Средний | 8-12 | 3-4 |
| Полный | 18+ | 5 |

## Когда делать shutdown?

После прохождения Quality Gate, НЕ сразу после волны. Между завершением волны и gate агенты могут понадобиться для уточнений. НЕ ДЕРЖИ завершённых агентов -- они забивают ресурсы.

---

## Как восстановить при сбое агента?

1. Проверь выходной файл через Explore-агента (НЕ читай сам)
2. Если файл есть но неполный -> новый агент с промптом: "Продолжи. Готовая часть: [путь]"
3. Если файла нет -> перезапуск с тем же промптом
4. Обнови TaskUpdate: переназначь задачу новому агенту

### Протокол диагностики (ПЕРЕД перезапуском)

1. Проверь: файл создан? (ls через Bash, НЕ читай содержимое)
2. Если файл есть но пуст -> агент стартовал, но не получил задачу (mailbox miss)
3. Если файла нет -> агент не стартовал / упал на ранней стадии
4. Если "Prompt is too long" -> слишком много файлов, раздели задачу

ПОСЛЕ диагностики -- СМЕНИ ПОДХОД:
- Mailbox miss -> переключись на обычный субагент (без team_name)
- Prompt too long -> раздели на 2 агента по 3-4 файла
- Rate limit -> подожди 60 сек, дай другим агентам приоритет

---

## Что делать если контекст заканчивается?

1. НЕМЕДЛЕННО: shutdown всех idle тиммейтов
2. Сгенерируй файл продолжения (ПРОДОЛЖЕНИЕ_ВОЛНА_{N}.md)
3. Сохрани TaskList статус в файл
4. Закрой сессию
5. Открой новую сессию с файлом продолжения

---

## Можно ли объединять роли?

Да, для малых команд. Совместимые роли:

| Роль A | + Роль B | = Объединённая роль | Когда |
|--------|----------|--------------------|----|
| critic | advocate | verifier | Малый проект (<10 разделов) |
| qa-tester | template-creator | qa-templates | Средний проект |
| diagram-designer | template-creator | assets-creator | Средний проект |
| presentation-architect | design-system | presentation-planner | Быстрая презентация |
| design-system | html-css-developer | presentation-builder | Подтверждено Битрикс24 |
| presentation-finalizer | interactive-developer | presentation-polisher | Подтверждено Битрикс24 |

НЕЛЬЗЯ объединять:

| Роль A | + Роль B | Почему нельзя |
|--------|----------|---------------|
| researcher | critic (СВОЙ файл) | Нельзя проверять СВОЙ файл; чужой -- можно |
| architect | researcher | Architect должен видеть общую картину, не детали |
| html-css-developer | interactive | Слишком большой контекст для одного агента |
| technical-writer | researcher | Writer должен работать с ПРОВЕРЕННЫМИ данными |

## Нужна ли верификация для малых проектов?

Да, верификация ОБЯЗАТЕЛЬНА. Формат по масштабу:
- < 6 файлов = 1 verifier (совмещённый critic+advocate)
- >= 6 файлов = отдельные critic + advocate

В первом проекте нашли 7 критических ошибок -- верификация себя окупает.

---

## Тиммейты или обычные субагенты?

По умолчанию -- ОБЫЧНЫЕ СУБАГЕНТЫ (Task без team_name):
- Получают промпт напрямую (не через mailbox)
- Завершаются чисто (нет idle-спама)
- Проверено на 5 проектах: субагенты = 100% успех

Тиммейты нужны ТОЛЬКО когда:
- Агенты должны общаться между собой (SendMessage)
- Нужна двусторонняя координация в реальном времени
- Есть сложные зависимости требующие обмена данными между агентами

В проектах gaming-guides и puzzlebot тиммейты ПРОВАЛИЛИСЬ (0 файлов), обычные субагенты -- 100% успех.

## Что делать если TaskOutput пуст?

TaskOutput может вернуть пустой результат, хотя агент реально завершил работу и создал целевой файл. Это НЕ значит что агент упал.

1. НЕ перезапускай агента сразу
2. Проверь целевой файл напрямую: запусти Explore-агента
3. Если файл на месте и не пуст -- задача выполнена, продолжай
4. Если файла нет -- тогда перезапускай

## Какой retry budget у агентов?

| Роль | Max повторов | Всего попыток |
|------|-------------|--------------|
| Исследователь | 2 | 3 |
| Critic/Advocate | 1 | 2 |
| Writer | 1 | 2 |
| Presentation | 2 | 3 |
| QA/Diagrams | 1 | 2 |

Если retry budget исчерпан: сохрани что агент успел, запиши проблему в _qa/failures.md, продолжай с частичным результатом, пометь [INCOMPLETE].

## Система приоритетов при нехватке ресурсов?

**P0 -- НЕЛЬЗЯ ПРОПУСТИТЬ:**
- Волна 1 (исследование) -- без данных нет проекта
- Волна 2 (верификация) -- без проверки данные ненадёжны
- Волна 3 (написание) -- это основной результат

**P1 -- ПРОПУСТИТЬ = ПОТЕРЯ КАЧЕСТВА:**
- QA-тестер -- ошибки останутся
- Diagram-designer -- нет визуализации
- Quality Gates -- возможны сбои

**P2 -- МОЖНО СДЕЛАТЬ ПОЗЖЕ (в другой сессии):**
- Презентация (Волна 4) -- можно добавить потом
- Template-creator -- шаблоны не критичны
- Interactive-developer -- интерактивность = бонус

### Минимальная жизнеспособная команда (MVP)

| Этап | Агентов | Кто |
|------|---------|-----|
| Исследование | 3-4 | researchers (объединить разделы) |
| Верификация | 1 | critic-advocate (совмещённая роль) |
| Написание | 1 | technical-writer |
| **ИТОГО MVP** | **5-6** | **Без презентации и QA** |

### Решение по ходу

Если после Волны 2 контекст > 60%:
- Запусти technical-writer
- Сгенерируй файл продолжения
- Презентацию и улучшения -- в новой сессии

Если после Волны 3 контекст > 60%:
- Сгенерируй файл продолжения
- Всё остальное -- в новой сессии

## Как работает Pre-Research протокол?

Перед Волной 1 запусти 1-2 агента для сбора контекста (если тема новая / незнакомая):

1. **Агент анализа примеров** -- читает существующие справочники/скиллы, извлекает структуру
2. **Агент исследования темы** -- WebSearch по теме, сбор основных фактов
3. Оба запускаются ПАРАЛЛЕЛЬНО (run_in_background: true)
4. Результаты сохраняются в {PROJECT_PATH}/_research/pre-research/
5. Architect получает эти файлы как INPUT для structure-plan.md

Timeout для TaskOutput: 300 секунд (pre-research агенты легковесные).

## Золотые правила (топ-5)

1. **Главное окно = диспетчер.** Не читай файлы >5KB. Если контекст кончится -- ВСЯ РАБОТА ПРОПАДЁТ.
2. **Верификация обязательна.** < 6 файлов = 1 verifier, >= 6 = critic + advocate.
3. **Shutdown после Quality Gate**, не после волны.
4. **Задачи Волны 1 -- сразу**, Волны 2-5 -- уточнить после architect.
5. **Детальные промпты** -- каждый агент должен знать ЧТО делать, КУДА сохранить, КАКОЙ формат.
