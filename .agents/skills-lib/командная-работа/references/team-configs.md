# Конфигурации команд

> Источник: SKILL.md -- секции "Адаптация под проект", "Слияние ролей", "Приоритеты при нехватке ресурсов", "Контент-миграция", "Презентация из исследования"

Справочник по составу команд для разных масштабов проекта.
Включает типовые конфигурации, специализированные варианты и правила миграции между размерами.

---

## Как определить размер команды

| Критерий | Малая (3-5) | Средняя (8-12) | Полная (18+) |
|----------|-------------|-----------------|--------------|
| Источников данных | 2-3 | 4-6 | 7+ |
| Выходных файлов | 3-5 | 6-10 | 15+ |
| Требуется презентация | Нет | Опционально | Да |
| Требуется верификация | Базовая | Стандартная | Полная |

---

## Малая команда (3-5 агентов)

### Когда использовать

- Проект с 6-8 разделами
- Знакомая тема (low complexity)
- Нет презентации
- Ограниченные ресурсы или deadline

### Состав

| # | Роль | Задача | Волна |
|---|------|--------|-------|
| 1 | architect | structure-plan.md | 1 |
| 2-3 | researcher (x2-3) | По 2-3 раздела каждый | 1 |
| 4 | verifier | critic + advocate (совмещённая роль) | 2 |
| 5 | technical-writer | SKILL.md + references/ | 3 |

### Волновая структура

```
Волна 1: architect + 2-3 исследователя (параллельно)
   ↓ Gate G1 (файлы на месте, >1KB)
Волна 2: verifier (critic+advocate в одном агенте)
   ↓ Gate G2 (0 критических)
Волна 3: technical-writer
   ↓ Gate G3 (файлы созданы)
ЗАВЕРШЕНО
```

### Особенности

- Verifier объединяет critic + advocate -- допустимо при <10 разделах
- Без QA, без диаграмм, без шаблонов
- Презентация и улучшения -- в следующей сессии (если потребуются)
- Минимум зависимостей, быстрое выполнение

### Пример: скилл на 6 разделов

```
Волна 1 (параллельно):
  - architect: structure-plan.md
  - researcher-1: разделы 1-3
  - researcher-2: разделы 4-6

Волна 2 (последовательно):
  - verifier: проверяет все 3 файла, critic-report + advocate

Волна 3:
  - writer: создаёт SKILL.md + references/

Итого: 5 агентов, 3 волны
```

## Средняя команда (8-12 агентов)

### Когда использовать

- Проект с 8-12 разделами
- Средняя сложность (medium complexity)
- Опциональная презентация
- Стандартная верификация

### Состав

| # | Роль | Задача | Волна |
|---|------|--------|-------|
| 1 | architect | structure-plan.md | 1 |
| 2-5 | researcher (x4-6) | По 2-3 раздела каждый | 1 |
| 6 | critic | critic-report.md | 2 |
| 7 | advocate | advocate-verification.md | 2 |
| 8 | technical-writer | SKILL.md + references/ | 3 |
| 9 | qa-templates | QA + шаблоны (совмещённая) | 4-5 |
| 10 | assets-creator | Диаграммы + шаблоны (совмещённая) | 4-5 |

### Волновая структура

```
(Pre-research: 2 агента -- если medium/high complexity)
   ↓
Волна 1: architect + 4-6 исследователей (параллельно)
   ↓ Gate G1
Волна 2: critic → advocate (последовательно)
   ↓ Gate G2
Волна 3: technical-writer
   ↓ Gate G3
Волна 4-5: qa-templates + assets-creator (параллельно)
ЗАВЕРШЕНО
```

### Пример объединения ролей

| # | Роль | Объединяет | Экономия |
|---|------|------------|----------|
| 5 | verifier | critic + advocate | -1 агент (если <10 разделов) |
| 7 | qa-templates | qa-tester + template-creator | -1 агент |
| 8 | assets-creator | diagram-designer + template-creator | -1 агент |

### Пример: скилл на 10 разделов

```
Pre-research (параллельно):
  - analyzer: анализ существующих примеров
  - web-researcher: WebSearch по теме

Волна 1 (параллельно):
  - architect: structure-plan.md
  - researcher-1: разделы 1-3
  - researcher-2: разделы 4-5
  - researcher-3: разделы 6-8
  - researcher-4: разделы 9-10

Волна 2:
  - critic: проверка всех файлов
  - advocate: верификация критических ошибок

Волна 3:
  - writer: SKILL.md + references/

Волна 5 (параллельно):
  - qa-templates: тестирование + шаблоны
  - assets-creator: диаграммы

Итого: 2 (pre) + 5 (W1) + 2 (W2) + 1 (W3) + 2 (W5) = 12 агентов
```

## Полная команда (18+ агентов)

### Когда использовать

- Масштабный проект: справочники, базы данных, 14+ разделов
- Высокая сложность (high complexity)
- Обязательная презентация
- Полная верификация (critic + advocate)
- Нужны QA, диаграммы, шаблоны, интерактивность

### Состав

| # | Роль | Задача | Волна |
|---|------|--------|-------|
| 0a | pre-research-analyzer | Анализ примеров | Pre |
| 0b | pre-research-web | WebSearch по теме | Pre |
| 1 | architect | structure-plan.md | 1 |
| 2-8 | researcher (x7) | По 2 раздела каждый | 1 |
| 9 | critic | critic-report.md | 2 |
| 10 | advocate | advocate-verification.md | 2 |
| 11 | technical-writer | SKILL.md + references/ | 3 |
| 12 | presentation-architect | Структура презентации | 4 |
| 13 | design-system | Стили и CSS | 4 |
| 14 | html-css-developer | Вёрстка HTML | 4 |
| 15 | presentation-finalizer | Финальная полировка | 4 |
| 16 | qa-tester | QA-отчёт | 5 |
| 17 | diagram-designer | Диаграммы | 5 |
| 18 | template-creator | Шаблоны | 5 |
| 19 | interactive-developer | Интерактивность | 5 |
| +2-3 | fix-agents | Исправления по ходу | любая |

### Волновая структура

```
Pre-research: 2 агента (параллельно)
   ↓
Волна 1: architect + 7 исследователей (параллельно)
   ↓ Gate G1 (все файлы >1KB)
Волна 2: critic → advocate (последовательно)
   ↓ Gate G2 (0 критических неразрешённых)
Волна 3: technical-writer
   ↓ Gate G3 (SKILL.md + references/)
Волна 4: presentation-architect → design-system → html-css-developer → presentation-finalizer
Волна 5: qa-tester + diagram-designer + template-creator + interactive-developer (параллельно)
   (Волны 4 и 5 могут стартовать параллельно -- обе зависят от Волны 3)
ЗАВЕРШЕНО
```

### Вариант со слиянием ролей (18 -> 15-16 агентов)

| Стандартная роль | Слияние | Объединённая роль |
|-----------------|---------|-------------------|
| design-system + html-css-developer | -> | presentation-builder |
| presentation-finalizer + interactive-developer | -> | presentation-polisher |
| qa-tester + template-creator | -> | qa-templates |

Экономия: 3 агента. Подтверждено проектом Битрикс24 (QA 8.5/10).

### Пример: проект Битрикс24 (14 разделов)

```
Pre-research (параллельно):
  - analyzer: анализ существующих справочников
  - web-researcher: WebSearch по Битрикс24

Волна 1 (параллельно):
  - architect: structure-plan.md (14 разделов)
  - 7 исследователей: по 2 раздела каждый

Волна 2:
  - critic: нашёл 27 ошибок
  - advocate: подтвердил 13, ложных срабатываний 9 (33%)

Волна 3:
  - writer: 198K токенов (предел для 1 агента)

Волна 4 (со слиянием):
  - presentation-architect: структура
  - presentation-builder: design + html (слияние)
  - presentation-polisher: finalizer + interactive (слияние)

Волна 5 (параллельно):
  - qa-tester, diagram-designer, template-creator

Итого: 18 агентов (2 pre + 8 W1 + 2 W2 + 1 W3 + 3 W4 + 3 W5 = 19, -1 слияние)
Запущено: 20+ (с fix-агентами)
Пересессий: 0
```

## Специализированные конфигурации

### Контент-миграция (формат A -> формат B)

Когда данные трансформируются из одного формата в другой.
Подтверждено в проекте bot-migration (2026-02-16).

| Волна | Задача | Агенты | Артефакты |
|-------|--------|--------|-----------|
| 0 (подготовка) | Маппинг источник->цель + шаблоны выхода | 1 mapper | mapping.md + templates/ |
| 1 (конвертация) | Параллельно по сегментам, макс 10 файлов/агент | 2-4 конвертера | Файлы в целевом формате |
| 2 (QA + фиксы) | Верификация + исправление | 1 verifier + 1 fixer | Исправленные файлы |

Особенности:
- БЕЗ WebSearch (все данные локальные)
- 1 verifier достаточно (вместо critic + advocate)
- Маппинг в Волне 0 ОБЯЗАТЕЛЕН -- корректирует оценку масштаба
  (bot-migration: 43 оценка vs 27 реальных = экономия 37%)
- >10 файлов на агента = разделяй на 2
- Рекомендуемый размер: 3-6 агентов + 1 fixer

Пример (bot-migration):
- Волна 0: mapper создал маппинг WhatsApp -> Telegram + шаблоны
- Волна 1: 3 конвертера (Dubai-1: 9 карточек, Dubai-2: 9, Other Emirates: 9)
- Волна 2: verifier нашёл 7 ошибок (15%), fixer исправил

### Презентация из исследования (конвейер)

Когда нужна презентация из множества исходных файлов (>10 файлов / >200KB).
Подтверждено в проекте "Обмен Валюты" (2026-02-18).

| Этап | Агент | Задача | Артефакт |
|------|-------|--------|----------|
| 1 | researcher | Чтение всех исходных файлов | content_brief.md |
| 2 | presenter | Создание HTML-презентации | presentation.html |
| 3 | debugger | QA через Chrome DevTools MCP | скриншоты + отчёт |
| 4 (опц.) | animator | CSS @keyframes + JS trigger | presentation_animated.html |
| 5 (опц.) | debugger | QA анимаций | скриншоты + отчёт |

Особенности:
- ПОСЛЕДОВАТЕЛЬНЫЙ конвейер -- каждый агент зависит от предыдущего
- Researcher ОБЯЗАТЕЛЕН если >10 файлов / >200KB
- Рекомендуемый размер: 3 основных + 2 анимация + 1 lead = 6 участников

## Миграция между размерами

### Когда масштабировать вверх (малая -> средняя)

| Сигнал | Действие |
|--------|----------|
| Разделов оказалось больше (8+) | Добавь исследователей |
| Найдены критические ошибки (>5) | Добавь отдельного advocate |
| Нужна презентация | Добавь 2-4 презентационных агента |
| Тема сложнее ожидаемого | Добавь pre-research + diagrams |

### Когда масштабировать вниз (полная -> средняя)

| Сигнал | Действие |
|--------|----------|
| Контекст > 60% после Волны 2 | Пропусти презентацию (P2), сохрани файл продолжения |
| API-лимиты исчерпаны | Объедини роли, сократи researcher-ов |
| Deadline жёсткий | MVP команда: 5-6 агентов |
| Writer на пределе (>190K токенов) | Раздели writer на 2 агента |

### Решение по ходу проекта

```
Если после Волны 2 контекст > 60%:
  -> Запусти technical-writer
  -> Сгенерируй файл продолжения
  -> Презентацию и улучшения -- в новой сессии

Если после Волны 3 контекст > 60%:
  -> Сгенерируй файл продолжения
  -> Всё остальное -- в новой сессии
```

## Приоритеты при нехватке ресурсов

### P0 -- НЕЛЬЗЯ ПРОПУСТИТЬ

- Волна 1 (исследование) -- без данных нет проекта
- Волна 2 (верификация) -- без проверки данные ненадёжны
- Волна 3 (написание) -- это основной результат

### P1 -- ПРОПУСТИТЬ = ПОТЕРЯ КАЧЕСТВА

- QA-тестер -- ошибки останутся
- Diagram-designer -- нет визуализации
- Quality Gates -- возможны сбои

### P2 -- МОЖНО СДЕЛАТЬ ПОЗЖЕ (в другой сессии)

- Презентация (Волна 4) -- можно добавить потом
- Template-creator -- шаблоны не критичны
- Interactive-developer -- интерактивность = бонус

## Минимальная жизнеспособная команда (MVP)

Для проектов с жёсткими ограничениями по ресурсам:

| Этап | Агентов | Кто |
|------|---------|-----|
| Исследование | 3-4 | researchers (объединить разделы) |
| Верификация | 1 | critic-advocate (совмещённая роль) |
| Написание | 1 | technical-writer |
| **ИТОГО MVP** | **5-6** | **Без презентации и QA** |

MVP даёт: скилл + проектная папка. Презентацию и QA -- в следующей сессии.
