# Make.com -- Часто задаваемые вопросы (FAQ)

---

## Основы

### 1. Как создать первый сценарий?

1. Зайти на make.com -> Dashboard -> **Create a new scenario**
2. Нажать **+** -> выбрать первый модуль (триггер)
3. Создать **Connection** (авторизовать сервис)
4. Добавить action-модули (действия)
5. Настроить **маппинг** данных между модулями (панель справа)
6. Нажать **Run once** (тестовый запуск)
7. Проверить результат -> **Toggle ON** -> **Save**

### 2. Как считаются операции и сколько их нужно?

**Формула:** `Операции/мес = Платных модулей x Bundles x Запусков/день x 30`

1 модуль + 1 bundle = 1 операция. Если модуль обрабатывает 10 строк -- это 10 операций.

**Бесплатные модули (0 ops):** Router, Filter, Iterator, Repeater, Set/Get Variable, Sleep, Error handlers.

**Пример расчета:** Сценарий с 3 платными модулями, 5 bundles, запускается 10 раз в день = 3 x 5 x 10 x 30 = 4,500 ops/мес.

### 3. Чем отличаются триггеры: Instant vs Scheduled?

**Instant (Webhook):** Мгновенная реакция по событию (< 1 сек). Экономит операции -- не тратит на пустые проверки. Пример: Telegram Watch Updates.

**Scheduled (Polling):** Проверяет по расписанию (каждые 1-15 мин). Тратит операцию на каждую проверку, даже если новых данных нет. Пример: Google Sheets Watch Rows.

**Правило:** Если сервис поддерживает webhook -- всегда выбирайте Instant.

### 4. Какой тариф выбрать?

- **Free ($0, 1K ops):** Для тестирования, 2 активных сценария, интервал 15 мин
- **Core ($9, 10K ops):** Для малого бизнеса, неограниченные сценарии, интервал 1 мин
- **Pro ($16, 10K ops):** Cron scheduling, 60 дней истории, 5 параллельных выполнений
- **Teams ($29, 10K ops):** Командная работа, 180 дней истории

Для туристического бизнеса в ОАЭ рекомендуется **Core**.

## Настройка и подключение

### 5. Как подключить Telegram-бота к Make.com?

1. Создать бота через @BotFather в Telegram (`/newbot`)
2. Скопировать token (формат: `123456789:ABCdef...`)
3. В Make.com: добавить модуль Telegram -> Watch Updates
4. Создать Connection -> вставить Bot Token
5. "Run Once" -> отправить сообщение боту -> данные появятся в модуле

### 6. Как подключить Google Sheets?

1. Добавить модуль Google Sheets -> выбрать действие
2. Создать Connection -> авторизоваться через Google OAuth 2.0
3. Выбрать Spreadsheet (файл) и Sheet (лист)
4. Если есть заголовки -- данные маппятся по именам колонок: `{{1.Name}}`, `{{1.Email}}`

### 7. Как настроить Webhook?

1. Добавить модуль **Webhooks -> Custom webhook**
2. Нажать **Add** -> дать имя -> **Save**
3. Скопировать URL (формат: `https://hook.eu1.make.com/...`)
4. Нажать **Run Once** -> отправить тестовый запрос на URL (curl, Postman, сервис)
5. Make автоматически определит структуру данных
6. Данные доступны для маппинга в следующих модулях

### 8. Как подключить OpenAI/ChatGPT?

1. Получить API Key на platform.openai.com -> API Keys
2. В Make.com: добавить модуль **OpenAI -> Create a Completion (Chat)**
3. Создать Connection -> вставить API Key
4. Настроить: Model (gpt-4o-mini для бюджета), System Prompt (инструкции), User Message (входные данные)
5. Результат: `{{2.choices[0].message.content}}`

### 9. Как подключить WhatsApp Business?

1. Создать Meta Business Account
2. Настроить WhatsApp Business API (Meta Developer Console)
3. В Make.com: модуль WhatsApp Business Cloud API -> Watch Messages
4. Подключить через Meta Access Token
5. Номер формат: `79991234567` (без +, без пробелов)
6. Помнить: 24-часовое окно для свободных сообщений, вне окна -- только Templates

## Работа с данными

### 10. Как передать данные между модулями (маппинг)?

Кликнуть в поле настройки модуля -> открывается панель маппинга справа -> выбрать переменную из предыдущих модулей.

Синтаксис: `{{1.fieldName}}` (где 1 = номер модуля).
Вложенные: `{{1.data.user.name}}`.
Со спецсимволами: `` {{1.`Имя клиента`}} ``.

### 11. Как работать с массивами (Iterator/Aggregator)?

**Iterator** разбивает массив на отдельные элементы (bundles). Каждый элемент обрабатывается отдельно. `{{i}}` = индекс, `{{length}}` = всего. **0 операций.**

**Aggregator** собирает bundles обратно в один результат: Array Aggregator (массив), Text Aggregator (строка), Numeric Aggregator (сумма/среднее). **1 операция.**

**Паттерн:** Get данные -> Iterator -> Обработка каждого -> Array Aggregator -> Bulk операция.

### 12. Как использовать Data Stores?

Data Store -- встроенная база данных в Make.com. Scenario -> Data Stores -> Add data store -> задать Structure (поля).

**Модули:** Add/Replace a record, Update a record, Get a record, Search records, Delete a record, Delete all records.

**Применения:** кеширование (курсы валют), очереди (отложенные задачи), маппинги (ID связки между системами), логирование, конфигурация.

### 13. Как настроить Router с фильтрами?

1. ПКМ на линию между модулями -> **Add a Router**
2. Router создает параллельные ветки
3. На каждую ветку: клик на "гаечный ключ" -> **Set up a filter** -> задать условие
4. Ветка без фильтра = fallback (выполняется если ни один фильтр не подошел)
5. Если несколько фильтров подходят -- выполнятся ВСЕ подходящие ветки

## Оптимизация

### 14. Как оптимизировать расход операций?

**Топ-5 техник:**
1. **Bulk операции:** Google Sheets Bulk Add Rows = 1 op вместо N (экономия в 100 раз)
2. **Webhook вместо Polling:** 0 ops в ожидании vs 288 ops/день (polling каждые 5 мин)
3. **Aggregator вместо N действий:** собрать данные -> 1 отправка
4. **Data Store кеширование:** справочники обновлять по расписанию
5. **Conditional execution:** Router с фильтрами -- ненужные ветки не тратят ops

**Правило 80/20:** найти 20% сценариев, которые тратят 80% операций, и оптимизировать их.

### 15. Как экспортировать/импортировать сценарий (Blueprint)?

**Экспорт:** Открыть сценарий -> Menu (...) -> Export Blueprint -> сохранится JSON файл.

**Импорт:** Create new scenario -> Menu (...) -> Import Blueprint -> выбрать JSON.

Blueprints используются для: шаринга сценариев, бэкапа, версионирования, миграции между организациями.

При импорте нужно переподключить Connections (они не экспортируются по соображениям безопасности).

### 16. Как настроить расписание запуска?

Открыть сценарий -> кликнуть на часы (Scheduling) внизу:
- **At regular intervals:** каждые N минут (1 мин -- 24 часа)
- **Once:** один раз в указанное время
- **Every day/week:** конкретные дни и время
- **Cron expression (Pro+):** для сложных расписаний

**Совет:** для экономии операций запускайте реже в нерабочие часы.

## Обработка ошибок

### 17. Как обработать ошибки в сценарии?

1. ПКМ на модуль -> **Add error handler**
2. Выбрать директиву:
   - **Resume** -- продолжить с подставленными данными
   - **Break** -- прервать и сохранить для retry (Incomplete Executions)
   - **Rollback** -- откатить все операции
   - **Ignore** -- просто пропустить ошибку
3. Можно добавить модули после error handler (логирование, уведомление)

**Паттерн для алертов:** Error Handler -> HTTP POST -> webhook алерт-сценария -> Telegram "Ошибка в сценарии X: {описание}".

### 18. Почему копятся Incomplete Executions?

Incomplete Executions появляются когда используется директива **Break** (или включен "Allow storing incomplete executions" в настройках сценария).

**Решения:**
- Настроить auto-retry (Break -> Advanced -> Auto retry)
- Ручная обработка: History -> Incomplete Executions -> Retry / Delete
- Исправить корневую причину ошибки (проверить Connection, формат данных)

## Продвинутое

### 19. Как использовать HTTP модуль для любого API?

1. Добавить **HTTP -> Make a request**
2. Настроить: URL, Method (GET/POST/PUT/DELETE), Headers, Body
3. Body Type: Raw (JSON) для API, Multipart для файлов, URL-encoded для форм
4. Authorization: добавить в Headers `Authorization: Bearer {token}` или `X-API-Key: {key}`
5. Результат: `{{X.data}}` (ответ), `{{X.statusCode}}` (HTTP код)
6. Если JSON не парсится автоматически: добавить **JSON -> Parse JSON** после HTTP

**Пример Telegram API:**
```
POST https://api.telegram.org/bot{{TOKEN}}/sendMessage
Body: {"chat_id": "123", "text": "Hello"}
```

### 20. Как создать AI-агента на Make.com?

1. **System Prompt:** описать роль, правила, ограничения
2. **Tools:** каждый tool = отдельный Make-сценарий с Webhook (поиск данных, создание записей и т.д.)
3. **Memory:** short-term (контекст текущего диалога), long-term (Data Store с историей)
4. **Архитектура:** Webhook (user message) -> OpenAI (с описанием tools) -> Router -> вызов нужного Tool-сценария -> ответ
5. Макс 10-15 tools на агента

### 21. Как использовать функции в формулах?

**Синтаксис:** `{{functionName(arg1; arg2)}}` -- разделитель `;` (точка с запятой!), не запятая.

**Вложенность:** `{{upper(substring(1.email; 0; indexOf(1.email; "@")))}}` -- извлечь username из email в верхнем регистре.

**Частые формулы:**
- Условие: `{{if(1.status = "active"; "Активен"; "Неактивен")}}`
- Дефолт: `{{ifempty(1.phone; "Не указан")}}`
- Дата Дубай: `{{formatDate(now; "DD.MM.YYYY HH:mm"; "Asia/Dubai")}}`
- Конвертация: `{{multiply(1.priceAED; 0.27)}}` (AED -> USD)
- Разбить строку: `{{split(1.tags; ",")}}` -- строка в массив

### 22. В чем разница между Set Variable и Data Store?

| Характеристика | Set Variable | Data Store |
|----------------|-------------|------------|
| Область действия | Текущее выполнение | Постоянное хранение |
| Персистентность | Пропадает после выполнения | Сохраняется между запусками |
| Операции | 0 (бесплатно) | 1 за каждую операцию |
| Применение | Промежуточные вычисления | Кеш, маппинги, очереди, конфиг |
| Лимит | 100 переменных | Free 500 records, Core 10K |

### 23. Как настроить мониторинг сценариев?

1. **Встроенные:** Organization -> Settings -> Notifications (email при ошибках, автовыключении, истекших connections)
2. **Telegram алерты:** Создать отдельный сценарий: Error Handler в основном -> HTTP POST на webhook алерт-сценария -> Format -> Telegram Send
3. **Health Checks:** Сценарий каждый час: Test Connections -> Check Data Stores -> Verify Webhooks -> Alert if problems
4. **Dashboard:** Google Sheets или Notion с метриками: success/error rate, операции, топ ошибок

### 24. Как связать PuzzleBot с Make.com?

PuzzleBot поддерживает Webhooks для отправки данных:
1. В Make.com создать **Custom Webhook** -> скопировать URL
2. В PuzzleBot: настроить Webhook -> вставить URL Make.com
3. При событии (новый пользователь, заказ, форма) PuzzleBot отправит данные на webhook
4. Make.com получит данные и выполнит сценарий (запись в CRM, уведомление, AI-обработка)

Альтернативно: использовать Telegram Bot модуль в Make.com напрямую (если бот подключен и к PuzzleBot, и к Make).
