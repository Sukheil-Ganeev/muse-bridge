# Optional backend evaluation gates

The attached user vision names OpenHands (agent execution), OpenViking (agent context database), Cognee and Microsoft GraphRAG (graph/RAG), and LlamaIndex (retrieval composition). Official documentation changes; verify current primary docs before choosing or installing a version. Presence in a plan is not runtime integration.

Run only a bounded public/synthetic or already authorized Marsel development fixture first. Record exact version, license, runtime dependencies, model and embedding provider, RAM/disk/network needs, how source IDs/evidence and unknown scope survive ingestion, query correctness, cost and rollback. Reject a backend that loses provenance, merges people by phone, promotes unknown content to seller facts, or silently transmits personal text.

Do not configure the OpenViking Codex hook or an OpenHands automation until the exact endpoint, model/reasoning, report route, source scope, local binding and one-writer ownership are tested. An OpenViking setup needs an embedding model and a VLM provider; a semantic answer from the current chat is not an embedding vector. Prefer reusing the project's working SQLite/FTS/graph and existing Muse/Codex execution adapters unless a bounded benchmark shows a material improvement.

No public port by default. New service ports bind localhost; external publication follows the owner's Docker/ufw rule. External API spend and production sends keep their existing authority gate.
