## Критические уроки (топ-14)

> Читать при каждой активации скилла!

### 1. Интернет-данные НЕНАДЁЖНЫ -- Волна 2 (critic + advocate) ОБЯЗАТЕЛЬНА
**Проблема:** При создании Notion и NocoDB справочников ОБА исследователя ошибались в ценах. NocoDB advocate нашёл 4 несуществующие функции из блогов. Цены, функции, лицензии устаревают каждые 3-6 месяцев.
**Решение:** НИКОГДА не пропускать Волну 2. Advocate отдельно проверяет: цены (на официальном сайте), лицензию (на GitHub), ключевые интеграции (в official docs). Каждую цену помечать [ПРОВЕРЕНО] или [ТРЕБУЕТ ПРОВЕРКИ].
**Влияние:** Без Волны 2 writer копирует ошибки в финальный справочник. Notion critic: 10 противоречий + 13 [ТРЕБУЕТ ПРОВЕРКИ]. NocoDB critic: 19 противоречий + 4 фактические ошибки. WARN-008, FIX-009.

### 2. Critic -- попарное чтение, Writer -- последовательное чтение
**Проблема:** Чтение всех 7-9 файлов сразу вызывает context overflow у агентов.
**Решение:** Critic: читать research-файлы попарно по смежным темам, записывать находки сразу. Writer: сначала structure-plan + critic-report + advocate-verification, затем для КАЖДОГО раздела отдельно: прочитать research-N -> написать -> следующий.
**Влияние:** Предотвращает потерю данных из-за переполнения контекста. PAT-011.

### 3. `.slide > *` ломает position:absolute у декоративных элементов
**Проблема:** Общий CSS-селектор `.slide > *` применяет стили ко ВСЕМ дочерним элементам слайда, включая декоративные (bg-glow, slide-decor-*, slide-number), ломая их position:absolute.
**Решение:** Использовать `:not()` селектор -- `.slide > *:not(.bg-glow):not(.slide-decor-circle):not(.slide-number)` или задать общий класс `.slide-decor` и исключить его.
**Влияние:** Без этого фикса декоры налезают на контент или исчезают. EXP-091, EXP-097.

### 4. 4 волны / 13 агентов -- оптимальный формат для справочников без презентации
**Проблема:** Оригинальный план (5 волн, 15+ агентов) избыточен, если презентация не нужна.
**Решение:** Волна 1 (6-7 исследователей) -> Волна 2 (critic + advocate) -> Волна 3 (writer) -> Волна 4 (QA + diagrams + templates параллельно). 12 разделов -- золотое количество.
**Влияние:** Позволило создать 2 справочника за одну сессию (~70 мин суммарно). IMP-006.

### 5. Главное окно = ТОЛЬКО диспетчер, 2 справочника за сессию -- предел
**Проблема:** Чтение больших файлов в главном окне заполняет контекст, и управление командой становится невозможным.
**Решение:** Ни одного большого файла в главном окне. Вся работа через субагентов. Между проектами -- shutdown всех агентов. Максимум 2 справочника за сессию.
**Влияние:** 26 субагентов (13+13) успешно управлялись из одного окна без переполнения. PAT-011.

### 6. Скилл >7000 слов = 1 агент на 1 скилл при рефакторинге (EXP-099)
**Проблема:** 2 тяжёлых скилла (11,551 + 9,227 = 20,778 слов) на одном агенте → провал: один вырос на 430 слов, другой без изменений.
**Решение:** >7000 = 1 скилл/агент, 5500-7000 = 2/агент, <5500 = до 4/агент.
**Влияние:** Предотвращение провала рефакторинга и бесполезной траты вычислительных ресурсов.

### 7. Аудит после рефакторинга: карта секций + grep сущностей (EXP-100, EXP-101)
**Проблема:** Агент может агрессивно сократить скилл (7,892→1,346 слов), потеряв ~3,000 слов контента.
**Решение:** Двухэтапная верификация: (1) карта секций бэкап→текущий, (2) grep 20+ ключевых сущностей по всем файлам. Бэкап ДО рефакторинга обязателен.
**Влияние:** Обнаружение и восстановление потерянного контента. 3 скилла восстановлены с 0% потерь.

### 8. Дедупликация = главный источник сокращения (EXP-102)
**Проблема:** SKILL.md содержал полные копии контента, уже существующего в references/. Фото-редактор: 11,981 слов, vercel: 7,708 слов.
**Решение:** Проверяй existing references ПЕРЕД переносом нового контента. Порядок: (1) ls references/, (2) grep дубликатов в references/, (3) удалить из SKILL.md найденные дубликаты, (4) перенести остатки.
**Влияние:** Подтверждено: фото-редактор 11,981→2,700 (-77%), vercel 7,708→2,841 (-63%). Дедупликация даёт больший эффект, чем перенос нового контента.

### 9. 1 скилл = 1 агент при ЛЮБОМ размере (EXP-103)
**Проблема:** В партии 1 некоторые агенты получали 2 скилла — результат: 6/8 успешных (2 провала из-за переполнения контекста).
**Решение:** Строго 1 скилл на 1 агента, независимо от размера. Даже маленькие скиллы лучше обрабатывать отдельно.
**Влияние:** Партия 2: 7/7 агентов = 0 сбоев (100% успех vs 75% в партии 1).

### 10. Оптимизация существующего скилла != создание с нуля (EXP-104)
**Проблема:** Стандартный pipeline (4 волны: исследование -> critic/advocate -> writer -> QA) избыточен для оптимизации существующего скилла. Critic/advocate не нужен когда контент из knowledge base, а не из интернета.
**Решение:** Pipeline оптимизации: анализ пробелов (analysis-*.md) -> фазы P0/P1/P2 по приоритету -> QA. Файл ПРОМТЫ_АГЕНТОВ.md хранит все промты централизованно -- агенты читают свою секцию сами, экономя контекст главного окна.
**Влияние:** Docker-справочник: 20% -> 100% покрытие. SKILL.md 3096 -> 4516 слов, references 3/8 -> 8/8, templates 0 -> 8, examples 0 -> 25 файлов. ~40% времени от создания с нуля.

### 11. DAG-зависимости для справочников по связанным темам (EXP-CMD-017)
**Проблема:** При создании справочников по N связанным темам + сравнительный документ + презентации, последовательное выполнение тратит ~30% лишнего времени. Презентация по теме A не зависит от исследования темы B.
**Решение:** Исследования параллельно (1 агент = 1 тема), сравнение блокировано ОБОИМИ исследованиями, презентации блокированы ТОЛЬКО своим документом. Brainstorm -> AskUser -> Plan -> Team + DAG с addBlockedBy.
**Влияние:** Credit Cards Research: 7 агентов, экономия ~30% времени. Презентации ОАЭ и РФ начали работу до завершения сравнительного документа.

### 12. Детальная структура документа в промпте исследователя (EXP-CMD-018)
**Проблема:** Без детальной структуры исследователь пишет "обзорную статью" вместо справочника -- поверхностный текст без таблиц, конкретных чисел, практических рекомендаций.
**Решение:** Промпт обязательно содержит: (1) все разделы и подразделы, (2) язык + объём (~3000 слов) + формат (MD с таблицами), (3) специфика аудитории, (4) маркировка [ТРЕБУЕТ ПРОВЕРКИ]. Тип агента: general-purpose. 1 агент = 1 тема, строго.
**Влияние:** Оба справочника Credit Cards получились структурированными с таблицами сравнения карт и практическими рекомендациями для целевой аудитории.

### 13. Контекстный документ КОНТЕКСТ-*.md для межсессионной передачи (EXP-CMD-019)
**Проблема:** При завершении большого проекта (6+ файлов) вся информация о структуре, палитрах и решениях остаётся в контексте сессии. Новая сессия начинает с нуля -- заново исследует файлы, восстанавливает палитры, вспоминает решения.
**Решение:** При завершении проекта с 5+ файлами ВСЕГДА создавать КОНТЕКСТ-{project}.md: (1) структура файлов (полные пути), (2) палитры (CSS :root), (3) ключевые находки, (4) архитектурные решения, (5) TODO для следующей сессии.
**Влияние:** Экономия ~15-20 минут на каждый проект при продолжении в новой сессии. Без документа новая сессия рискует потерей принятых решений.

### 14. Шаблонизация промптов для зеркальных справочников -- ускорение 3x (EXP-CMD-019)
**Проблема:** Первый справочник серии требует полного проектирования промптов: структура документа, палитры, запреты CSS, Playwright, формат (~15 мин). Повторять для каждого проекта -- потеря времени.
**Решение:** Копировать промпт предыдущего агента, менять ТОЛЬКО 3 элемента: (1) тему (содержание), (2) палитру (CSS :root), (3) специфичные разделы (уникальные для темы). НЕ менять: структуру слайдов, запреты CSS, Playwright, формат документа, DAG-зависимости, формулу команды.
**Влияние:** Debit Cards запустился в 3x быстрее Credit Cards. Время проектирования: ~15 мин -> ~5 мин. 0 retry в обоих проектах. Первый проект серии = шаблон для всех последующих.

| 2 | Детальная структура в промпте исследователя | EXP-CMD-018 | Все разделы/подразделы + аудитория + формат. Без структуры = "обзорная статья" |

### Паттерн: Research + Presentation DAG Pipeline для справочников

Для справочников по N связанным темам с презентациями:
1. **Brainstorm:** Темы, аудитория, стиль презентаций
2. **AskUser:** Уточнить предпочтения
3. **DAG задачи:** Все задачи сразу с addBlockedBy
4. **Исследования:** N параллельных агентов (general-purpose + WebSearch), детальная структура в промпте
5. **Сравнение:** 1 агент, addBlockedBy = все исследования
6. **Презентации:** N+1 агент, addBlockedBy = ТОЛЬКО свой документ. CSS :root палитра + Playwright в промпте
7. **Shutdown:** По gate-правилу после каждого артефакта
