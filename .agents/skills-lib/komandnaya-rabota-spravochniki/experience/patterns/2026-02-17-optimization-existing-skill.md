# EXP-104: Паттерн оптимизации существующего скилла (отличается от создания с нуля)

**Дата:** 2026-02-17
**Проект:** Оптимизация Docker-справочника (20% -> 100%)
**Категория:** pattern

## Проблема

Стандартный pipeline создания справочника (4 волны: исследование -> critic/advocate -> writer -> QA) избыточен для ОПТИМИЗАЦИИ существующего скилла. Существующий контент не нужно исследовать в интернете -- нужно определить ПРОБЕЛЫ и заполнить их.

## Ключевые отличия от создания с нуля

| Аспект | Создание с нуля | Оптимизация существующего |
|--------|-----------------|---------------------------|
| Начало | Исследование (6-7 агентов) | Анализ пробелов (analysis-*.md) |
| Волна 2 | Critic + Advocate обязательны | НЕ нужен если контент из knowledge base |
| Приоритеты | Все разделы равны | P0/P1/P2 по важности |
| Источник контента | Интернет (ненадёжный) | Existing knowledge base (надёжный) |
| Промпты | В каждом task | В ПРОМТЫ_АГЕНТОВ.md (централизованно) |

## Решение: Pipeline оптимизации

### 1. Анализ пробелов (заменяет pre-research волну)
- 3 файла analysis-*.md: (1) текущее состояние, (2) целевое состояние, (3) план фаз
- Агенты читают ТОЛЬКО свой analysis-файл + текущий SKILL.md

### 2. Фазы P0/P1/P2 (заменяют единую волну исследования)
- **P0 (critical):** SKILL.md + ядро references/ (cheatsheet, faq, troubleshooting)
- **P1 (high):** templates/, examples/ -- практический контент
- **P2 (nice-to-have):** scripts/, experience/, дополнительные references/

### 3. ПРОМТЫ_АГЕНТОВ.md (экономия контекста)
- Один файл хранит ВСЕ промты централизованно
- Каждый агент читает ТОЛЬКО свою секцию (## Агент-N: название)
- Главное окно НЕ содержит длинных промтов -- только ссылку на файл

### 4. Critic/Advocate НЕ нужен когда:
- Контент генерируется из knowledge base (не из интернета)
- Нет спорных фактов (цены, лицензии, совместимость)
- Всё верифицируется по official docs

## Влияние

Оптимизация существующего скилла занимает ~40% времени от создания с нуля, при этом результат может быть ЛУЧШЕ (т.к. основа уже проверена). Pipeline: analysis -> P0 -> P1 -> P2 -> QA.
