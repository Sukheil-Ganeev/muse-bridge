# EXP-102/103: Дедупликация перед рефакторингом

**Дата:** 2026-02-17
**Проект:** Волна 5, партия 2

## Проблема
При рефакторинге скиллов (сокращение SKILL.md до ≤5000 слов) обнаружено, что некоторые SKILL.md содержали ПОЛНЫЕ КОПИИ контента, уже существующего в references/.

## Масштаб дупликации
| Скилл | SKILL.md | После дедупликации | Экономия |
|-------|----------|-------------------|----------|
| фото-редактор-промты | 11,981 | 2,700 | -77% |
| vercel-деплой | 7,708 | 2,841 | -63% |
| netlify-deployment | 9,227 | 3,175 | -66% |

## Причина
При создании справочников writer копировал контент из research-файлов в SKILL.md, а затем тот же контент дублировался в references/ (cheatsheet, faq, troubleshooting). Со временем SKILL.md "распух" из-за двойного хранения.

## Решение: Порядок проверки при рефакторинге
1. `ls references/` — посмотри что уже есть
2. Для каждого блока в SKILL.md — grep в references/
3. Если НАЙДЕН дубликат → удали из SKILL.md, оставь ссылку
4. Если НЕ найден → перенеси в новый файл references/
5. Финальная проверка: суммарный wordcount >= исходного

## Влияние на pipeline
- До: агент искал "что перенести" (долго, много контекста)
- После: агент СНАЧАЛА ищет дубликаты (быстро, большой эффект), ПОТОМ переносит остатки

## Подтверждено
- 7/7 скиллов обработаны успешно
- 0% потерь контента
- Аудит: 7/7 PASS
