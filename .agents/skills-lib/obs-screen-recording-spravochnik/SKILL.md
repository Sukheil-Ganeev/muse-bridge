## 1. Quick Start — запись за 2 минуты

### Минимальная настройка OBS для первой записи

**Шаг 1: Определи свой энкодер**

```
NVIDIA GPU  →  NVENC H.264
AMD GPU     →  AMF H.264
Intel iGPU  →  QSV H.264
Нет GPU     →  x264 (CPU)
```

Проверить: Settings → Output → Recording → Encoder (выпадающий список).
Если в списке есть NVENC — используй его. Он разгружает CPU.

**Шаг 2: Настройки записи**

```
Settings → Output → Output Mode: Advanced → Recording tab

Encoder:         NVIDIA NVENC H.264 (или x264)
Rate Control:    CQP (NVENC) / CRF (x264)
CQP / CRF:      20
Preset:          Quality (NVENC) / veryfast (x264)
Profile:         high
Container:       MKV (Matroska)
```

**Шаг 3: Видео**

```
Settings → Video

Base Resolution:   1920×1080 (или текущее разрешение монитора)
Output Resolution: 1920×1080
FPS:               30 (для скринкастов)
```

**Шаг 4: Добавь источник**

```
Scenes → + (новая сцена) → Sources → + → Display Capture
```

Для записи конкретного окна: Window Capture вместо Display Capture.

**Шаг 5: Проверь и записывай**

```
1. Посмотри Preview — видишь ли свой экран?
2. Проверь уровни звука в Audio Mixer (зелёные полоски двигаются?)
3. Нажми "Start Recording"
4. Запиши 10 секунд → Stop → открой файл → проверь
```

### Чеклист Quick Start

- [ ] Энкодер выбран (NVENC / x264)
- [ ] CQP/CRF = 20, контейнер MKV
- [ ] Разрешение 1080p, FPS 30
- [ ] Источник добавлен, Preview работает
- [ ] Тестовая запись 10 сек — ОК

**Результат:** файл MKV, ~30-50 МБ/мин, хорошее качество для скринкаста.
После записи: File → Remux Recordings → конвертируй MKV → MP4 для загрузки.

## 2. OBS Studio — Полный разбор

OBS Studio — бесплатный open-source инструмент для записи экрана и стриминга.
Поддерживает Windows, macOS, Linux. Расширяется плагинами.

### 2.1 Энкодеры

Энкодер — ключевой компонент, определяющий качество, размер файла и нагрузку на систему.

#### x264 (CPU-энкодер)

Программный энкодер H.264. Работает на любом ПК, но нагружает процессор.

**Rate Control для записи: CRF (Constant Rate Factor)**

| Значение CRF | Качество        | Размер файла | Применение          |
|---------------|-----------------|--------------|---------------------|
| 0             | Lossless        | Огромный     | Мастер-копия        |
| 15-17         | Визуально без потерь | Большой | Production, монтаж  |
| 18-20         | Отличное        | Средний      | Скринкасты          |
| 21-23         | Хорошее         | Умеренный    | Длинные записи      |
| 24-28         | Приемлемое      | Маленький    | Черновики, превью   |

**Presets (скорость кодирования)**

От самого быстрого к самому медленному:

```
ultrafast → superfast → veryfast → faster → fast → medium → slow → slower → veryslow
```

| Preset    | Нагрузка CPU | Качество на бит | Для записи                |
|-----------|-------------|-----------------|---------------------------|
| ultrafast | Минимальная | Низкое          | Слабый ПК, фоновая запись |
| veryfast  | Низкая      | Среднее         | Стандартная запись         |
| faster    | Умеренная   | Хорошее         | Качественная запись       |
| fast      | Средняя     | Хорошее+        | Если CPU позволяет        |
| medium    | Высокая     | Высокое         | Только мощный ПК          |
| slow+     | Очень высок | Максимальное    | Не для реального времени  |

Для записи в реальном времени: **veryfast** или **faster**. Медленнее — только на мощном CPU.

**Profiles**

| Profile  | Описание                    | Когда использовать        |
|----------|-----------------------------|---------------------------|
| baseline | Без B-frames, совместимость | Старые устройства         |
| main     | B-frames, средняя сложность | Стриминг                  |
| high     | Максимальная эффективность  | Запись (рекомендуется)     |

**Рекомендуемые настройки x264 для записи:**

```
Rate Control:   CRF
CRF:            20
Preset:         veryfast
Profile:        high
Tune:           (пусто) или animation для анимации
Key Interval:   0 (авто) или 250 кадров
```

#### NVENC (NVIDIA GPU)

Аппаратный энкодер на видеокартах NVIDIA (GTX 600+ / RTX серия).
Практически не нагружает CPU. Кодирование идёт на выделенном чипе GPU.

**Rate Control для записи: CQP (Constant Quantization Parameter)**

| Значение CQP | Качество          | Применение           |
|---------------|--------------------|----------------------|
| 0             | Lossless           | Мастер-копия         |
| 15-17         | Визуально lossless | Production           |
| 18-20         | Отличное           | Скринкасты, геймплей |
| 21-23         | Хорошее            | Длинные записи       |
| 24+           | Приемлемое         | Черновики            |

CQP и CRF дают похожие результаты. CQP = 20 примерно = CRF 20.

**Presets NVENC (современные, OBS 28+)**

| Preset | Обозначение | Качество | Скорость | Применение        |
|--------|-------------|----------|----------|-------------------|
| P1     | Fastest     | Базовое  | Макс     | Если GPU на пределе|
| P3     | Fast        | Среднее  | Быстро   | Стриминг          |
| P4     | Medium      | Хорошее  | Средне   | Запись по умолчанию|
| P5     | Slow        | Хорошее+ | Медленно | Качественная запись|
| P6     | Slower      | Высокое  | Медленно | Постобработка     |
| P7     | Slowest     | Макс     | Мин      | Оффлайн кодировка |

Legacy-названия (старые версии OBS): Quality, Max Quality, Low Latency Quality.

**B-Frames**

- 0 — без B-frames (минимальная задержка)
- 2 — рекомендуется для записи (лучшее сжатие)
- 4 — максимальное сжатие (RTX 20xx+)

**Рекомендуемые настройки NVENC для записи:**

```
Encoder:          NVIDIA NVENC H.264
Rate Control:     CQP
CQP:              20
Preset:           P5 (Quality) или P4 (Medium)
Profile:          high
Look-ahead:       Включить (если есть)
B-Frames:         2
Max B-Frames:     2
GPU:              0 (основной)
```

**NVENC AV1 (RTX 40xx+)**

Новый кодек AV1 доступен аппаратно на RTX 4000+. Даёт на 20-30% лучшее
сжатие при том же качестве по сравнению с H.264. Но не все плееры и
редакторы поддерживают AV1 (ситуация улучшается).

```
Encoder:     NVIDIA NVENC AV1
CQP:         22-24 (даёт качество примерно как H.264 CQP 20)
```

#### AMF (AMD GPU)

Аппаратный энкодер на видеокартах AMD (RX 400+).

**Настройки AMF для записи:**

```
Encoder:        AMD HW H.264 (AVC)
Rate Control:   CQP
CQP:            20
Quality Preset: Quality
Profile:        high
B-Frames:       0 (AMF хуже работает с B-frames)
```

AMF в целом даёт чуть худшее качество на бит по сравнению с NVENC при
равных настройках. Для записи это не критично — CQP 18-20 компенсирует.

**AMF AV1 (RX 7000+)**

Доступен на RDNA 3+. Настройки аналогичны NVENC AV1.

#### QSV (Intel Quick Sync Video)

Аппаратный энкодер на встроенной графике Intel (Intel HD/UHD/Iris/Arc).

**Настройки QSV для записи:**

```
Encoder:        Intel QSV H.264
Rate Control:   ICQ (Intelligent Constant Quality)
ICQ Quality:    20-23
Target Usage:   Quality (или Balanced)
Profile:        high
```

ICQ — аналог CRF/CQP для QSV. Значения 20-23 дают хорошее качество.

QSV полезен когда:
- Нет дискретной видеокарты
- Нужно разгрузить дискретный GPU (для игр)
- Ноутбук с Intel + NVIDIA — можно записывать через QSV, оставив NVIDIA для игры

#### AV1 — Программный (SVT-AV1)

Программный энкодер AV1. Очень требователен к CPU.

```
Encoder:     SVT-AV1
CRF:         25-30 (AV1 более эффективен, поэтому значения выше)
Preset:      8-10 (для реального времени)
```

**Когда использовать AV1:**
- У вас RTX 40xx+ (аппаратный NVENC AV1)
- Или RX 7000+ (аппаратный AMF AV1)
- Или мощный CPU (12+ ядер) для SVT-AV1
- Вам важен минимальный размер файла
- Совместимость с AV1 не проблема

**Когда НЕ использовать AV1:**
- Файлы пойдут в монтаж (не все NLE поддерживают)
- Нужна максимальная совместимость
- Слабый ПК без аппаратного AV1

#### Сводная таблица: Энкодер x Сценарий

| Сценарий            | Рекомендация 1      | Рекомендация 2     | Избегать          |
|---------------------|---------------------|--------------------|-------------------|
| Скринкаст           | NVENC CQP 20       | x264 CRF 20       | UTVideo, CBR      |
| Геймплей            | NVENC CQP 18       | AMF CQP 18        | x264 (нагрузка)   |
| Стриминг            | NVENC CBR 6000     | x264 CBR 6000     | CRF/CQP           |
| Для монтажа         | x264 CRF 16        | NVENC CQP 16      | Высокий CRF       |
| Минимальный размер  | NVENC AV1 CQP 24   | SVT-AV1 CRF 28    | UTVideo, PCM      |
| Слабый ПК           | QSV ICQ 22         | NVENC CQP 22      | x264 slow         |

### 2.2 Rate Control — Подробный разбор

Rate Control определяет, как энкодер распределяет биты между кадрами.

| Метод | Расшифровка                      | Описание                                           | Для записи | Для стрима |
|-------|----------------------------------|-----------------------------------------------------|------------|------------|
| CRF   | Constant Rate Factor             | Постоянное визуальное качество, переменный битрейт  | Да         | Нет        |
| CQP   | Constant Quantization Parameter  | Фиксированный параметр квантования, перем. битрейт  | Да         | Нет        |
| CBR   | Constant Bitrate                 | Фиксированный битрейт, переменное качество          | Нет        | Да         |
| VBR   | Variable Bitrate                 | Переменный битрейт в заданных рамках                | Опционально| Да         |
| ABR   | Average Bitrate                  | Средний битрейт, варьируется покадрово              | Нет        | Редко      |
| ICQ   | Intelligent Constant Quality     | CRF-аналог для Intel QSV                           | Да         | Нет        |

**Ключевое правило:**
- **Запись** → CRF (x264) или CQP (NVENC/AMF) — качество приоритет
- **Стриминг** → CBR — стабильный битрейт для сети

**Почему CBR плохо для записи:**
CBR выделяет одинаковое количество бит для простых и сложных сцен.
Простая сцена (статичный слайд) получает лишние биты → раздутый файл.
Сложная сцена (быстрое движение) не получает достаточно бит → артефакты.

CRF/CQP автоматически адаптируются: меньше бит на простые сцены,
больше на сложные. Результат: меньший файл при лучшем качестве.

### 2.3 Форматы контейнеров

Контейнер — обёртка для видео- и аудиопотоков. Не влияет на качество.

#### MKV (Matroska) — РЕКОМЕНДУЕТСЯ

```
Settings → Output → Recording → Recording Format: MKV
```

**Плюсы:**
- Crash-safe: если OBS упадёт, файл сохранится (только потеряете последние секунды)
- Поддерживает любые кодеки (H.264, H.265, AV1, VP9 и т.д.)
- Несколько аудиодорожек (до 16)
- Субтитры

**Минусы:**
- Не все платформы принимают MKV напрямую (YouTube принимает)
- Некоторые видеоредакторы не работают с MKV

**Решение:** после записи: File → Remux Recordings → MKV → MP4 (мгновенно, без перекодирования).

#### MP4

**Плюсы:**
- Универсальная совместимость
- Любой плеер, редактор, платформа

**Минусы:**
- НЕ crash-safe: если OBS упадёт — файл будет повреждён и невосстановим
- Метаданные записываются в конец файла при финализации

**Правило:** Никогда не записывай напрямую в MP4. Записывай в MKV, потом Remux.

#### FLV (Flash Video)

- Legacy-формат от Adobe Flash
- Crash-safe (как MKV)
- Ограничен одной аудиодорожкой
- Не рекомендуется для новых записей

#### MOV (QuickTime)

- Формат Apple
- Хорошая совместимость с Final Cut Pro, macOS
- НЕ crash-safe (как MP4)
- Используй на macOS, если нужна совместимость с Apple-софтом

#### TS (MPEG Transport Stream)

- Crash-safe
- Используется в телевещании
- Большие файлы из-за overhead
- Для записи экрана обычно не нужен

**Рекомендация по контейнерам:**

```
Запись       → MKV (всегда)
Загрузка     → MP4 (Remux из MKV)
Apple-софт   → MOV (если надо)
Всё остальное → MKV
```

### 2.4 Сцены и источники

#### Сцены (Scenes)

Сцена — набор источников с определённым расположением. Можно переключаться между сценами.

Примеры организации сцен:

```
Сцена "Скринкаст"     → Display Capture + Микрофон
Сцена "Камера"         → Video Capture Device (вебкамера)
Сцена "Камера + Экран" → Display Capture + вебкамера в углу
Сцена "Заставка"       → Изображение (Starting Soon / BRB)
```

#### Источники (Sources)

**Display Capture** — захват всего экрана
- Захватывает всё, включая курсор
- Работает надёжно на большинстве систем
- На Windows: может потребовать выбор метода захвата (WGC / BitBlt / DXGI)

```
Рекомендация: Windows Graphics Capture (WGC) — современный, стабильный
```

**Window Capture** — захват конкретного окна
- Записывает только выбранное окно
- Другие окна поверх — не попадают в запись
- Настройка: выбрать окно из списка, включить "Capture cursor"

**Game Capture** — захват полноэкранных игр
- Самый эффективный для DirectX/Vulkan/OpenGL игр
- Использует хуки для прямого захвата
- Настройки: "Capture any fullscreen application" или выбрать конкретную игру
- Не работает с UWP-приложениями (используй Window Capture)

**Audio Input Capture** — захват микрофона
- Выбери конкретное устройство (не "Default")
- Установи уровень громкости в Audio Mixer

**Audio Output Capture** — захват системного звука
- Захватывает звук из колонок/наушников
- На Windows обычно работает автоматически через Desktop Audio

**Browser Source** — встраивание веб-страниц
- URL или локальный HTML-файл
- Полезно для оверлеев, чатов (стриминг), виджетов
- Настройки: URL, ширина, высота, CSS, FPS

**Image** — статичное изображение (логотип, фон, рамка)

**Text (GDI+)** — текстовый оверлей (Windows)
- Шрифт, размер, цвет, обводка, тень
- Может читать из файла (для динамического текста)

**Media Source** — видео/аудио файл
- Для интро, аутро, фоновой музыки
- Поддерживает зацикливание (Loop)

**Порядок источников:** верхние источники перекрывают нижние (как слои в Photoshop).

### 2.5 Фильтры видео

Правый клик на источнике → Filters → Effect Filters / Audio/Video Filters

**Crop/Pad**
- Обрезка краёв источника
- Полезно: убрать лишние элементы UI, сфокусировать на области

```
Left:   100    (обрезать 100px слева)
Top:    50     (обрезать 50px сверху)
Right:  100
Bottom: 50
```

**Scaling/Aspect Ratio**
- Принудительное масштабирование источника
- Полезно: привести 4:3 источник к 16:9

**Color Correction**
- Яркость, контраст, гамма, насыщенность
- Полезно: сделать скринкаст ярче, поднять контраст для читаемости

```
Gamma:       0.00 (норма) → -0.50 (ярче) или +0.50 (темнее)
Contrast:    0.00 (норма) → 0.20 (больше контраста)
Brightness:  0.00 (норма)
Saturation:  0.00 (норма) → -1.00 (ч/б) или +0.50 (насыщеннее)
```

**Chroma Key**
- Удаление фона определённого цвета (зелёный/синий экран)
- Настройки: тип ключа (Green/Blue/Custom), similarity, smoothness

**LUT Filter (Look-Up Table)**
- Применение цветовых пресетов (.cube файлы)
- Для кинематографичного вида вебкамеры

**Image Mask/Blend**
- Наложение маски (PNG с альфа-каналом)
- Полезно: круглая камера, рамки, фигурная обрезка

**Render Delay**
- Задержка рендера источника в мс
- Полезно: синхронизация видео с задержанным аудио

### 2.6 Плагины (топ-10)

Топ-10 плагинов OBS: StreamFX (3D, blur), Move Transition (анимированные переходы), Advanced Scene Switcher (автоматизация), Source Dock (мульти-превью), obs-backgroundremoval (AI-удаление фона), obs-websocket (API, встроен с OBS 28+), Input Overlay (клавиши), obs-shaderfilter (кастомные эффекты), obs-localvocal (AI-субтитры), Source Record (раздельная запись).

## 3. Аудио в OBS

### Основные настройки

```
Settings → Audio

Sample Rate:    48 kHz (стандарт для видео)
Channels:       Stereo
```

**Sample Rate: 44.1 kHz vs 48 kHz**

| Параметр  | 44.1 kHz         | 48 kHz              |
|-----------|-------------------|----------------------|
| Стандарт  | CD, музыка        | Видео, ТВ, кино     |
| Для видео | Работает, но не идеально | Рекомендуется  |
| Проблемы  | Ресемплинг при монтаже | Нет             |

**Используй 48 kHz** — это стандарт для видеопроизводства.

### Аудиокодек и битрейт

```
Settings → Output → Audio

Audio Encoder:  AAC
Audio Bitrate:  160 kbps (скринкаст) / 192 kbps (геймплей) / 320 kbps (music)
```

| Битрейт AAC | Качество               | Применение                    |
|-------------|------------------------|-------------------------------|
| 96 kbps     | Приемлемое             | Голос, разговорное видео      |
| 128 kbps    | Хорошее                | Стриминг                      |
| 160 kbps    | Хорошее+               | Скринкаст (рекомендация)      |
| 192 kbps    | Высокое                | Геймплей, музыкальный контент |
| 256 kbps    | Отличное               | Продакшн                      |
| 320 kbps    | Максимальное для AAC   | Мастеринг, музыка             |

Для записи под монтаж: PCM (несжатый, WAV) — максимальное качество,
но огромные файлы. Используй только при последующей постобработке.

### Аудиофильтры — полная цепочка

Порядок фильтров критичен. Правильная цепочка обработки:

```
Микрофон → Noise Suppression → Noise Gate → Compressor → Limiter → Gain (если нужно)
```

Добавление: правый клик на микрофоне в Audio Mixer → Filters → "+"

#### 1. Noise Suppression (Подавление шума)

Удаляет постоянный фоновый шум (гул вентилятора, кондиционер, шум улицы).

**Методы:**

| Метод          | Качество | Нагрузка | Описание                      |
|----------------|----------|----------|-------------------------------|
| RNNoise        | Отличное | Низкая   | AI-модель, рекомендуется      |
| NVIDIA Noise Removal | Отличное | GPU  | Только NVIDIA RTX             |
| Speex          | Среднее  | Мин.     | Лёгкий, для слабых ПК        |

```
Рекомендация:
Method:           RNNoise
Suppress Level:   Автоматический (RNNoise не требует настройки)
```

#### 2. Noise Gate (Шумовой порог)

Полностью отключает микрофон, когда вы не говорите. Убирает тихие
остаточные шумы, дыхание, щелчки в паузах.

```
Close Threshold:  -32 dB  (ниже этого — микрофон выключен)
Open Threshold:   -26 dB  (выше этого — микрофон включен)
Attack Time:       10 ms  (скорость включения)
Hold Time:        200 ms  (держать открытым после тишины)
Release Time:     150 ms  (скорость затухания)
```

**Настройка:**
1. Молчите — смотрите уровень в Audio Mixer (запомните "шумовой пол", например -45 dB)
2. Close Threshold = на 10-15 дB выше шумового пола
3. Open Threshold = на 5-6 dB выше Close Threshold
4. Говорите тихо — должно срабатывать. Говорите нормально — должно работать плавно.

#### 3. Compressor (Компрессор)

Выравнивает громкость: делает тихие части громче, громкие — тише.
Предотвращает резкие перепады громкости.

```
Ratio:               4:1      (степень сжатия)
Threshold:          -18 dB    (выше этого — сжимать)
Attack:               6 ms    (скорость реакции)
Release:             60 ms    (скорость отпускания)
Output Gain:          6 dB    (компенсация потери громкости)
Sidechain/Ducking:   (не трогать для микрофона)
```

**Значения Ratio:**

| Ratio  | Эффект               | Применение        |
|--------|----------------------|-------------------|
| 2:1    | Мягкое сжатие        | Естественный звук |
| 4:1    | Умеренное сжатие     | Рекомендуется     |
| 8:1    | Сильное сжатие       | Радио-голос       |
| 20:1+  | Практически лимитер  | Редко нужно       |

#### 4. Limiter (Лимитер)

Жёсткий потолок громкости. Не даёт сигналу превышать заданный уровень.
Предотвращает клиппинг (искажение от перегрузки).

```
Threshold:   -1.5 dB   (максимальный уровень)
Release:      60 ms     (скорость отпускания)
```

Лимитер — последний в цепочке. Страховочная сетка от пиков.

#### 5. Gain (Усиление) — опционально

Если после всех фильтров звук слишком тихий/громкий:

```
Gain:   3 dB (усилить) или -3 dB (уменьшить)
```

Целевой уровень голоса в Audio Mixer: **-12 до -6 dB** при обычной громкости речи.

### Настройка микрофона — пошагово

1. **Выбор устройства:** Settings → Audio → Mic/Auxiliary Audio → выбрать конкретный микрофон
2. **Уровень:** Audio Mixer → ползунок — говорите нормально, пики должны быть около -12 dB
3. **Мониторинг:** правый клик → Advanced Audio Properties → Monitor Off (для записи)
4. **Аудиодорожки:** в Advanced Audio Properties → назначить дорожки (Track 1 = основная)

### Desktop Audio

На Windows: обычно добавляется автоматически.
Если нет:
```
Settings → Audio → Desktop Audio → выбрать ваше устройство вывода
```

Или: Sources → + → Audio Output Capture → выбрать устройство.

**Разделение дорожек:**

Для монтажа полезно записать микрофон и desktop audio на разные дорожки:

```
Advanced Audio Properties:
  Desktop Audio  → Track 1 ✓  Track 2 ✓
  Mic/Aux        → Track 1 ✓  Track 3 ✓
```

Track 1 = микс (для быстрого просмотра)
Track 2 = только desktop audio
Track 3 = только микрофон

## 9. Типичные ошибки — топ-10

### 1. UTVideo / PCM вместо H.264

**Проблема:** запись 2 минуты = 2 ГБ. Lossless-кодеки (UTVideo, PCM audio)
создают гигантские файлы.

**Решение:** переключись на H.264 (NVENC CQP 20 или x264 CRF 20).
Визуальная разница неразличима, файл в 20-50 раз меньше.

### 2. CBR для записи

**Проблема:** используешь CBR (Constant Bitrate) для локальной записи.
Статичные сцены раздуты, динамичные — размытые.

**Решение:** CRF (x264) или CQP (NVENC). Rate Control для записи должен
быть quality-based, не bitrate-based.

### 3. 60 FPS для скринкастов

**Проблема:** скринкаст с IDE/браузером в 60 FPS. Размер файла на 40-50%
больше, но разницу никто не видит.

**Решение:** 30 FPS для скринкастов. 60 FPS только для геймплея и
динамичного контента.

### 4. Запись напрямую в MP4

**Проблема:** записываешь в MP4. OBS крашнулся / ПК выключился → файл
полностью потерян (MP4 записывает metadata в конец).

**Решение:** записывай в MKV. После записи: File → Remux Recordings → MP4.
Мгновенная конвертация без потери качества.

### 5. Нет аудиофильтров на микрофоне

**Проблема:** в записи слышен шум вентилятора, гул, эхо. Голос то тихий,
то громкий.

**Решение:** добавь цепочку фильтров:
Noise Suppression (RNNoise) → Noise Gate → Compressor → Limiter.
Настройки — см. раздел 3 "Аудио в OBS".

### 6. Слишком низкий CRF/CQP (перфекционизм)

**Проблема:** CRF/CQP = 12-15 для обычного скринкаста. Файл огромный,
а визуальной разницы с CRF 20 нет.

**Решение:** для скринкастов CRF/CQP 20-22 достаточно. Используй 16-18
только для production-записей, идущих в серьёзный монтаж.

### 7. Запись в 4K для YouTube 1080p

**Проблема:** записываешь в 4K, потом загружаешь на YouTube, где 95%
зрителей смотрят в 1080p или ниже.

**Решение:** записывай в 1080p (или 1440p если нужен zoom в монтаже).
4K-запись оправдана только если финальный продукт публикуется в 4K.

### 8. Нет тестовой записи

**Проблема:** начал записывать 2-часовой скринкаст, а потом обнаружил:
нет звука / чёрный экран / неправильный источник.

**Решение:** ВСЕГДА делай тестовую запись 10-15 секунд. Проверь видео И
аудио перед реальной записью.

### 9. Desktop Audio не захвачен

**Проблема:** в записи нет системного звука (музыка, звуки приложений).

**Решение:**
1. Settings → Audio → Desktop Audio → выбери своё устройство вывода
2. Или: Sources → + → Audio Output Capture
3. Проверь Audio Mixer — должна быть активная дорожка "Desktop Audio"
4. Windows: убедись, что звук идёт на то устройство, которое захватывает OBS

### 10. Не тот источник захвата (Display vs Window vs Game)

**Проблема:** выбрал Display Capture, но записывает не тот монитор.
Или Window Capture, но окно свернулось и запись остановилась.
Или Game Capture, но игра не видна (чёрный экран).

**Решение:**
- **Display Capture:** выбери правильный монитор в свойствах источника
- **Window Capture:** выбери конкретное окно; не сворачивай его
- **Game Capture:** попробуй "Capture any fullscreen application" или
  конкретную игру. Если чёрный экран — запусти OBS от имени администратора
  или попробуй другой метод захвата

**Бонус: Частая ошибка Windows — "Чёрный экран"**

Причина: ПК с двумя GPU (Intel + NVIDIA). OBS использует один GPU,
а приложение — другой.

Решение:
```
Windows Settings → Display → Graphics Settings →
  Найди OBS Studio → Options → High Performance (NVIDIA)
```

Или: Settings → Display → Настройки графики → OBS → Высокая производительность.
