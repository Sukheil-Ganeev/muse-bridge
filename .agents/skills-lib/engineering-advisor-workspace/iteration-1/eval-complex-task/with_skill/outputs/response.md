## Что это означает на практике

### 1. JWT авторизация — MANDATORY ревью

Это безопасность. Типичные ошибки:

- `process.env.JWT_SECRET || ''` — пустой secret принимает **любой** токен. Zod schema: `z.string().min(32)`, падение при старте если не задан.
- `body as any` перед Prisma — SQL injection. Нужна Zod schema на каждый endpoint.
- `return` пропущен после `reply.code(401).send()` — код продолжает выполняться после отказа.

**Действие:** Сначала ревью безопасности, потом написание кода.
Скилл: `superpowers:requesting-code-review`

### 2. Endpoint для заказов — MANDATORY: авторизация + валидация + rate limit

Триггер #13 обязывает:
- Авторизацию (middleware, проверка JWT)
- Валидацию входных данных (Zod schema перед каждым Prisma вызовом)
- Rate limiting (с обязательным cleanup — иначе Map растёт бесконечно, триггер #24)

**Действие:** Написать план файлов и изменений перед началом.
Скилл: `superpowers:writing-plans`

### 3. Redis — новый пакет

- Добавить в `requirements.txt` / `package.json` с зафиксированной версией.
- Проверить совместимость с текущими зависимостями.
- Graceful degradation если Redis недоступен (чтобы не уронить весь сервис).

### 4. Деплой на продакшн — MANDATORY: сначала план

Деплой без плана — группа потерялась в дюнах. Обязательно:

- Шаг отката (rollback plan)
- Проверка переменных окружения (JWT_SECRET, Redis URL) до деплоя
- .env не в git (триггер #11)
- SSL/HTTPS через nginx
- systemd unit файл с `Restart=always`

**Действие:** Сначала план 5-7 шагов.
Скилл: `superpowers:writing-plans`

## Мой прямой ответ на "Можешь всё это сделать?"

Технически — да, могу. Но не "всё сразу за один раз".

**Вот почему порядок важен:**

1. Если сначала написать JWT, а потом окажется что secret хранится неправильно — придётся переписывать endpoint тоже.
2. Деплой без плана отката = риск упасть и не знать как вернуться назад.
3. 4 задачи параллельно в одном окне = гарантированные незамеченные ошибки (по правилу инкрементальных изменений из твоего CLAUDE.md).

**Предлагаю:**

1. Уточни стек: Python или Node.js/TypeScript? FastAPI, Flask, Fastify, Express?
2. Есть ли уже существующий проект или начинаем с нуля?
3. Начнём с Волны 1 (JWT ревью + план) — я покажу что именно сделаю, ты подтвердишь, потом выполним.

Это не медленнее — это так, чтобы не переделывать.
