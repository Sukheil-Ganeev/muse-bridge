## Главный совет: НЕ переписывать с нуля

**Триггер #9 — Recommended (жёлтый):** "Смена системы бронирований без проверки = потерянные заказы."

Переписывание с нуля — это самая дорогостоящая операция в разработке. Вот почему:

- Весь рабочий код (включая неочевидные edge cases) пишется заново
- Накопленные фиксы багов теряются
- Бот не работает пока идёт переписывание
- 800 строк — это НЕ критично. Это решаемо за 2-3 часа рефакторинга.

**Что на самом деле нужно:** не "переписать с нуля", а **структурировать существующий код**.

## Что делать вместо этого: план из 5 шагов

### Шаг 1: Диагностика (30 минут)

Прежде чем трогать код — понять структуру:

```bash
# Посмотреть все функции в handlers.py
grep -n "^def \|^async def " handlers.py

# Найти что вызывает что
grep -n "def \|import " handlers.py | head -50
```

Составить список: какие функции есть, как они группируются по смыслу.

### Шаг 2: Разделить на логические группы (без трогания кода)

Типичная структура Telegram-бота на aiogram:

```
bot/
├── main.py              # Точка входа, запуск
├── config.py            # Настройки, токены
├── handlers/
│   ├── __init__.py
│   ├── commands.py      # /start, /help, /cancel
│   ├── messages.py      # Текстовые сообщения
│   └── callbacks.py     # Inline-кнопки
├── keyboards/
│   └── inline.py        # Клавиатуры
├── services/
│   └── business.py      # Бизнес-логика (отдельно от хэндлеров!)
└── database/
    └── db.py            # Работа с БД
```

### Шаг 3: Перенос кода по одной группе (не всё сразу!)

Принцип: **один файл за раз, с проверкой после каждого**.

```
Итерация 1: вынести keyboards → keyboards/inline.py → проверить что бот работает
Итерация 2: вынести /start, /help → handlers/commands.py → проверить
Итерация 3: вынести бизнес-логику → services/ → проверить
... и так далее
```

Никогда не переносить всё разом — потеряешь где сломалось.

### Шаг 4: Критическая проверка aiogram — порядок хэндлеров

**EXP-053 (CRITICAL):** Это самая частая скрытая ошибка при рефакторинге aiogram-бота.

При переносе хэндлеров в новые файлы — ОБЯЗАТЕЛЬНО проверить:

```python
# НЕПРАВИЛЬНО — F.text перехватит всё, команды не сработают
router.message.register(text_handler, F.text)       # catch-all ВЫШЕ
router.message.register(start_handler, Command("start"))  # никогда не вызовется

# ПРАВИЛЬНО — конкретные фильтры выше общих
router.message.register(start_handler, Command("start"))  # сначала команды
router.message.register(text_handler, F.text)             # потом catch-all
```

Мнемоника: "Конкретные фильтры — вверху, общие — внизу. Как воронка."

### Шаг 5: Убрать "лишнее" только после структурирования

После разделения на модули — станет видно что реально не нужно. До этого удалять код опасно (можно убрать "спящий код" который на самом деле нужен).

Из `references/aiogram-checklist.md`:

```

```
