### Кнопки и клавиатуры

**Q:** Как сделать бесшовный переход по кнопке HTML в другое мини-приложение?
**A:** Есть 3 способа:
1. Аттрибут `goto_web_page` для тега `<a>`. В него пишут id веб-аппа (например `bb0ad173446c99b1`), после загрузки страницы этот аттрибут заменяется на href.
Пример: `<a goto_web_page="*тут айди второй страницы*">Перейти на вторую страницу</a>`
2. Функция `gotoWebPage("id_веб-аппа", true | false)` -- перейти на другую страницу. Второй аргумент false (по умолчанию) делает переход, true открывает в стороннем браузере.
Пример: `<button onclick="gotoWebPage('bb0ad173446c99b1')">Перейти</button>`
3. Функция `getWebPageUrl("id_веб-аппа")` -- просто вернуть ссылку текстом, не переходя.

**Q:** Как сделать инлайн команду (редактирование сообщения вместо удаления + нового)?
**A:** Используйте **Инлайн команду** -- вид команд из 1 блока, позволяющий создать цепочку самозаменяющихся команд (без отправки нового сообщения).
Особенности:
1. Можно добавить только 1 блок
2. Можно добавить только инлайн клавиатуру
3. Блок текста можно заменить только на Блок текста, Блок медиа -- только на Блок медиа
4. При переходе между разными видами (обычная и инлайн) команда будет отправлена новым сообщением

---

**Q:** Как сделать тест в боте с подсчетом баллов (5 сфер по 10 баллов, 100+ вариантов ответов)?
**A:** Оформляете вопросы и в кнопки встраиваете "изменить переменную". Создаете числовую переменную `{{otvet}}` и текстовые `{{sfera1}}`, `{{sfera2}}`. В конечном результате в блоке текст пишете формулу:
`{{=if {{otvet}} > 5 ; {{sfera1}} ; {{sfera2}} }}`
Формулы прямо в текст можно вставлять -- они делают вычисления и подставляют нужную переменную. Если слишком много вариантов -- используйте NocoDB/Google Таблицы, так как количество переменных на конструкторе ограничено.

**Q:** Как удалить уже отправленную команду с кнопками у всех пользователей?
**A:** Удалить не получится. На будущее лучше ставить действие удаления через время или галочку "удалить после вызова следующей команды". Если это кнопка "Платеж" -- отредактируйте ее в конструкторе и при сохранении дайте согласие (зеленая галочка) на изменение суммы тем, кто уже получил ее. Сама кнопка формируется в момент активации блока, но платеж формируется только при нажатии. Это работает только с кнопками типа ПЛАТЕЖ.

---

**Q:** Если человек не нажмет кнопку, то через таймер выйдет следующий блок, а если нажмет -- блок сразу. Как?
**A:** Сделать через сценарий: где кнопка -- запускать сценарий с отправкой поста через время. По кнопке, по которой нужен переход, сразу ведем на команду и в этой команде отключаем ранее запущенный сценарий.

---

**Q:** Как публиковать видео от пользователя в канале после модерации?
**A:** Надо ID видео записывать в таблицу. Далее в канале публиковать блок "Видео", подтягивая из таблицы ID видео интегрированной переменной. Каждая заявка должна нумероваться, чтобы по номеру заявки бот доставал нужные видео для публикации.

---

**Q:** Как сделать систему обработки заявок с кнопками для админов?
**A:** Присваивайте заявкам статусы: 0 -- оплачено, 1 -- в работе, 2 -- отгружено. Создаете команду "В работу". Админ её запускает. Команда находит первую не обработанную заявку и втягивает данные из таблицы. Статус меняется на "в работе". Админ нажимает "Отправить клиенту" -- статус меняется на "отгружено", данные улетают.

**Q:** Как сделать кнопки-карточки в мини-приложении (блог, база знаний, сообщество)?
**A:** HTML-код с flexbox/grid:
```html

  <div style="display: block; margin-left: 2%; margin-right: 2%;">
    <a href="https://puzzlebot.top/blog" target="_blank">
      <img src="URL_КАРТИНКИ" style="width: 100%; border-radius: 5px;">
    </a>
  </div>
  <div style="margin-right: 2%;">
    <a href="URL_ССЫЛКИ" target="_blank">
      <img src="URL_КАРТИНКИ_2" style="width: 100%; border-radius: 5px;">
    </a>
  </div>
</div>
```

### Оплата и платежи

**Q:** Как ограничить доступ к контенту через 30 дней после оплаты?
**A:** При оплате создается переменная с датой через месяц от текущей. Запускается сценарий, который каждый день сравнивает сегодняшнюю дату с переменной. Если даты равны -- выполняются все действия по запрету доступа (смена категории, отключение и т.д.).

---

**Q:** Как настроить отслеживание оплат по реферальным ссылкам?
**A:** Нужно сначала назначить реферера -- рефералу через изменение переменных в действиях. Далее можно будет считать количество оплат на каждого пригласителя.

---

**Q:** Как оплатить тариф PuzzleBot по безналичному счету (ЮЛ)?
**A:** Для запроса счета оплаты отправить на email weare@puzzlebot.top:
- Карточку компании (реквизиты)
- Юзернейм бота или аккаунта
- Предпочитаемый тариф
- Период тарифа (минимальный по счету -- 3 месяца)

---

**Q:** Как оплатить криптовалютой?
**A:** Оплатить тариф криптовалютой можно через бот @paypuzzlebot. Важно: вход в бот должен осуществляться с того аккаунта, для которого был выдан тариф.

---

**Q:** Ошибка 80 при оплате через бота (Робокасса). Что это?
**A:** Превышен лимит по доходу за месяц или сумма товаров превышает допустимый лимит по общему доходу аккаунта. Лимиты указаны на странице Тарифов. Лимит дохода сбрасывается 1 числа каждого месяца.

---

**Q:** Как реализовать премиум-подписку с проверкой статуса?
**A:** Если человек блокирует бота, но не отписался от подписки -- остается в категории "подписчики премиум", и при следующем запуске у него будет премиум доступ. Если отписался -- переходит в другую категорию. При возвращении идет проверка на действие подписки: если оплачен период -- снова возвращается в премиум.

---

**Q:** Рекуррентный платеж: что будет если пользователь заблокирует бота?
**A:** Сценарий может не отработать корректно. Рекомендуется менять логику так, чтобы проверка подписки происходила при активации бота пользователем, а не только через сценарий.

---

**Q:** Почему месяц в PuzzleBot -- 29 дней?
**A:** Согласно оферте (раздел "Тарифы", пункт 9.1), месяц = 30 календарных дней. Если начислено 29 -- предыдущий платеж был внесен с задержкой. Боты продолжают работу "в долг" до 2 дней после окончания оплаченного периода, и это компенсируется из следующего платежа.

### Рассылки

**Q:** Как настроить рассылку-напоминание тем, кто не заходил 2 месяца?
**A:** На /start вешаете сценарий. Раз в 2 месяца запускаете условие: если пользователь не обращался к команде N (той, мимо которой не пройти), отправить пост. Иначе -- ничего не делать.

---

**Q:** Как сделать рассылку тем, кто отписался от канала?
**A:** Отправляете пост с действием "переход к команде или условию" --> условие с проверкой подписки. Если подписан -- ничего. Если нет -- отправить сообщение.

---

**Q:** Как настроить авторассылку на конкретную дату, выбранную пользователем?
**A:** Создать 31 сценарий -- под каждый день, и 31 команду под запуск каждого сценария. В синонимах каждой команды указать вызов. Юзер указывает дату -> команда активирует для него сценарий.

---

**Q:** Как сделать рассылку по пользователям из Google Таблиц с персонализированным текстом?
**A:** Рассылка ведет на условие. Условие проверяет есть ли ID в таблице. Если есть -- отправить команду с интегрированной переменной (текст из таблицы). Важно: ставьте большое кэширование в условии и в интегрированной переменной.
