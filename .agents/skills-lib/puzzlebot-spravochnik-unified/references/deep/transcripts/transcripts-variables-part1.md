## Video 12: Условия и кнопка условия

В данном видео мы рассмотрим возможности сущности условия и ее подтипов «Обычное условие» и «Кнопка условия». Перейдем в бота, откроем вкладку «Конструктор». Добавим условие. Условие — это отдельная сущность наравне с командами. Условие состоит из правил, которые в свою очередь состоят из проверок и действий. При вызове условия всегда будет выполнено только одно из правил. Дадим название условию. Выберем тип условия. Условие может быть двух типов — «Обычное условие» и «Кнопка условия». «Обычное условие» — это условие, которое можно вызвать так же, как и команду — по названию, переходам, кнопкой и другими способами. «Кнопка условия» — это условие, которое определяет настройки инлайн-кнопки. С данным типом условия можно настроить связь только через действие в инлайн-кнопке «Кнопка условия». Обратите внимание! Что изменить тип условия после сохранения нельзя. В дополнительных настройках можно выбрать перечень опций. Выполнение с текущей группы означает, что команда будет выполнена только если пользователь находится в текущей группе команд. Также можно выбрать случайную отправку правила и отображение в меню. Перейдем к блоку правила. Правило — это блок в условиях, содержащий проверку и действия. Рассмотрим правило. Для начала нужно выбрать тип. Проверка — это набор параметров, на наличие которых проверяется пользователь, вызвавший условия. Она имеет два типа. Тип «Все проверки» означает, что действие из правила будет выполнено только при прохождении всех проверок. Любая проверка — действия из правила будут выполнены при прохождении одной любой проверки. Добавим проверку. Напишем необходимое название команды или условия. Далее мы можем выбрать необходимые нам параметры. Задать количество проверяет, сколько раз была выполнена функция, например, вызов команды или условия. Без опции «Задать количество» проверяет, был ли вызов хотя бы один раз. Если включить «Задать количество» и указать «Равно 3», то проверка будет пройдена только если пользователь вызвал выбранные команды ровно три раза. Задать период проверяет, была ли выполнена функция в указанных правилах. Промежуток. Существуют следующие типы промежутков. Количественный период определяет промежуток относительно текущего часа дня и месяца. Например, выбран тип «Количество дней» со значением 5. Если в течение пяти прошедших дней пользователь вызвал команду на нужное количество раз, то правило будет выполнено. Каждый последующий день промежуток будет смещаться относительно текущего дня. Датированный период — это точный промежуток. Календарный период — промежуток относительно календарных значений . Каждый последующий день промежуток будет смещаться относительно текущего дня, недели, месяца и т.д. Параметр «Проверить другого пользователя» позволяет выполнить проверку на основе данных другого пользователя по Telegram ID или юзернейму. Перейдем к выбору действия. Действия — это набор функций, которые будут выполнены для пользователя, вызвавшего условие. Действия имеют два типа. «Все действия» — значит, что каждое действие будет выполнено поочередно. «Случайное действие» — значит, что будет выполнено одно случайное действие. Можно задать вероятность выполнения каждого действия. При нажатии на кнопку «Добавить действие» раскрывается следующий список действий, который также разделен по вкладкам. Также необходимо добавить исключающее правило. Исключающее правило — это последнее правило в условии. Состоящее только из действий применяется в случае, когда все предшествующие правила не прошли проверки. А теперь разберем отличия типа кнопки «Условия» от типа «Обычные условия». Для этого сохраним наши условия и создадим новые, выбрав кнопку «Условия». Кнопку «Условия» можно вызвать только нажатием на инлайн-кнопку. В отличие от обычного условия, в условии «Кнопки» у настроек действия появляются дополнительные опции, такие же, как у инлайн-кнопки, что позволяет задать разные названия. Данный тип условия позволяет задать название кнопки и ее действия, исходя из заданных правил. То есть до отправки команды, содержащей инлайн-клавиатуру и кнопку «Условия», будет происходить проверка. В зависимости от результата в этой проверке пользователю будет отображена кнопка с соответствующим действием. Например, в условии с типом «Кнопка условия» задано два правила. Первое правило с проверкой на активный сценарий — «Сценарий 1». Другой правило — «Сценарий 2». Второе правило — «Исключающее». И оно будет выполнено, если ни одно другое правило не прошло проверки. В конкретном примере исключающее правило будет выполнено при отсутствии пользователя в сценарии «Сценарий 1». Для первого правила зададим действие «Ссылка» и название кнопки «Ссылка на ваш подарок». Для исключающего правила зададим действие «Переход к команде» и назовем кнопку «Регистрация». И если пользователь с активным сценарием, «Сценарий 1» вызовет команду, содержащую инлайн-клавиатуру с кнопкой «Условия», то кнопка у него будет называться «Ссылка на ваш подарок» и содержать ссылку. А если вызовет пользователь без сценария «Сценарий 1», то у него на том же месте будет отображена кнопка «Регистрация» и «Вести к другой команде». Для того, чтобы создать связь с кнопкой «Условия», необходимо создать инлайн-клавиатуру в любой команде, затем добавить кнопку, выбрать действие для кнопки «Условия» и показать название условия с типом «Кнопка условия». Другие типы отображаться не будут. Отлично! Мы ознакомились с интерфейсом и возможностями сущности условия и ее подтипов «Обычное условие» и «Кнопка условия», а также узнали, чем они отличаются друг от друга.
