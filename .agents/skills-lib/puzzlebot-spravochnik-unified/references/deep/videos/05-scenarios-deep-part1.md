# 05. Сценарии -- Глубокий справочник

## Video 03: 03_Bot_Taksi_Bez_Koda
**Тема:** Создание чат-бота для такси без кода: личные кабинеты пассажира и водителя, регистрация водителя с формами ввода, прием заказов, интеграция с Google Sheets, оплата через Telegram Stars, удаление заявок из канала.
**PuzzleBot-элементы:** Формы ввода (текст, изображение), Переменные (персональные, глобальные, формула), Условия (проверка регистрации по значению переменной), Группы переменных, Google Sheets (создание строки), Платежные системы (Telegram Stars), Ресурсы (канал заявок), Инлайн-кнопки, Start Payload (deep linking), Внутреннее API PuzzleBot (запрос на удаление сообщения), GET-запросы.
**Категория:** Сценарии
**Ключевые техники:**
- Регистрация водителя через цепочку форм ввода (имя, марка, цвет, госномер, телефон, фото) с проверкой через условие наличия значения переменной
- Использование маски ввода "Изображение" для загрузки фото автомобиля
- Итоговое сообщение с подтверждением: блок "Изображение" с ID файла из переменной + текст с переменными
- Запись данных в Google Sheets через действие "Создать строку"
- Start Payload (deep linking) для передачи номера заявки в ссылке: `t.me/botname?start=yes_{{global_number}}`
- Формула-переменная для извлечения номера заявки из start payload
- Удаление заявки из канала через внутреннее API PuzzleBot (GET-запрос с deleteMessage)
- Глобальная переменная-счетчик для нумерации заявок (синхронизация с номером сообщения в канале)
- Подключение Telegram Stars как платежной системы
**Шаги реализации:**
1. Создать переменные для водителя (name, марка, цвет, госномер, телефон, фото, баланс, кол-во заказов), группировать в группу "Водители"
2. Создать цепочку регистрации: Ввести имя -> Марка -> Цвет -> Госномер -> Фото -> Итоговое сообщение -> Добавление в таблицу -> Завершение регистрации
3. Создать условие "Проверка регистрации" по наличию значения переменной name -- если есть, направить в ЛК; если нет -- на регистрацию
4. Настроить Google Sheets: лист "Водитель" с колонками (ID, Имя, Телефон, Кол-во заказов, Марка, Госномер, Цвет, Баланс)
5. Подключить Telegram Stars: Настройки > Платежные системы > Telegram Stars
6. Создать глобальную переменную global_number для нумерации заявок и синхронизировать с номером последнего сообщения в канале
7. В заявке создать ссылку "Забрать заказ" формата: `t.me/botname?start=yes_{{global_number}}`
8. Создать условие "Проверка условия" по start payload: если содержит "yes" -- перейти к обработке заказа
9. Получить API-токен: Настройки > Интеграции > Сгенерировать API-токен
10. Получить Chat ID канала через бот @getmyidbot (переслать сообщение из канала)
11. Создать команду "Запрос удаления" с GET-запросом для удаления заявки из канала
12. Выстроить цепочку: Проверка условия -> Запрос удаления -> Забрал заказ
**Полезные детали:**
- Последовательность действий критична: команды с вычислениями и работой с числами должны быть СВЕРХУ, отправка в другую команду -- СНИЗУ
- Глобальная переменная global_number должна точно совпадать с номером последнего сообщения в канале, иначе удаление не работает
- Рекомендуется хранить chat_id и другие изменяемые данные в переменных, а не хардкодить
- В скобках формы ввода можно указывать примеры формата (например, пример госномера)
- Группировка переменных по категориям (Водители, Пассажиры) критична для навигации в больших ботах
- Для тестирования нужны минимум 2 аккаунта Telegram (пассажир и водитель)

## Video 17: 17_Napominanie_Vyzov_Komandy
**Тема:** Создание напоминания о вызове следующей команды в боте (автоматическое сообщение, если пользователь не выполнил нужное действие)
**PuzzleBot-элементы:** Конструктор, команда Старт, текстовый блок, инлайн-клавиатура, переход к команде, вкладка Сценарии, пост в сценарии (тип отправки "Через"), действие "Изменить сценарии" (тумблер вкл/выкл)
**Категория:** Сценарии
**Ключевые техники:**
- Создание сценария-напоминания: добавление поста с типом отправки "Через" и заданным временем задержки
- Запуск сценария через действие в команде: тумблер направо = запуск
- Остановка сценария при вызове целевой команды: тумблер налево = остановка
- Связка двух команд для управления сценарием (запуск в одной, остановка в другой)
**Шаги реализации:**
1. Открыть вкладку "Конструктор", в команде "Старт" добавить текстовый блок с сообщением
2. Создать инлайн-клавиатуру с кнопкой перехода к целевой команде
3. Создать целевую команду с текстовым блоком
4. Перейти на вкладку "Сценарии", создать новый сценарий
5. В сценарии добавить пост с типом отправки "Через" и выставить нужное время
6. Добавить текстовый блок с текстом напоминания
7. Изменить статус поста из "Черновик" в "Запланирован"
8. Вернуться в Конструктор, открыть команду "Старт"
9. В разделе "Действия" добавить "Изменить сценарии" -> тумблер направо (запуск)
10. В целевой команде добавить действие "Изменить сценарии" -> тумблер налево (остановка)
11. Сохранить и опубликовать изменения
**Полезные детали:** Логика работы: при вызове "Старт" запускается таймер напоминания. Если пользователь вызвал целевую команду до истечения таймера, сценарий останавливается и напоминание не приходит. Если не вызвал -- получает напоминание через заданное время. Рекомендуется сначала посмотреть видео по созданию и привязке бота.

## Video 20: 20_Scenarii_Chast_1
**Тема:** Обзор возможностей вкладки "Автопостинг" (Сценарии) -- настройка отправки постов по индивидуальному расписанию пользователя
**PuzzleBot-элементы:** Вкладка Автопостинг (Сценарии), настройки сценария (автоотключение, количество прохождений, перезапуск), типы отправки (Сразу, Через, Точная дата), повторение поста (по дням недели, через количество дней), дополнительные настройки поста (добавить категорию, изменить сценарий, для категорий, действие в ресурсах, переход к команде)
**Категория:** Сценарии
**Ключевые техники:**
- Автопостинг vs. Постинг: в автопостинге каждый пользователь получает посты по личному расписанию от даты запуска сценария
- Три типа отправки: "Сразу", "Через" (от начала сценария или в точное время), "Точная дата и время"
- Тип "Через" имеет два подварианта: от начала сценария (через X дней, Y часов, Z минут) и в точное время (через X дней в HH:MM)
- Повторение поста: по дням недели или через определённое количество дней, с возможностью ограничения повторов
- Дополнительные настройки: добавление в категорию, управление сценариями, фильтрация по категориям, действия в ресурсах
- Сценарий создаётся выключенным по умолчанию; пост также выключен по умолчанию
**Шаги реализации:**
1. Перейти на вкладку "Автопостинг" в боте
2. Нажать "Добавить сценарий", открыть его
3. Настроить параметры сценария: автоотключение, количество прохождений, перезапуск при повторном вызове
4. Добавить пост, выбрать тип отправки
5. Настроить повторение поста при необходимости
6. Добавить контент (текстовые блоки, медиа и т.д.)
7. Настроить дополнительные параметры (категории, действия в ресурсах, переход к команде)
8. Переключить статус поста из выключенного во включённый
9. Активировать сценарий
**Полезные детали:** Время указывается по часовому поясу владельца бота, а НЕ пользователя. Переключатель состояния имеет три позиции: нейтральный, включить, выключить. Это первая часть -- во второй части показан практический пример платной подписки.

## Video 25: 25_Scenarii_Chast_2_Platnaja_Podpiska
**Тема:** Практический пример: создание сценария платной подписки с напоминанием об истечении и автоблокировкой
**PuzzleBot-элементы:** Вкладка Автопостинг (Сценарии), вкладка Модерация (категории), тип отправки "Через" (от начала сценария), повторение поста, дополнительная настройка "Добавить категорию" (сброс в "Без категории"), настройки сценария (перезапуск при повторном вызове), платёжные сервисы, группа команд с ограничением по категории, кнопка оплаты
**Категория:** Сценарии
**Ключевые техники:**
- Сценарий из 3 постов: активация подписки (сразу) -> напоминание (через 28 дней) -> блокировка (через 30 дней)
- Повторение поста для напоминания: через 1 день с ограничением в 1 повтор (28-й и 29-й день)
- Сброс категории через "Добавить категорию" -> "Без категории" для блокировки доступа
- Перезапуск сценария при повторном вызове: если пользователь оплатит заранее, сценарий перезапустится
- Связка: оплата -> присвоение категории -> запуск сценария подписки
- Группа команд с доступом по категории: ограничение контента для подписчиков
**Шаги реализации:**
1. В Модерации создать категорию для пользователей с активной подпиской
2. На вкладке "Автопостинг" создать сценарий "Подписка"
3. Пост 1: тип "Сразу", текст "Подписка активирована", активировать
4. Пост 2: тип "Через 28 дней", повторение через 1 день (лимит 1 повтор), текст напоминания, активировать
5. Пост 3: тип "Через 30 дней", в допнастройках добавить пользователя в "Без категории", текст блокировки, активировать
6. В настройках сценария включить "Перезапуск при повторном вызове"
7. Активировать сценарий
8. В Настройках подключить платёжные сервисы
9. В Конструкторе создать команду после успешной оплаты: присвоить категорию + запустить сценарий
10. Создать кнопку оплаты в основной команде
11. Создать группу команд с доступом по категории подписчиков
12. Опубликовать изменения
**Полезные детали:** При перезапуске сценария (досрочная оплата) все таймеры сбрасываются. Сценарий создаётся выключенным -- не забыть активировать. Для тестирования можно менять время отправки постов на минимальное. Сценарий работает в связке: оплата -> категория -> доступ -> отсчёт времени.
