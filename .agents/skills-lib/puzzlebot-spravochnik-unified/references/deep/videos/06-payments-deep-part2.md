# 06. Оплата и Магазин -- Глубокий справочник

## Video 73: 73_Obzor_Vkladki_Magazin_Servise
**Тема:** Обзор вкладки «Магазин» -- часть 1: включение магазина, автоматические команды (корзина, доставка, оплата, выбор валюты), блок товар (слайдер/блоки), основные настройки магазина, способы оплаты и доставки.
**PuzzleBot-элементы:** Магазин (включение, группа команд), блок «Товар» (слайдер / блоки), команды магазина (Выбор валюты, Корзина, Доставка, Оплата), настройки: время/дни работы, скрытие при нулевых остатках, кнопка продолжения оформления, группа товаров (свёрнутый вид), остаток товара, способы доставки и оплаты (дерево вариантов, подварианты, изменение суммы чека), мин/макс сумма и количество товаров, резервирование, статус заказа, оповещение о смене статуса
**Категория:** Магазин
**Ключевые техники:**
- При включении магазина автоматически создаётся группа команд с 4 обязательными этапами
- Блок «Товар» в режиме слайдера позволяет листать товары в одном блоке сообщений
- Дерево вариантов оплаты/доставки с подвариантами и изменением суммы чека
- Резервирование товаров: вычитание из остатков на период оформления
- Ограничения Telegram: оплата от $1 до $10000 через встроенные сервисы
**Шаги реализации:**
1. Вкладка «Магазин» > включить магазин > автоматическое создание группы команд
2. Группа команд магазина: настроить формы ввода в командах «Доставка» и «Оплата» (ответы попадают в чек)
3. Блок «Товар»: выбрать режим (слайдер / блоки), добавить товары по отдельности или категорией
4. Основные настройки: время/дни работы, скрытие при нулевых остатках, отображение остатка и артикула
5. Настроить мин/макс сумму и количество товаров для перехода к оформлению
6. Способы доставки: создать варианты с изменением суммы чека
7. Способы оплаты: создать дерево вариантов > подварианты > настройки (завершение без оплаты, изменение суммы)
8. Резервирование: задать время оформления, товары вычитаются из остатков после нажатия «Оформить»
9. Статус заказа: настроить этапы обработки, включить оповещение о смене статуса
10. Опубликовать изменения (аналогично конструктору)
**Полезные детали:** Команды «Доставка» и «Оплата» нельзя вызвать напрямую или настроить переход к ним -- они являются этапами оформления. Команды «Выбор валюты» и «Корзина» можно вызвать и настроить переход по кнопке. В блоках товары не повторяются даже при добавлении и по отдельности, и по категории. Все изменения в настройках оплаты/доставки нужно публиковать. При создании кнопок в оплате/доставке переходы возможны только вверх или вниз по ветке.

## Video 76: 76_Obzor_Obnovlenija_PuzzleBot_Magazin
**Тема:** Магазин в мини-приложениях: создание товаров (обычных и электронных), групп товаров, категорий с характеристиками, рекомендации, настройка доставки/оплаты/акций, блок «Товар» и навигация.
**PuzzleBot-элементы:** Магазин > Товары (обычный, электронный, группа товаров), категории (характеристики как шаблон), блок «Товар» (расположение, количество в ряду, поиск, фильтры по характеристикам), избранные товары, форма ввода «Выбор адреса» (системная в доставке), группа товаров (объединение по характеристикам, переключение вариантов), рекомендации (товары добавить, покупают вместе), блок «Меню» (корзина, заказы), акции (промокод, условия, бейдж), доставка (курьер, изменение стоимости), оплата (при получении), платёжные системы (30+), мульти-валюта
**Категория:** Магазин
**Ключевые техники:**
- Категории с характеристиками-шаблонами (например, «Вес») -- автоматически подставляются при создании товара
- Электронный товар: список элементов построчно, переменная для выданного элемента, режим «по списку» или «без ограничения» (цикличная выдача)
- Группа товаров: объединение по характеристикам (цвет, размер) с переключением вариантов в карточке
- Рекомендации: «Товары добавить» (допродажи) и «Покупают вместе» (целые категории)
- Подстановка мини-приложения на страницу товара (размерная сетка, условия доставки)
- Форма ввода «Выбор адреса» -- системная в командах доставки
- Поддержка 30+ платёжных систем
**Шаги реализации:**
1. Создать категорию с характеристиками (например, «Вес») -- шаблон для всех товаров категории
2. Создать обычные товары: название, описание, категория, медиа, тип «Обычный», остаток, цена, артикул
3. Доп. настройки товара: пропуск доставки, лимит на корзину, подстановка мини-приложения, команда/сценарий после покупки
4. Создать электронный товар: тип «Электронный», заполнить список элементов построчно, настроить режим выдачи
5. Объединить товары в группу: выбрать характеристику для вариантов (цвет/размер)
6. Настроить рекомендации: «Товары добавить» + «Покупают вместе» (товары или категории)
7. Настройки магазина > Доставка (включить курьер) > Оплата (при получении) > Платёжная система
8. Создать акцию-промокод с условием (определённая категория товара), добавить бейдж
9. Конструктор: мини-приложение > блок «Товар» (расположение, количество в ряду, поиск + фильтры) + блок «Избранные» + блок «Меню» (корзина, заказы)
10. Стартовая команда > переход к мини-приложению > опубликовать и проверить
**Полезные детали:** Характеристики категории автоматически наследуются товарами -- удобно для единообразия. Элементы электронного товара разделяются построчно, система отслеживает использованные. Подстановка на странице товара не отображает навигационные элементы (формы ввода, меню, клавиатуры, блоки товаров). Артикул должен быть уникальным. Бейдж акции отображается на карточках товаров-участников.

## Video 91: Sozdaem_Telegram_Bota_Vydachej
**Тема:** Создание бота с выдачей подарка при покупке от определённой суммы с использованием таблиц NocoDB
**PuzzleBot-элементы:** Интеграция NocoDB, действия «Обновить строку» и «Создать строку», условия с проверкой строки (фильтры по User ID и сумме), inline-клавиатура с платежом, исключающее правило
**Категория:** Магазин
**Ключевые техники:**
- Проверка наличия пользователя в таблице NocoDB и суммы его предыдущих оплат
- Условие с двумя правилами + исключающее правило: (1) есть в таблице + сумма >= порога → подарок; (2) есть в таблице + сумма < порога → без подарка; (исключение) нет в таблице → создать строку + без подарка
- Обновление строки с прибавлением суммы оплаты
- Обновление данных пользователя в таблице при каждом старте
**Шаги реализации:**
1. В NocoDB: создать таблицу с колонками (User ID, Username, Оплаченная сумма и др.)
2. В стартовой команде: добавить действие «Обновить строку» (поиск по User ID, запись актуальных данных) для обновления информации о пользователе
3. Добавить текстовый блок и inline-кнопку с платежом (выбрать валюту, стоимость, команду успеха)
4. Создать команды «Подарок» (текст с подарком) и «Без подарка» (текст без подарка)
5. Создать условие: Правило 1 — проверка строки (User ID совпадает + Оплаченная сумма >= порог) → обновить строку (прибавить сумму) + отправить команду «Подарок»
6. Правило 2 — проверка строки (User ID совпадает + Оплаченная сумма < порог) → обновить строку (прибавить сумму) + отправить команду «Без подарка»
7. Исключающее правило — создать строку с данными пользователя и начальной суммой + отправить «Без подарка»
8. В команде успешной оплаты: добавить действие «Отправить условие» + текстовый блок
9. Опубликовать и проверить
**Полезные детали:** Исключающее правило условия используется для обработки новых пользователей, которых ещё нет в таблице. При обновлении строки можно использовать операцию «Прибавить» для накопления суммы. Фильтры позволяют комбинировать условия: полное совпадение User ID + числовое сравнение суммы. Данные пользователя обновляются при каждом старте бота.
