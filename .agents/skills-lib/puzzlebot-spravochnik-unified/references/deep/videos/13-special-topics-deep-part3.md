# 13. Модерация и спецтемы -- Глубокий справочник

## Video 90: Sobiraem_Zajavki_Chat_Bota
**Тема:** Одобрение/отклонение заявок из подключённой группы с записью в Google Sheets (на примере проверки домашних работ)
**PuzzleBot-элементы:** Глобальные и персональные переменные, интегрированные переменные (Google Sheets), форма ввода, триггеры (в ресурсе), действия «Изменить переменную», «Обновить строку», «Отправить команду другому пользователю», условия с проверкой переменных, кнопка «Пропустить», удаление через время
**Категория:** Сценарии
**Ключевые техники:**
- Генерация уникального номера заявки через глобальную переменную-счётчик
- Формирование уникальных команд одобрения/отклонения через переменные (Accept/Reject), привязанные к номеру заявки
- Интегрированные переменные Google Sheets для поиска User ID по номеру заявки
- Триггер в ресурсе: запись сообщения в переменную + отправка условия «другому пользователю» (по User ID из таблицы)
- Выполнение команды другому пользователю через интегрированную переменную
**Шаги реализации:**
1. Создать переменные: глобальная Number (число), персональные Accept и Reject (текст), глобальная NumberGroup (текст)
2. Создать Google-таблицу с заголовками (User ID, Username, ФИО, Одобрение, Отклонение и др.)
3. Создать команду «Домашняя задача»: форма ввода → вопрос → кнопка «Пропустить» (переход к команде пропуска)
4. Добавить действия: увеличить Number на 1, записать Number в переменные Accept и Reject (формируя уникальные идентификаторы)
5. Создать команду-уведомление с текстом и переменными Accept/Reject, отправлять в ресурс (группу)
6. Настроить запись данных в Google Sheets (действие «Обновить строку» / «Создать строку»)
7. Создать интегрированные переменные IntegrAccept и IntegrReject: тип Google Sheets, поиск по столбцу «Одобрение»/«Отклонение», вывод User ID, кэшировать лист
8. Создать условие «Условие DZ1»: правило 1 — если переменная одобрения существует → отправить команду «Одобрить» другому пользователю (через IntegrAccept); правило 2 — аналогично для отклонения
9. В ресурсе → Триггеры: добавить триггер (текст, длина < 5 символов) → записать в переменную NumberGroup + отправить условие DZ1 в бот
10. Опубликовать и проверить
**Полезные детали:** Переменные для интеграции Google Sheets должны быть в текстовом формате. Порядок действий (ротация) важен — уведомление должно быть последним. Последовательность выполнения действий с переменными — «После». Триггер фильтрует сообщения по длине (< 5 символов), чтобы реагировать только на короткие номера-ответы. Галочка «Выполнить другому пользователю» позволяет отправить команду конкретному юзеру по ID.

## Video 92: Sozdaem_Kapchu_Dostupa_Kanal
**Тема:** Создание капчи для защиты канала/группы от спама — проверка перед одобрением заявки на вступление
**PuzzleBot-элементы:** Модерация (категории), inline-команды, группа команд, форма ввода (тестирование), случайный порядок вариантов, действие «Отправить случайную команду из группы», поп-ап, события ресурса (заявка на вступление), пригласительная ссылка с заявкой, действие «Принять/Отклонить заявку на вступление», действие «Изменить категорию»
**Категория:** Модерация
**Ключевые техники:**
- Пригласительная ссылка с обязательной заявкой на вступление
- Случайная капча из группы команд (действие «Отправить случайную команду из группы»)
- Тестирование с случайным порядком вариантов ответов
- Категория модерации как флаг прохождения капчи
- Автоматическое одобрение/отклонение заявки на основе наличия категории
**Шаги реализации:**
1. В «Модерации» создать категорию «Доступ» (флаг прохождения капчи)
2. В Telegram: создать пригласительную ссылку с включённым тумблером «Заявка на вступление», скопировать
3. Создать 4 inline-команды: Приветствие, Правила, Отправка случайной капчи, Успешное прохождение
4. Создать группу обычных команд для капч; внутри — несколько команд с разными капчами
5. Каждая капча: форма ввода (изображение) + тип ввода «Тестирование» + варианты (верные/неверные) + случайный порядок + поп-ап при ошибке + переход к команде случайной капчи при неверном ответе
6. При верном ответе: отправить команду «Успешное прохождение»; включить «Удалить текущую команду после вызова следующей»
7. Inline-команда «Отправка капчи»: действие «Отправить случайную команду из группы»
8. Inline-команда «Успех»: кнопка-ссылка на пригласительную ссылку + действие «Изменить категорию» (добавить «Доступ»)
9. Стартовая команда → отправить команду «Приветствие»
10. В ресурсе → События → «Заявка на вступление»: реакция 1 — «Принять заявку» (допнастройки: категория «Доступ» активна); реакция 2 — «Отклонить заявку» + отправить стартовую команду в бот + деактивировать категорию
**Полезные детали:** Inline-команды удаляются после вызова следующей (через допнастройки) — это предотвращает накопление сообщений. Случайный порядок вариантов включается в допнастройках формы ввода. Тумблер «Заявка на вступление» в пригласительной ссылке позволяет проверить пользователя до входа. При отклонении заявки категория деактивируется и пользователю снова отправляется стартовая команда (для повторной попытки).
