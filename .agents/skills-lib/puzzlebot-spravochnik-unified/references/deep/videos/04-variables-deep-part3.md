## Video 78: 78_Obzor_Standartnyh_Peremennyh
**Тема:** Обзор стандартных персональных переменных: имя, фамилия, юзернейм, ID, Premium-статус, дата регистрации, активные сценарии, категории, startPayload, аватар пользователя.
**PuzzleBot-элементы:** Переменные: FirstName / FirstNameText, LastName / LastNameText, Username / UsernameText, FullName, UserId / UserIdText, hasPremium / hasPremiumBool, joinDate / joinDateTimeStamp, ActiveScenarios, categoryName / categoriesNames, startPayload, UserAvatarUrl; условия с переменными, блок HTML, формулы (floor, timestamp-расчёты)
**Категория:** Переменные и условия
**Ключевые техники:**
- FirstName (ссылка) vs FirstNameText (текст) -- разные форматы вывода имени
- hasPremiumBool (1/0) удобен для логических проверок в условиях
- joinDateTimeStamp + формула floor для расчёта дней с момента регистрации: `floor((currentTimestamp - joinDateTimeStamp) / 604800)`
- startPayload -- данные после `start=` в ссылке бота (промокод, UTM, ID реферала)
- UserAvatarUrl -- ссылка на аватарку для личных кабинетов и интеграций
- categoriesNames -- все категории пользователя через запятую
**Шаги реализации:**
1. Приветственное сообщение: использовать FirstName / FirstNameText для обращения по имени
2. FullName -- вывод полной информации (имя + фамилия + юзернейм) в виде ссылки
3. UserId -- использовать для интеграций с базами данных (неизменный идентификатор)
4. hasPremiumBool: создать условие для проверки Premium-подписки (1 = есть, 0 = нет)
5. joinDate: отслеживание давности регистрации; joinDateTimeStamp: расчёт дней с регистрации через timestamp
6. ActiveScenarios: мониторинг активных сценариев пользователя (через запятую)
7. categoryName / categoriesNames: отображение текущих категорий пользователя
8. startPayload: отслеживание источника перехода (реклама, реферал, акция)
9. UserAvatarUrl: вставить в блок HTML для отображения аватарки в мини-приложении
10. Проверить вывод всех переменных в боте
**Полезные детали:** Пользователь может сменить имя, фамилию, юзернейм, но UserId всегда остаётся одинаковым -- используйте его для интеграций. hasPremium выводит текст «есть»/«нет», hasPremiumBool -- числа 1/0 для условий. Расчёт недель с регистрации: (currentTimestamp - joinDateTimeStamp) / 604800 (7 дней в секундах). startPayload полезен для UTM-меток, промокодов и реферальных систем.

## Video 105: Sozdajom_Chekboks_Telegram_Chat
**Тема:** Создание чекбоксов (переключаемых кнопок) в Telegram-боте с использованием переменных и кнопок-условий
**PuzzleBot-элементы:** Переменные (Icon1, Icon2), инлайн-команда, кнопка «Условия», проверка значения переменной, действие «Изменить переменную», действие «Отправить команду или условия», исключающее правило, инлайн-клавиатура, дублирование кнопки
**Категория:** Переменные и условия
**Ключевые техники:**
- Создание переключаемых кнопок через переменные с иконками (галочка/пусто)
- Использование кнопки «Условия» с проверкой значения переменной
- Переключение значения переменной на противоположное при нажатии
- Перезагрузка инлайн-команды для обновления отображения кнопок
- Режим «только одна галочка»: при активации одной кнопки сброс всех остальных переменных
**Шаги реализации:**
1. Создать переменные для каждой кнопки (Icon1, Icon2) со значением по умолчанию — иконка галочки
2. Создать инлайн-команду с текстовым блоком
3. Создать кнопку «Условия»: проверка значения Icon1 -> если галочка, то сменить на пустое + отправить инлайн-команду
4. Исключающее правило: сменить на галочку + отправить инлайн-команду
5. Аналогично создать кнопку «Условия» для Icon2
6. В инлайн-команде добавить кнопки типа «Кнопка условия» с ссылками на созданные кнопки
7. В стартовой команде добавить действие «Отправить команду» -> инлайн-команда
8. Для режима «только одна галочка»: в каждой кнопке при установке галочки добавить сброс всех остальных переменных
9. Опубликовать и проверить
**Полезные детали:** Переменные используют иконки (галочка для выбрано, ничего для невыбрано) — они отображаются в названии кнопки через двойные фигурные скобки. При нажатии на кнопку меняется переменная и заново отправляется инлайн-команда для обновления вида. Для радио-кнопок (только один выбор) нужно в исключающем правиле удалить действие изменения, а в основном правиле добавить сброс всех остальных переменных.
