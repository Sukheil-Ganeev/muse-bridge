## Video 02: 02_Pro_Dostup_Za_Podpisku
**Тема:** Выдача trial-периода за подписку на два канала с автоматической проверкой подписки раз в час и завершением trial через 3 дня.
**PuzzleBot-элементы:** Ресурсы (каналы), Категории пользователей, Сценарии (с таймерами и перезапуском), Условия (проверка подписки на ресурс), Группы команд (с ограничением по категории), Действия (изменить сценарий, изменить категорию, отправить команду), Пригласительные ссылки.
**Категория:** Группы и каналы
**Ключевые техники:**
- Добавление бота как администратора в канал (с полными правами, включая "Выбор администратора") для подключения ресурса
- Создание категории пользователей (например, "Промо-про") для управления доступом к группам команд
- Использование двух сценариев: один для периодической проверки подписки (раз в час), другой для завершения trial-периода (через 3 дня)
- Проверка подписки на несколько каналов одновременно через условие "Наличие подписки"
- Создание отдельной группы команд с ограничением доступа по категории пользователей
- Перезапуск сценария при повторном вызове для корректной работы периодических проверок
**Шаги реализации:**
1. Добавить бота как администратора в целевые каналы (обязательно все права, включая "Выбор администратора")
2. Написать сообщение в канал (можно удалить) для активации ресурса
3. Добавить ресурсы (каналы) в панели PuzzleBot
4. Создать категорию "Промо-про" для пользователей с trial-доступом
5. Создать два сценария: "Проверка триала раз в час" и "Завершение trial-периода через 3 дня"
6. Создать команду "Тестовый доступ" с кнопками-ссылками на каналы и кнопкой проверки подписки
7. Создать условие проверки подписки: если подписан на оба канала -- "Успешная подписка", иначе -- "Неуспешная подписка"
8. В "Успешная подписка": запустить оба сценария, присвоить категорию "Промо-про", перевести в группу команд "Pro"
9. Настроить сценарий "Завершение trial": через 3 дня вызвать команду "Trial завершён"
10. Настроить сценарий "Проверка триала": раз в час вызывать условие проверки подписки в ресурсах; перезапуск при повторном вызове
11. В "Trial завершён": отключить оба сценария, сменить категорию на "Бесплатный"
12. В "Trial заблокирован" (при отписке от канала): отключить сценарии, сменить категорию, уведомить
13. Создать группу команд "Pro" с ограничением доступа по категории "Промо-про"
**Полезные детали:**
- Бот обязательно должен быть администратором канала с полными правами, иначе ресурс не добавится
- Сценарий проверки подписки должен иметь включенный "Перезапуск при повторном вызове"
- Для отслеживания переходов в канал можно использовать пригласительные ссылки (Изменить > Пригласительная ссылка > Создать ссылку)
- Категорию "Бесплатный" используют, чтобы у пользователя пропала кнопка "Активировать бесплатно" и он не мог повторно получить trial
- Пост в сценарии обязательно должен быть "Запланирован" для корректной работы

## Video 41: 41_Vhod_Zajavkam_Chaty_Kanaly
**Тема:** Автоматический прием заявок на вступление в чат/канал через бота, бот пишет пользователю первым
**PuzzleBot-элементы:** Ресурс (чат/канал), вкладка "События" (ресурса), реакция на заявку на вступление, действие "Принять заявку на вступление", текстовый блок, инлайн-клавиатура, переход к команде
**Категория:** Группы и каналы
**Ключевые техники:**
- Добавление бота в ресурс (чат/канал) как администратора с полными правами
- При подключении канала -- отправка любого сообщения для обнаружения ботом
- Настройка реакции на событие "Заявка на вступление" -- отправка команды "Старт" в бот
- Действие в ресурсе: "Принять заявку на вступление"
- Бот пишет первым пользователю при появлении заявки
- Пригласительная ссылка с включенной функцией "Заявки на вступление"
**Шаги реализации:**
1. Добавить бота в ресурс (чат/канал) как администратора с полными правами
2. При подключении канала отправить и удалить любое сообщение, чтобы бот увидел ресурс
3. В личном кабинете нажать "Добавить ресурс", выбрать ресурс
4. В конструкторе настроить команду "Старт" с приветствием и кнопкой "Вступить в чат"
5. Создать команду "Вступление" с действием "Принять заявку на вступление" + текстовый блок об успешном вступлении
6. В настройках ресурса -> "События" -> активировать "Заявка на вступление" -> добавить реакцию -> отправить команду "Старт" в бот
7. В Telegram создать пригласительную ссылку с включенной функцией "Заявки на вступление"
8. Опубликовать и протестировать
**Полезные детали:** Ключевой момент -- бот может писать первым пользователю, который подал заявку, даже если ранее не общался с ботом. Пользователь переходит по ссылке -> подает заявку -> бот автоматически пишет -> пользователь нажимает кнопку -> заявка принимается. Ресурс = чат или канал в терминологии PuzzleBot.

## Video 43: 43_Vydajom_Dostup_Kommentarijam_Posle
**Тема:** Ограничение комментариев в канале только для подписчиков, автоматическая отправка правил чата под постом
**PuzzleBot-элементы:** Ресурс (канал + группа/чат для комментариев), категории (модерация), вкладка "События" (подписка/отписка на канал), триггеры (в группе), действие "Удалить сообщения", тип сообщения "Все", условие длина > 0, дополнительные настройки триггера "Для категории", вкладка "Постинг", событие "Новый пост в канале"
**Категория:** Группы и каналы
**Ключевые техники:**
- Создание категории "Подписчик" для отслеживания статуса подписки
- Событие "Пользователь подписался на канал" -> добавление в категорию; "Покинул канал" -> деактивация категории
- Ручное добавление существующих подписчиков в категорию (массовое выделение + "Изменить категорию")
- Триггер в группе: удаление всех сообщений (длина > 0) для пользователей без категории "Подписчик"
- В дополнительных настройках триггера: "Для категории" -> отключить тумблер напротив категории с доступом
- Автоматическое сообщение с правилами чата при новом посте в канале (событие "Новый пост в канале")
- Постинг для планирования публикаций
**Шаги реализации:**
1. Подключить канал и группу (чат комментариев) к боту
2. В разделе "Модерация" канала создать категорию "Подписчик"
3. Вручную добавить существующих подписчиков в категорию (выделить всех -> "Изменить категорию")
4. Во вкладке "События" канала: при подписке -- добавить в категорию, при отписке -- деактивировать
5. Перейти в подключенную группу -> вкладка "Триггеры"
6. Создать триггер: тип "Удалить сообщения", тип сообщения "Все", условие "длина > 0"
7. В дополнительных настройках триггера: "Для категории" -> отключить тумблер для категории "Подписчик" (триггер сработает для всех, кроме подписчиков)
8. Во вкладке "События" группы: "Новый пост в канале" -> написать сообщение с правилами
9. Через вкладку "Постинг" запланировать пост для проверки
10. Опубликовать и протестировать
**Полезные детали:** Ключевой нюанс -- триггер работает по принципу исключения: он срабатывает для ВСЕХ категорий, кроме тех, где тумблер отключен. Поэтому подписчики с категорией не попадают под удаление. Существующих подписчиков нужно добавить в категорию вручную, так как событие подписки фиксируется только для новых. Связка канал + группа комментариев -- стандартная схема Telegram.

## Video 46: 46_Dobavljaem_Proverku_Podpiski_Chat
**Тема:** Ограничение доступа к командам бота для неподписанных на чат/канал пользователей
**PuzzleBot-элементы:** Группы команд (с привязкой к ресурсу), ресурс (чат/канал), настройки группы команд (выбор ресурса для проверки подписки), инлайн-клавиатура, переход к команде из другой группы
**Категория:** Группы и каналы
**Ключевые техники:**
- Создание отдельной группы команд с привязкой к ресурсу: доступ только для подписчиков
- Настройки группы команд -> выбор ресурса для проверки подписки
- Кнопка в стартовой команде с переходом к команде из защищенной группы
- Простейший способ проверки подписки без условий и категорий
**Шаги реализации:**
1. Подключить бота к ресурсу (чат/канал) и добавить его как администратора
2. В конструкторе создать новую группу команд, дать название
3. Открыть настройки группы команд, выбрать ресурс для проверки подписки, сохранить
4. Добавить команды с контентом в новую группу
5. В основной группе в команде "Старт" написать текст со ссылкой на ресурс
6. Добавить кнопку с переходом к команде из новой группы
7. Опубликовать и протестировать
**Полезные детали:** Это самый простой способ проверки подписки -- без условий, категорий и сложной логики. Достаточно привязать группу команд к ресурсу. Если пользователь не подписан, при попытке перейти к команде из защищенной группы он получит ошибку. После подписки команда станет доступна. Подходит для простых сценариев, где не нужна гибкая логика.
