# Решение проблем PuzzleBot

> 15 типичных проблем и их решения.
> Собрано из видеоуроков и 68,659 сообщений сообщества.

---

## 1. Ресурс не появляется в списке для подключения

**Симптомы:** Добавили бота в канал/группу как админа, но в ЛК PuzzleBot ресурс не виден.

**Решение:**
1. Убедиться, что боту выданы ВСЕ права администратора, **включая последний переключатель** (нужен для юзер-бота)
2. **Отправить любое сообщение** в ресурс (можно сразу удалить) -- без этого бот не обнаружит ресурс
3. Подтвердить ресурс в ЛК **в течение 20 минут** -- после этого бот автоматически выйдет из неподтвержденного ресурса

## 2. Google Sheets перестает работать при рассылке

**Симптомы:** При массовой рассылке с интегрированными переменными из Google Sheets данные не подгружаются, ошибки.

**Причина:** Google Sheets допускает только **60 запросов в минуту**.

**Решение:**
- Ставить **большое кэширование** в условиях и интегрированных переменных
- Для больших баз (>1000 пользователей) рассмотреть переход на **NocoDB** (10 запросов/секунду)
- Разбивать рассылки на порции с задержкой

---

## 3. Интегрированная переменная не загружается с первого раза в мини-приложении

**Симптомы:** При первом открытии мини-приложения данные пустые, при повторном -- появляются.

**Причина:** Действия «До» в мини-приложениях выполняются не совсем «До», а «Между».

**Решение:**
1. Создать промежуточное мини-приложение для изменения переменной и переадресации на целевое
2. Или получать данные скриптом напрямую, без интегрированной переменной

---

## 4. Бот не реагирует на триггеры в группе

**Симптомы:** Триггер настроен, но бот не отвечает. Ошибка «не удалось найти пользователя».

**Причина:** Включена настройка «действие выполнять пользователю, получившему ответ», а сообщение отправлено не ответом (reply).

**Решение:**
- Убрать настройку «действие выполнять пользователю, получившему ответ»
- ИЛИ отвечать на сообщения через кнопку «Ответить» (reply)

---

## 5. Нельзя зациклить команды в конструкторе

**Симптомы:** Нужно повторять команду до выполнения условия, но конструктор запрещает зацикливание.

**Решение (3 варианта):**
1. **Форма ввода** с параметром «Ограничение времени» (минимум 5 сек). Если пользователь не ответил -- условие проверяет, нужно ли повторить
2. **Сценарий** с типом отправки «Через» (минимум 1 минута), который отправляет условие, запускающее сценарий заново
3. **API-запрос** к PuzzleBot (для продвинутых)

**Важно:** Сценарий работает ТОЛЬКО с типом «Через», не «Сразу».

## 6. Файлы загружаются в неправильном формате/размере через ЛК

**Симптомы:** Видео или документ не загружается в личном кабинете (лимит размера).

**Решение -- загрузка через File ID:**
1. Открыть бота в Telegram
2. Отправить команду `/cp`
3. Выбрать «Загрузить файл» и отправить файл боту
4. Скопировать ID вида `AgACAgIAAxkBA...`
5. Вставить ID в блок в личном кабинете

Лимит через File ID -- **до 2 ГБ**. Важно: ID уникальны для каждого бота.

## 7. Переменная не отображается после создания

**Симптомы:** Создал переменную, но она не появляется в списке доступных для подстановки.

**Решение:**
- **Перезапустить конструктор** (перезагрузить страницу) -- после создания переменной она может не сразу появиться в списке
- Убедиться, что имя переменной содержит только **латиницу A-Z, цифры и нижнее подчеркивание**
- Для форм ввода: переменная создается автоматически -- искать среди системных переменных формы

## 8. Ошибка 80 при оплате

**Симптомы:** При попытке оплаты через бота (Робокасса) пользователь видит ошибку 80.

**Причина:** Превышен лимит дохода за месяц или суммарного дохода аккаунта.

**Решение:**
- Проверить лимиты на странице Тарифов PuzzleBot
- Лимит сбрасывается **1-го числа каждого месяца**
- Перейти на более высокий тариф для увеличения лимита

---

## 9. Сценарий не работает / не отправляет посты

**Симптомы:** Сценарий создан, но пользователь не получает посты.

**Чек-лист:**
1. Сценарий **активирован** (переключатель включен)?
2. Пост в сценарии имеет статус **«Запланирован»** (не «Черновик»)?
3. Если зацикливание -- тип отправки **«Через»** (не «Сразу», минимум 1 минута)?
4. Снята ли галочка **«Завершить после выполнения всех постов»** (если нужен бесконечный цикл)?
5. Включен ли **«Перезапуск при повторном вызове»** (если нужен сброс таймеров)?

## 10. Кнопки формы ввода удаляются после нажатия

**Симптомы:** Пользователь нажимает кнопку в форме ввода -- она исчезает.

**Причина:** Это стандартное поведение форм ввода -- после ответа форма удаляется.

**Решение:**
- Использовать обычный блок с инлайн-кнопками вместо формы ввода
- Каждая кнопка ведет на отдельную команду с формой ввода
- Или включить в каждом варианте «Не записывать ответ» для кнопки выхода

---

## 11. Уведомления сыплются для каждой формы ввода отдельно

**Симптомы:** При заполнении анкеты из 5 форм приходит 5 отдельных уведомлений.

**Решение:**
1. Перейти в **Настройки > Формы ввода**
2. **Создать правило** объединения уведомлений
3. Выбрать тип **«Сложный»** (если пользователь может ответить не на все формы)
4. Указать завершающие формы ввода и все участвующие формы
5. Теперь придет **одно общее уведомление** вместо отдельных

## 12. Тип условия нельзя изменить после сохранения

**Симптомы:** Создал «Обычное условие», а нужна «Кнопка условия» (или наоборот).

**Причина:** Тип условия (Обычное / Кнопка) фиксируется при создании и не подлежит изменению.

**Решение:**
- Удалить условие и создать новое с правильным типом
- **На будущее:** внимательно выбирать тип при создании
- **Подсказка:** «Кнопка условия» видна только при выборе действия «Кнопка условия» в инлайн-кнопке

## 13. Бот не пишет первым после подписки на открытый канал

**Симптомы:** Пользователь подписался на канал, но бот не отправляет ему сообщение.

**Причина:** Ограничение Telegram -- бот не может писать пользователю, который никогда не взаимодействовал с ботом.

**Решение:**
- **Закрытый ресурс** с функцией «Заявка на вступление» -- единственный способ, когда бот может написать первым
- Для открытых каналов: событие подписки сработает только если пользователь **уже запускал бота ранее**

---

## 14. Глобальная переменная-счетчик не синхронизируется с номером сообщения в канале

**Симптомы:** Используете глобальную переменную для нумерации заявок, но номер не совпадает с номером сообщения в канале.

**Решение:**
- Глобальная переменная `global_number` должна быть **числового типа** (не текст!)
- Значение должно **точно совпадать** с номером последнего сообщения в канале
- При первой настройке: посмотреть номер последнего сообщения в канале (через @getmyidbot) и установить начальное значение переменной
- Рекомендуется хранить `chat_id` и другие изменяемые данные в переменных, а не хардкодить

---

## 15. Порядок выполнения действий неправильный

**Симптомы:** Действие выполняется после отправки сообщения, хотя нужно до. Или переменная не успевает обновиться.

**Причина:** По умолчанию действия выполняются ПОСЛЕ отправки блоков.

**Решение:**
- Установить **последовательность выполнения «До»** (в настройках действия) -- сначала действие, потом блок
- Для команд с вычислениями: действия с числами должны быть **СВЕРХУ**, отправка в другую команду -- **СНИЗУ**
- Для сценариев: сначала вычесть/прибавить (последовательность «До»), потом отправить условие

**Правило:** Если нужно изменить переменную до использования её в тексте -- всегда ставить «До».

## Быстрая диагностика

| Проблема | Первое действие |
|----------|----------------|
| Ресурс не подключается | Отправить сообщение в ресурс + проверить права бота |
| Данные не загружаются | Проверить кэширование + лимиты API (60/мин для Sheets) |
| Сценарий не работает | Проверить статус поста (Запланирован) + активация сценария |
| Условие не срабатывает | Проверить тип проверки (Все/Любая) + порядок правил |
| Оплата не проходит | Проверить лимиты тарифа + подключение платежной системы |
| Переменная пустая | Перезагрузить конструктор + проверить последовательность «До» |
| Бот не отвечает | Проверить публикацию изменений (кнопка «Опубликовать») |
