# 10. Рассылки и категории

## Массовая рассылка (блок Рассылка)

Рассылка отправляется через вкладку **Постинг** с выбором места отправки **Бот**.

### Создание рассылки

1. Вкладка **Постинг** > кнопка **Создать новый пост**
2. В модальном окне: добавить блоки (текст, медиа, инлайн-кнопки)
3. Место отправки: выбрать **Бот** (обязательно для рассылки по категориям)
4. Можно одновременно выбрать бот + ресурсы -- пост уйдёт и в бот, и в каналы/группы
5. Дата/время: **Запланировать** на нужное время или **Отправить сейчас**
6. Дополнительные настройки: защита от пересылки/сохранения, отправка без уведомления

### Повторяющаяся рассылка

В дополнительных настройках поста можно включить **повторение**:
- Выбрать интервал (каждый день, каждую неделю, каждый месяц)
- Выбрать конкретный день недели
- Пост будет автоматически отправляться по расписанию

### Действия при рассылке

В разделе **Действия** поста можно добавить:
- **Отправить команду или условие** -- запустить команду конструктора
- **Смена категории** -- автоматически присвоить/убрать категорию получателям
- **Закрепление** -- закрепить пост в чате/канале
- **Удаление** -- удалить пост через определённое время

### Статусы постов

- **Отправленные** -- уже опубликованные посты (можно редактировать текст, но нельзя добавлять блоки)
- **В очереди** -- запланированные посты
- **Черновики** -- сохранённые, но не запланированные

### Навигация по рассылкам (из OCR)

**Вкладка:** `Постинг` в левом меню бота
- Верхняя панель: Статистика `Сообщений: День` / `Команд: День` / `Топ пользователей: День` / `Топ команд: День`
- Кнопка: **Создать новый пост**
- Категории: снять галочку `Любая` -> выбрать нужные
- Место отправки: `Бот` + ресурсы (каналы/группы)

## Категории пользователей

Категории -- инструмент сегментации аудитории бота. Позволяют разделять пользователей на группы для рассылок, ограничения доступа и автоматизации.

### Создание категории

1. Вкладка **Модерация** > кнопка **+**
2. Ввести название категории (например, "VIP", "Новичок", "Оплатил курс")
3. Сохранить

### Ручное присвоение

- Во вкладке **Модерация** навести на пользователя > столбец **Категория** > выбрать нужную
- Для просмотра пользователей по категории: вверху страницы навести на текущую категорию и выбрать нужную

### Автоматическое присвоение

Через действие **Изменить категории** в любой команде конструктора:

1. Добавить действие **Изменить категории**
2. Выбрать нужную категорию
3. Выбрать тип операции:
   - **Изменение** -- добавляет/убирает только указанные категории (остальные не трогает)
   - **Замена** -- заменяет ВСЕ категории пользователя на указанные

Разница важна: если у пользователя 3 категории и вы используете **Замену** -- останется только новая. При **Изменении** -- добавится к существующим.

### Применение категорий

- Рассылки по группам
- Ограничение доступа к группам команд
- Ограничение прав в чатах (разрешение/запрет сообщений)
- Проверка в условиях (наличие/отсутствие категории)
- Динамические кнопки (кнопка-условие с проверкой категории)
- Флаги одноразовых действий (например, "получил баллы за подписку")

## Рассылка по категориям

Рассылка по категориям доступна **ТОЛЬКО** если среди мест отправки выбран **Бот**. При отправке только в ресурс -- выбор категории недоступен.

### Шаги

1. Вкладка **Постинг** > **Новый пост**
2. Место отправки: выбрать **Бот** (можно дополнительно выбрать ресурсы)
3. В разделе категорий: убрать галочку с **Любая**
4. Раскрыть список, отметить нужную категорию (или несколько)
5. Заполнить текст поста, добавить медиа, кнопки
6. Выбрать время, запланировать или отправить

Пост получат **только** пользователи с отмеченными категориями.

### Категории vs Аудитории

- **Категория** -- группа пользователей бота (присваивается вручную или автоматически)
- **Аудитория** -- подписчики ресурса, которые также являются пользователями бота

При отправке в ресурс пост получают все подписчики ресурса вне зависимости от категорий.

## Рассылка по покупкам

Для рассылки по пользователям, совершившим покупку:

### Вариант 1: Через категорию

1. Создать категорию **Купил продукт X**
2. В команде успешной оплаты: действие **Изменить категории** > добавить категорию
3. При рассылке: выбрать эту категорию

### Вариант 2: Через условие и таблицу

1. Рассылка ведёт на **условие**
2. Условие проверяет наличие ID в таблице (Google Sheets / NocoDB)
3. Если есть -- отправить команду с контентом
4. Если нет -- ничего не делать

Важно: при использовании Google Sheets ставьте большое кэширование. Google допускает только **60 запросов в минуту**.

## Кнопка под сообщение + рассылка

В постинге можно добавлять **инлайн-кнопки** под сообщение:

1. Создать пост во вкладке **Постинг**
2. Добавить текстовый блок
3. Добавить **инлайн-клавиатуру**
4. Действия кнопок: ссылка, переход к команде, реакция, платёж

Обычную клавиатуру в постинге добавить **нельзя** -- только инлайн.

### Кнопки-реакции

Тип действия кнопки **Реакция**: вписать эмодзи для каждой кнопки. Пользователи голосуют нажатием, счётчик увеличивается.

## Отслеживание трафика (источники, переменная Source)

### Концепция

Три задачи отслеживания трафика:
1. **Определить** источник (откуда пришёл пользователь)
2. **Записать** данные в переменную/базу данных
3. **Направить** пользователя по нужной воронке

### Настройка переменной Source

1. Во вкладке **Переменные** создать персональную переменную **Source** (тип: текст)
2. В команде/условии при входе: действие **Изменить переменную** > Source = "Название источника"
3. Использовать Source в уведомлениях, таблицах, условиях

### Уведомление в группу-форум

1. Создать команду уведомления: текст с переменными (FirstName, Username, Source)
2. **Изменить место отправки** > ресурс (группа-форум) > выбрать топик **Новые подписчики**
3. В стартовой команде: действие перехода к условию проверки источника

Если тема форума создана до подтверждения ресурса -- она не отобразится. Нужно изменить название темы в Telegram, затем обновить страницу конструктора.

## UTM-метки и startPayload

### startPayload для бота

Переменная `startPayload` содержит данные после `start=` в ссылке бота:
- Формат ссылки: `https://t.me/UserNameBot?start=метка`
- Значение метки записывается в startPayload автоматически
- Можно использовать для UTM, промокодов, реферальных ID

### WebPageStartPayload для мини-приложений

Для мини-приложений используется переменная `WebPageStartPayload`:
- Формат ссылки: `https://t.me/UserNameBot?startapp=метка`
- Значение после `_` записывается в переменную
- Лимит: до **512 символов** после `_`

### Извлечение данных из startPayload

Для парсинга данных из метки используется формула **match**:
```
match(startPayload, "PB(.*)")
```
Это позволяет извлечь часть строки по регулярному выражению.

### Многоразовые ссылки с категориями

1. Вкладка **Вход** > **Создать многоразовую ссылку**
2. Название для статистики
3. **Изменить список категорий**: включить нужную (например, "Лид-магнит"), выключить "Без категории"
4. Использовать ссылку для отслеживания -- при переходе автоматически присваивается категория

### Цепочка условий для маршрутизации

1. Условие **"Есть ли источник"**: проверка наличия переменной Source и категории
2. Условие **"По какой ссылке"**: проверка категории "Лид-магнит" > запись Source > переход к нужной воронке
3. **Исключающее правило**: Source = "Неизвестно" > приветствие по умолчанию

## Статистика рассылок

### Фильтры в постинге

- Фильтрация по статусу: **отправленные**, **в очереди**, **черновики**
- Фильтрация по дате
- Рядом с датой в левой панели отображается количество постов (запланированных/черновых/отправленных)

### Статистика доставки

- Количество получателей -- видно после отправки
- Для анализа эффективности: добавляйте инлайн-кнопки в пост и отслеживайте нажатия через действия (изменение переменной-счётчика)
- Используйте категории для A/B тестирования: разделите аудиторию на группы и отправляйте разные версии

### Советы по рассылкам

- **Напоминание для неактивных**: на /start вешать сценарий. Через N дней запускать условие: если не обращался к ключевой команде -- отправить пост
- **Рассылка отписавшимся от канала**: пост с действием "переход к условию" > условие проверки подписки > если не подписан -- отправить сообщение
- **Пуш для бросивших бота**: сценарий с постом, тип "через 7 дней", перезапуск при повторном вызове. Активный пользователь перезапускает сценарий. Неактивный получит пост через 7 дней
- **Загрузка списка для рассылки**: отправить на support@puzzlebot.top username бота и файл (.csv / Excel) с Telegram ID пользователей
