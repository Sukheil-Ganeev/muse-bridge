
# PuzzleBot Конструктор -- Полный справочник

> Источники: 112 видео-туториалов (официальный канал PuzzleBot) + 68,659 сообщений сообщества (8,712 Q&A пар, 9 категорий) + OCR 3,859 кадров (3 млн символов экранного текста, 164 кнопки, 238 команд). Период: 2024-03 -- 2026-02.

---

## 1. Quick Start: бот за 5 минут

### Шаг 1. Создать бота в BotFather
1. Открыть Telegram, найти **@BotFather** (обязательно с галочкой верификации -- существуют фейки).
2. Отправить `/newbot`.
3. Ввести **название бота** (отображаемое имя).
4. Выбрать **username** -- уникальный, заканчивается на `bot` (например, `MyShopBot`).
5. Скопировать **API-ключ** (токен) из ответа BotFather. Это конфиденциальная информация.

### Шаг 2. Подключить бота к PuzzleBot
1. Перейти на **puzzlebot.top** -> "Личный кабинет".
2. Войти через Telegram (кнопка "Войти через Telegram" -> "Начать" в Telegram -> перейти по ссылке).
3. Нажать "Добавить бота" -> вставить API-ключ -> подтвердить.

### Шаг 3. Создать приветственную команду /start
1. Перейти во вкладку **Конструктор**.
2. Удалить шаблонные команды: зажать **Shift** -> выделить все -> удалить -> **Опубликовать**.
3. Открыть команду **Start** -> добавить **Текстовый блок** с приветствием.
4. Для персонализации вставить переменную `{{FIRST_NAME_TEXT}}` (имя пользователя).

### Шаг 4. Добавить кнопки
1. Создать **Обычную клавиатуру** (навигация, сохраняется до замены другой командой).
2. Добавить кнопки с действием "Переход к команде или условию".
3. Создать целевые команды, заполнить контентом.
4. Нажать **Опубликовать** -> проверить бота в Telegram.

### Быстрые советы
- Для slash-команд (`/command`): только латиница и цифры, до 32 символов.
- Включить "Отображать в меню" в дополнительных настройках -- появится кнопка "Меню" в Telegram.
- Форматирование текста: **только через встроенную панель** (выделить текст -> B/I/подчеркивание). Markdown-символы и HTML-теги НЕ работают.

### Рекомендация: /start должна быть пустой
Лучшая практика из сообщества: команда /start должна быть **пустой и переадресующей**. Скопируйте содержимое в другую команду, а со старта перенаправляйте через условие с проверкой категорий. Это позволяет гибко маршрутизировать новых и возвращающихся пользователей.

## 2. Архитектура PuzzleBot

### Основные вкладки панели управления

| Вкладка | Назначение |
|---------|------------|
| **Вход** | Многоразовые ссылки, промо-ссылки, реферальная система, отслеживание источников трафика |
| **Конструктор** | Создание команд, условий, кнопок, форм ввода, действий, мини-приложений |
| **Модерация** | Пользователи, категории, блокировка, массовые действия, экспорт в Excel |
| **Постинг** | Создание и рассылка постов в бота, каналы, чаты. Мультипостинг |
| **Автопостинг (Сценарии)** | Индивидуальные сценарии для каждого пользователя (таймеры, цепочки, напоминания) |
| **Магазин** | Товары, корзина, доставка, оплата, промокоды, электронные товары |
| **Настройки** | Платежные системы, интеграции (Google Sheets, NocoDB, Bitrix24, AmoCRM), подписки на события, уведомления, дублирование/перенос |
| **Статистика** | Ответы на формы ввода, аналитика |
| **Переменные** | Персональные и глобальные переменные |

### Типы команд

| Тип | Цвет | Поведение | Клавиатуры | Блоки |
|-----|-------|-----------|------------|-------|
| **Обычная** | Синий | Отправляется как новое сообщение | Обычная + инлайн | Несколько |
| **Инлайн** | Розовый | Заменяет текущее сообщение (на месте) | Только инлайн | Один |

**Правила перехода:**
- Обычная -> Инлайн = замена текста ответа бота (инлайн-режим)
- Инлайн -> Обычная = новое сообщение
- Инлайн -> Инлайн = замена на месте (блок того же типа)
- Обычная клавиатура ведет на обычные команды; инлайн-клавиатура -- на оба типа

### Категории пользователей
- Объединяют пользователей для применения действий (права в группе, доступ к командам, рассылки).
- Категория "Без категории" -- стандартная, не удаляется.
- Пользователь может находиться в **любом количестве** категорий одновременно.
- Создаются во вкладке **Модерация**.
- Изменяются: автоматически (действия в командах/сценариях) или вручную (модерация).

### Ресурсы (каналы, группы)
- Подключение: добавить бота как **администратора с полными правами** (включая "Выбор администратора").
- Для каналов: обязательно **написать любое сообщение** в канал (можно удалить) -- иначе ресурс не обнаружится.
- В ЛК: "Добавить ресурс" -> выбрать из списка.
- Бот автоматически покинет неподтвержденные ресурсы через 20 минут.

### Группы команд
- Изолированные наборы команд с ограничением доступа.
- Доступ по **категориям пользователей** или **подписке на ресурс**.
- Событие "Нет доступа" настраивается во вкладке "События".
- Перемещение команд между группами: кнопка перемещения в меню команды.
- При дублировании основной группы -- создается с цифрой "2" в новом боте.
- Публикация: **каждая группа публикуется отдельно**.

### Вкладка "Вход"
Три вида ссылок для привлечения пользователей:

| Тип | Описание | Особенности |
|-----|----------|-------------|
| **Многоразовые** | Постоянные ссылки | 5 видов URL, добавление в категорию, команда при переходе, ограничение переходов, срок действия |
| **Промо** | Одноразовые ссылки | Генерация пакета, скачивание в текстовом формате или отправка в Telegram |
| **Реферальные** | Индивидуальные ссылки | Переменная для генерации, таблица переходов (кто, кого, когда), ограничение генераций |

- Ссылка создается **остановленной** -- необходимо запустить.
- При достижении лимита переходов -- автоматическое отключение.
- Можно одновременно добавить в категорию бота И в категорию ресурса.

### Вкладка "События"
Системные события бота с настраиваемыми реакциями:
- Пользователь заблокирован в боте
- Запрет доступа к команде
- Бот добавлен в ресурс
- Бот остановлен пользователем
- Неизвестная команда
- Начало / завершение диалога

Типы реакций: текстовое сообщение, команда или условие.

### Встроенные stats-переменные
Создаются автоматически, начинаются с префикса `stats`:
- `stats.total.users` -- всего пользователей
- `stats.today.users` -- новых сегодня
- `stats.today.left` -- ушедших сегодня
- `stats.total.payment.count` -- всего оплат
- `stats.total.payment.sum` -- сумма оплат

## 3. Все блоки конструктора

### 3.1. Команда (блоки контента)

**Блоки контента:**
- **Текстовый блок** -- основной блок, поддерживает форматирование и переменные.
- **Изображение** -- загрузка файла или вставка ID файла (ID уникален для каждого бота). Для файлов >20 МБ: `/cp` -> "Загрузить файл" -> скопировать ID (лимит 2 ГБ).
- **Видео, Аудио, Документ** -- аналогично изображению.
- **Геолокация, Контакт** -- отправка координат или карточки контакта.
- **Медиагруппа** -- набор медиа в одном сообщении.

**Специальные блоки:**
- **Форма ввода** -- сбор данных от пользователя (см. раздел 3.4).
- **Таймаут** -- задержка между блоками (для комфортного UX).
- **Товар** -- блок магазина, отображает товары из вкладки "Магазин".
- **Список** -- подстановка одного элемента из списка при каждом вызове (промокоды, ротация контента).
- **Результат** -- подсчет правильных ответов в тестировании.
- **Слайдер** -- отображение данных из Google Sheets с фильтрацией.

**Дополнительные настройки команды:**
- **Синонимы** -- альтернативные фразы вызова (5 типов: полное совпадение, частичное, начинается с, заканчивается, регулярное выражение). Шанс срабатывания, регистр.
- **Выполнить до** -- действия выполняются ДО отправки блока (критично для вычислений).
- **Удалить команду после вызова следующей** -- очистка чата.
- **Защита контента от пересылки** -- запрет пересылки и сохранения.
- **Отображать в меню** -- slash-команда с коротким описанием.
- **Отправить случайный блок** -- рандомизация контента.
- **Выполнение только из клавиатуры** -- защита от прямого вызова (обход оплаты).

### 3.2. Кнопки

**Обычная клавиатура:**
- Одна на команду, сохраняется до замены другой командой.
- Может быть скрыта, но не удалена.
- Ведет только на обычные команды.

**Инлайн-клавиатура:**
- Прикрепляется к конкретному блоку, остается в переписке.
- Кнопки расставляются перетаскиванием (по рядам).

**Действия инлайн-кнопок:**
- Переход к команде / условию
- Ссылка (URL)
- Начало диалога
- Платёж
- Поп-ап (всплывающее окно с текстом, лимит символов)
- Кнопка условия (разное содержимое для разных пользователей)
- Изменение сценария
- Подставить текст
- Поделиться текстом
- Веб-приложение (ссылка / магазин)

**Проверка подписки на кнопке:**
- Галочка "Проверка подписки на ресурс" прямо в настройках кнопки.
- Два варианта поп-апа: для подписанных и для неподписанных.

### 3.3. Кнопка условия

**Назначение:** Показывать разные кнопки разным пользователям (разные названия и действия).

**Принцип работы:**
1. Создать условие с типом "Кнопка условия" (тип нельзя изменить после сохранения!).
2. Каждое правило определяет: название кнопки + действие кнопки для данной группы пользователей.
3. Проверка выполняется **ДО отправки** сообщения (на этапе формирования).
4. В инлайн-кнопке выбрать действие "Кнопка условия" -> указать нужное условие.

**Пример:** Подписчик с активным сценарием видит кнопку "Ссылка на подарок", без сценария -- "Регистрация".

**Скрытие кнопки:** В исключающем правиле -- кнопка не отображается у пользователей, не прошедших проверку.

### 3.4. Форма ввода

**Типы ввода:**
- **Отправка сообщения** -- текст от пользователя
- **Запрос контакта** -- кнопка "Поделиться контактом" (телефон)
- **Тестирование** -- варианты ответов с подсчетом (блок "Результат")
- **Выбор варианта** -- варианты с действием при выборе (переход к команде)

**Маски ввода:**
- Текст, Число, Телефон, Email, Ссылка, Крипто-кошелек, Изображение
- **Регулярное выражение** -- пользовательская валидация

**Ключевые настройки:**
- **Название для статистики** -- внутреннее имя (не видно пользователю).
- **Переменная** -- автоматически создается для хранения ответа.
- **Реакция на ответ** -- подтверждение с подстановкой переменной.
- **Текст ошибки** -- при несоответствии маске.
- **Тайм-аут** -- задержка между формами.
- **Отключение повторного прохождения** -- перенаправление в другую команду.
- **Возможность пропуска** -- необязательный ответ.
- **Удаление формы после ответа** -- очистка чата.
- **Галочка "Не записывать ответ"** -- кнопка выхода без уведомления.
- **Ограничение времени** -- минимум 5 сек (для циклических вызовов).

**Объединение уведомлений:**
- Настройки бота -> Формы ввода -> Создать правило.
- Тип "Сложный" -- для вариативных квизов (не все формы будут заполнены).
- Указать команды с завершающими формами и остальные участвующие формы.
- После настройки: одно общее уведомление вместо отдельных на каждую форму.

**Статистика:** Вкладка "Статистика" -> Формы ввода -> выбрать команду -> просмотр/удаление ответов.

**Принятие произвольного текста (без формы ввода):**
Легкого решения нет. Через "костыли":
1. Создать переменную-флаг "ожидает_текст".
2. В команде с кнопками установить флаг.
3. Переопределить "Неизвестная команда" -> условие проверки флага. Если ожидается -> записать. Если нет -> "Я не знаю, как ответить".

**Редактирование ответов (пользователь ошибся):**
- Способ 1: показывать результат после каждого ответа + кнопка "Редактировать" (каждая форма в отдельной команде).
- Способ 2: по окончанию опроса вывести все ответы для проверки + кнопки "Редактировать" (каждая ведет на свою форму) и "Отправить".

**Запись фото без формы ввода:**
Фото без контекста = "неизвестная команда". Решение: из неизвестной команды -- прокладка "фото не определилось" с формой ввода. Или в /start поставить действие "отправить команду" с блоком формы.

### 3.5. Действия команды

**Полный список действий:**
- **Изменить категорию** -- активация/деактивация категории
- **Изменить переменную** -- операторы: заменить, прибавить, вычесть (числовые); заменить (текстовые, значение в кавычках)
- **Очистить переменную** -- сброс до значения по умолчанию
- **Отправить команду или условие** -- с возможностью изменения места отправки (ресурс)
- **Отправить другому пользователю** -- по юзернейму или Telegram ID
- **Изменить сценарий** -- тумблер вправо (запуск) / влево (остановка)
- **Действие в ресурсах** -- принять заявку, удалить сообщения
- **Создать строку (Spreadsheets)** -- запись в Google Sheets
- **Обновить строку** -- изменение существующей записи
- **NocoDB: создать строку** -- запись в NocoDB
- **Bitrix24** -- интеграция с CRM
- **Удалить через время** -- автоочистка сообщений
- **Удалить клавиатуру** -- принудительное удаление обычной клавиатуры
- **Уведомления** -- отправка уведомлений
- **Удалить сообщения** -- удаление предыдущих сообщений
- **Закрепить блок** -- закрепление сообщения
- **Отправить запрос** -- GET/POST запрос к внешнему API
- **Поставить реакцию** -- эмодзи-реакция на сообщение
- **Очистить статистику** -- сброс данных форм
- **Очистить корзину** -- сброс корзины магазина
- **Диалог** -- управление режимом обратной связи

### 3.6. Условия (Обычное условие)

**Структура:** Правило = Проверка + Действие. При вызове выполняется только ОДНО правило (первое подходящее).

**Типы проверок:**
- **Все проверки** -- все условия должны пройти
- **Любая проверка** -- достаточно одной
- Вызов команды или условия (был ли вызван ранее)
- Оплаченные платежи
- Наличие подписки на ресурс
- Значение переменной (=, >, <, >=, <=, содержит)
- Проверить строку (Google Sheets / NocoDB)
- Голос для ресурсов (бусты)
- Источник трафика

**Параметры проверок:**
- "Задать количество" -- точное число вызовов
- "Задать период" -- количественный / датированный / календарный
- "Проверить другого пользователя" -- по Telegram ID или юзернейму

**Типы действий:**
- **Все действия** -- выполнить все
- **Случайное действие** -- с настройкой вероятности

**Исключающее правило:** Последнее правило, срабатывает если ни одно другое не прошло. Стандартный паттерн "если найдено / если нет".

### 3.7. Сценарии (Автопостинг)

**Назначение:** Индивидуальное расписание для каждого пользователя от момента запуска сценария.

**Типы отправки:**
- **Сразу** -- немедленно при запуске сценария
- **Через** -- от начала сценария (X дней, Y часов, Z минут) ИЛИ в точное время (через X дней в HH:MM)
- **Точная дата и время** -- конкретный момент

**Повторение поста:** По дням недели или через N дней (с ограничением количества повторов).

**Настройки сценария:**
- Автоотключение после выполнения
- Количество прохождений
- **Перезапуск при повторном вызове** -- критично для подписок (таймеры сбрасываются)

**Важно:** Время по часовому поясу **владельца бота**, не пользователя. Пост создается выключенным -- необходимо активировать.

### 3.8. Поп-ап / Скрытое продолжение

- Действие кнопки "Поп-ап" -- всплывающее окно Telegram (alert/toast) с текстом.
- Можно включить проверку подписки: разные тексты для подписанных/неподписанных.
- Работает в боте, канале и чате.

## 4. Переменные и формулы

### 4.1. Персональные переменные

Индивидуальные значения для каждого пользователя.

**Системные (встроенные):**
- `{{FIRST_NAME_TEXT}}` -- имя
- `{{LAST_NAME_TEXT}}` -- фамилия
- `{{USER_NAME_TEXT}}` -- юзернейм
- `{{USER_ID_TEXT}}` -- Telegram ID
- `{{JOIN_DATE}}` -- дата присоединения к боту
- `{{USER_AVATAR_URL}}` -- URL аватара (для мини-приложений)
- `{{HAS_PREMIUM}}` -- наличие Telegram Premium
- `{{START_PAYLOAD}}` -- параметр deep linking

**Пользовательские:**
- Создание: Вкладка "Переменные" -> Персональные -> Добавить.
- Синтаксис: `{{имя_переменной}}` -- латиница A-Z, цифры, нижнее подчеркивание.
- Форматы: текст, число, формула, ссылка, документ.

### 4.2. Глобальные переменные

Общие значения для всех пользователей.

**Встроенные stats-переменные (создаются автоматически):**
- `{{stats.total.users}}` -- всего пользователей
- `{{stats.today.users}}` -- новых сегодня
- `{{stats.today.left}}` -- ушедших сегодня
- `{{stats.total.payment.count}}` -- всего оплат
- `{{stats.total.payment.sum}}` -- сумма оплат

**Интегрированные переменные:**
- Тип значения "Интегрированный" -- данные из внешнего API (GET-запрос, JSON).
- Источники: HTTP-запрос, Google Sheets, NocoDB.
- Обновляются при каждом обращении.
- Проверка: кнопка "Проверить запрос" при создании.

### 4.3. Формулы и функции

**Формулы в тексте** (мощный инструмент, выполняют вычисления прямо в блоке текста):
```
{{=выражение}}
```

**Условия (if/else):**
```
{{=if {{переменная}} > 5 ; результат_да ; результат_нет}}
```
Можно вкладывать: `{{=if {{a}} > 0 ; {{=if {{b}} > 0 ; оба ; только a}} ; ни одного}}`

**Операции с датами:**
- `ADD_DAYS("03.09.2023 15:34:12", 4)` -- прибавить дни
- `ADD_MONTHS(...)`, `ADD_YEARS(...)`, `ADD_HOURS(...)`, `ADD_MINUTES(...)`, `ADD_SECONDS(...)`
- Вычитание через отрицательное значение: `ADD_HOURS("дата", -2)`
- `DAYS_BETWEEN("15.09.2023", "11.09.2023")` -- разница в днях
- `DATE_FORMAT("15.09.2023 15:34:12", "d F Y")` -- форматирование

**Функции форматирования:**
- `plure(число, "день", "дня", "дней")` -- склонение
- `numberFormat(число, разделитель, знаки)` -- форматирование чисел
- `round(число)`, `ceil(число)`, `floor(число)` -- округление
- `random(от, до)` -- случайное число

**Регулярные выражения:**
- `match(текст, "/паттерн/флаги")` -- первое совпадение
- `match_all(текст, "/паттерн/флаги", индекс)` -- все совпадения с индексом
- `replace(текст, "что", "на что")` -- замена

**Разбивка ответа формы ввода на несколько переменных (через regex):**
```
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 0) = Строка 1
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 1) = Строка 2
match_all({{var}}, "/([a-zA-Z0-9]+)/m", 2) = Строка 3
```

**Конвертация секунд в ЧЧ:ММ:СС:**
```
(floor({{SEC}}/3600))+":"+(floor(({{SEC}}-floor({{SEC}}/3600)*3600)/60))+":"+({{SEC}}-floor({{SEC}}/3600)*3600-floor(({{SEC}}-floor({{SEC}}/3600)*3600)/60)*60)
```

**Верхний регистр (без интеграций):**
Цепочка replace: `replace(replace(replace({{переменная}}, "а", "А"), "б", "Б"), "в", "В")` (для всех 33 букв).

**Операторы изменения переменных:**
- Числовые: заменить, прибавить (+), вычесть (-)
- Текстовые: только заменить (значение в кавычках)
- Очистка: сброс до значения по умолчанию

**Формат даты:**
- Ввод: любой общепринятый формат (dd.mm.yyyy, dd/mm/yyyy, yyyy-mm-dd), год всегда 4 цифры.
- Форматирование: `DATE_FORMAT("15.09.2023 15:34:12", "d F Y")` -- символы как в PHP.

**Генерация уникального ID:**
Две числовые переменные. Начальное значение одной = 0. Проверка: если пусто -> +1 к счетчику и присвоить значение.

### 4.4. Start Payload (Deep Linking)

Передача параметров через ссылку: `t.me/botname?start=параметр`

Переменная `{{START_PAYLOAD}}` содержит текст после `?start=`.

Пример: `t.me/botname?start=yes_{{global_number}}` -- при переходе пользователь попадает в /start, а в переменной `{{START_PAYLOAD}}` будет значение `yes_123`.

## 5. Интеграции

### 5.1. Google Sheets

**Подключение:**

3. Можно подключить несколько аккаунтов.

**Форма ввода со списком из NocoDB (мини-апп):** Столбец для отображения (1) и столбец для записи (2). При выборе строки из 1 записывается значение из 2.

**Дополнительные параметры:**

- Инлайн-клавиатура
- Фиксированная клавиатура (одна на приложение)

**Для каждой кнопки** можно настроить вибрацию.

### 6.3. Формы ввода в мини-приложениях

**Типы:**
- Текст (однострочный / многострочный, placeholder, ограничение символов)

- Выбор варианта (количество вариантов, вид переключателей, варианты по умолчанию)

**Маски:** текст, телефон, почта, ссылка, число, крипто-кошелек, регулярное выражение.

**Настройки:** обязательность, повторное прохождение, подстановка из переменной, вибрация при клике.

### 6.4. Меню мини-приложения

- До **5 кнопок** в фиксированном меню.
- Иконки: SVG или PNG.

### 6.5. Вкладки

- До **24 вкладок** для навигации по разделам.

### 6.6. HTML-блок и Substitution-блок

**HTML-блок** -- произвольный HTML/CSS/JS код.

Пример аватара пользователя:
```html
<div style="display: flex; align-items: center; gap: 10px;">
  <img src="{{USER_AVATAR_URL}}" alt="Аватар"
       style="width: 60px; height: 60px; border-radius: 60%;
              border: 2px solid #1590b7;">
  <div>
    <span style="font-size: 20px; color: #333;">
      <strong>{{FIRST_NAME_TEXT}}, приветствуем</strong>
    </span>
  </div>
</div>
```

**Кнопки-карточки (flexbox):**
```html
<div style="display: flex; align-items: center; gap: 10px;">
  <div style="display: block; margin-left: 2%; margin-right: 2%;">
    <a href="URL"><img src="URL_КАРТИНКИ" style="width: 100%; border-radius: 5px;"></a>
  </div>
</div>
```

**Важно:** Сложный HTML может не работать (ограничения сервиса). Решение: разместить код на GitHub и открывать по внешней ссылке.

### 6.7. Навигация между мини-приложениями

**3 способа бесшовного перехода:**

1. **Атрибут `goto_web_page`** для тега `<a>`:
```html
<a goto_web_page="ID_ПРИЛОЖЕНИЯ">Перейти</a>
```

2. **Функция `gotoWebPage()`:**
```javascript
gotoWebPage("ID_ПРИЛОЖЕНИЯ") // переход
gotoWebPage("ID_ПРИЛОЖЕНИЯ", true) // открыть в браузере
```

3. **Функция `getWebPageUrl()`** -- получить ссылку текстом (без перехода).

### 6.8. Popup / модальные окна в мини-приложениях

- Поп-ап может быть настроен как предупреждение перед закрытием.
- Модальные окна для подтверждения действий.
- Настройка через дополнительные параметры мини-приложения.

### 6.9. Поиск внутри мини-приложения

- Встроенная функция поиска по контенту мини-приложения.
- Пользователь вводит запрос -- фильтруется содержимое.

### 6.10. Ограничение доступа и аналитика

- Ограничение доступа по категориям пользователей.
- StartPayload/UTM для отслеживания источников трафика.
- "Отправить один случайный блок" -- рандомизация контента.

### 6.11. Важные нюансы мини-приложений

- Действия "До" выполняются не совсем "До", а **"Между"** -- для интегрированных переменных используйте промежуточное приложение для изменения переменной и переадресации.
- Клавиатура в мини-приложении -- **самостоятельный блок** (в отличие от бота, где она привязана к команде).
- Документы из мини-приложения отправляются в **личные сообщения** бота.
- Одна картинка растягивается по ширине с сохранением пропорций; две+ -- карусель.
- Фиксированная клавиатура -- одна на все приложение.
- Для получения данных из таблицы лучше использовать скрипт напрямую, без интегрированной переменной.

## 7. Оплата и магазин

### 7.1. Платежные системы

**Подключение:** Настройки -> Платежные системы.

**Telegram Stars:**
- Подключается одним нажатием, без настроек.
- Валюта: звезды (Stars).

**Prodamus:**
- URL магазина + секретный ключ + адрес уведомления (копируется из PuzzleBot -> вставляется в настройки Prodamus).

**Другие системы:** ЮMoney, ЮКасса, Робокасса и 30+ через вкладку "Магазин".

**Кнопка "Платеж":**
- Действие инлайн-кнопки -> "Платеж".
- Указать: валюту, цену, команду при успешной оплате.
- Можно две кнопки с разными системами на одном экране.

**Правила Telegram:** Запрета на другие платежные системы нет, но оплата Stars не должна быть спрятана. Рекомендуется: оба варианта.

### 7.2. Магазин (вкладка)

**Активация:** Магазин -> включить -> выбрать валюты (поддерживается мультивалютность, например рубли + доллары).

**Варианты доставки:**
- Настройка древовидных вариантов с подвариантами (курьер / самовывоз / почта / без доставки).
- Формы ввода для адреса (в шаблоне курьера автоматически).
- Скидка на самовывоз через "Изменить стоимость чека" -> "Понизить".

**Варианты оплаты:**
- Наличный / безналичный с подвариантами (нужна сдача / без сдачи).
- Галочка "Завершить оформление заказа без оплаты" -- для оплаты вне бота.

**Товары:**
- Информация, изображения, цена в нескольких валютах, остаток, категория.
- **Группы товаров** -- отображение нескольких товаров в одном блоке-карусели.
- **Электронные товары** -- список промокодов (каждый покупатель получает уникальный код).

**Промокоды и скидки:**
- Акция типа "промокод" (уникальный, с генерацией).
- Применяется к сумме товаров, но НЕ к доставке.
- Настройка процента или суммы снижения.

**Блок "Товар" в конструкторе:**
- Добавить в команду -> выбрать товары/группы -> настроить отображение.
- Полная цепочка: товар -> корзина -> оформление -> доставка -> оплата -> чек.

### 7.3. Платный доступ в канал/группу

**Способ 1: через реферальную систему (одноразовая ссылка)**
1. Вкладка "Вход" -> "Реферальная система".
2. Убрать категорию "У бота", добавить категорию "Канала".
3. Количество переходов = 1.
4. Скопировать переменную для генерации ссылки.
5. После оплаты -- текстовый блок с переменной ссылки.

**Способ 2: через категории и права**
1. Категория "Без" -- запретить отправку сообщений в чате.
2. Платная категория -- разрешить.
3. После оплаты -- присвоить платную категорию + запуск сценария.

### 7.4. Подписки с автопродлением

**Схема:** Оплата -> категория -> запуск сценария -> через N дней сброс категории.

**Сценарий платной подписки (3 поста):**
1. Пост "Сразу" -- подписка активирована.
2. Пост "Через 28 дней" -- напоминание (повторение через 1 день, лимит 1).
3. Пост "Через 30 дней" -- блокировка (сброс в "Без категории").

**Перезапуск при повторном вызове** -- при досрочной оплате все таймеры сбрасываются.

**Защита:** "Выполнение только из клавиатуры" на команде успешной оплаты.

### 7.5. Ограничение доступа через 30 дней

При оплате: переменная с датой через месяц (`ADD_DAYS(текущая_дата, 30)`). Сценарий каждый день сравнивает текущую дату с переменной. При совпадении -- действия по запрету доступа (смена категории, отключение сценариев).

### 7.6. Рекуррентные платежи

- При блокировке бота пользователем -- сценарий может не отработать.
- Рекомендация: проверка подписки при активации бота пользователем, а не только через сценарий.
- Если человек отписался -- переходит в другую категорию; при возвращении -- проверка действия подписки.

### 7.7. Лимиты доходов

- Ошибка 80 (Робокасса) -- превышен лимит дохода за месяц.
- Лимиты указаны на странице Тарифов PuzzleBot.
- Сброс 1-го числа каждого месяца.
- Решение: перейти на более высокий тариф.

### 7.8. Электронные товары (автовыдача)

1. В магазине создать электронный товар.
2. Вставить **список промокодов/ссылок/ключей** (каждая строка = один элемент).
3. Скопировать переменную для вывода одного элемента из списка.
4. В команде после покупки: текстовый блок с переменной.
5. Каждый покупатель получает **уникальный** код из списка.

## 8. Рассылки и постинг

### 8.1. Вкладка "Постинг" (массовые рассылки)

**Создание поста:**
1. Вкладка "Постинг" -> создать пост.
2. Дата/время отправки.
3. Места отправки: бот (по умолчанию) + каналы + чаты.
4. Блоки: текст, медиа, инлайн-клавиатура.

**Статусы:** Черновик -> В очереди -> Отправлен.

**Мультипостинг:** Одновременная отправка в несколько мест.

**Редактирование отправленного поста:** Можно менять текст/медиа, но НЕ добавлять новые блоки. Изменения обновляются во всех местах одновременно.

**Автомат:** Автоматический переход к команде после отправки (только для бота).

**Отключение уведомлений:** Пост без звука.

### 8.2. Рассылка по категориям

- Создать пост -> выбрать категории получателей.
- Условная рассылка: пост ведет на условие -> разные команды для разных пользователей.

### 8.3. Рассылка с условиями (по покупкам)

1. Условие с проверкой "Оплаченные платежи".
2. Сегментация: разные предложения для купивших / не купивших.
3. Тип "Все проверки" для одновременной проверки нескольких продуктов.

### 8.4. Рассылка-напоминание (неактивным)

Сценарий с постом "через 7 дней" + "перезапуск при повторном вызове". Запуск в ключевых командах бота. Активный пользователь перезапускает сценарий; неактивный получает пост.

### 8.5. Рассылка по Google Таблицам (персонализированная)

Рассылка -> условие -> проверка ID в таблице -> команда с интегрированной переменной. Обязательно большое кэширование (60 запросов/мин).

### 8.6. Загрузка списка юзеров

Отправить на support@puzzlebot.top: юзернейм бота + файл (.csv / Excel) с Telegram ID.

### 8.7. Постинг в каналы

- Реакции на посты.
- Расписание публикаций.
- Черновики и редактирование.
- Автоматическое сообщение с правилами чата при новом посте (событие "Новый пост в канале").

### 8.8. Отправка команд в ресурс

Действие "Отправить команду или условие" с галочкой "Изменить места отправки":
1. Выбрать ресурс (группу/канал).
2. Нажать "Добавить".
3. Команда будет отправлена В РЕСУРС, а не в бота.

Используется для:
- Уведомлений о заявках в группу.
- Публикации контента от пользователей.
- Автоматических оповещений администраторам.

### 8.9. Рассылка отписавшимся от канала

Пост с действием "переход к команде или условию" -> условие с проверкой подписки. Если подписан -- ничего. Если нет -- отправить сообщение.

### 8.10. Дублирование поста

Функция дублирования: выбрать отправленный пост -> нажать "Дублировать". Создается копия с возможностью редактирования перед отправкой.

### 8.11. Отключение уведомлений

Пост без звука: включить "Отключить уведомления" при создании поста. Пользователь получит пост, но без звукового/вибрационного оповещения.

### 8.12. Количество подписчиков и скорость

Количество подписчиков бота влияет на скорость отправки постов. Большие базы -- рассылка может занимать значительное время.

## 9. Группы, каналы, модерация

### 9.1. Подключение ресурсов

1. Добавить бота в канал/группу как **администратора с полными правами**.
2. Для каналов: написать любое сообщение (обязательно!).
3. ЛК -> "Добавить ресурс" -> выбрать.
4. Бот покинет неподтвержденные ресурсы через 20 минут.

### 9.2. Проверка подписки

**Простой способ:** Группа команд -> настройки -> выбрать ресурс для проверки подписки. Без условий и категорий.

**Через условие:** Условие с проверкой "Наличие подписки" на ресурс. Два правила: подписан -> доступ, не подписан -> сообщение с ссылкой.

**На кнопке:** Галочка "Проверка подписки на ресурс" -> два текста поп-апа.

### 9.3. Капча

Форма ввода с вопросом (картинка или текст) -> ответ -> условие проверки переменной на точное соответствие.

### 9.4. Триггеры и приветствия

**Приветствие новых пользователей:** Ресурс -> "События" -> включить "Приветствие новых пользователей" -> настроить текст.

**Триггеры:**
- Ресурс -> "Триггеры" -> "Добавить триггер".
- Тип сообщения: текст, все.
- Тип условия: "Сообщение содержит" (частичное совпадение).
- Действия: текстовое сообщение, поставить реакцию, удалить сообщение, отправить команду.
- "Для категории" -- срабатывает для всех, КРОМЕ отключенных категорий.

### 9.5. Реакции на бусты

- Событие "Пользователь дал буст" / "Забрал голос" / "Истек срок".
- Условие: тип проверки "Голос для ресурсов", количество бустов.
- Разделение контента: для бустеров и для остальных.

### 9.6. Автоматический прием заявок (бот пишет первым)

1. Ресурс -> "События" -> "Заявка на вступление" -> отправить команду "Старт".
2. В "Старт": приветствие + кнопка "Вступить".
3. Команда "Вступление": действие "Принять заявку на вступление".
4. Пригласительная ссылка с включенной функцией "Заявки на вступление".
**Ключевой момент:** Бот может писать первым даже без предыдущего общения.

### 9.7. Ограничение комментариев в канале

1. Категория "Подписчик" в модерации канала.
2. Событие "Подписался" -> добавить в категорию; "Покинул" -> деактивировать.
3. Триггер в группе комментариев: удалить все сообщения для пользователей БЕЗ категории "Подписчик".

### 9.8. Модерация (вкладка)

- **Таблица пользователей:** фильтры (в боте / вышедшие / забаненные), поиск, настройка столбцов.
- **Информация о пользователе:** 6 вкладок (общие, сценарии, категории, события, переменные, комментарий).
- **Массовые действия:** выделение -> блокировка / разблокировка / присвоение категории.
- **Блокировка:** в конкретном боте, ресурсе или во всех местах.
- **Экспорт** списка категории в Excel.

### 9.9. Бизнес-аккаунт

Подключение бота к бизнес-аккаунту Telegram для расширенных возможностей.

### 9.10. Уведомления (вкладка Настройки)

**Простой способ (шаблонное уведомление):**
- Настройки -> Уведомления -> правило дублирования -> выбрать ресурс.
- Шаблонное, нередактируемое.

**Сложный способ (полная настройка):**
1. Форма ввода -> отдельная команда-уведомление.
2. В команде: текстовый блок с переменными (имя + ответ из формы).
3. Действие "Отправить команду" с галочкой "Изменить места отправки" -> ресурс (группа/канал).

**Уведомление администратору:**
- "Отправить команду другому пользователю" (по юзернейму).
- Галочка "Выполнить другому пользователю" с указанием юзернейма.

**Где приходят уведомления:** Telegram + email + ЛК PuzzleBot.

### 9.11. Управление правами в ресурсах

- Настройка прав и разрешений для пользователей и категорий.
- Запрет/разрешение отправки сообщений по категориям.
- Массовое изменение прав через модерацию.

## 10. Баллы и геймификация

### 10.1. Внутренний баланс

1. Создать персональную переменную типа "число" (например, `Balance`) со значением 0.
2. Начисление: действие "Изменить переменную" `Balance` + N.
3. Списание: действие "Изменить переменную" `Balance` - N.
4. Проверка: условие с проверкой значения переменной (>=, >, = и т.д.).

### 10.2. Приветственный бонус с защитой от повторного начисления

1. Переменная `Balance` (число, значение по умолчанию 0).
2. Команда "Начисление бонуса": действие `Balance + 7`, настройка "Выполнить до".
3. Условие "Вызов команды": если "Начисление бонуса" уже вызвано -> в меню; если нет -> начислить.

### 10.3. Начисление за активность

Через действия в командах: при вызове определенных команд -> `Balance + N`.

### 10.4. Ручное начисление админом

Админ-панель: проверка `{{USER_ID_TEXT}}` -> кнопки для зачисления/снятия -> уведомление пользователю.

### 10.5. Списание баллов за доступ к контенту

Трехуровневая кнопка условия:
1. **Уже куплено** (проверка категории) -> переход к контенту.
2. **Достаточно баллов** (Balance >= цена) -> списать + категория + контент.
3. **Недостаточно** (исключающее правило) -> скрыть кнопку.

### 10.6. Лидерборд

Глобальная переменная-счетчик + сортировка. Форматирование через `numberFormat()`.

### 10.7. Чекбоксы через переменные

1. Переменные `Icon1`, `Icon2` со значением по умолчанию = иконка (галочка).
2. Кнопка условия: проверка значения -> если галочка -> сменить на пустое; если пустое -> сменить на галочку.
3. Перезагрузка инлайн-команды для обновления отображения.
4. Режим "только одна галочка": при установке сброс всех остальных переменных.

### 10.8. Автоматическое начисление энергии

Сценарий: пост "через 1 час" -> действие `Energy + 5` -> запустить этот же сценарий. Настройки: "Перезапуск при повторном вызове", снять "Завершить после выполнения".

## 11. Сценарии и автоматизация

### 11.1. Напоминания (autosend с задержкой)

**Паттерн:** Запуск сценария -> если пользователь не выполнил действие -> напоминание.

1. Создать сценарий с постом "через X минут/часов".
2. В команде "Старт": действие "Изменить сценарий" -> запуск (тумблер вправо).
3. В целевой команде: "Изменить сценарий" -> остановка (тумблер влево).
4. Если пользователь вызвал целевую команду до таймера -- напоминание не придет.

### 11.2. "Пушить" неактивных пользователей

Сценарий "через 7 дней" + "перезапуск при повторном вызове". Запуск в ключевых командах бота. Активный -- перезапуск; неактивный -- получает пост.

### 11.3. Периодические начисления (энергия/баллы каждый час)

Сценарий -> пост "через 1 час" -> действие изменения переменной -> запуск самого себя. Тип отправки обязательно "Через" (не "Сразу"), минимум 1 минута.

### 11.4. Проверка подписки каждый час (trial-период)

Два сценария: (1) проверка подписки раз в час с перезапуском, (2) завершение trial через N дней.

### 11.5. Пароли и ограничение доступа

**Метод:** Инлайн-команда с названием = пароль.
1. Пользователь вводит текст = вызывает команду.
2. Команда присваивает категорию "Авторизованный".
3. Вторая группа команд с доступом по категории.
4. Любой другой текст игнорируется.

### 11.6. Дублирование и перенос ботов

**Дублирование:** Настройки -> "Дублировать бота".
- Выбор целевого бота или API-ключ (другой аккаунт).
- Выбор вкладок и групп команд для дублирования.
- "Дублировать с заменой" -- ВСЕ данные целевого бота удаляются **безвозвратно**.
- "Удалить информацию пользователей" -- бот пишет только тем, с кем общался.
- **Только на платных тарифах.**

**Перенос:** Настройки -> "Перенести бота" -> юзернейм целевого аккаунта. Опция переноса с ресурсами и администраторами.

**Дублирование группы команд внутри бота:** Прямой возможности нет. Хитрость: дублировать в другой бот -> обратно (БЕЗ замены).

### 11.7. Обратная связь (диалог)

1. Кнопка с действием "Начало диалога".
2. Пользователь нажимает -> пишет сообщение -> владелец получает уведомление.
3. Ответ: обязательно через **reply** (ответ на конкретное сообщение).
4. Управление: команда `/CP` или вкладка "Диалоги".

### 11.8. Автопубликация в канале за донаты

**Полная цепочка:**
1. Подключить платежную систему.
2. Конструктор: Start -> кнопка "Платеж" -> команда "Успех".
3. "Успех": текст + форма ввода (сообщение пользователя).
4. Настройки -> "Подписки на события" -> тип "Форма ввода команд" -> указать команду.
5. Integromat: Webhook -> Custom Webhook -> скопировать URL.
6. В PuzzleBot: вставить URL в подписку, включить.
7. Тестовый ответ для активации.
8. Integromat: модуль TelegramBot -> отправка текста -> токен бота + юзернейм канала + переменные.
9. Включить сценарий на постоянной основе.
10. "Выполнение только из клавиатуры" на команде с формой.

### 11.9. Формирование документов

Только через интеграцию со сторонними сервисами: формирование файла на внешнем сервере и отправка обратно через API. PuzzleBot не имеет встроенного генератора документов.

### 11.10. Запросы к внешним API с долгой обработкой

Интегрированные переменные не подходят -- ожидают быстрый ответ. Обратная отправка через ноду Telegram send message, указывая userid и бота. User ID передавайте с самого начала на webhook. Ограничение 4096 символов -- если превышает, нужна скриптовая разбивка.

### 11.11. Авторассылка на конкретную дату

31 сценарий (под каждый день) + 31 команда. В синонимах каждой команды -- вызов. Пользователь указывает дату -> активируется нужный сценарий.

## 13. Типичные ошибки и решения

### Ошибка 1: Интегрированная переменная не загружается в мини-приложении
**Причина:** Действия "До" в мини-приложениях выполняются "Между", а не "До".
**Решение:** Переход через промежуточное приложение для изменения переменной. Или получать данные скриптом напрямую.

### Ошибка 2: Бот не реагирует на триггеры в группе ("не удалось найти пользователя")
**Причина:** Включена настройка "действие выполнять пользователю, получившему ответ", но сообщение отправлено не как reply.
**Решение:** Убрать настройку или отвечать через кнопку "Ответить".

### Ошибка 3: Google Sheets перестают работать при рассылке
**Причина:** Лимит 60 запросов/минуту.
**Решение:** Большое кэширование везде. Рассмотреть переход на NocoDB (10 запросов/сек).

### Ошибка 4: Нельзя зациклить команды в конструкторе
**Причина:** Конструктор запрещает прямое зацикливание.
**Решение:** (а) Форма ввода с "Ограничением времени" (5 сек) + условие проверки. (б) Сценарий с типом "Через" (минимум 1 минута). (в) API-запрос к PuzzleBot.

### Ошибка 5: Файлы загружаются в неправильном формате/размере
**Причина:** Лимит загрузки через ЛК.
**Решение:** Через ID файла: `/cp` в боте -> "Загрузить файл" -> скопировать ID -> вставить в блок. Лимит через ID -- до 2 ГБ. ID уникальны для каждого бота!

### Ошибка 6: Сценарий не работает при зацикливании
**Причина:** Тип отправки "Сразу".
**Решение:** Изменить на "Через" (минимум 1 минута). Снять "Завершить после выполнения всех постов".

### Ошибка 7: Ошибка 80 при оплате (Робокасса)
**Причина:** Превышен лимит дохода за месяц.
**Решение:** Лимит сбрасывается 1-го числа. Или перейти на более высокий тариф. Лимиты -- на странице Тарифов.

### Ошибка 8: Пользователь не может вернуться к форме ввода после ошибки
**Причина:** Нет механизма редактирования заполненных форм.
**Решение:** По окончанию опроса вывести все ответы + кнопка "Редактировать" (каждая кнопка ведет на свою форму).

### Ошибка 9: Бот не пишет первым после подписки на открытый канал
**Причина:** Telegram API не позволяет писать пользователям без предыдущего взаимодействия.
**Решение:** Единственный вариант -- закрытый ресурс + событие "Заявка на вступление".

### Ошибка 10: Формы ввода засыпают уведомлениями
**Причина:** Каждая форма отправляет отдельное уведомление.
**Решение:** Настройки -> Формы ввода -> Создать правило для объединения уведомлений. Тип "Сложный" -- для вариативных квизов.

## Карта интерфейса PuzzleBot (данные OCR из 112 видео)

> Источник: Google Vision OCR по 3,859 кадрам из 112 обучающих видео. 3 млн символов экранного текста, 164 кнопки, 238 команд.

### Панель управления (cp.puzzlebot.top)

**Главное меню личного кабинета (левая панель):**
```
PuzzleBot :// Личный кабинет
├── Конструктор          (основная рабочая область)
├── Модерация            (пользователи, категории)
├── Постинг              (рассылки, посты)
├── Сценарии             (автопостинг)
├── Магазин              (товары, заказы)
├── Диалоги              (обратная связь)
├── События              (реакции на действия)
├── Вход                 (ссылки, рефералы)
├── Переменные           (персональные, глобальные)
├── Статистика           (формы ввода, аналитика)
└── Настройки            (интеграции, платежи, дублирование)
```

**Верхняя панель конструктора:**

## Приложение: Ключевые паттерны

### Паттерн "Регистрация с защитой от повторного прохождения"
Форма ввода -> в дополнительных настройках отключить повторное прохождение -> указать команду перенаправления (меню).

### Паттерн "Проверка: найдено / не найдено" (Google Sheets)
Условие -> проверить строку -> основное правило (найдено) + исключающее правило (не найдено).

### Паттерн "Скрытие кнопки для определенных пользователей"
Кнопка условия -> основное правило (показать) + исключающее правило (скрыть).

### Паттерн "Администраторская кнопка"
Категория "Администратор" -> кнопка условия с проверкой категории -> исключающее правило: скрыть.

### Паттерн "Слайдер изображений"
Цепочка инлайн-команд с медиаблоками. Кнопки "Вперед"/"Назад" переключают между инлайн-командами (замена на месте).

### Паттерн "Таймер/Напоминание через сценарий"
Запуск сценария (действие) -> отключение в целевой команде. Сценарий с задержкой отправляет пост, если действие не выполнено.

### Паттерн "Случайная выдача из таблицы"
Переменная `Random` (формула `random(1, N)`) -> текстовая переменная `RandomX = Random` (выполнить "До") -> интегрированная переменная из таблицы с фильтром по RandomX.

### Паттерн "Обработка заявок с кнопками для админов"
Присвоить заявкам статусы: 0 = оплачено, 1 = в работе, 2 = отгружено. Админ запускает команду "В работу" -> находит первую необработанную заявку -> втягивает данные из таблицы. Статус = "в работе". Кнопка "Отправить клиенту" -> статус = "отгружено", данные отправляются.

### Паттерн "Реферальная система с бонусами"
1. Создать реферальную ссылку (вкладка "Вход").
2. Переменные: баланс без рефералов + баланс за рефералов.
3. Условие: проверка набрал ли реферал N бонусов.
4. Если набрал: "отправить другому юзеру" (через глобальную переменную "Юзернейм создателя последней активированной реферальной ссылки").
5. В новой команде: изменить переменную бонусов.

### Паттерн "Таймер с кнопкой (если не нажал -- следующий блок)"
Сценарий с отправкой поста через время. По кнопке перехода -- сразу на команду + отключение сценария. Если не нажал -- сценарий отправляет следующий блок.

### Паттерн "A/B тест (равномерное распределение)"
Условие: если не в группах -> присвоить категорию X + переменная X+1. Условие: если X > Y -> проверить Y > Z -> присвоить Z. Если Y < Z -> присвоить Y. Равномерное распределение.

### Паттерн "Определение номера недели"
Категория или переменная + сценарий. Сценарий через 7, 14, 21 дней меняет переменную (номер недели: 1, 2, 3). Условием проверяете значение и выдаете актуальное расписание.

### Паттерн "Публикация видео от пользователя после модерации"
ID видео записывается в таблицу. В канале блок "Видео" подтягивает из таблицы ID через интегрированную переменную. Каждая заявка нумеруется для идентификации.

### Паттерн "Напоминание о встрече из Google Таблиц"
1. Таблица: Дата | Время | С кем | Тема | Место.
2. Форма ввода -> сохранение через интеграцию.
3. Команда "Мои встречи" -> фильтр Дата >= Сегодня.
4. Автонапоминание: триггер "Каждое утро в 9:00" -> встречи на сегодня.

### Паттерн "Внутренний баланс с NocoDB"
Персональные числовые переменные для баллов + числовые для зачисления/снятия. БД -- NocoDB. Админ-панель через проверку `{{USER_ID_TEXT}}`. Кнопки зачисления/снятия + уведомление.

## Приложение F: FAQ (Часто задаваемые вопросы)

**Q: Нужен ли /privacy для бота без форм ввода?**
A: Стандартные данные (юзернейм, имя) отдает сам Telegram. При регистрации пользователь уже согласился по политике Telegram. Если есть формы ввода -- да, нужен. Если только стандартные данные -- необязательно.

**Q: Где найти клиентов на создание ботов?**
A: Лучше всего сарафанное радио. Делайте ботов "за спасибо" с условием: вы видны как автор/создатель со ссылкой. Делаете много и разных, набиваете руку. Через время появятся клиенты.

**Q: Как сделать админ-панель внутри бота?**
A: Доступ через проверку `{{USER_ID_TEXT}}` конкретного админа. Команды-условия для проверки, сценарии для уведомлений. Категория "Администратор" для ограничения кнопок.

**Q: Как передать права на бота заказчику?**
A: Передать право владения в @BotFather. Перенести бота на аккаунт заказчика в PuzzleBot (Настройки -> Дублировать/Перенести). Для переноса подписчиков: support@puzzlebot.top.

**Q: Можно ли одновременно принимать инлайн-кнопки и произвольный текст?**
A: Нет простого решения. Через костыли: переменная-флаг "ожидает текст" + переопределение "Неизвестной команды" -> условие проверки флага.

**Q: Как загрузить файл больше лимита ЛК?**
A: Через ID файла: `/cp` в боте -> "Загрузить файл" -> скопировать ID -> вставить в блок. Лимит через ID -- до 2 ГБ. ID уникальны для каждого бота.

**Q: Как вывести все записи из NocoDB в мини-приложении?**
A: Интегрированная переменная с форматом "наличие", вариант поиска "все". Разделитель `<br>` для строк. Вывод всей таблицы со всеми столбцами -- задание со звездочкой.

**Q: NocoDB vs Google Таблицы -- что выбрать?**
A: NocoDB рекомендуется: скорость почти моментальная, лимиты 10 запросов/сек (vs 60/мин у Google), данные на своих серверах. Документация: docs.nocodb.com.

**Q: Как опрашивать Google Таблицу каждые X минут?**
A: Варианты: (1) n8n -- сценарии с таймерами через API (мин 1 мин), (2) Google Apps Script -- триггер на новую строку или по времени, (3) Make (Integromat) -- мин 15 мин на бесплатном, (4) Apix-Drive -- без кода.

**Q: White Label (WL) для разработчиков ботов?**
A: WL расширение к тарифу: клиенты получают ЛК брендированный под вас на вашем домене. Оплату получаете вы, стоимость устанавливаете сами. Подробнее: puzzlebot.top/blog/JAO3CBYV2X

**Q: Почему месяц в PuzzleBot -- 29 дней?**
A: Согласно оферте (раздел "Тарифы", п. 9.1), месяц = 30 календарных дней. Если начислено 29 -- предыдущий платеж был с задержкой. Боты работают "в долг" до 2 дней, это компенсируется из следующего платежа.

**Q: Как оплатить тариф PuzzleBot по безналу (ЮЛ)?**
A: Отправить на weare@puzzlebot.top: карточку компании (реквизиты), юзернейм бота/аккаунта, тариф, период (минимум 3 месяца).

**Q: Как сделать тест в боте с подсчетом баллов?**
A: Вопросы с кнопками "изменить переменную". Числовая переменная `{{otvet}}` и текстовые `{{sfera1}}`, `{{sfera2}}`. Формула в тексте: `{{=if {{otvet}} > 5 ; {{sfera1}} ; {{sfera2}} }}`. При 100+ вариантах -- NocoDB/Google Таблицы.

**Q: Как сделать +5 энергии каждый час?**
A: Сценарий: пост "через 1 час" -> действие `Energy + 5` -> запуск самого себя. Настройки: "Перезапуск при повторном вызове", снять "Завершить после выполнения всех постов".

**Q: Бот может первым написать пользователю?**
A: Нет, если пользователь не был в боте до подписки. Единственный вариант -- событие подачи заявки на закрытый ресурс (с ограничениями от Telegram).
