# FAQ -- PuzzleBot Project

## Общие вопросы

### Q1: Чем отличаются два pipeline?

**Chat Analysis** работает с текстовыми сообщениями Telegram-группы: извлекает Q&A-пары, строит цепочки диалогов, скорит экспертов и генерирует FAQ. Входные данные -- JSON-экспорт из Telegram Desktop.

**Video-to-Knowledge** работает с видеофайлами: транскрибирует речь (Whisper), извлекает ключевые кадры (SSIM), распознаёт текст с экрана (OCR) и генерирует Obsidian Markdown-статьи.

### Q2: Какой Python нужен?

Python 3.10+ (для синтаксиса `int | None`). Рекомендуется 3.11 или 3.12.

### Q3: Можно ли использовать на другой Telegram-группе?

Да. Нужно обновить в `pipelines/chat-analysis/config.py`:
- `DATA_DIR` -- путь к экспорту
- `TOPIC_MAP` -- ID и названия топиков новой группы
- `QUESTION_STARTERS` -- при необходимости адаптировать под тематику

В `scripts/telegram_exporter.py` обновить `GROUP` (ID группы).

## Chat Analysis

### Q4: Что такое topic_id и зачем TOPIC_MAP?

В Telegram-супергруппах с форумом каждая тема (topic) имеет уникальный числовой ID. `TOPIC_MAP` связывает эти ID с человекочитаемыми названиями. `TOPIC_IDS` используется для критической проверки: если `reply_to` указывает на topic_id, это корневое сообщение, а не ответ.

### Q5: Почему BFS, а не DFS для цепочек?

BFS корректно вычисляет глубину (расстояние от корня). DFS проще в реализации, но глубина может быть неточной из-за порядка обхода. Для аналитики (метрики цепочек) BFS даёт более надёжные результаты.

### Q6: Как определяется "эксперт"?

Формула: `helpfulness = answers_count * 2 + unique_topics * 3 + avg_answer_length / 100`. Ответы весят больше вопросов (помощь ценится выше любопытства). Охват топиков даёт бонус (широкий эксперт).

### Q7: Можно ли запустить один шаг отдельно?

Да: `python run_pipeline.py --only-step qa`. Доступные шаги: `loader`, `threads`, `qa`, `experts`, `faq`, `report`. Pipeline автоматически подгрузит промежуточные данные из `output/`.

### Q8: Как обновить данные без полного перезапуска?

1. Обновить `messages.json` новым экспортом
2. `python run_pipeline.py --skip-cache` (перечитать JSON, обновить кеш)
3. Или запустить конкретные шаги: `--only-step loader`, затем `--only-step qa`

## Video-to-Knowledge

### Q9: Какая видеокарта нужна?

Для GPU-ускорения: NVIDIA с поддержкой CUDA (GTX 1060+ / RTX серия). Рекомендуется 6+ GB VRAM. large-v3 int8 требует ~5 GB VRAM. При отсутствии GPU автоматически используется CPU (в ~10 раз медленнее).

### Q10: Зачем нужен stability_wait?

При анимациях и скролле SSIM может кратковременно упасть ниже порога, но через долю секунды экран ещё не стабилизировался. `stability_wait` (0.5 сек) ждёт завершения перехода и проверяет, что новый кадр устоялся (SSIM между текущим и "после паузы" > 0.95). Это фильтрует промежуточные кадры.

### Q11: Можно ли использовать без Tesseract?

Да. Установите `"ocr_enabled": False` в `config.py`. Кадры будут извлечены, но OCR-текст не будет добавлен в статьи.

### Q12: Как обработать YouTube-видео?

Скрипт принимает URL напрямую:
```bash
python video_to_knowledge.py "https://www.youtube.com/watch?v=XXX" --single
```
Видео скачивается через yt-dlp в директорию `input/`.

## Экспорт Telegram

### Q13: Как экспортировать только один топик?

```bash
python scripts/telegram_exporter_topic.py 425001
```
Каждый топик создаёт отдельную Telethon-сессию (`telegram_session_topic_{ID}`) и сохраняет данные в `telegram_export_topic_{ID}/`.

### Q14: Нужен ли Telegram API ID?

Да. API credentials уже указаны в скриптах. При необходимости получить свои: https://my.telegram.org/apps

### Q15: Экспорт зависает на долго -- это нормально?

Да, при экспорте >10,000 сообщений Telegram отправляет FloodWaitError (rate limiting). Telethon автоматически ждёт указанное время (обычно 5-30 секунд). Полный экспорт группы с 21,000 сообщениями занимает 15-30 минут.

## WSL2 Batch Processing

### Q16: Как запустить пакетную обработку в WSL2?

Активируйте venv, перейдите в pipelines/video-to-knowledge/, запустите: `for i in 4 5 6 7 8 9 10; do python3 process_batch$i.py; done`. Batch-скрипты пропускают уже обработанные видео (проверяют наличие frames_index.json и transcription.json).

### Q17: Что делает repair_outputs.py?

Сканирует все 110 выходных папок, находит отсутствующие metadata.json и frames_transcript.json, генерирует их из существующих данных. НЕ перезапускает GPU-операции. Занимает ~30 секунд для всех 84 папок. Используйте --dry-run для предварительного просмотра.

### Q18: Почему видео #75 не прошло извлечение кадров?

Аппаратное декодирование кодека AV1 не поддерживается в WSL2. cv2.VideoCapture завершается ошибкой. Транскрипция аудио работает нормально (88 сегментов). Исправление: перекодируйте с `ffmpeg -i input.webm -c:v libx264 output.mkv`.

### Q19: Почему у некоторых видео 0 сегментов транскрипции?

Короткие скринкаст-видео без речи. Whisper VAD (Voice Activity Detection) удаляет 100% аудио как тишину. Затронуты видео #04, #30-37, #39, #99. Это валидные беззвучные демонстрации.

### Q20: Сколько времени занимает пакетная обработка?

84 видео заняли ~9.6 часов на RTX 3060 (large-v3 int8). В среднем ~7 минут на видео. Самое долгое: "Такси бот" (161 кадр, 532 сегмента, 850 секунд обработки).
