## Критические уроки (топ-5)

### 1. Ctrl+Shift+M СЛОМАН в PuzzleBot
**Дата:** 2026-02-15 | **Подтверждено:** 2x
**Проблема:** Горячая клавиша Ctrl+Shift+M для моноширинного форматирования в PuzzleBot вводит букву "m" вместо применения формата и стирает выделенный текст.
**Решение:** Использовать кнопку `</>` на всплывающей панели форматирования через screenshot + click.
**Урок:** Всегда иметь fallback для горячих клавиш: screenshot → визуальный поиск → click.

### 2. innerHTML injection + обязательный Save workflow
**Дата:** 2026-02-15 | **Обновлено:** 2026-02-16 | **Подтверждено:** 3x
**Проблема:** innerHTML injection и Quill API оба работают для вставки форматированного HTML, но форматирование терялось после перезагрузки страницы. Посимвольный ввод ломает `{{переменные}}` и работает в 3 раза медленнее.
**Решение:** Использовать `javascript_tool` с `editor.innerHTML = '...'` для мгновенной вставки HTML. После вставки ОБЯЗАТЕЛЬНО выполнить Save workflow:
1. Кликнуть на пустое место canvas (вне блока) — закрыть панель блока
2. Кликнуть оранжевую кнопку SAVE (верхний левый угол, иконка upload)
3. Кликнуть зелёную галочку в диалоге "Вы уверены, что хотите применить все изменения этой группы?"
4. Дождаться зелёного тоста "Отличная работа. Изменения применены!"
**Урок:** innerHTML injection работает идеально — проблема была в Save workflow, а не в методе вставки. Без шагов 2-4 изменения теряются при перезагрузке. PuzzleBot НЕ автосохраняет изменения конструктора.

### 3. Claude Desktop Cowork и Claude Code конфликтуют
**Дата:** 2026-02-16 | **Источник:** Trail of Bits, GitHub Issue #23434
**Проблема:** Оба регистрируют native messaging host для одного extension ID, но используют несовместимые форматы сокетов. Результат: "Browser extension is not connected" без видимых причин.
**Решение:** Отключить native host неиспользуемого приложения. ОБЯЗАТЕЛЬНО перезапустить Chrome.
**Урок:** При "Browser extension is not connected" — первым делом проверить, нет ли конфликта с Cowork.

### 4. computer tool: 13 actions, НЕ 15
**Дата:** 2026-02-16 | **Источник:** ToolSearch (верифицировано)
**Проблема:** Документация Anthropic API описывает generic computer_use tool (15 actions), но Claude in Chrome MCP имеет СВОЙ набор (13 actions). `left_mouse_down`, `left_mouse_up`, `hold_key`, `middle_click` — НЕ существуют в Claude in Chrome.
**Решение:** Использовать только верифицированные actions: left_click, right_click, double_click, triple_click, type, screenshot, wait, scroll, key, left_click_drag, zoom, scroll_to, hover.
**Урок:** Не смешивать данные из generic Anthropic API Docs и реальных MCP-схем Claude in Chrome.

### 5. gif_creator: start_recording / stop_recording / export / clear
**Дата:** 2026-02-16 | **Источник:** ToolSearch (верифицировано)
**Проблема:** В некоторых источниках указаны action="start"/"stop" и output_path — это НЕВЕРНО.
**Решение:** Правильные actions: start_recording, stop_recording, export, clear. Параметра output_path НЕ СУЩЕСТВУЕТ. Вместо него: download=true + filename.
**Урок:** Всегда верифицировать параметры инструментов через ToolSearch или /mcp.

## Общие правила

- **Первый вызов = tabs_context_mcp** — Tab ID из прошлых сессий невалидны
- **НИКОГДА alert() в JS injection** — блокирует ВСЕ browser events
- **Один Chrome-профиль** с расширением — несколько профилей = конфликт сокетов
- **Checkpoint каждые 25 записей** — Claude может остановиться на длинных списках
- **Screenshot перед кликом по floating toolbar** — координаты меняются каждый раз
- **Правило 2-3 попыток** — после 3 неудач остановиться и спросить пользователя
- **wait(3) после navigate** — страница PuzzleBot может не загрузиться мгновенно, скриншот будет пустым
- **Claude Code + Chrome MCP для batch** — для 100+ карточек ТОЛЬКО вариант A (Claude Code читает файлы, javascript_tool вставляет)

### FIX-006: PuzzleBot Quill Editor — innerHTML injection
**Дата:** 2026-02-16 | **Подтверждено:** 1x (пилот)
**Проблема:** Нужно вставлять форматированный текст (жирный, моноширинный, переменные) в PuzzleBot редактор.
**Решение:**
```javascript
const editor = document.querySelector('.ql-editor.bound');
editor.innerHTML = htmlContent;
editor.dispatchEvent(new Event('input', {bubbles: true}));
editor.dispatchEvent(new Event('change', {bubbles: true}));
```
**Результат:** Контент вставляется мгновенно, счётчик символов обновляется. **ВАЖНО:** PuzzleBot НЕ автосохраняет — нужен ручной Save workflow (см. FIX-010).
**Урок:** Quill editor с классом `.ql-editor.bound` — точка входа. ОБЯЗАТЕЛЬНО триггерить input+change events, иначе PuzzleBot не увидит изменения.

### FIX-007: Форматирование HTML для PuzzleBot Quill
**Дата:** 2026-02-16 | **Подтверждено:** 1x
**Проблема:** Как правильно форматировать HTML для вставки в Quill editor PuzzleBot.
**Решение:**
- `<strong>текст</strong>` — жирный (Ctrl+B тоже работает)
- `<em>текст</em>` — курсив (Ctrl+I тоже работает)
- `<code>текст</code>` — моноширинный (Ctrl+Shift+M СЛОМАН! Только кнопка `</>`)
- `<p>текст</p>` — каждая строка в отдельном `<p>`
- `<p><br></p>` — пустая строка (так Quill создаёт отступы)
- `{{переменные}}` ломаются при ручном вводе — ТОЛЬКО через innerHTML
**Урок:** Полный контроль форматирования — только через innerHTML. Ручной ввод/горячие клавиши ненадёжны.

### FIX-008: Навигация по PuzzleBot конструктору
**Дата:** 2026-02-16 | **Подтверждено:** 1x
**Проблема:** PuzzleBot рисует блоки на SVG canvas. Текст кнопок — SVG `<text>` элементы, НЕ редактируемые напрямую.
**Решение:**
- Настоящий редактор блока — боковая панель справа (открывается по клику на блок)
- Кнопки инлайн-клавиатуры: single click открывает панель редактирования ВЫШЕ текущей позиции — ПРОКРУТИТЬ ВВЕРХ
- Double-click и triple-click НЕ помогают для кнопок
- Прокрутка внутри боковой панели: scroll вверх/вниз по правой стороне экрана (x ~1400)
**Урок:** PuzzleBot конструктор = SVG canvas + боковая панель. read_page(filter: "interactive") бесполезен — конструктор на canvas.

### PAT-001: Оптимальный конвейер MD -> PuzzleBot
**Дата:** 2026-02-16 | **Подтверждено:** 1x (пилот на 1 карточке)
**Паттерн:**
1. **Офлайн:** Python-парсер (`md-to-puzzlebot-html.py`) читает MD-файлы карточек -> генерирует HTML-фрагменты (innerHTML) + JSON метаданные (кнопки)
2. Парсер определяет заголовки для bold: первая строка + строки с emoji + ALL CAPS + двоеточие
3. **Онлайн:** Claude Code читает HTML с диска -> `javascript_tool` вставляет в `.ql-editor` -> скриншот для верификации
4. **Save workflow (ОБЯЗАТЕЛЬНО!):** Клик вне блока -> оранжевая кнопка SAVE -> зелёная галочка подтверждения -> дождаться тоста "Отличная работа"
5. Кнопки: пока вручную (click -> scroll up -> edit)
6. ~10 секунд на вставку текста одной карточки
**Урок:** Разделение офлайн-подготовки (парсер) и онлайн-вставки (MCP) — ключ к масштабированию на 100+ карточек. Не забывать Save workflow после каждой вставки!

### FIX-009: PuzzleBot Quill — все 6 HTML-тегов работают через innerHTML
**Дата:** 2026-02-16 | **Подтверждено:** 1x (тест в live Quill)
**Проблема:** Какие HTML-теги реально работают при innerHTML injection в PuzzleBot Quill editor?
**Решение:** Протестированы и подтверждены ВСЕ 6 тегов:
- `<strong>` — жирный
- `<em>` — курсив
- `<code>` — моноширинный (красный)
- `<u>` — подчёркивание
- `<s>` — зачёркивание
- `<a href="url">` — ссылка
Комбинации тоже работают: `<strong><em>`, `<strong><code>`, `<em><code>`, `<strong><u>`.
**Урок:** Quill.js в PuzzleBot принимает полный набор HTML-тегов. Не нужно ограничиваться только bold — используй italic, code, underline, strikethrough, links.

### PAT-003: 9 правил inline-форматирования для карточек
**Дата:** 2026-02-16 | **Подтверждено:** 1x (111 карточек)
**Паттерн:**
1. Буллет с `--`: `• Место -- описание` → `• <code>Место</code> — <em>описание</em>`
2. Текст в «кавычках» → `<em>«текст»</em>`
3. Время HH:MM--HH:MM → `<code>HH:MM–HH:MM</code>`
4. Конвертация (~NNN AED) → `<code>(~NNN AED)</code>`
5. Категория цен: Label: $NNN → `<strong>Label:</strong> <strong>$NNN</strong>`
6. Цены $NNN → `<strong>$NNN</strong>`
7. "бесплатно" → `<strong>бесплатно</strong>`
8. Отмена: за Xч → `<strong>`, возврат → `<em>`
9. Тарифы: Name (desc): → `<strong>Name</strong> <em>(desc)</em>:`
**Урок:** Контентные паттерны (цены, места, тайминги) определяются regex'ами на УЖЕ экранированном тексте. Сначала html.escape(), потом форматирование.

### WARN-003: Telegram карточки — компактность критична
**Дата:** 2026-02-16 | **Подтверждено:** 1x
**Предупреждение:** Пустые строки `<p><br></p>` между секциями делают карточку слишком длинной. Клиенты на телефонах не скроллят длинные сообщения.
**Решение:** compact_html() функция — убирает ВСЕ пустые строки кроме:
- Перед bold-заголовками секций (emoji + CAPS + :)
- Перед тарифными подзаголовками (bold + italic)
- Перед разделителями (──────)
**Урок:** Для Telegram-ботов ВСЕГДА минимизировать вертикальные отступы. Emoji-заголовки сами служат визуальными разделителями.

### FIX-011: PuzzleBot — `<p>` всегда = `\n\n` в Telegram (платформенное ограничение)
**Дата:** 2026-02-17 | **Подтверждено:** 3x (тест с `<p>`, тест с `<br>`, тест с Quill Delta API)
**Проблема:** Каждая граница `<p>` в PuzzleBot Quill editor превращается в `\n\n` (двойной перенос строки с пустой строкой) в Telegram. Из-за этого карточки получаются очень растянутыми.
**Проведённые тесты:**
- `<p>A</p><p>B</p>` → `A\n\nB` в Telegram (одна пустая строка)
- `<p>A</p><p><br></p><p>B</p>` → `A\n\n\nB` (две пустые строки)
- `<br>` внутри `<p>` → стрипается Quill, игнорируется PuzzleBot
- Quill Delta `insertText('A\nB')` → всё равно `A\n\nB` в Telegram
**Корневая причина:** Бэкенд PuzzleBot конвертирует Quill output в формат Telegram, маппя каждую границу параграфа в `\n\n`. Это стандартное поведение (аналогично библиотеке tghtml).
**Потенциальные решения для тестирования:**
1. Shift+Enter в Quill — может создать `<br>` который маппится в одинарный `\n`
2. PuzzleBot HTML Block (новая фича Dec 2024) — raw HTML с контролем `\n`
3. HTTP Request block — отправка через Telegram API напрямую с явным `\n`
**Урок:** Невозможно получить одинарные переносы строк через `<p>` теги или Quill Delta API. Нужен альтернативный подход.

### PAT-004: Правильный маппинг PuzzleBot → Telegram
**Дата:** 2026-02-17 | **Подтверждено:** 3x
**Паттерн:**
- `<p>text</p>` → `text\n\n` (всегда двойной перенос)
- `<p><br></p>` → дополнительный `\n\n` (пустая строка, итого = 2 пустые строки)
- `<strong>` → `<b>` в Telegram (жирный) -- сохраняется
- `<em>` → `<i>` в Telegram (курсив) -- сохраняется
- `<code>` → `<code>` в Telegram -- сохраняется
- `<u>`, `<s>` → сохраняются
- `<br>` внутри `<p>` → стрипается/игнорируется
**Урок:** Для компактных карточек минимизировать количество строк. Каждая строка = одна пустая строка в Telegram.
