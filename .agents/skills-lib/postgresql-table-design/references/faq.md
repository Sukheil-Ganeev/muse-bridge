# FAQ — postgresql-table-design

## Q1: BIGINT GENERATED ALWAYS vs UUID для первичного ключа?
**BIGINT GENERATED ALWAYS AS IDENTITY** — по умолчанию. Компактный (8 байт), быстрая сортировка, последовательная вставка в B-tree (минимум page splits), читаемый в логах. **UUID** — когда нужна глобальная уникальность (распределённые системы, merge данных из разных БД), непредсказуемость ID (публичные API) или генерация на клиенте. Предпочитайте UUIDv7 (PG18+) — он time-ordered, лучше для B-tree индексов чем случайный UUIDv4.

## Q2: Когда использовать JSONB вместо отдельных колонок?
JSONB подходит для: опциональных/полуструктурированных атрибутов (метаданные, настройки), данных с переменной схемой (разные типы товаров), прототипирования (быстрый старт). **НЕ** используйте JSONB для: часто фильтруемых/сортируемых полей (отдельная колонка эффективнее), внешних ключей, данных со строгой схемой. Помните: JSONB не поддерживает constraints на отдельные поля (только CHECK с jsonb_typeof/operators).

## Q3: Нужно ли добавлять индекс на FK колонку?
Да, обязательно! PostgreSQL НЕ создаёт индекс на FK автоматически (в отличие от MySQL). Без индекса: JOIN по FK = sequential scan, DELETE/UPDATE в родительской таблице = блокировка + full scan дочерней. Исключение: если FK-колонка уже является частью другого индекса или таблица очень маленькая (<1000 строк).

## Q4: TEXT vs VARCHAR(n) — что выбрать?
Всегда **TEXT**. В PostgreSQL TEXT и VARCHAR хранятся абсолютно одинаково — нет разницы в производительности. VARCHAR(n) создаёт иллюзию контроля, но на практике: изменение лимита требует ALTER TABLE, ошибки при вставке неожиданны. Вместо VARCHAR(n) используйте `CHECK (LENGTH(col) <= 255)` — это явнее и гибче (можно менять без перестроения таблицы).

## Q5: Как хранить деньги в PostgreSQL?
**NUMERIC(p,s)** — единственный правильный вариант. Типичный выбор: `NUMERIC(12,2)` для AED/USD (до 9,999,999,999.99). Никогда не используйте: `FLOAT/DOUBLE PRECISION` (ошибки округления: 0.1+0.2 != 0.3), встроенный тип `MONEY` (locale-dependent, устаревший). Для мультивалютности: хранить сумму + код валюты (TEXT или ENUM) отдельно. Альтернатива: хранить в минимальных единицах (копейки/филсы) как BIGINT.

## Q6: TIMESTAMP vs TIMESTAMPTZ — в чём разница?
**TIMESTAMPTZ** (timestamp with time zone) — всегда. PostgreSQL хранит UTC внутри, конвертирует при выводе в timezone сессии. **TIMESTAMP** (без timezone) — хранит "как есть", не учитывает часовые пояса. Ловушка: если сервер/клиент переедет в другой timezone, все TIMESTAMP значения станут неправильными. Единственное исключение для TIMESTAMP: расписания (будильник в 7:00 утра независимо от пояса).
