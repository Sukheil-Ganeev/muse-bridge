# Troubleshooting — Яндекс Диск MCP

## Проблема: Overflow метаданных (>30K символов)

### Симптомы
- Вызов `get_metadata` для большой папки возвращает огромный JSON
- Результат обрезается или сохраняется в temp-файл автоматически
- В ответе видно `[Content saved to file: ...]`

### Причина
Папки с большим количеством элементов (БИЛЕТЫ — 232 папки, Яхты для PDF — 250 папок) генерируют JSON-ответ, превышающий лимит MCP.

### Решение
1. Найди сохранённый temp-файл (путь в сообщении об overflow)
2. Парси через Python:

```python
import json
import sys

sys.stdout.reconfigure(encoding='utf-8')

# Читаем temp-файл с метаданными
with open('путь_к_temp_файлу.json', 'r', encoding='utf-8') as f:
    raw = json.load(f)

# Структура: [{type: "text", text: "json_string"}]
text_content = raw[0]['text']
data = json.loads(text_content)

# Извлекаем список элементов
items = data['_embedded']['items']
print(f"Всего элементов: {len(items)}\n")

for item in items:
    icon = 'D' if item['type'] == 'dir' else 'F'
    size = item.get('size', '-')
    print(f"[{icon}] {item['name']}  ({size})")
```

3. Альтернатива: используй `limit` и `offset` в `get_metadata` для постраничной загрузки

### Профилактика
- Для известных больших папок (БИЛЕТЫ, Яхты для PDF) — сразу используй пагинацию
- Лимит по умолчанию: 20 элементов

## Проблема: Download URL истёк

### Симптомы
- `curl` возвращает ошибку 403 или 410
- Ранее полученный URL не работает
- Ошибка "Gone" или "Forbidden"

### Причина
URL из `get_download_url` содержит временный токен, срок жизни ~30 минут.

### Решение
1. Получи новый URL: `yandex_disk_get_download_url(path="disk:/путь/файл")`
2. Сразу скачай: `curl -L -o "D:/Downloads/file.jpg" "НОВЫЙ_URL"`

### Профилактика
- Скачивай файл СРАЗУ после получения URL
- НЕ сохраняй URL для повторного использования
- При пакетном скачивании: получай URL и скачивай по одному

## Проблема: Кодировка кириллических имён файлов

### Симптомы
- Имена файлов отображаются как `?????` или мусорные символы
- Python `print()` падает с UnicodeEncodeError
- JSON парсится, но имена нечитаемы в консоли

### Причина
Консоль Windows по умолчанию использует cp1251 или cp866, а файлы в UTF-8.

### Решение

**В Python-скрипте:**
```python
import sys
sys.stdout.reconfigure(encoding='utf-8')
```

**В Git Bash:**
```bash
export PYTHONIOENCODING=utf-8
```

**При чтении файла:**
```python
with open('file.json', 'r', encoding='utf-8') as f:
    data = json.load(f)
```

**При записи результатов:**
```python
with open('output.txt', 'w', encoding='utf-8') as f:
    for item in items:
        f.write(f"{item['name']}\n")
```

## Проблема: Пустые папки

### Симптомы
- `get_metadata` возвращает папку с `_embedded.items = []`
- Ожидались файлы, но их нет

### Известные пустые папки
| Путь | Комментарий |
|------|------------|
| `ГРУППОВЫЕ ЭКСКУРСИИ/НА САФАРИ/` | Пустая! Фото сафари — в `ИНДИВИДУАЛЬНЫЕ ЭКСКУРСИИ/НА САФАРИ/` |

### Решение
- Проверь альтернативные папки (ГРУППОВЫЕ vs ИНДИВИДУАЛЬНЫЕ)
- Используй карту диска: `experience/patterns/disk-structure.md`
- Некоторые папки были созданы как заглушки и никогда не заполнялись

## Проблема: MCP-инструмент не найден / не отвечает

### Симптомы
- Ошибка "tool not found" при вызове yandex_disk_*
- Таймаут при вызове инструмента

### Решение
1. Убедись, что инструменты загружены: `ToolSearch("yandex disk")`
2. Если не найдены — загрузи через `ToolSearch("select:mcp__yandex-disk__yandex_disk_info")`
3. Проверь доступность: вызови `yandex_disk_info` (самый лёгкий запрос)

## Проблема: Путь не найден (404)

### Симптомы
- `get_metadata` возвращает "not found" или "DiskPathDoesNotExistsError"

### Частые ошибки в путях
| Неправильно | Правильно |
|------------|-----------|
| `disk:/CRM система (ОАЭ)/` | `disk:/CRM системы стран/CRM система (ОАЭ)/` |
| `disk:/Яхты/` | `disk:/Яхты для PDF/` |
| `disk:/Instagram/` | `disk:/фирменный стиль Дубаи/Instagram/` |
| `disk:/Машины/` | `disk:/Машины PDF/` |

### Решение
- Начинай навигацию с корня: `get_metadata("disk:/")`
- Используй точные имена папок (с учётом регистра и пробелов)
- Путь ВСЕГДА начинается с `disk:/`

## Проблема: Файл слишком большой для скачивания

### Симптомы
- `curl` зависает или обрывается на больших файлах
- Фото HD ~3.5MB, но соединение нестабильное

### Решение
```bash
# Использовать curl с прогрессбаром и продолжением
curl -L -C - -o "D:/Downloads/photo.jpg" "URL"

# Или с таймаутом
curl -L --connect-timeout 30 --max-time 300 -o "D:/Downloads/photo.jpg" "URL"
```
