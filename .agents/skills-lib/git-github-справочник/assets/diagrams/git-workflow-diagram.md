# Git Workflow Diagram - Базовый процесс работы с Git

## Основной workflow (3 стадии)

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  Working        │    │  Staging        │    │  Local          │    │  Remote         │
│  Directory      │───▶│  Area           │───▶│  Repository     │───▶│  Repository     │
│  (Рабочая папка)│    │  (Индекс)       │    │  (.git)         │    │  (GitHub)       │
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
      (edit)               (git add)             (git commit)            (git push)

   Изменяешь          Подготавливаешь        Сохраняешь           Отправляешь
     файлы                к commit             локально              на сервер
```

## Полный цикл: от создания до push

```
1. СОЗДАНИЕ/ИЗМЕНЕНИЕ ФАЙЛОВ
   ┌────────────────┐
   │ code index.html│  ← Редактируешь в VS Code
   └────────────────┘
          ↓

2. ПРОВЕРКА СТАТУСА
   ┌────────────────┐
   │  git status    │  ← Видишь: index.html modified
   └────────────────┘
          ↓

3. STAGING (Подготовка к commit)
   ┌────────────────┐
   │ git add .      │  ← Добавляешь ВСЕ измененные файлы
   └────────────────┘
          ↓
   или
   ┌────────────────────────┐
   │ git add index.html     │  ← Только конкретный файл
   └────────────────────────┘
          ↓

4. COMMIT (Сохранение локально)
   ┌─────────────────────────────────────┐
   │ git commit -m "Add hero section"    │  ← Создаешь snapshot
   └─────────────────────────────────────┘
          ↓

5. PUSH (Отправка на GitHub)
   ┌────────────────────────┐
   │ git push origin main   │  ← Отправляешь на сервер
   └────────────────────────┘
          ↓

6. GITHUB
   ┌──────────────────────────────────────┐
   │  Твой commit появился на GitHub!     │
   └──────────────────────────────────────┘
```

## Получение изменений с GitHub

```
GITHUB (Remote)
      │
      git fetch origin
      │
      ▼
┌─────────────────────────┐
│  Remote Tracking Branch │  ← origin/main обновлен, но main еще старый
│  origin/main            │
└─────────────────────────┘
      │
      git merge origin/main
      │
      ▼
┌─────────────────────────┐
│  Local Branch           │  ← main обновлен
│  main                   │
└─────────────────────────┘
      │
      автоматически
      │
      ▼
┌─────────────────────────┐
│  Working Directory      │  ← Файлы обновлены
└─────────────────────────┘

ИЛИ КОРОЧЕ:

git pull origin main
    ↓
(git fetch + git merge одной командой)
```

## Сравнение git add, commit, push

```
                 git add              git commit           git push
                    ↓                      ↓                   ↓
             ┌─────────────┐        ┌──────────┐       ┌──────────┐
Что делает?  │ Подготовка  │        │ Сохранение│      │ Отправка │
             │ к commit    │        │ локально  │      │ на сервер│
             └─────────────┘        └──────────┘       └──────────┘

Где?         Working Dir            Local Repo         Remote Repo
             → Staging              (.git folder)      (GitHub)

Можно        Да                     Да                 Нет
отменить?    (git restore           (git reset         (нужен
             --staged)              --soft HEAD~1)     force push)

Частота      После каждого          После логической   После
             изменения файла        единицы работы     завершенной
                                                        фичи
```

## Параллельное состояние файлов

Один файл может быть в разных состояниях одновременно!

```
index.html:

┌───────────────────┐
│ Working Directory │  ← Версия 3 (только что отредактирована)
├───────────────────┤
│ <h1>New Title</h1>│
└───────────────────┘

┌───────────────────┐
│ Staging Area      │  ← Версия 2 (добавлена через git add 5 минут назад)
├───────────────────┤
│ <h1>Old Title</h1>│
└───────────────────┘

┌───────────────────┐
│ Local Repo        │  ← Версия 1 (закоммичена вчера)
├───────────────────┤
│ <h1>First</h1>    │
└───────────────────┘

git status покажет:
Changes to be committed:
    modified: index.html          ← Версия 2 в staging
Changes not staged for commit:
    modified: index.html          ← Версия 3 в working dir
```

## Визуализация .git директории

```
Твой проект/
│
├── index.html        ← Working Directory (видимые файлы)
├── style.css
├── script.js
│
└── .git/             ← Git Repository (скрытая папка)
    ├── objects/      ← Все commits, blobs, trees
    ├── refs/         ← Указатели на ветки
    ├── HEAD          ← Текущая ветка
    ├── index         ← Staging Area
    └── config        ← Настройки репозитория
```

## Заключение

**Три ключевые зоны Git:**

1. **Working Directory** - твои файлы (видимые)
2. **Staging Area** - подготовка к commit (невидимая)
3. **Repository** - история commits (.git папка)

**Основные команды:**
- `git add` - Working → Staging
- `git commit` - Staging → Repository
- `git push` - Local Repository → Remote Repository
- `git pull` - Remote Repository → Local Repository + Working Directory

**Главное правило:** Изменения проходят через все стадии последовательно!
