# Make.com -- Типичные проблемы и решения (Troubleshooting)

---

## 1. Сценарий не запускается

**Симптомы:** Сценарий включен (Toggle ON), но не выполняется.

**Решения:**
- Проверить **Toggle ON** (переключатель активности)
- Проверить **Scheduling** (расписание): кликнуть на часы внизу сценария
- Для Instant (webhook): убедиться, что внешний сервис отправляет данные на правильный URL
- Для Scheduled: проверить, что интервал не слишком большой (Free = минимум 15 мин)
- Проверить **лимит операций** (Organization -> Usage) -- при исчерпании сценарии останавливаются
- Проверить **лимит активных сценариев** (Free = 2)
- Посмотреть **History** -- возможно сценарий запускался, но с ошибкой

---

## 2. Connection Error: сервис не авторизован

**Симптомы:** Ошибка `ConnectionError`, `401 Unauthorized`, `403 Forbidden`.

**Решения:**
- Перейти в **Connections** -> найти проблемный -> **Reauthorize** (переподключить)
- Для OAuth 2.0: токен мог истечь -- переавторизоваться
- Для API Key: проверить что ключ не отозван/изменен в исходном сервисе
- Для Google: проверить что приложение не отозвано в security.google.com
- Проверить **scopes** (права): может не хватать прав для конкретного действия
- Создать новый Connection с нуля, если переавторизация не помогает

---

## 3. Ошибка маппинга: данные не приходят / пустые

**Симптомы:** `undefined`, `null`, пустое поле, `The operation failed with an error`.

**Решения:**
- Проверить **номер модуля** в `{{N.field}}` -- он мог измениться после реорганизации
- **Run Once** -> посмотреть Output проблемного модуля -- есть ли нужное поле
- Проверить **вложенность**: `{{1.data.user.name}}` vs `{{1.name}}`
- Для полей со спецсимволами: `` {{1.`Имя клиента`}} `` (обратные кавычки)
- Если данные приходят иногда -- использовать `{{ifempty(1.field; "default")}}` для дефолтного значения
- Проверить что предыдущий модуль выполнился успешно (не ошибка, не пропущен)

---

## 4. Rate Limit: превышен лимит API

**Симптомы:** `429 Too Many Requests`, `RateLimitError`.

**Решения:**
- Добавить **Sleep** модуль между запросами (0 ops): 1-2 секунды
- Уменьшить **частоту polling** (увеличить интервал расписания)
- Использовать **Aggregator** для batch-запросов вместо итерации
- Для Telegram: 30 msg/сек max, Sleep 35ms между сообщениями при рассылке
- Для Google Sheets: 100 req/100 sec, использовать Bulk операции
- Для Notion: 3 req/sec, обязательно Sleep между запросами
- Добавить **Error Handler -> Break** с auto-retry (автоповтор через время)

---

## 5. Webhook не получает данные

**Симптомы:** "Waiting for data" висит бесконечно, данные не появляются.

**Решения:**
- Проверить **URL webhook** -- скопировать заново (регион, unique ID)
- Проверить что внешний сервис отправляет на правильный URL (не на старый)
- **Run Once** должен быть нажат ДО отправки тестового запроса
- Проверить **IP Restrictions** -- может IP отправителя не в whitelist
- Проверить **формат данных**: Content-Type должен соответствовать (application/json для JSON)
- Проверить **payload size**: максимум 5 MB
- Протестировать через curl: `curl -X POST -H "Content-Type: application/json" -d '{"test":1}' YOUR_WEBHOOK_URL`
- Проверить **статус Make.com**: status.make.com

---

## 6. Iterator возвращает пустой массив / один элемент

**Симптомы:** Iterator обрабатывает 1 элемент вместо массива, или 0 элементов.

**Решения:**
- Проверить что предыдущий модуль выдает **массив** (Array), а не объект (Collection)
- Посмотреть **Output** предыдущего модуля в Run Once -- там должен быть `[]` (массив)
- Если данные в виде JSON строки -- добавить **JSON: Parse JSON** перед Iterator
- Проверить **Source module** в настройках Iterator -- указан ли правильный модуль
- Если массив вложен: `{{1.data.items}}` вместо `{{1.data}}`

---

## 7. formatDate неправильно форматирует / ошибка

**Симптомы:** Неверная дата, ошибка "Invalid date", странный формат.

**Решения:**
- Проверить что входные данные -- **дата** (Date), а не строка (Text)
- Если строка -- сначала `{{parseDate("15.01.2024"; "DD.MM.YYYY")}}`, потом `formatDate`
- Формат: `DD` = день (01-31), `MM` = месяц (01-12), `YYYY` = год (4 цифры)
- Внимание: `mm` = минуты, `MM` = месяц! Регистр важен
- Для timezone: `{{formatDate(now; "DD.MM.YYYY HH:mm"; "Asia/Dubai")}}` (третий параметр)
- ISO 8601 формат: `{{formatDate(now; "YYYY-MM-DDTHH:mm:ssZ")}}`

## 8. Incomplete Executions копятся

**Симптомы:** Список Incomplete Executions растет, сценарий помечен предупреждением.

**Решения:**
- **Массовая обработка**: History -> Incomplete Executions -> Select All -> Retry или Delete
- **Автоматический retry**: в Error Handler (Break) включить Auto retry с интервалом
- **Отключить накопление**: Scenario Settings -> "Allow storing incomplete executions" -> Off (если не нужен retry)
- **Найти корневую причину**: посмотреть ошибку в Incomplete -> исправить -> retry
- **Установить лимит**: Scenario Settings -> "Max number of consecutive errors" (авто-выключение)

---

## 9. Сценарий работает, но данные дублируются

**Симптомы:** Одинаковые записи создаются повторно.

**Решения:**
- Добавить **Search** перед Create: искать по email/phone/ID -> Router: Found -> Update, Not Found -> Create
- Использовать **Data Store** для отслеживания обработанных записей (deduplication)
- Для Watch модулей: проверить настройку "From" -- должно быть "From now", не "All"
- Использовать **Upsert** вместо Create (если сервис поддерживает)
- При webhook: проверить что сервис не отправляет дубли (идемпотентность)

---

## 10. Ошибка JSON parsing

**Симптомы:** `SyntaxError: Unexpected token`, `Invalid JSON`, данные не парсятся.

**Решения:**
- Проверить формат JSON: валидировать на jsonlint.com
- Убедиться что Content-Type = `application/json` (не text/plain)
- Если JSON приходит как строка -- добавить **JSON: Parse JSON** модуль
- Проверить **экранирование**: кавычки внутри строк должны быть `\"`, не `"`
- Для XML данных: использовать **XML: Parse XML** вместо JSON parser
- Если HTTP модуль не парсит автоматически: включить "Parse response" в настройках

---

## 11. Telegram модуль: бот не отвечает / ошибки

**Симптомы:** Бот не реагирует на сообщения, ошибки отправки.

**Решения:**
- Проверить **Bot Token**: не изменился ли, не отозван ли через @BotFather
- Бот **не может писать первым** -- пользователь должен сначала отправить /start
- Проверить **Chat ID**: `{{1.message.chat.id}}` (число, не строка)
- **Markdown V2**: экранировать спецсимволы `_*[]()~>#+-=|{}.!`
- Длина сообщения: максимум **4096 символов**, разбивать через `substring`
- Rate limit: 1 msg/сек в один чат, использовать Sleep при рассылке
- Callback query: обязательно отвечать **Answer Callback Query** (убирает "часики")
- Проверить что webhook Make.com не конфликтует с другими ботами/сервисами на том же токене

## 12. Google Sheets: "Row not found" / ошибка записи

**Симптомы:** `Row not found`, пустой результат поиска, ошибка обновления.

**Решения:**
- **Row not found**: строка с таким номером не существует -- проверить номер строки
- **Search Rows** не находит: проверить условия фильтра, регистр, пробелы
- **Формулы Google Sheets** в ячейках могут возвращать пустоту -- использовать "Formula" режим в Search
- Проверить что **Sheet name** правильный (регистрозависимо)
- **Rate limit 100 req/100 sec**: использовать Bulk операции для массовых действий
- **Лимит колонок**: макс 18,278 (до ZZZ)
- **Timeout**: для больших таблиц увеличить timeout в настройках модуля

---

## 13. Фильтр Router не пропускает данные

**Симптомы:** Данные не проходят через фильтр, ни одна ветка не срабатывает.

**Решения:**
- **Run Once** -> посмотреть реальные данные в Output предыдущего модуля
- Проверить **тип данных**: текстовое "5" не равно числовому 5
- Проверить **регистр**: "Active" != "active" (использовать `lower()` для нормализации)
- Проверить **пробелы**: `"Active "` (с пробелом) != `"Active"` -- использовать `trim()`
- Оператор **"contains"** вместо **"equal to"** для частичного совпадения
- Добавить **fallback ветку** (без фильтра) для отладки -- увидите что проходит мимо
- Regex в фильтрах: `^` (начало), `$` (конец), `.*` (любые символы), `\d+` (цифры)

## 14. Операции расходуются слишком быстро

**Симптомы:** Лимит операций исчерпан до конца месяца.

**Решения:**
- **Dashboard -> Usage**: найти топ-потребителей операций
- **Bulk операции**: Google Sheets Bulk Add/Update = 1 op вместо N (экономия до 100x)
- **Webhook > Polling**: переключить с polling (тратит на пустые проверки) на webhook
- **Aggregator**: собрать данные, отправить одним запросом
- **Data Store кеширование**: не запрашивать справочные данные каждый раз
- **Расписание**: реже запускать в нерабочие часы (ночь, выходные)
- **Фильтры раньше**: ставить Filter ближе к началу сценария -- отсекать ненужные данные до платных модулей
- **Правило 80/20**: оптимизировать 20% сценариев, потребляющих 80% операций

## 15. Ошибка аутентификации OAuth

**Симптомы:** `Invalid grant`, `Token expired`, `Refresh token revoked`.

**Решения:**
- **Переподключить Connection**: Connections -> Reauthorize (Make автоматически обновляет access tokens)
- **Google**: проверить что приложение не отозвано в myaccount.google.com -> Security -> Third-party apps
- **Проверить scopes**: возможно нужны дополнительные разрешения
- **Удалить и создать заново**: если Reauthorize не помогает -- удалить Connection, создать новый
- **Проверить redirect URI**: для Custom OAuth -- URI должен совпадать с настройками приложения
- **API лимиты**: некоторые сервисы лимитируют количество активных OAuth tokens

---

## 16. HTTP модуль возвращает ошибку

**Симптомы:** `400 Bad Request`, `404 Not Found`, `500 Internal Server Error`.

**Решения:**
- **400**: проверить формат тела запроса (JSON валидный?), обязательные поля, Content-Type header
- **401/403**: проверить авторизацию (токен, ключ, права)
- **404**: проверить URL (опечатки, версия API, endpoint существует?)
- **429**: rate limit -- добавить Sleep, уменьшить частоту (см. пункт 4)
- **500/502/503**: проблема на стороне сервера -- Make автоматически retry 3 раза
- **Timeout**: увеличить timeout (Settings -> Timeout, макс 300 сек)
- **Отладка**: скопировать запрос в Postman и протестировать отдельно от Make

---

## 17. Data Store: "Record not found" / переполнение

**Симптомы:** Запись не найдена, ошибка при добавлении, Data Store full.

**Решения:**
- **Record not found**: проверить Key -- точное совпадение, регистр
- **Переполнение**: Free = 500 records / 1MB, Core = 10K / 10MB, Pro = 50K / 100MB
- **Очистка**: создать сценарий для удаления старых записей (Schedule -> Search -> Delete)
- **Ротация логов**: удалять записи старше 30 дней
- **Проверить Structure**: поля Data Store должны совпадать с тем что вы записываете

---

## 18. Сценарий выполняется слишком долго / timeout

**Симптомы:** `ExecutionTimeout`, сценарий обрывается на середине.

**Решения:**
- **Максимум 40 минут** на выполнение (Enterprise -- настраиваемо)
- Разбить на несколько сценариев: первый обрабатывает и сохраняет в Data Store, второй продолжает
- Уменьшить количество данных: фильтровать раньше, использовать pagination
- Убрать лишние Sleep модули
- Для HTTP: уменьшить timeout на каждый запрос
- Использовать **Webhook chaining**: один сценарий вызывает другой через HTTP/Webhook
