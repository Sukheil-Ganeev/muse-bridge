# Миграция с Airtable на NocoDB -- пошаговый гайд

> Версия: 1.0 | Дата: 2026-02-15

---

## Зачем переходить?

| Критерий | Airtable | NocoDB |
|---|---|---|
| 100 пользователей/год | ~$54,000 (Business) | ~$2,592 (Plus self-hosted) |
| Записей | 50K (тормозит) | Миллионы (PostgreSQL) |
| Данные | На серверах Airtable (USA) | Ваш сервер / ваша БД |
| Vendor lock-in | Да | Нет |

---

## Способ 1: Встроенный импорт из Airtable (рекомендуемый)

Встроенный инструмент NocoDB для миграции с Airtable. Переносит структуру таблиц, данные, связи и вложения.

### Шаг 1: Получить Personal Access Token в Airtable

1. Открыть https://airtable.com/create/tokens
2. Нажать **"Create new token"**
3. Настроить:
   - **Name:** NocoDB Migration
   - **Scopes:**
     - `data.records:read` -- чтение записей
     - `schema.bases:read` -- чтение структуры
   - **Access:** выбрать нужные bases (или All)
4. Нажать **"Create token"**
5. Скопировать токен (начинается с `pat...`)

**Важно:** Токен показывается один раз! Сохраните его.

### Шаг 2: Импорт в NocoDB

1. Открыть NocoDB
2. На главной странице нажать **"+ New Base"** -> **"Import from Airtable"**
3. Вставить Airtable Personal Access Token
4. Выбрать base для импорта
5. Настройки:
   - **Import Data** -- импортировать данные (включить)
   - **Import Attachments** -- импортировать вложения (включить, если нужны файлы)
6. Нажать **"Import"**
7. Дождаться завершения (может занять несколько минут для больших баз)

### Шаг 3: Проверка после импорта

После завершения проверьте:

- [ ] Все таблицы созданы
- [ ] Записи перенесены корректно
- [ ] Связи между таблицами работают
- [ ] Вложения доступны (если импортировали)
- [ ] SingleSelect/MultiSelect опции на месте

## Способ 2: CSV Export / Import

Если встроенный импорт не работает или нужен выборочный перенос.

### Экспорт из Airtable

1. Открыть таблицу в Airtable
2. Нажать **"..."** (меню view) -> **"Download CSV"**
3. Повторить для каждой таблицы
4. Сохранить CSV-файлы

### Импорт в NocoDB

1. Создать новый Base в NocoDB
2. **"+ New Table"** -> **"Import"** -> **"CSV"**
3. Загрузить CSV-файл
4. Проверить и настроить типы полей
5. Повторить для каждой таблицы
6. **Вручную** создать связи между таблицами (Links)

**Недостатки CSV:**
- Связи между таблицами не переносятся -- нужно создавать вручную
- Вложения не переносятся
- MultiSelect может некорректно парсить значения с запятыми
- Формулы не переносятся

## Что переносится / что НЕ переносится

### Переносится (встроенный импорт)

| Элемент | Статус | Примечание |
|---|---|---|
| Таблицы | Да | Структура и данные |
| Записи | Да | Все строки |
| Поля (большинство) | Да | SingleLineText, Number, Date, SingleSelect, MultiSelect, Checkbox, URL, Email, Phone, Currency, Percent, Rating, LongText |
| Связи (Links) | Да | Has-Many, Many-to-Many |
| Вложения | Да | Файлы копируются в NocoDB storage |
| SingleSelect/MultiSelect | Да | Опции и цвета |
| Lookup | Да | Пересоздаются |
| Rollup | Да | Базовые функции (count, sum, avg) |

### НЕ переносится (требует ручной настройки)

| Элемент | Статус | Что делать |
|---|---|---|
| **Формулы** | Частично | Синтаксис отличается! Пересоздать вручную. См. таблицу ниже |
| **Views** | Нет | Создать вручную (Grid, Kanban, Calendar, Form, Gallery) |
| **Фильтры Views** | Нет | Настроить заново в каждом view |
| **Automations** | Нет | Пересоздать через Webhooks + n8n/Make.com |
| **Interfaces** | Нет | Использовать Shared Views или Dashboards (Enterprise) |
| **Extensions** | Нет | Аналоги через плагины NocoDB |
| **Sync (Airtable Sync)** | Нет | Настроить через API/интеграции |
| **Scripting** | Нет | Заменить на API v2 вызовы |
| **Comments** | Нет | Не переносятся |

### Различия формул (Airtable -> NocoDB)

| Функция Airtable | Аналог NocoDB | Примечание |
|---|---|---|
| `CREATED_TIME()` | `{CreatedTime}` | Автоматическое системное поле |
| `LAST_MODIFIED_TIME()` | `{LastModifiedTime}` | Автоматическое системное поле |
| `RECORD_ID()` | `RECORD_ID()` | Работает одинаково |
| `DATEDIF()` | `DATETIME_DIFF()` | Другое название! |
| `DATEADD()` | `DATEADD()` | Аналогично |
| `IF()` | `IF()` | Аналогично |
| `SWITCH()` | `SWITCH()` | Аналогично |
| `CONCATENATE()` | `CONCAT()` | Короче название |
| `LEN()` | `LEN()` | Аналогично |
| `FIND()` | `SEARCH()` | Другое название |
| `SUBSTITUTE()` | `REPLACE()` | Другое название и поведение |
| `ARRAYJOIN()` | Нет прямого аналога | Используйте Lookup + формулу |
| `COUNTALL()` | `COUNTALL()` | Аналогично |
| `COUNTA()` | `COUNTA()` | Аналогично |
| `COUNT()` | `COUNT()` | Аналогично |

**Важно:**
- Все формулы нужно проверять после миграции!
- `DATEDIFF` в NocoDB называется `DATETIME_DIFF`
- Функции `COUNTLINKS` не существует в NocoDB -- используйте Links field

## Типичные проблемы и решения

### Проблема: Импорт зависает

**Решение:**
- Проверьте Personal Access Token (не устарел ли)
- Убедитесь, что scopes включают `data.records:read` и `schema.bases:read`
- Для больших баз (>100K записей) импорт может занимать 10-30 минут
- Если зависает -- попробуйте CSV-способ для проблемных таблиц

### Проблема: Вложения не отображаются

**Решение:**
- Проверьте настройку хранилища (S3/local)
- Убедитесь, что включили "Import Attachments" при импорте
- Для self-hosted: проверьте доступное место на диске

### Проблема: Связи не работают

**Решение:**
- Убедитесь, что все таблицы импортированы в один Base
- Связи работают только внутри одного Base
- Если импортировали таблицы по отдельности -- создайте Links вручную

### Проблема: Формулы показывают ошибку

**Решение:**
- Формулы Airtable и NocoDB имеют разный синтаксис
- Все формулы нужно пересоздать вручную
- Используйте таблицу соответствий выше
- Главное: `DATEDIF` -> `DATETIME_DIFF`

### Проблема: CSV-импорт путает типы полей

**Решение:**
- После импорта CSV пройдите по каждому полю и измените тип вручную
- Number, Currency, Date -- часто импортируются как SingleLineText
- SingleSelect -- создайте поле нужного типа и перенесите значения

## Рекомендуемый порядок миграции

1. **Подготовка:** создать NocoDB инстанс (Docker или Cloud)
2. **Тест:** импортировать одну таблицу, проверить результат
3. **Полный импорт:** импортировать весь base
4. **Формулы:** пересоздать все формулы
5. **Views:** создать нужные представления
6. **Автоматизации:** настроить Webhooks + n8n/Make.com
7. **Тестирование:** 1-2 дня параллельной работы в обеих системах
8. **Переключение:** перевести все процессы на NocoDB
9. **Архив:** сохранить Airtable base как backup на 30 дней
10. **Удаление:** удалить Airtable base (по желанию)
