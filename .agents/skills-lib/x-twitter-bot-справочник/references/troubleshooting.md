# Troubleshooting — X (Twitter) Bot API v2

## 1. 401 Unauthorized при публикации поста

**Симптом:** `{"title":"Unauthorized","status":401}`
**Причины:**
- Неверные ключи API или токены
- Access Token истёк (живёт 2 часа при OAuth 2.0 PKCE)
- App не имеет прав на запись (проверить App permissions в Developer Portal)
**Решение:**
- Проверить все 4 ключа (API Key, Secret, Access Token, Access Token Secret)
- Для OAuth 2.0: обновить access_token через refresh_token
- Developer Portal -> App -> Settings -> App permissions -> Read and Write

## 2. 403 Forbidden — You are not permitted to perform this action

**Симптом:** `{"detail":"You are not permitted to perform this action."}`
**Причины:**
- Free tier не позволяет данную операцию (чтение, DM, search)
- Недостаточные scopes в OAuth 2.0 PKCE
- Аккаунт заблокирован или ограничен
**Решение:**
- Проверить тариф: Free не даёт read/search/DM
- Проверить scopes при авторизации (tweet.write, dm.write и т.д.)
- Проверить статус аккаунта на x.com

## 3. 429 Too Many Requests

**Симптом:** `{"title":"Too Many Requests","status":429}`
**Причины:**
- Превышен rate limit по endpoint (15-минутное окно)
- Превышена месячная квота чтения
**Решение:**
- Прочитать заголовки `x-rate-limit-reset` и ждать до сброса
- Реализовать exponential backoff
- Уменьшить частоту запросов
- При превышении месячной квоты — только апгрейд тарифа

## 4. Filtered Stream не получает данные

**Симптом:** Соединение установлено, но посты не приходят.
**Причины:**
- Нет активных правил (rules)
- Правила слишком узкие (нет совпадений)
- Free tier — stream недоступен
**Решение:**
- Проверить правила: `GET /2/tweets/search/stream/rules`
- Расширить правила (убрать лишние операторы)
- Проверить тариф (минимум Basic)
- Тест: добавить широкое правило `lang:en has:media` для проверки работы

## 5. Stream обрывается каждые несколько минут

**Симптом:** `StreamDisconnected` или таймаут соединения.
**Причины:**
- Нестабильное сетевое соединение
- Сервер не обрабатывает heartbeat вовремя
- Несколько одновременных подключений к stream
**Решение:**
- Реализовать reconnect с exponential backoff (1s, 2s, 4s, ..., max 300s)
- Убедиться что только 1 соединение к stream (лимит: 1 на App)
- Использовать keep-alive и обработку heartbeat (пустые строки)

## 6. Media Upload возвращает ошибку

**Симптом:** 400 Bad Request при загрузке изображения/видео.
**Причины:**
- Файл слишком большой (>5MB для изображений, >512MB для видео)
- Неподдерживаемый формат
- Используется устаревший v1.1 endpoint после июня 2025
**Решение:**
- Проверить размер и формат файла (JPEG, PNG, GIF, WEBP, MP4)
- Использовать v2 endpoint: `POST /2/media/upload`
- Для видео >8MB использовать chunked upload (INIT -> APPEND -> FINALIZE)
- Аутентификация: требуется OAuth 2.0 PKCE со scope `media.write`

## 7. DM не отправляется

**Симптом:** 403 или 400 при `POST /2/dm_conversations/.../messages`
**Причины:**
- Free tier не поддерживает DM API
- Получатель заблокировал бота или закрыл DM
- Нет scope `dm.write`
- Лимит DM исчерпан
**Решение:**
- Проверить тариф (минимум Basic)
- Проверить scopes OAuth 2.0
- Бот может отправлять DM только тем, кто начал диалог первым или подписан

## 8. Дубликаты постов отклоняются

**Симптом:** `{"detail":"You are not allowed to create a Tweet with duplicate content."}`
**Причина:** X не позволяет публиковать идентичный текст.
**Решение:**
- Добавлять уникальный элемент: дату, время, рандомный хэштег
- Использовать шаблоны с переменными: `f"Desert Safari — {price} AED! {datetime.now().strftime('%d.%m')}"

## 9. OAuth 2.0 PKCE: redirect_uri mismatch

**Симптом:** `{"error":"invalid_request","error_description":"redirect_uri does not match"}`
**Причина:** URI в запросе не совпадает с URI в настройках App.
**Решение:**
- Developer Portal -> App -> Settings -> Authentication -> Callback URI
- URL должен быть **точно** идентичен (включая trailing slash)
- Для локальной разработки: `http://127.0.0.1:3000/callback`

## 10. Refresh Token перестал работать

**Симптом:** `{"error":"invalid_grant"}` при обновлении токена.
**Причины:**
- Refresh Token истёк (6 месяцев)
- Токен уже был использован (одноразовый — каждое обновление выдаёт новый)
- Пользователь отозвал доступ
**Решение:**
- Каждый раз при refresh сохранять **новый** refresh_token
- Если истёк — пройти авторизацию заново
- Хранить токены в надёжном хранилище (БД, encrypted file)

## 11. Поиск возвращает пустые результаты

**Симптом:** `search_recent_tweets` возвращает `None` или пустой `data`.
**Причины:**
- Запрос слишком узкий (нет совпадений за 7 дней)
- Free tier: search недоступен
- Неправильные операторы запроса
**Решение:**
- Упростить запрос, убрать лишние фильтры
- Проверить тариф (минимум Basic для recent search)
- Протестировать запрос в X search bar на сайте

## 12. tweepy.errors.BadRequest при create_tweet

**Симптом:** `400 Bad Request`
**Причины:**
- Пост длиннее 280 символов
- Невалидный media_id
- Некорректный reply_to_tweet_id
**Решение:**
- Проверить длину текста (280 символов max, URL считается как 23)
- Проверить что media_id получен из upload и ещё валиден
- Проверить что tweet_id для reply существует и не удалён

## 13. CRC-проверка webhook падает

**Симптом:** Webhook не регистрируется, CRC failed.
**Причина:** Неверная реализация HMAC SHA-256 или таймаут >3 секунды.
**Решение:**
- Использовать Consumer Secret (не API Key Secret)
- HMAC-SHA256: `hmac.new(consumer_secret.encode(), crc_token.encode(), hashlib.sha256)`
- Ответ: `{"response_token": "sha256=<base64_hash>"}`
- Сервер должен отвечать за <3 секунды

## 14. Бот забанен за спам

**Симптом:** Аккаунт заблокирован, API возвращает 403.
**Причины:**
- Массовые лайки/ретвиты без задержек
- Одинаковые ответы на разные посты
- Агрессивная рассылка DM
**Решение:**
- Добавить задержки между действиями (5-10 секунд)
- Разнообразить контент (шаблоны + рандомизация)
- Подать апелляцию через help.x.com
- Соблюдать X Automation Rules

## 15. Не работает тред — посты публикуются отдельно

**Симптом:** Посты не цепляются в тред, каждый отдельный.
**Причина:** Неверный `in_reply_to_tweet_id` или гонка запросов.
**Решение:**
- Каждый следующий пост в треде должен ссылаться на ID **предыдущего** (не первого)
- Дождаться ответа от API перед отправкой следующего (await/sync)
- Проверить что ID берётся из `response.data["id"]`, а не из input
