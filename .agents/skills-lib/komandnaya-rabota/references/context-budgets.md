# Бюджеты контекстных окон

> Источник: SKILL.md — секции "Защита контекста главного окна", "Калькулятор размера команды", "Приоритеты при нехватке ресурсов", "Золотые правила", "Антипаттерны"

## Формулы расчёта токенов

| Операция | Стоимость (токены) |
|----------|-------------------|
| Запуск одного тиммейта | ~2-3K |
| Одно сообщение от тиммейта | ~500-1K |
| Один TaskCreate / TaskUpdate | ~200 |
| Writer на крупном проекте (Битрикс24) | 198K (предел для одного агента) |

### Бюджет главного окна

**Лимит:** ~150K токенов

### Бюджет токенов за волну

**Формула:** кол-во агентов x 150K = бюджет волны

**Пример:** 5 агентов x 150K = 750K за одну волну

> Учитывай лимиты API — большие проекты с множеством агентов быстро расходуют токены.

### Максимум тиммейтов

- Базовый состав: **18**
- С fix-агентами: **до 21** (+2-3)
- Если больше 21 — разделять на сессии

### Формула размера команды

```
pre_research = 2 if complexity in [medium, high] else 0
researchers = ceil(sections / 2.5)
architect = 1 (всегда)
critic = 1 if verification in [basic, full] else 0
advocate = 1 if verification == full else 0
writer = 1 (всегда)
presentation = 4 if presentation == yes else 0
qa = 1 if verification in [basic, full] else 0
diagrams = 1 if complexity in [medium, high] else 0
templates = 1 if complexity in [medium, high] else 0
interactive = 1 if presentation == yes else 0

TOTAL = pre_research + researchers + architect + critic + advocate + writer +
        presentation + qa + diagrams + templates + interactive
BUFFER = ceil(TOTAL * 0.15)  # 15% запас на фиксы
```

## Правила защиты контекста главного окна

### Критическое правило

Главное окно = ДИСПЕТЧЕР. Оно ТОЛЬКО:
- Создаёт задачи (TaskCreate)
- Назначает задачи (TaskUpdate)
- Запускает агентов (Task tool)
- Принимает краткие отчёты (SendMessage)
- Останавливает агентов (shutdown_request)

### Ограничения действий в главном окне

| Действие | Почему нежелательно | Что делать вместо |
|----------|---------------------|-------------------|
| Систематически читать файлы >5KB | Заполняет контекст | Делегируй агенту. Одноразовая проверка до 10KB — допустима |
| Запускать WebSearch | Результаты огромные | Делегируй агенту |
| Писать файлы | Контент занимает место | Делегируй агенту |
| Длинные промпты | Каждый символ на счету | Ссылайся на файлы |

### Размеры файлов и влияние на контекст

| Размер файла | Правило |
|-------------|---------|
| <5KB | Можно читать в главном окне (но систематически — нежелательно) |
| 5-10KB | Одноразовая проверка допустима |
| >10KB | ТОЛЬКО через агента |
| >5 больших файлов | Нельзя давать одному субагенту — максимум 3-4 файла на агента |

## Правила делегирования для экономии контекста

### Проверка Quality Gate (экономя контекст)

НЕ читай файлы сам. Запусти Explore-агента:
> "Проверь что файлы [список путей] существуют и содержат данные. Для critic-report: покажи только секцию КРИТИЧЕСКИЕ."

### Handoff — ссылайся на файлы, не копируй контент

**Анти-паттерн:** "Прочитай все файлы проекта" — слишком широко, агент потеряется.

**Хорошо:** "Прочитай 3 конкретных файла: [путь1], [путь2], [путь3]" — точно.

### Диагностика сбоев (экономя контекст)

При сбое агента:
1. Проверь выходной файл: `ls` через Bash, НЕ читай содержимое
2. Делегируй Explore-агенту: "Проверь что файл [путь] существует и содержит данные"

## Пороги заполнения контекста и действия

| Порог контекста | Когда | Что делать |
|-----------------|-------|-----------|
| >60% после Волны 2 | Запусти technical-writer, сгенерируй файл продолжения, презентацию — в новую сессию |
| >60% после Волны 3 | Сгенерируй файл продолжения, всё остальное — в новую сессию |
| >70% | ПЕРЕД shutdown сохрани состояние в файл и создай новую сессию |
| Контекст заканчивается | 1) НЕМЕДЛЕННО shutdown всех idle тиммейтов. 2) Сгенерируй файл продолжения. 3) Сохрани TaskList статус в файл. 4) Закрой сессию. 5) Открой новую сессию с файлом продолжения |

## Файл продолжения — страховка контекста

### Когда генерировать

- После КАЖДОЙ завершённой волны (обязательно)
- Перед shutdown если контекст >70% заполнен
- При любом сбое агента

### Шаблон

Сохранять в: `{PROJECT_PATH}/ПРОДОЛЖЕНИЕ_ВОЛНА_{N}.md`

```
# Продолжение проекта: {TOPIC}

## Статус
- Команда: {team_name}
- Завершённые волны: 1, 2
- Текущая волна: 3
- Следующая волна: 4

## Завершённые файлы
- _research/structure-plan.md
- _research/research-*.md (7 шт)
- _research/critic-report.md
- _research/advocate-verification.md

## Незавершённые задачи
- Задача 10: technical-writer (IN PROGRESS)
- Задачи 11-18: PENDING

## Действия
1. TeamCreate -> team_name: "{team_name}"
2. Создай задачи 10-18 (или оставшиеся)
3. Запусти текущую волну

## Последний checkpoint
{PROJECT_PATH}/_qa/checkpoints/wave-{N}-checkpoint.md
```

## Checkpoint Snapshots — снимок состояния

После каждой волны — автоматический снимок.
Сохранять в: `{PROJECT_PATH}/_qa/checkpoints/wave-{N}-checkpoint.md`

### Использование

- При СБОЕ сессии: прочитай последний checkpoint — точно знаешь что пересоздать
- При ручном аудите: покажи checkpoint пользователю для подтверждения
- В файле продолжения: ссылка на checkpoint для контекста

## Retry и его влияние на контекст

> Каждый перезапуск тратит контекст главного окна (Золотое правило #11).

| Роль | Max повторов | Всего попыток |
|------|-------------|--------------|
| Исследователь | 2 | 3 |
| Critic | 1 | 2 |
| Advocate | 1 | 2 |
| Technical-writer | 1 | 2 |
| Presentation-* | 2 | 3 |
| QA/Diagrams/Templates | 1 | 2 |

### Если retry budget исчерпан

1. Сохрани что агент успел
2. Запиши проблему в `{PROJECT_PATH}/_qa/failures.md`
3. Продолжай с частичным результатом
4. Пометь `[INCOMPLETE - retry budget exhausted]`

## Антипаттерны расхода контекста

| Делать (плохо) | Вместо этого (хорошо) |
|----------------|----------------------|
| Читать файлы в главном окне | Делегировать агенту |
| Давать субагенту >5 больших файлов | Максимум 3-4 файла/раздела на агента |
| Длинные промпты | Ссылайся на файлы |
| Перезапускать агента без диагностики | Остановиться, выяснить причину, сменить подход |
| Держать idle агентов | Shutdown после Quality Gate |
| Ждать агента синхронно | run_in_background: true |
