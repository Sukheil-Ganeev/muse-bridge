# Решение проблем командной работы
> Актуально на: 2026-02-21

## Агент упал / не завершил задачу
**Симптом:** Задача не completed, файл неполный/отсутствует
**Решение:**
1. Проверь файл через Explore-агента
2. Если частичный → новый агент с "Продолжи"
3. Если отсутствует → перезапуск с тем же промптом
4. Обнови TaskUpdate

## Контекст главного окна заканчивается
**Симптом:** Автосжатие, потеря контекста
**Решение:**
1. Shutdown всех idle
2. Файл продолжения
3. Новая сессия

## Агент вернул некачественный результат
**Симптом:** Ошибки, неполные данные
**Решение:**
1. НЕ фикси сам
2. Fix-агент с конкретными проблемами
3. Retry budget: см. секцию ниже

## Конфликт ресурсов

### Проблема: два агента пишут в один файл
**Симптом:** Один агент перезаписал результат другого
**Решение:** Каждый агент пишет в СВОЙ файл. Объединение — задача writer/finalizer.

### Проблема: API rate limit
**Симптом:** Ошибка 429 Too Many Requests
**Решение:** Только 1 агент использует API за раз. Приоритет: advocate > critic > researcher.

## Quality Gate не проходит
**Симптом:** Файлы отсутствуют или критические ошибки
**Решение:**
1. Определи причину (какой агент)
2. Fix-агент
3. Повтори gate

## Resource Contention Protocol

Когда два+ агента нуждаются в одном ресурсе одновременно.

### Типы конфликтов

| Ресурс | Пример | Решение |
|--------|--------|---------|
| API с лимитами | Google Maps 15 вызовов | Очередь: critic > advocate > researcher |
| Один файл на запись | SKILL.md | Только 1 агент пишет, остальные читают |
| Один файл на чтение | experience/_index.md | Все могут читать параллельно — ОК |
| MCP сервер | Chrome DevTools | Один агент за раз, остальные ждут |

### Приоритеты доступа к API

ВЫСШИЙ: advocate (верификация, дорогие вызовы)
СРЕДНИЙ: critic (перепроверка)
НИЗШИЙ: researcher (основной сбор данных)

### Правила

1. Advocate имеет эксклюзивный доступ к API во время Волны 2
2. Researchers используют ТОЛЬКО WebSearch (не API) в Волне 1
3. Если агент получил ошибку rate limit → подождать 60 сек → retry
4. Два агента НИКОГДА не пишут в один файл — лидер распределяет файлы

## Retry Budget

Максимальное количество перезапусков агента при сбое:

| Роль | Max повторов | Всего попыток | Почему |
|------|-------------|--------------|--------|
| Исследователь | 2 | 3 | Данные можно собрать с 2й-3й попытки |
| Critic | 1 | 2 | Критичная задача, 2й сбой = эскалация |
| Advocate | 1 | 2 | API-вызовы, повтор дорог |
| Technical-writer | 1 | 2 | Объёмная задача, контекст ограничен |
| Presentation-* | 2 | 3 | HTML/CSS может потребовать итераций |
| QA/Diagrams/Templates | 1 | 2 | Некритичные задачи |

### Если retry budget исчерпан

1. Сохрани что агент успел (Read выходной файл)
2. Запиши проблему: {PROJECT_PATH}/_qa/failures.md
3. Продолжай с частичным результатом
4. Пометь [INCOMPLETE - retry budget exhausted] в итоговом файле
5. Включи в пост-мортем

## Тиммейт ушёл в idle без работы (Mailbox Miss)
**Симптом:** Тиммейт запустился, но файл не создан, задача не выполнена
**Причина:** Mailbox-доставка задачи "промахнулась" — агент стартовал пустым
**Решение:**
1. НЕ перезапускай тиммейта — проблема системная
2. Переключись на обычный субагент (Task без team_name)
3. Обычный субагент получает промпт напрямую — надёжнее

## Субагент упал с "Prompt is too long"
**Симптом:** Ошибка "Prompt is too long" в логах агента
**Причина:** Слишком много больших файлов в задаче
**Решение:**
1. Раздели задачу на 2 агента
2. Максимум 3-4 больших файла на агента
3. Для справочников >500KB — обязательно дробить

## Старые тиммейты шлют idle-уведомления
**Симптом:** После замены тиммейтов на субагентов, старые продолжают слать idle
**Причина:** shutdown_request не всегда срабатывает
**Решение:** Игнорируй idle от старых тиммейтов. Они перестанут при завершении сессии.

## Pre-flight Check (чек-лист перед запуском)
> Источник: SKILL.md

Перед запуском Волны 1 -- ОБЯЗАТЕЛЬНАЯ проверка.
НЕ запускай агентов пока все пункты не пройдены.

### Чеклист

- [ ] TeamCreate выполнен (team_name задано)
- [ ] Папки созданы:
      - {PROJECT_PATH}/_research/
      - {PROJECT_PATH}/_qa/
      - Presentation path (если нужна)
- [ ] ВСЕ задачи созданы через TaskCreate
- [ ] Зависимости настроены через addBlockedBy
- [ ] Пресет выбран (architect знает какие разделы)
- [ ] API доступен (если нужен Google Maps / другое)
- [ ] Существующие файлы скилла известны architect'у (пути в промпте)

### Как проверять (экономя контекст)

Запусти Bash: `ls {PROJECT_PATH}/_research/`
Проверь TaskList -- все задачи на месте?

### Если проверка не пройдена

Исправь проблему ПЕРЕД запуском. Не запускай "потом разберёмся".

### Типичные ошибки pre-flight

| Ошибка | Последствие | Как избежать |
|--------|-------------|--------------|
| Забыли создать папку _research/ | Агенты пишут в корень проекта | Всегда создавай структуру ДО запуска |
| TaskCreate без blockedBy | Волна 2 стартует до завершения Волны 1 | Проверь зависимости через TaskList |
| Architect не знает пути к файлам | Генерирует неверный plan | Включи пути в промпт architect |
| API не проверен | Агенты упадут на rate limit | Сделай тестовый запрос |

## Pre-Research Protocol (предварительное исследование)
> Источник: SKILL.md

Перед Волной 1 -- запусти 1-2 агента для сбора контекста.
Это даёт architect'у и team-lead'у ЛУЧШУЮ основу для планирования.

### Когда применять

- Тема новая / незнакомая (справочник по продукту, которым не пользовались)
- Есть существующие примеры в проектной папке (другие скиллы, справочники)
- Нужно понять масштаб задачи ДО распределения по агентам

### Протокол

1. **Агент анализа примеров** -- читает существующие справочники/скиллы,
   извлекает структуру, объём, паттерны (Explore-агент, 5-10 мин)
2. **Агент исследования темы** -- WebSearch по теме, сбор основных фактов,
   определение количества разделов (general-purpose агент, 5-10 мин)
3. Оба запускаются ПАРАЛЛЕЛЬНО (run_in_background: true)
4. Результаты сохраняются в {PROJECT_PATH}/_research/pre-research/
5. Architect получает эти файлы как INPUT для structure-plan.md

### Правила

- НЕ заменяет Волну 1 -- это ДОПОЛНЕНИЕ к ней
- Output pre-research агентов может не записаться в файл (API возвращает
  результат, но Write не вызван) -- проверяй через ls или Explore-агента
- Если pre-research не дал значимых результатов -- не задерживай проект,
  запускай Волну 1 без него
- Timeout для TaskOutput: 300 секунд (pre-research агенты легковесные)

### Пример (проект Битрикс24)

2 pre-research агента запущены ДО команды:
- Агент 1: анализ существующих справочников (структура, объём разделов)
- Агент 2: WebSearch по Битрикс24 (основные модули, разделы)
- Результат: architect получил точное понимание масштаба (14 разделов)

### Проблемы pre-research и решения

| Проблема | Симптом | Решение |
|----------|---------|---------|
| Файл не записан | ls показывает пустую папку | Перезапусти агента как обычный субагент (без team_name) |
| Pre-research затянулся | >15 мин, блокирует Волну 1 | Не жди, запускай Волну 1 без него |
| Результат поверхностный | Мало конкретики, общие фразы | Не критично, researcher'ы дополнят в Волне 1 |
| Output пуст (TaskOutput) | TaskOutput вернул пустую строку | Проверь файл напрямую через ls/Explore |

## Quality Gates (ворота качества)
> Источник: SKILL.md

Между волнами -- обязательная точка контроля. Лидер НЕ запускает
следующую волну пока не проверит gate.

### Протокол Gate

GATE = лидер делегирует агенту-ревьюеру краткую проверку:

| Gate | Между | Что проверить | Критерий прохождения |
|------|-------|--------------|---------------------|
| G1 | Волна 1 → 2 | Все файлы на месте, не пустые | 100% файлов существуют, >1KB каждый |
| G2 | Волна 2 → 3 | Критические ошибки в critic-report | 0 неразрешённых КРИТИЧЕСКИХ |
| G3 | Волна 3 → 4,5 | Основные файлы созданы | SKILL.md + все reference файлы |

### Если gate НЕ пройден

1. Определи что не так (какой агент не доставил)
2. Запусти fix-агента для устранения
3. Повтори gate
4. Только после прохождения -- следующая волна

### Как проверять gate (экономя контекст)

НЕ читай файлы сам. Запусти Explore-агента:
"Проверь что файлы [список путей] существуют и содержат данные.
Для critic-report: покажи только секцию КРИТИЧЕСКИЕ."

### Типичные провалы Quality Gate

| Gate | Частая причина | Исправление |
|------|---------------|-------------|
| G1 -- файл 0 KB | Агент стартовал но не получил задачу (mailbox miss) | Перезапуск как обычный субагент |
| G1 -- файл <1KB | Агент завершился преждевременно (контекст) | Раздели задачу на 2 агента поменьше |
| G2 -- неразрешённые критические | Advocate не успел верифицировать | Дай advocate больше времени (timeout 600 сек) |
| G2 -- слишком много ложных | Critic пере-осторожен (>30% false positive) | Нормально, advocate отфильтрует |
| G3 -- SKILL.md неполный | Writer получил слишком много данных (>200KB) | Раздели на 2 writer'а по секциям |

### Метрики quality gate из реальных проектов

| Проект | G1 с первой попытки | G2 с первой попытки | Ложные critic | QA оценка |
|--------|-------------------|-------------------|--------------|-----------|
| Битрикс24 | Да (7/7 файлов) | Да (13/27 подтв.) | 33% | 8.5/10 |

## Восстановление при сбоях (полный протокол)
> Источник: SKILL.md

### Агент упал / не завершил задачу (расширенный)

1. Проверь выходной файл: существует? полный?
   (делегируй Explore-агенту, НЕ читай сам)
2. Если файл есть но неполный:
   -- Новый агент с промптом: "Продолжи. Готовая часть: [путь]"
3. Если файла нет:
   -- Запусти задачу заново с тем же промптом
4. Обнови TaskUpdate: переназначь задачу новому агенту

### Output файлы TaskOutput иногда пусты

TaskOutput может вернуть пустой результат, хотя агент реально
завершил работу и создал целевой файл. Это НЕ значит что агент упал.

**Что делать:**
1. НЕ перезапускай агента сразу
2. Проверь целевой файл напрямую: запусти Explore-агента
   с промптом "Проверь что файл [путь] существует и содержит данные"
3. Если файл на месте и не пуст -- задача выполнена, продолжай
4. Если файла нет -- тогда перезапускай

**Почему это происходит:** Агент записал файл через Write tool,
но API вернул результат через другой канал. Не критично,
но нужно учитывать при автоматизации.

### Контекст главного окна заканчивается (расширенный)

1. НЕМЕДЛЕННО: shutdown всех idle тиммейтов
2. Сгенерируй файл продолжения (см. "Промпт продолжения" в SKILL.md)
3. Сохрани TaskList статус в файл
4. Закрой сессию
5. Открой новую сессию с файлом продолжения

### Протокол диагностики (ПЕРЕД перезапуском)

При сбое агента -- НЕ ПЕРЕЗАПУСКАЙ СРАЗУ. Выполни диагностику:

1. Проверь: файл создан? (ls через Bash, НЕ читай содержимое)
2. Если файл есть но пуст → агент стартовал, но не получил задачу (mailbox miss)
3. Если файла нет → агент не стартовал / упал на ранней стадии
4. Если "Prompt is too long" → слишком много файлов, раздели задачу

ПОСЛЕ диагностики -- СМЕНИ ПОДХОД:
- Mailbox miss → переключись на обычный субагент (без team_name)
- Prompt too long → раздели на 2 агента по 3-4 файла
- Rate limit → подожди 60 сек, дай другим агентам приоритет

НИКОГДА не повторяй одно и то же действие больше 1 раза без диагностики.
Retry budget: 1 попытка того же метода, затем ОБЯЗАТЕЛЬНО смена подхода.

### Агент вернул некачественный результат (расширенный)

1. НЕ фикси сам в главном окне
2. Запусти fix-агента: "Прочитай [файл]. Проблемы: [список]. Исправь."
3. Fix-агент сохраняет исправленную версию

### Дерево решений при сбое

```
Агент сбоил
├── Файл существует?
│   ├── Да, полный (>1KB) → Задача выполнена, продолжай
│   ├── Да, пустой (0 KB) → Mailbox miss → обычный субагент
│   └── Да, частичный → Новый агент с "Продолжи"
└── Нет
    ├── "Prompt is too long" → Раздели на 2 агента
    ├── Rate limit 429 → Подожди 60 сек, retry
    ├── Timeout → Увеличь timeout до 600 сек
    └── Неизвестная ошибка → Обычный субагент с тем же промптом
```

## Retry Budget (полная таблица)
> Источник: SKILL.md

Максимальное количество перезапусков агента при сбое:

| Роль | Max повторов | Всего попыток | Почему |
|------|-------------|--------------|--------|
| Исследователь | 2 | 3 | Данные можно собрать с 2й-3й попытки |
| Critic | 1 | 2 | Критичная задача, 2й сбой = эскалация |
| Advocate | 1 | 2 | API-вызовы, повтор дорог |
| Technical-writer | 1 | 2 | Объёмная задача, контекст ограничен |
| Presentation-* | 2 | 3 | HTML/CSS может потребовать итераций |
| QA/Diagrams/Templates | 1 | 2 | Некритичные задачи |

### Если retry budget исчерпан

1. Сохрани что агент успел (Read выходной файл)
2. Запиши проблему: {PROJECT_PATH}/_qa/failures.md
3. Продолжай с частичным результатом
4. Пометь [INCOMPLETE - retry budget exhausted] в итоговом файле
5. Включи в пост-мортем

### Эскалация при исчерпании бюджета

| Ситуация | Действие |
|----------|----------|
| Researcher (3/3 попытки) | Пометь раздел [INCOMPLETE], продолжай без него |
| Critic (2/2 попытки) | Эскалация: лидер запускает облегчённую проверку сам |
| Writer (2/2 попытки) | Раздели SKILL.md на секции, 2 writer'а параллельно |
| Presentation (3/3 попытки) | Откажись от презентации, сохрани текстовые артефакты |

### Стоимость retry в контексте

| Действие | Цена (токены главного окна) | Допустимость |
|----------|-----------------------------|-------------|
| Перезапуск субагента | ~500-1000 | Допустимо |
| Перезапуск тиммейта | ~2000-3000 | Дорого, лучше субагент |
| Диагностика через Explore | ~300-500 | Дёшево |
| Чтение файла лидером | ~2000-5000+ | Избегать |

## Checkpoint Snapshots (снимки состояния)
> Источник: SKILL.md

После каждой волны -- автоматический снимок состояния.
Сохранять в: {PROJECT_PATH}/_qa/checkpoints/

### Шаблон checkpoint

Файл: `{PROJECT_PATH}/_qa/checkpoints/wave-{N}-checkpoint.md`

```
# Checkpoint: Волна {N}
Дата: {DATE}
Статус: ЗАВЕРШЕНА

## Файлы
| Путь | Размер | Статус |
|------|--------|--------|
| _research/research-1.md | 45 KB | готов |
| _research/research-2.md | 38 KB | готов |
| _research/research-3.md | 0 KB | пустой |

## Задачи (из TaskList)
| ID | Задача | Статус | Агент |
|----|--------|--------|-------|
| 1 | architect | completed | teammate-1 |
| 2 | researcher-1 | completed | teammate-2 |
| 3 | researcher-2 | completed | teammate-3 |
| 4 | researcher-3 | failed | teammate-4 |

## Проблемы
- researcher-3: упал на середине, файл пустой -> нужен retry
```

### Использование checkpoint

- При СБОЕ сессии: прочитай последний checkpoint -- точно знаешь что пересоздать
- При ручном аудите: покажи checkpoint пользователю для подтверждения
- В файле продолжения: ссылка на checkpoint для контекста

### Когда создавать checkpoint

| Событие | Обязательность | Кто создаёт |
|---------|----------------|-------------|
| Завершение каждой волны | ОБЯЗАТЕЛЬНО | Лидер (или делегирует агенту) |
| Контекст > 70% заполнен | ОБЯЗАТЕЛЬНО | Лидер (немедленно) |
| Сбой агента | РЕКОМЕНДУЕТСЯ | Лидер |
| Перед shutdown сессии | ОБЯЗАТЕЛЬНО | Лидер |

### Проблемы с checkpoint и решения

| Проблема | Решение |
|----------|---------|
| Checkpoint устарел (агенты работали после) | Создай новый checkpoint перед следующим gate |
| Checkpoint содержит ошибки в размерах | Проверяй через `ls -la`, не вручную |
| Нет checkpoint для предыдущей волны | Создай ретроспективно через Explore-агента |

## Приоритеты при нехватке ресурсов
> Источник: SKILL.md

Если кончается контекст, время или API-лимиты -- следуй приоритетам.

### Уровни приоритета

**P0 -- НЕЛЬЗЯ ПРОПУСТИТЬ:**
- Волна 1 (исследование) -- без данных нет проекта
- Волна 2 (верификация) -- без проверки данные ненадёжны
- Волна 3 (написание) -- это основной результат

**P1 -- ПРОПУСТИТЬ = ПОТЕРЯ КАЧЕСТВА:**
- QA-тестер -- ошибки останутся
- Diagram-designer -- нет визуализации
- Quality Gates -- возможны сбои

**P2 -- МОЖНО СДЕЛАТЬ ПОЗЖЕ (в другой сессии):**
- Презентация (Волна 4) -- можно добавить потом
- Template-creator -- шаблоны не критичны
- Interactive-developer -- интерактивность = бонус

### Минимальная жизнеспособная команда (MVP)

Если ресурсов на полную команду нет:

| Этап | Агентов | Кто |
|------|---------|-----|
| Исследование | 3-4 | researchers (объединить разделы) |
| Верификация | 1 | critic-advocate (совмещённая роль) |
| Написание | 1 | technical-writer |
| **ИТОГО MVP** | **5-6** | **Без презентации и QA** |

MVP даёт: скилл + проектная папка. Презентацию и QA -- в следующей сессии.

### Решение по ходу

**Если после Волны 2 контекст > 60%:**
- Запусти technical-writer
- Сгенерируй файл продолжения
- Презентацию и улучшения -- в новой сессии

**Если после Волны 3 контекст > 60%:**
- Сгенерируй файл продолжения
- Всё остальное -- в новой сессии

### Таблица решений при дефиците

| Ресурс | Дефицит | Что сокращать первым | Что сокращать последним |
|--------|---------|---------------------|------------------------|
| Контекст | <30% осталось | Презентацию, QA | Исследование, Writer |
| Время | Менее 1 часа | Интерактивность, шаблоны | Верификацию, основные файлы |
| API лимиты | <10 вызовов | Researcher'ов (WebSearch вместо API) | Advocate (ему нужны точные данные) |
| Токены | Близко к лимиту | Параллельность (уменьши до 3 агентов) | Writer (основной результат) |

## Definition of Done (DoD) -- критерии завершённости
> Источник: SKILL.md

Проект считается ЗАВЕРШЁННЫМ когда ВСЕ пункты выполнены:

### Основные артефакты
- [ ] SKILL.md создан и ~5000 слов
- [ ] Все reference файлы на месте и не пустые (>1KB каждый)
- [ ] README.md создан
- [ ] experience/_index.md заполнен реальными уроками

### Проектная папка (если создаётся)
- [ ] Все разделы на месте (по structure-plan.md)
- [ ] _research/ содержит все файлы исследований
- [ ] _qa/qa-report.md: 0 критических, 0 средних нерешённых

### Презентация (если создаётся)
- [ ] presentation.html существует и < 250KB
- [ ] Overlay fade работает (не CSS transition)
- [ ] Dark mode: контраст >= 4.5:1
- [ ] Hotkeys: ← → D T H F работают
- [ ] Кастомный scrollbar 6px

### Завершение
- [ ] Метрики проекта записаны ({PROJECT_PATH}/МЕТРИКИ_ПРОЕКТА.md)
- [ ] Файл продолжения НЕ нужен (всё завершено)
- [ ] Все тиммейты shutdown
- [ ] TeamDelete выполнен
- [ ] Лидер подтвердил: "Проект завершён"

### Опционально (если было полезно)
- [ ] Новые уроки записаны в experience/
- [ ] Agent profiling данные сохранены

### Типичные пропуски при DoD

| Пропуск | Последствие | Как избежать |
|---------|-------------|--------------|
| Забыли shutdown агентов | Ресурсы заняты, idle-уведомления | Всегда shutdown после последнего gate |
| Нет файла метрик | Не извлечён опыт для следующих проектов | Делегируй агенту генерацию метрик |
| experience/_index.md пуст | Следующий проект повторит те же ошибки | Запиши минимум 3 урока из проекта |
| TeamDelete не выполнен | Команда висит в системе | Последнее действие лидера |
| Файлы < 1KB | Reference файл создан но не наполнен | Проверь через gate G3 |

## Быстрая диагностика (сводная таблица)

| Симптом | Вероятная причина | Первое действие |
|---------|-------------------|-----------------|
| Файл 0 байт | Mailbox miss | Субагент без team_name |
| Файл < 1KB | Агент упал рано | Retry с упрощённым промптом |
| "Prompt is too long" | Слишком много входных файлов | Раздели на 2 агента |
| Ошибка 429 | API rate limit | Подожди 60 сек, дай приоритет advocate |
| TaskOutput пуст | Баг API (не критично) | Проверь файл через ls/Explore |
| Тиммейт idle 5+ мин | Задача не доставлена | Shutdown + субагент |
| Контекст > 70% | Слишком много в главном окне | Срочный checkpoint + shutdown idle |
| Gate G1 провал | Не все файлы готовы | Fix-агент на отсутствующие |
| Gate G2 провал | Critic нашёл критические | Advocate не верифицировал → дать время |
| Writer timeout | Слишком большой объём (>200KB) | 2 writer'а параллельно |
| Презентация с артефактами | Нет скилла pdf-презентации | Загрузи скилл, перезапусти агента |
| Конфликт имён между агентами | Нет интерфейс-контракта | Определи API заранее, передай всем |
