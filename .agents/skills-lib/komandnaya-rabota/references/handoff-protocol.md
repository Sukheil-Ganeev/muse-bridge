# Протокол Handoff между волнами

> Источник: SKILL.md — протоколы передачи между волнами

---

## Что такое Handoff

Handoff — стандарт передачи контекста между волнами командной работы. Каждый промпт следующей волны ДОЛЖЕН содержать точные пути к файлам, созданным предыдущей волной. Без корректного handoff агенты следующей волны не получат нужные данные и произведут мусор.

---

## Шаблон Handoff-сообщения

```
ВОЛНА {N} -> ВОЛНА {N+1}:
  Передать:
    paths: [список путей к файлам]
    format: "Прочитай файлы: {paths}"
    critical: "ИСПОЛЬЗУЙ ИСПРАВЛЕННЫЕ данные из advocate, НЕ исходные"
```

### Обязательные элементы шаблона

| Элемент | Описание | Пример |
|---------|----------|--------|
| paths | Точные пути к файлам предыдущей волны | `_research/research-1.md`, `_research/critic-report.md` |
| format | Инструкция что делать с файлами | "Прочитай файлы: [путь1], [путь2]" |
| critical | Критическое предупреждение (если есть) | "Используй ИСПРАВЛЕННЫЕ данные, НЕ исходные!" |

---

## Конкретные Handoff'ы по волнам

| Откуда | Куда | Что передать | Критическое замечание |
|--------|------|-------------|----------------------|
| Волна 1 | Волна 2 (critic) | Пути к 7 файлам `_research/` | "Ищи ПРОТИВОРЕЧИЯ между файлами" |
| Волна 2 (critic) | Волна 2 (advocate) | `critic-report.md` | "Верифицируй ТОЛЬКО критические и средние" |
| Волна 2 | Волна 3 | ВСЕ 9 файлов + исправления | "Используй ИСПРАВЛЕННЫЕ данные, НЕ исходные!" |
| Волна 3 | Волна 4 | `SKILL.md` + проектная папка | "Создай презентацию ПО этим файлам" |
| Волна 3 | Волна 5 (qa) | Все файлы скилла | "Проверь ВСЁ" |
| Волна 3 | Волна 5 (diagrams) | `SKILL.md` + `references/` | "Создай диаграммы ПО этим данным" |
| Волна 4 (html) | Волна 5 (interactive) | `presentation.html` | "Добавь интерактивность В этот файл" |

## Правила завершения волны перед началом следующей

### Quality Gate — обязательная точка контроля

Лидер НЕ запускает следующую волну пока не проверит gate. Gate = лидер делегирует агенту-ревьюеру краткую проверку.

| Gate | Между | Что проверить | Критерий прохождения |
|------|-------|--------------|---------------------|
| G1 | Волна 1 -> 2 | Все файлы на месте, не пустые | 100% файлов существуют, >1KB каждый |
| G2 | Волна 2 -> 3 | Критические ошибки в critic-report | 0 неразрешённых КРИТИЧЕСКИХ |
| G3 | Волна 3 -> 4,5 | Основные файлы созданы | SKILL.md + все reference файлы |

### Если gate НЕ пройден

1. Определи что не так (какой агент не доставил)
2. Запусти fix-агента для устранения
3. Повтори gate
4. Только после прохождения — следующая волна

### Как проверять gate (экономя контекст)

НЕ читай файлы сам. Запусти Explore-агента:
```
"Проверь что файлы [список путей] существуют и содержат данные.
Для critic-report: покажи только секцию КРИТИЧЕСКИЕ."
```

### Shutdown после gate, НЕ сразу после завершения

Между завершением волны и gate агенты могут понадобиться для уточнений. Поэтому shutdown именно после gate, а не сразу после завершения задачи.

## Checkpoint Snapshots (снимок состояния перед handoff)

После каждой волны — автоматический снимок состояния. Сохранять в: `{PROJECT_PATH}/_qa/checkpoints/`

### Шаблон checkpoint

Файл: `{PROJECT_PATH}/_qa/checkpoints/wave-{N}-checkpoint.md`

```
# Checkpoint: Волна {N}
Дата: {DATE}
Статус: ЗАВЕРШЕНА

## Файлы
| Путь | Размер | Статус |
|------|--------|--------|
| _research/research-1.md | 45 KB | готов |
| _research/research-2.md | 38 KB | готов |
| _research/research-3.md | 0 KB | пустой |

## Задачи (из TaskList)
| ID | Задача | Статус | Агент |
|----|--------|--------|-------|
| 1 | architect | completed | teammate-1 |
| 2 | researcher-1 | completed | teammate-2 |
| 3 | researcher-2 | completed | teammate-3 |
| 4 | researcher-3 | failed | teammate-4 |

## Проблемы
- researcher-3: упал на середине, файл пустой -> нужен retry
```

### Использование checkpoint

- **При СБОЕ сессии:** прочитай последний checkpoint — точно знаешь что пересоздать
- **При ручном аудите:** покажи checkpoint пользователю для подтверждения
- **В файле продолжения:** ссылка на checkpoint для контекста

## Промпт продолжения (страховка handoff между сессиями)

После КАЖДОЙ завершённой волны лидер генерирует файл продолжения. Это страховка от потери контекста при смене сессии.

### Шаблон

Сохранять в: `{PROJECT_PATH}/ПРОДОЛЖЕНИЕ_ВОЛНА_{N}.md`

```
# Продолжение проекта: {TOPIC}

## Статус
- Команда: {team_name}
- Завершённые волны: 1, 2
- Текущая волна: 3
- Следующая волна: 4

## Завершённые файлы
- _research/structure-plan.md
- _research/research-*.md (7 шт)
- _research/critic-report.md
- _research/advocate-verification.md

## Незавершённые задачи
- Задача 10: technical-writer (IN PROGRESS)
- Задачи 11-18: PENDING

## Действия
1. TeamCreate -> team_name: "{team_name}"
2. Создай задачи 10-18 (или оставшиеся)
3. Запусти текущую волну

## Последний checkpoint
{PROJECT_PATH}/_qa/checkpoints/wave-{N}-checkpoint.md
-> Прочитай его для полного списка готовых файлов
```

### Когда генерировать

- После КАЖДОЙ завершённой волны (обязательно)
- Перед shutdown если контекст > 70% заполнен
- При любом сбое агента

## Анти-паттерны Handoff

### Критический анти-паттерн: нечёткие ссылки

| ПЛОХО | ХОРОШО | Почему |
|-------|--------|--------|
| "Прочитай все файлы проекта" | "Прочитай 3 конкретных файла: [путь1], [путь2], [путь3]" | Слишком широко — агент потеряется, потратит контекст на ненужные файлы |

### Остальные анти-паттерны передачи

| Анти-паттерн | Правильный подход |
|--------------|-------------------|
| Запускать следующую волну без Quality Gate | ВСЕГДА проверять gate между волнами |
| Передавать исходные данные вместо исправленных | После critic+advocate — ТОЛЬКО исправленные данные |
| Не указывать критическое замечание в handoff | Каждый handoff содержит поле `critical` с предупреждением |
| Читать файлы в главном окне для проверки gate | Делегировать Explore-агенту |
| Держать idle агентов после прохождения gate | Shutdown после gate |
| Пропускать checkpoint snapshot | Автоматический checkpoint после каждой волны |
| Не генерировать файл продолжения | Генерировать после КАЖДОЙ волны как страховку |
| Давать агенту >5 больших файлов в handoff | Максимум 3-4 файла/раздела на агента |
| Не указывать пути к файлам в промпте следующей волны | Каждый промпт ДОЛЖЕН содержать точные пути |

## Примеры хороших и плохих Handoff

### Пример 1: Волна 1 -> Волна 2 (critic)

**ПЛОХО:**
```
"Проверь результаты исследования"
```
Проблемы: нет путей, нет инструкции что именно проверять, агент потратит контекст на поиск файлов.

**ХОРОШО:**
```
"Прочитай 7 файлов исследования:
- _research/research-metro.md
- _research/research-bus.md
- _research/research-tram.md
- _research/research-taxi.md
- _research/research-ferry.md
- _research/research-parking.md
- _research/research-cycling.md

Ищи ПРОТИВОРЕЧИЯ между файлами. Для каждой ошибки укажи:
серьёзность (КРИТИЧЕСКАЯ / СРЕДНЯЯ / НИЗКАЯ), файл, строку, описание.
Сохрани отчёт в: _research/critic-report.md"
```

### Пример 2: Волна 2 -> Волна 3 (technical-writer)

**ПЛОХО:**
```
"Напиши SKILL.md по данным из _research/"
```
Проблемы: не указаны конкретные файлы, не сказано использовать исправленные данные.

**ХОРОШО:**
```
"Создай SKILL.md используя ВСЕ 9 файлов:
- _research/structure-plan.md (структура)
- _research/research-1.md ... research-7.md (данные)
- _research/advocate-verification.md (ИСПРАВЛЕНИЯ)

КРИТИЧНО: Используй ИСПРАВЛЕННЫЕ данные из advocate-verification.md,
НЕ исходные данные из research-*.md при расхождении!

Сохрани в: SKILL.md (корень проекта)"
```

### Пример 3: Волна 3 -> Волна 5 (qa-tester)

**ПЛОХО:**
```
"Проверь скилл"
```

**ХОРОШО:**
```
"Проверь ВСЕ файлы скилла:
- SKILL.md
- README.md
- references/faq.md
- references/cheatsheet.md
- references/troubleshooting.md

Для каждого файла проверь:
1. Файл существует и >1KB
2. Нет пустых секций
3. Нет [TODO] или [ЗАПОЛНИТЬ]
4. Ссылки между файлами валидны

Сохрани отчёт в: _qa/qa-report.md"
```

### Пример 4: Handoff между сессиями (потеря контекста)

**ПЛОХО:**
Сессия оборвалась, новая сессия без контекста — работа потеряна.

**ХОРОШО:**
```
# Читай файл продолжения:
{PROJECT_PATH}/ПРОДОЛЖЕНИЕ_ВОЛНА_2.md

# Читай последний checkpoint:
{PROJECT_PATH}/_qa/checkpoints/wave-2-checkpoint.md

# Далее: запускай Волну 3 по инструкциям из файла продолжения
```

## Flowchart: последовательность Handoff

```
Волна 1 (Исследование)
    |
    v
[Gate G1: файлы на месте? >1KB?]
    |
    |-- НЕТ -> fix-агент -> повтор G1
    |
    v [ДА]
Checkpoint: wave-1-checkpoint.md
Файл продолжения: ПРОДОЛЖЕНИЕ_ВОЛНА_1.md
    |
    v
HANDOFF -> Волна 2 (Верификация)
  paths: 7 файлов _research/
  critical: "Ищи ПРОТИВОРЕЧИЯ"
    |
    v
[Gate G2: 0 критических неразрешённых?]
    |
    |-- НЕТ -> fix-агент -> повтор G2
    |
    v [ДА]
Checkpoint: wave-2-checkpoint.md
Файл продолжения: ПРОДОЛЖЕНИЕ_ВОЛНА_2.md
    |
    v
HANDOFF -> Волна 3 (Создание)
  paths: ВСЕ 9 файлов + исправления
  critical: "ИСПОЛЬЗУЙ ИСПРАВЛЕННЫЕ, НЕ исходные!"
    |
    v
[Gate G3: SKILL.md + references?]
    |
    |-- НЕТ -> fix-агент -> повтор G3
    |
    v [ДА]
Checkpoint: wave-3-checkpoint.md
Файл продолжения: ПРОДОЛЖЕНИЕ_ВОЛНА_3.md
    |
    v
HANDOFF -> Волна 4 (Презентация) + Волна 5 (Улучшения)
  [параллельно, обе зависят от Волны 3]
```

## Чеклист Handoff (копируй перед каждой передачей)

```
- [ ] Quality Gate предыдущей волны ПРОЙДЕН
- [ ] Checkpoint snapshot сохранён в _qa/checkpoints/
- [ ] Файл продолжения сгенерирован
- [ ] Промпт следующей волны содержит ТОЧНЫЕ ПУТИ к файлам
- [ ] Критическое замечание (critical) указано если есть
- [ ] Указано что использовать: исходные или ИСПРАВЛЕННЫЕ данные
- [ ] Количество файлов на агента <= 4-5 (если больше — разделить)
- [ ] Idle агенты предыдущей волны shutdown ПОСЛЕ gate
```
