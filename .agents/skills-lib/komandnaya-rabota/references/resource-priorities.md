| Ресурс | Пример | Решение |
|--------|--------|---------|

## Приоритеты доступа к API

| Приоритет | Роль | Обоснование |
|-----------|------|-------------|
| ВЫСШИЙ | advocate | Верификация, дорогие вызовы |
| СРЕДНИЙ | critic | Перепроверка данных |
| НИЗШИЙ | researcher | Основной сбор данных |

### Правила доступа к API

1. **Advocate** имеет эксклюзивный доступ к API во время Волны 2
2. **Researchers** используют ТОЛЬКО WebSearch (не API) в Волне 1
3. Если агент получил ошибку rate limit — подождать **60 сек** — retry
4. Два агента **НИКОГДА** не пишут в один файл — лидер распределяет файлы

## Конфликты при одновременной записи файлов

### Правило

Два агента НИКОГДА не пишут в один файл. Лидер распределяет файлы заранее.

### Что можно параллельно

| Операция | Параллельно? |
|----------|-------------|
| Чтение одного файла несколькими агентами | Да — ОК |
| Запись разных файлов разными агентами | Да — ОК |
| Запись одного файла двумя агентами | НЕТ — лидер назначает одного писателя |
| MCP сервер (Chrome DevTools) | НЕТ — один агент за раз |

## Блокировка ресурсов (blockedBy)

### Волновая система блокировок

| Волна | Зависит от | Блокирующий ресурс |
|-------|-----------|-------------------|
| Волна 2 (верификация) | Волна 1 (исследование) | Файлы _research/*.md |
| Волна 3 (написание) | Волна 2 (верификация) | critic-report.md + advocate-verification.md |
| Волна 4 (презентация) | Волна 3 (написание) | SKILL.md + references/ |
| Волна 5 (улучшения) | Волна 3 (написание) | SKILL.md + references/ |

### Волны 4 и 5 — параллельный старт

Поздние волны могут стартовать ПАРАЛЛЕЛЬНО если зависят от одной и той же предыдущей волны. Волна 4 и Волна 5 обе зависят от Волны 3 — могут идти одновременно.

### Shutdown — когда освобождать ресурсы

- Shutdown агентов **после прохождения Quality Gate** — не сразу после завершения
- Между завершением волны и gate агенты могут понадобиться для уточнений
- НЕ ДЕРЖИ завершённых агентов — они забивают ресурсы

## Приоритеты при нехватке ресурсов

### Уровни приоритета

| Уровень | Что входит | Можно пропустить? |
|---------|-----------|-------------------|
| **P0 — НЕЛЬЗЯ ПРОПУСТИТЬ** | Волна 1 (исследование), Волна 2 (верификация), Волна 3 (написание) | Нет — без данных нет проекта, без проверки данные ненадёжны, написание — основной результат |
| **P1 — ПОТЕРЯ КАЧЕСТВА** | QA-тестер, Diagram-designer, Quality Gates | Пропуск = ошибки останутся, нет визуализации, возможны сбои |
| **P2 — МОЖНО ПОЗЖЕ** | Презентация (Волна 4), Template-creator, Interactive-developer | Можно добавить в другой сессии |

### Минимальная жизнеспособная команда (MVP)

Если ресурсов на полную команду нет:

| Этап | Агентов | Кто |
|------|---------|-----|
| Исследование | 3-4 | researchers (объединить разделы) |
| Верификация | 1 | critic-advocate (совмещённая роль) |
| Написание | 1 | technical-writer |
| **ИТОГО MVP** | **5-6** | **Без презентации и QA** |

MVP даёт: скилл + проектная папка. Презентацию и QA — в следующей сессии.

## Стратегии при нехватке ресурсов

### Решение по ходу (контекст)

| Ситуация | Действие |
|----------|----------|
| После Волны 2 контекст >60% | Запусти technical-writer, сгенерируй файл продолжения, презентацию — в новую сессию |
| После Волны 3 контекст >60% | Сгенерируй файл продолжения, всё остальное — в новую сессию |
| Контекст заканчивается | НЕМЕДЛЕННО shutdown всех idle, сохрани состояние, новая сессия |

### Решение по ходу (API rate limits)

| Ситуация | Действие |
|----------|----------|
| Rate limit error | Подождать 60 сек, retry |
| Повторный rate limit | Дать приоритет advocate/critic, researcher ждёт |
| API недоступен | Переключиться на WebSearch как fallback |

### Решение по ходу (сбой агента)

| Ситуация | Действие |
|----------|----------|
| "Prompt is too long" | Слишком много файлов — раздели задачу на 2 агента по 3-4 файла |
| Mailbox miss (тиммейт) | Переключись на обычный субагент (без team_name) |
| Файл пустой после агента | Проверь через Explore-агента, не перезапускай сразу |
| Retry budget исчерпан | Сохрани частичный результат, пометь [INCOMPLETE], продолжай |

## Протокол диагностики (ПЕРЕД перезапуском)

При сбое агента — НЕ ПЕРЕЗАПУСКАЙ СРАЗУ. Выполни диагностику:

1. Проверь: файл создан? (`ls` через Bash, НЕ читай содержимое)
2. Если файл есть но пуст — агент стартовал, но не получил задачу (mailbox miss)
3. Если файла нет — агент не стартовал / упал на ранней стадии
4. Если "Prompt is too long" — слишком много файлов, раздели задачу

**ПОСЛЕ диагностики — СМЕНИ ПОДХОД:**

| Диагноз | Новый подход |
|---------|-------------|
| Mailbox miss | Переключись на обычный субагент (без team_name) |
| Prompt too long | Раздели на 2 агента по 3-4 файла |
| Rate limit | Подожди 60 сек, дай другим агентам приоритет |

**НИКОГДА** не повторяй одно и то же действие больше 1 раза без диагностики.

**Retry budget:** 1 попытка того же метода, затем ОБЯЗАТЕЛЬНО смена подхода.

## Слияние ролей — экономия ресурсов

### Совместимые роли (МОЖНО объединять)

| Роль A | + Роль B | = Объединённая | Когда | Статус |
|--------|----------|----------------|-------|--------|
| critic | advocate | verifier | <10 разделов | проверено |
| qa-tester | template-creator | qa-templates | Средний проект | проверено |
| diagram-designer | template-creator | assets-creator | Средний проект | проверено |
| presentation-architect | design-system | presentation-planner | Быстрая презентация | проверено |
| design-system | html-css-developer | presentation-builder | Стили + вёрстка одному | подтверждено Битрикс24 |
| presentation-finalizer | interactive-developer | presentation-polisher | Полировка + интерактивность | подтверждено Битрикс24 |

### Несовместимые роли (НЕЛЬЗЯ объединять)

| Роль A | + Роль B | Почему нельзя |
|--------|----------|---------------|
| researcher | critic (СВОЙ файл) | Нельзя проверять СВОЙ файл |
| architect | researcher | Architect должен видеть общую картину |
| html-css-developer | interactive | Слишком большой контекст для одного |
| technical-writer | researcher | Writer должен работать с ПРОВЕРЕННЫМИ данными |

## Retry Budget по ролям

| Роль | Max повторов | Всего попыток | Почему |
|------|-------------|--------------|--------|
| Исследователь | 2 | 3 | Данные можно собрать с 2й-3й попытки |
| Critic | 1 | 2 | Критичная задача, 2й сбой = эскалация |
| Advocate | 1 | 2 | API-вызовы, повтор дорог |
| Technical-writer | 1 | 2 | Объёмная задача, контекст ограничен |
| Presentation-* | 2 | 3 | HTML/CSS может потребовать итераций |
| QA/Diagrams/Templates | 1 | 2 | Некритичные задачи |

### Если retry budget исчерпан

1. Сохрани что агент успел (Read выходной файл)
2. Запиши проблему: `{PROJECT_PATH}/_qa/failures.md`
3. Продолжай с частичным результатом
4. Пометь `[INCOMPLETE - retry budget exhausted]` в итоговом файле
5. Включи в пост-мортем

## Антипаттерны управления ресурсами

| Делать (плохо) | Вместо этого (хорошо) |
|----------------|----------------------|
| Запускать все 18 агентов разом | Волнами с зависимостями |
| Держать idle агентов | Shutdown после Quality Gate |
| Один агент на всё | Разделять по специализации |
| Перезапускать без диагностики | Остановиться, выяснить причину, сменить подход |
| Параллельные агенты на связанных модулях без контракта | Определить интерфейсы ЗАРАНЕЕ и передать всем |
| QA только находит баги | QA-агент = фиксер (экономит round-trip) |
| Давать субагенту >5 больших файлов | Максимум 3-4 файла на агента |
