# Паттерн: Data Processing Pipeline

## Когда применять
- Исходные данные уже есть локально (не нужен WebSearch)
- Нужно обработать большой объём (>100 файлов, >1 МБ)
- Результат = структурированные файлы (справочники, индексы)

## Структура волн

| Волна | Агентов | Роль | Задача |
|-------|---------|------|--------|
| 0 (pre) | 1 Explore | data-explorer | Изучить формат данных |
| 1 | 1 general-purpose | script-writer | Написать Python-скрипт обработки |
| 2 | 1 general-purpose | script-runner | Запустить, починить ошибки |
| 3 | 2-3 general-purpose | reviewers | Параллельная полировка по областям |
| 4 | 1 general-purpose | verifier | Финальная верификация по чеклисту |

## Итого: 5-7 агентов

## Ключевые правила
1. Python скрипт должен включать auto-split для файлов >27 КБ
2. Промпт script-writer должен содержать ВСЕ форматы данных (из Волны 0)
3. Волна 3 делится по ОБЛАСТЯМ (videos/ocr/transcripts), не по операциям
4. Верификатор получает КОНКРЕТНЫЙ чеклист с критериями PASS/FAIL
5. Не нужны critic/advocate -- данные локальные, верифицированы при создании

## Отличия от Research Pipeline
- Нет WebSearch -- нет ошибок из интернета -- нет critic/advocate
- Python скрипт вместо исследователей -- детерминированный результат
- Меньше агентов (6 vs 18) -- экономия контекста и API
- Быстрее (~30 мин vs ~2 часа)

## Пример: PuzzleBot Deep Reference
- Вход: 112 видео (OCR, транскрипции, knowledge extraction)
- Выход: 94 файла, 1.7 МБ структурированного справочника
- Время: ~30 минут
- Результат: 7/7 критериев PASS
