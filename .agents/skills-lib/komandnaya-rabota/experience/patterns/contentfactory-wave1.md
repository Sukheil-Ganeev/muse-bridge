# ContentFactory Волна 1 — Паттерны

## Проект: Telegram-бот (aiogram 3) с AI-адаптацией контента

### Метрики
- Агентов: 17 (15 основных + 2 fix)
- Файлов .py: 41
- Тестов: 133, все passing
- Волн: 6 (pre-research → A foundation → B core → C adapters → D business → E handlers → F tests)
- Время: ~1 час, 1 сессия
- Пересессий: 0

### Структура волн (оптимальная для бот-проекта)

| Волна | Агенты | Что | Параллельность |
|-------|--------|-----|----------------|
| Pre-research | 2 | Чтение VTB паттернов | Параллельно |
| A: Foundation | 1 | Скелет: config, team.json, requirements | Последовательно |
| B: Core | 3 | main.py + database + ai_adapter | Параллельно |
| C: Adapters | 5 | 5 платформ (IG, TG, Threads, WA, VK) | Параллельно |
| D: Business | 2 | publisher + lessons (9 файлов) | Параллельно с C! |
| E: Handlers | 1 | 6 файлов UI бота (644 строки publish.py) | Последовательно |
| F: Tests | 1 | 133 теста | Последовательно |

### Ключевой паттерн: D параллельно с C
Lessons зависит от core (B), НЕ от адаптеров (C). Запуск D2 параллельно с C сэкономил целую волну.

### Паттерн: Foundation agent с полным кодом в промпте
Агент Foundation получил ПОЛНЫЙ код каждого файла в промпте (config.py, team.json, platform_rules.json). Результат: 100% точность, 0 правок. Для конфиг-файлов это оптимально.

### Паттерн: Адаптеры платформ = идеальная параллельность
5 адаптеров (IG, TG, Threads, WA, VK) полностью независимы. Все 5 агентов запущены одновременно, все завершились за ~1-2 минуты. Каждый читал base.py + config.py + свой справочник.

### Паттерн: Handlers = самая тяжёлая задача
publish.py вышел 644 строки — это самый тяжёлый файл проекта. Агенту понадобилось 83K токенов и 7.5 минут. Рекомендация: для хендлеров давать ДЕТАЛЬНЫЙ промпт с FSM-состояниями и callback_data.

### Антипаттерн: main.py без явных аргументов
Агент bot-core создал `AIAdapter()` без ключей. Фикс: в промпте указывать конкретные вызовы конструкторов:
`AIAdapter(gemini_api_key=config.GEMINI_API_KEY, groq_api_key=config.GROQ_API_KEY)`

### Антипаттерн: .pop() на глобальных данных
seed.py использовал `lesson_data.pop("is_pinned")` — мутировал глобальный SEED_LESSONS. Решение: `data = dict(lesson_data)` перед pop. Тесты это нашли.
