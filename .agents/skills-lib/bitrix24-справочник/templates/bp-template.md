# Шаблон: Бизнес-процессы Битрикс24

ДАННЫЕ АКТУАЛЬНЫ НА: 2026-02-16

## Назначение

Готовые шаблоны бизнес-процессов (БП) для турагентства. Включает полное описание шагов, условий и действий для визуального конструктора БП.

**Доступность:** Стандартный тариф -- базовые БП. Профессиональный и Энтерпрайз -- полные возможности.

---

## Пошаговая инструкция

### Как создать бизнес-процесс

1. Перейдите: **CRM > Еще > Настройки > Автоматизация > Бизнес-процессы**
2. Выберите тип элемента: **Сделка** (или Лид, Контакт)
3. Нажмите **"Создать шаблон бизнес-процесса"**
4. Выберите тип: **Последовательный** (для линейных сценариев) или **Со статусами**
5. Постройте схему с помощью визуального конструктора
6. Нажмите **"Сохранить"**

### Элементы конструктора БП

| Элемент | Описание | Лимиты |
|---------|----------|--------|
| Условие (if/else) | Ветвление логики по значению полей | -- |
| Параллельные ветки | Одновременное выполнение нескольких действий | БП ждет завершения всех |
| Цикл | Повторение действий | до 1 000 итераций (облако) |
| Переменные | Временные значения, меняются в процессе | -- |
| Константы | Постоянные значения (название компании и т.д.) | -- |
| Задержка | Пауза на заданное время или до даты | -- |
| Уведомление | Чат, email, push | -- |
| REST-действие | Вызов внешнего API | -- |

## БП 1: Обработка нового запроса на экскурсию

### Описание

Полный цикл обработки заявки клиента: от получения до бронирования или отказа. Последовательный тип.

### Схема процесса

```
СТАРТ: Новая сделка в воронке "Экскурсии"
    |
    v
[1] Уведомить менеджера (чат + push)
    |
    v
[2] Автоответ клиенту: "Спасибо за заявку!"
    |
    v
[3] Создать задачу: "Связаться с клиентом" (15 мин)
    |
    v
[4] ОЖИДАНИЕ: менеджер заполняет поля (дата, гости, тип)
    |
    v
[5] УСЛОВИЕ: Все поля заполнены?
    |--- ДА -----> [6] Проверка доступности
    |--- НЕТ ----> [5a] Напоминание менеджеру (через 2 часа) -> [4]
    |
    v
[6] Проверка доступности
    |
    v
[7] УСЛОВИЕ: Дата свободна?
    |--- ДА -----> [8] Расчет стоимости
    |--- НЕТ ----> [7a] Уведомить менеджера: "Дата занята" -> Предложить другую дату -> [4]
    |
    v
[8] Расчет стоимости
    Заполнить сумму сделки
    |
    v
[9] Отправка предложения клиенту
    Сообщение: "Ваша экскурсия {Тип}: {Дата}, {Количество} гостей.
    Стоимость: {Сумма} {Валюта}. Подтверждаете?"
    |
    v
[10] ОЖИДАНИЕ ответа клиента (макс. 48 часов)
    |
    v
[11] УСЛОВИЕ: Клиент подтвердил?
    |--- ДА -----> [12] Бронирование
    |--- НЕТ (отказ) ----> [14] Отказ
    |--- ТАЙМ-АУТ (48ч) ----> [11a] Follow-up сообщение -> [10] (ещё 24ч)
    |
    v
[12] Бронирование
    - Сменить стадию на "Подтверждение"
    - Создать задачу гиду
    - Создать задачу водителю (если трансфер = Да)
    - Сгенерировать номер бронирования
    |
    v
[13] Отправить подтверждение клиенту
    "Бронирование подтверждено! Номер: {Номер бронирования}"
    |
    v
КОНЕЦ (Успех)

[14] Отказ
    - Сменить стадию на "Провалена"
    - Указать причину
    - Запланировать повторный контакт через 30 дней
    |
    v
КОНЕЦ (Отказ)
```

### Детали каждого шага

| Шаг | Действие БП | Параметры |
|-----|-------------|-----------|
| 1 | Уведомление в чат | Получатель: Ответственный. Текст: "Новый запрос на экскурсию от {Имя}" |
| 2 | Отправить сообщение | Канал: Open Channel. Текст: приветствие |
| 3 | Создать задачу | Исполнитель: Ответственный. Дедлайн: +15 мин |
| 4 | Ожидание | Условие: поля UF_CRM_TOUR_DATE, UF_CRM_GUESTS заполнены |
| 5 | Условие | Проверка: поля не пусты |
| 6 | Задание сотруднику | "Проверьте доступность на {Дата тура}" |
| 7 | Условие | Проверка ответа сотрудника |
| 8 | Математическая операция | Расчет суммы (или ручной ввод) |
| 9 | Отправить сообщение | Канал: Open Channel |
| 10 | Ожидание | Тайм-аут: 48 часов |
| 11 | Условие | Проверка стадии или ответа |
| 12 | Множественные действия | Параллельно: задача гиду + задача водителю + изменение полей |
| 13 | Отправить сообщение | Подтверждение с деталями |
| 14 | Изменить элемент | Стадия = Провалена |

## БП 2: Ежемесячный отчет по продажам

### Описание

Автоматический сбор данных по сделкам за месяц с рассылкой отчета руководству. Запускается по расписанию (1 числа каждого месяца).

### Схема процесса

```
СТАРТ: 1-е число каждого месяца (по расписанию)
    |
    v
[1] Получить список сделок за прошлый месяц
    REST-запрос: crm.deal.list (фильтр по дате закрытия)
    |
    v
[2] ПАРАЛЛЕЛЬНЫЕ ВЕТКИ:
    |
    |--- Ветка А: Подсчет по воронке "Экскурсии"
    |    - Количество сделок
    |    - Общая сумма (AED, USD)
    |    - Конверсия (успешные / все)
    |
    |--- Ветка Б: Подсчет по воронке "Яхты"
    |    - Количество сделок
    |    - Общая сумма
    |    - Конверсия
    |
    |--- Ветка В: Подсчет по воронке "Авто"
    |    - Количество сделок
    |    - Общая сумма
    |    - Конверсия
    |
    v
[3] Объединение результатов
    |
    v
[4] Формирование отчета
    Переменные: total_deals, total_revenue, conversion_rate
    |
    v
[5] Отправить отчет
    - Уведомление в чат "Руководство"
    - Email Сухейлю, Марселю, Муфамаду
    |
    v
[6] Создать задачу
    "Проанализировать отчет за {Месяц}"
    Исполнитель: Сухейль
    Дедлайн: 3-е число
    |
    v
КОНЕЦ
```

### Шаблон текста отчета

```
ЕЖЕМЕСЯЧНЫЙ ОТЧЕТ: {Месяц} {Год}

ЭКСКУРСИИ (Сухейль):
- Сделок: {count_excursions}
- Выручка: {revenue_excursions} AED
- Конверсия: {conversion_excursions}%

АРЕНДА АВТО (Марсель):
- Сделок: {count_auto}
- Выручка: {revenue_auto} AED
- Конверсия: {conversion_auto}%

ЯХТЫ (Муфамад):
- Сделок: {count_yachts}
- Выручка: {revenue_yachts} AED
- Конверсия: {conversion_yachts}%

ИТОГО:
- Всего сделок: {total_deals}
- Общая выручка: {total_revenue} AED
- Средний чек: {avg_check} AED
- Средняя конверсия: {avg_conversion}%
```

## БП 3: Согласование скидки

### Описание

Когда менеджер хочет дать скидку клиенту -- автоматический процесс согласования с руководителем.

### Схема процесса

```
СТАРТ: Менеджер запускает БП из карточки сделки
    |
    v
[1] Менеджер заполняет форму:
    - Размер скидки (%)
    - Причина скидки (список: постоянный клиент, группа, VIP, конкурент, другое)
    - Комментарий
    |
    v
[2] УСЛОВИЕ: Скидка <= 10%?
    |--- ДА -----> [3] Автоматическое одобрение
    |--- НЕТ ----> [4] Согласование с руководителем
    |
    v
[3] Автоматическое одобрение
    - Применить скидку к сумме сделки
    - Уведомить менеджера: "Скидка {%} одобрена автоматически"
    -> КОНЕЦ
    |
    v
[4] Задание руководителю: "Согласовать скидку"
    Текст: "Менеджер {Имя} запрашивает скидку {%} на сделку '{Название}'.
    Сумма: {Сумма} -> {Сумма со скидкой}. Причина: {Причина}"
    Тайм-аут: 4 часа
    |
    v
[5] УСЛОВИЕ: Руководитель одобрил?
    |--- ДА -----> [6] Применить скидку
    |--- НЕТ ----> [7] Отказ в скидке
    |--- ТАЙМ-АУТ ----> Эскалация: уведомить директора
    |
    v
[6] Применить скидку
    - Изменить сумму сделки
    - Уведомить менеджера: "Скидка одобрена!"
    -> КОНЕЦ
    |
    v
[7] Отказ
    - Уведомить менеджера: "Скидка отклонена. Причина: {комментарий руководителя}"
    -> КОНЕЦ
```

## Формат описания БП (для собственных процессов)

Используйте этот шаблон для документирования новых бизнес-процессов:

```markdown
### БП: [Название]

**Тип:** Последовательный / Со статусами
**Привязка:** Сделка / Лид / Контакт / Смарт-процесс
**Воронка:** [Название воронки]
**Запуск:** Автоматически (при переходе на стадию) / Вручную / По расписанию
**Доступность:** Стандартный / Профессиональный / Энтерпрайз

**Описание:** [Зачем нужен этот процесс, 1-2 предложения]

**Входные данные:**
- [Поле 1]: [Тип] -- [Описание]
- [Поле 2]: [Тип] -- [Описание]

**Схема:**
СТАРТ -> [Шаг 1] -> [Шаг 2] -> УСЛОВИЕ -> ...

**Шаги:**
| # | Действие | Параметры | Тайм-аут |
|---|---------|-----------|----------|
| 1 | ... | ... | ... |
| 2 | ... | ... | ... |

**Результат:** [Что происходит при успешном завершении]
**Отказ:** [Что происходит при отказе/ошибке]
```
