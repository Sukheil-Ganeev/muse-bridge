# Giga Super Transcribe (Яндекс отключен)

Важно: этот скилл исторически называется `giga-transcribe-туризм`, но теперь это **полностью GigaAM-only** режим.

## Жесткое правило
- Никогда не использовать Yandex SpeechKit.
- Никогда не запрашивать `YANDEX_*` ключи.
- Никогда не предлагать Yandex как fallback.
- Если кто-то просит Яндекс: объяснить, что он выведен из эксплуатации в этом проекте.

## Когда применять
Используй этот скилл, когда пользователь просит:
- транскрибировать аудио/видео;
- сделать субтитры (`.vtt`);
- сделать OCR по кадрам видео;
- обработать сразу несколько файлов/папку;
- получить готовый отчет по результатам.

Ключевые триггеры:
- `транскрипция`, `транскрибировать`, `speech-to-text`, `STT`
- `голосовое`, `аудио в текст`, `видео в текст`
- `субтитры`, `vtt`
- `OCR`, `извлечь текст с видео`
- `giga`, `gigaam`

## Основной движок
- `GigaAM` (локально, через наш venv)
- Видеофайлы и аудиофайлы поддерживаются напрямую
- Для длинных файлов используется автоматическая нарезка на чанки

## Главный скрипт
- Скрипт: `scripts/giga_super_transcribe.py`
- Это единая точка входа для:
  - транскрибации
  - генерации `.vtt`
  - OCR по кадрам видео
  - JSON/CSV отчетов

## Рекомендуемый запуск (Windows)
```powershell
D:\Downloads\_SYSTEM\Tools_And_Runtime\_gigaam_venv\Scripts\python.exe \
  C:\Users\londo\.codex\skills\giga-transcribe-туризм\scripts\giga_super_transcribe.py \
  --inputs "D:\Downloads\file1.mp4" "D:\Downloads\file2.mp4" \
  --ocr
```

## Что делает скрипт
1. Проверяет входные файлы/папки/URL.
2. Приводит аудио к стабильному формату (16k mono WAV).
3. Нарезает длинное аудио на безопасные куски.
4. Делает транскрибацию через GigaAM.
5. Применяет словарь автокоррекций терминов.
6. Сохраняет:
   - `.transcript.txt`
   - `.segments.json`
   - `.vtt`
7. Если включен `--ocr`, извлекает текст с кадров видео.
8. Формирует `summary.json` и `summary.csv`.

## Выходные данные
По умолчанию результаты складываются в:
- `D:\Downloads\_audit\transcribe_YYYYMMDD_HHMMSS\...`

На каждый файл создается отдельная папка с артефактами.

## Полезные параметры
- `--inputs` список файлов, папок, wildcard-масок или URL
- `--recursive` рекурсивный обход папок
- `--ocr` включить OCR по кадрам видео
- `--ocr-interval 20` интервал кадров для OCR (сек)
- `--ocr-max-frames 120` ограничение кадров для OCR
- `--chunk-seconds 22` размер чанка для длинного аудио
- `--terms-file custom_terms.json` пользовательские замены терминов
- `--out-dir D:\Downloads\_audit\my_run` своя папка результатов

## Проверка результата
После запуска нужно проверить:
- есть ли `summary.json` и `summary.csv`;
- сколько файлов в статусе `ok`;
- открываются ли `.transcript.txt` и `.vtt`;
- если был `--ocr`, есть ли `.ocr.txt`/`.ocr.json`.

## Диагностика простыми словами
### Если «не нашел gigaam/torch»
Причина: запуск не тем Python.
Решение: запускать строго через
`D:\Downloads\_SYSTEM\Tools_And_Runtime\_gigaam_venv\Scripts\python.exe`.

### Если OCR не сработал
Причина: не найден PowerShell OCR-скрипт.
Решение: передать `--ocr-script <путь_к_ocr_extract.ps1>` или убрать `--ocr`.

### Если транскрипция пустая
Причина: тишина, сильный шум, или сложный отрезок.
Решение:
- уменьшить `--chunk-seconds` до `18-20`;
- проверить исходный звук;
- повторить запуск.

## Legacy-скрипты
Старые утилиты в `scripts/` оставлены только как архив опыта.
Рабочим стандартом считается только:
- `scripts/giga_super_transcribe.py`

## Принцип поддержки
- Минимальные изменения.
- Безопасные шаги.
- Прозрачные отчеты.
- Никакого возврата к Yandex в этом скилле.
