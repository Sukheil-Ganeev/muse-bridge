## 3. Отсутствующие кнопки "Back" в 40+ блоках

### Проблема
Многие блоки не имеют кнопки возврата, пользователь застревает в форме.

### Причина
Кнопки добавлялись непоследовательно, фокус был на движении вперед.

### Решение

**Добавить кнопку "Back" в каждый блок:**

```yaml
# Было:
block: FORM-GT-TIME-360
  message: text: "🕒 Выберите время:"
  buttons:
    - text: "➡️ Далее"
      screen: FORM-GT-GUESTS-370

# Стало:
block: FORM-GT-TIME-360
  message: text: "🕒 Выберите время:"
  buttons:
    - text: "🔙 Назад"
      screen: FORM-GT-DATE-350
    - text: "➡️ Далее"
      screen: FORM-GT-GUESTS-370
```

**Правило определения предыдущего блока:**
1. ID текущего блока: 360
2. ID предыдущего: 350 (на 10 меньше)
3. Найти блок с этим ID

**Автоматизация:**
```python
# Скрипт для добавления Back кнопок
def add_back_button(block_id, prev_block_id):
    return f"""
  buttons:
    - text: "🔙 Назад"
      screen: {prev_block_id}
    """
```

### Как избежать
- Создавать блоки парами (текущий + навигация)
- Использовать шаблоны с готовыми кнопками
- Тестировать каждый путь в форме
- Code review с фокусом на UX

## 4. Переменные не сохраняются

### Проблема
Пользователь вводит данные, но в Review блоке они пустые или показывают `{{variable_name}}`.

### Причина
1. Отсутствует `variable_name` в блоке ввода
2. Переменная не объявлена в разделе `variables:`
3. Опечатка в имени переменной

### Решение

**1. Проверить наличие `variable_name`:**
```yaml
# Неправильно:
block: FORM-GT-DATE-350
  message:
    input: true
    text: "📅 Введите дату:"

# Правильно:
block: FORM-GT-DATE-350
  message:
    input: true
    text: "📅 Введите дату:"
  variable_name: gt_date  # ← ОБЯЗАТЕЛЬНО
```

**2. Объявить переменную:**
```yaml
variables:
  - gt_date
  - gt_time
  - gt_guests
  # ... все остальные
```

**3. Проверить консистентность:**
```yaml
# В блоке ввода:
variable_name: gt_date

# В Review блоке:
{{gt_date}}  # ← Точное совпадение имени
```

**Инструмент проверки:**
```bash
# Найти все использования переменной
grep -r "gt_date" ./forms/
```

### Как избежать
- Использовать автодополнение IDE
- Создавать переменную сразу при создании блока
- Вести таблицу всех переменных
- Автотесты на сохранение данных

## 5. Дублирование блоков с одинаковыми ID

### Проблема
Несколько блоков имеют одинаковый ID, что вызывает конфликты навигации.

### Причина
Копирование блоков без изменения ID.

### Решение

**1. Найти дубликаты:**
```bash
# Поиск повторяющихся block ID
grep -r "block: FORM-" ./forms/ | sort | uniq -d
```

**2. Переименовать блоки:**
```yaml
# Было (дубликат):
block: FORM-RENT-ABU-DHABI-850
block: FORM-RENT-ABU-DHABI-850  # ← КОНФЛИКТ

# Стало:
block: FORM-RENT-ABU-DHABI-850
block: FORM-RENT-ABU-DHABI-ROUTE-2-851  # ← Уникальный ID
```

**3. Обновить ссылки:**
```yaml
# Обновить все кнопки, ведущие на переименованный блок
buttons:
  - text: "Маршрут 2"
    screen: FORM-RENT-ABU-DHABI-ROUTE-2-851  # ← Новый ID
```

### Как избежать
- Использовать уникальные суффиксы (-A, -B, -ROUTE-1)
- Автоматическая генерация ID
- Проверка уникальности при создании блока
- Линтер для YAML файлов

## 7. Некорректная валидация телефона

### Проблема
Валидация отклоняет корректные номера телефонов ОАЭ.

### Причина
Неправильное регулярное выражение или жесткие ограничения формата.

### Решение

**Правильная валидация для ОАЭ:**
```yaml
block: FORM-GT-PHONE-380
  message:
    input: true
    text: |
      📱 Введите номер телефона:

      Примеры:
      • +971501234567
      • +971 50 123 4567
      • 050 123 4567
  variable_name: gt_phone
  validation:
    # Гибкое регулярное выражение
    regex: "^(\\+971|00971|0)?[0-9\\s]{9,12}$"
    error: |
      ❌ Неверный формат телефона
      Используйте: +971XXXXXXXXX или 05XXXXXXXX
```

**Принимаемые форматы:**
- `+971501234567` - с кодом страны
- `+971 50 123 4567` - с пробелами
- `00971501234567` - альтернативный код
- `0501234567` - без кода страны
- `050 123 4567` - локальный с пробелами

**Нормализация на сервере:**
```javascript
function normalizePhone(phone) {
  // Убрать пробелы
  phone = phone.replace(/\s/g, '');

  // Заменить 00971 на +971
  phone = phone.replace(/^00971/, '+971');

  // Добавить +971 если начинается с 0
  if (phone.startsWith('0') && !phone.startsWith('00')) {
    phone = '+971' + phone.substring(1);
  }

  return phone;
}
```

### Как избежать
- Тестировать валидацию с реальными номерами
- Использовать международные стандарты
- Предусмотреть разные форматы ввода
- Показывать примеры в placeholder

block: FORM-GT-SUBMIT-410

## 9. Эмодзи не отображаются корректно

### Проблема
Эмодзи показываются как квадраты или знаки вопроса.

### Причина
1. Кодировка файла не UTF-8
2. Проблемы с Telegram клиентом
3. Использование устаревших эмодзи

### Решение

**1. Проверить кодировку файла:**
```bash
# Проверить кодировку
file -bi forms/form-gt.yaml

# Должно быть:
text/plain; charset=utf-8

# Если нет - конвертировать:
iconv -f WINDOWS-1251 -t UTF-8 form.yaml > form-utf8.yaml
```

**2. Использовать стандартные эмодзи:**
```yaml
# Рекомендуемые эмодзи для ОАЭ:
🏙️ - города
🕌 - мечети
🏨 - отели
🚗 - автомобили
🛳️ - круизы
🏍️ - багги/квадроциклы
🌊 - вода/море
🏖️ - пляж
⏰ - время
📅 - дата
👤 - человек
📱 - телефон
✅ - подтверждение
❌ - отмена
💰 - цена
```

**3. Тест эмодзи в сообщении:**
```yaml
message:
  text: |
    🏙️🕌🏨 Проверка эмодзи
    Если видите квадраты - проблема с кодировкой
```

### Как избежать
- Всегда использовать UTF-8
- Тестировать на разных устройствах
- Использовать только Unicode эмодзи
- Держать список проверенных эмодзи

## 10. Длинные сообщения обрезаются

### Проблема
Telegram обрезает длинные сообщения в Review блоках.

### Причина
Telegram имеет лимит 4096 символов на сообщение.

### Решение

**1. Разбить на несколько сообщений:**
```yaml
block: FORM-GT-REVIEW-400
  messages:  # ← множественное число
    - text: |
        ✅ *Проверьте вашу заявку (1/2):*

        📅 Дата: {{gt_date}}
        🕒 Время: {{gt_time}}
        👥 Количество гостей: {{gt_guests}}
        👤 Имя: {{gt_name}}

    - text: |
        ✅ *Проверьте вашу заявку (2/2):*

        📱 Телефон: {{gt_phone}}
        🏨 Отель: {{gt_hotel}}
        💬 Комментарии: {{gt_comments}}
```

**2. Сократить текст:**
```yaml
# Было (слишком длинно):
message: text: |
  Очень длинное описание с множеством деталей...
  (3000+ символов)

# Стало (компактно):
message: text: |
  📋 *Краткая информация*
  Детали: example.com/details
```

**3. Использовать вложения:**
```yaml
message:
  text: "✅ Заявка готова"
  file: "detailed_info.pdf"  # Детали в файле
```

### Как избежать
- Следить за длиной сообщений

## 12. Валидация даты не работает

### Проблема
Пользователь может ввести некорректную дату (32.13.2024).

### Причина
Валидация проверяет только формат, но не логику даты.

### Решение

**1. Улучшенная валидация:**
```yaml
block: FORM-GT-DATE-350
  message:
    input: true
    text: |
      📅 Выберите дату экскурсии:
      Формат: ДД.ММ.ГГГГ
  variable_name: gt_date
  validation:
    type: date
    format: "DD.MM.YYYY"
    min: "today"  # Не раньше сегодня
    max: "+6 months"  # Не позже 6 месяцев
    error: |
      ❌ Некорректная дата

      Требования:
      • Формат: ДД.ММ.ГГГГ
      • Не раньше сегодня
      • Не позже чем через 6 месяцев
```

**2. Серверная проверка:**
```javascript
function validateDate(dateString) {
  // Парсинг даты
  const [day, month, year] = dateString.split('.').map(Number);

  // Создать объект Date
  const date = new Date(year, month - 1, day);

  // Проверки
  if (date.getDate() !== day) return false;  // Неверный день
  if (date.getMonth() !== month - 1) return false;  // Неверный месяц
  if (date.getFullYear() !== year) return false;  // Неверный год
  if (date < new Date()) return false;  // В прошлом

  return true;
}
```

**3. Calendar picker (альтернатива):**
```yaml
block: FORM-GT-DATE-350
  message:
    calendar: true
    text: "📅 Выберите дату:"
    min_date: "today"
    max_date: "+6 months"
  variable_name: gt_date
```

### Как избежать
- Использовать календарь вместо текстового ввода
- Двойная валидация (клиент + сервер)
- Показывать примеры корректных дат
- Автоматическое форматирование ввода

2. Кнопка не блокируется после клика
3. Ретраи при ошибках сети

### Решение

**1. Блокировка кнопки:**
```yaml

  message:
    text: "✅ Подтвердить и отправить"
  buttons:

      screen: FORM-GT-SENDING-411
      disable_after_click: true  # ← Заблокировать после клика
```

**2. Debounce на сервере:**
```javascript
const submittedForms = new Set();

function submitForm(formId, userId) {
  const key = `${userId}-${formId}-${Date.now()}`;

  // Проверить, не была ли форма отправлена в последние 10 секунд
  if (submittedForms.has(`${userId}-${formId}`)) {
    return { error: "Форма уже отправлена" };
  }

  submittedForms.add(`${userId}-${formId}`);
  setTimeout(() => submittedForms.delete(`${userId}-${formId}`), 10000);

  // Отправить форму
  sendToAdmin(formId);
}
```
