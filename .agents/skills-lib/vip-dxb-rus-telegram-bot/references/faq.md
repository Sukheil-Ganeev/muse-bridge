# FAQ - Часто задаваемые вопросы

## Общие вопросы

### 1. Когда использовать групповую форму (GT) vs приватную (PT)?

**Групповая форма (GT):**
- Для экскурсий с несколькими участниками
- Используется для туров с фиксированным расписанием
- Цена обычно ниже за счет разделения затрат

**Приватная форма (PT):**
- Для индивидуальных заказов
- Гибкое время и маршрут
- Более высокая цена, но максимальный комфорт

**Выбор:** Зависит от предпочтений клиента по цене и формату.

### 2. Как добавить новый эмират в систему?

**Шаги:**

1. Открыть файл с формами (например, `FORM-RENT`)
2. Найти блок с эмиратами (обычно начинается с `FORM-RENT-EMIRATES`)
3. Добавить новый блок по аналогии:

```
block: FORM-RENT-NEW-EMIRATE-870
  message: text: |
    🏙️ *Новый Эмират*
    Описание нового эмирата
```

4. Добавить переменную в список (например, `rent_new_emirate`)
5. Обновить навигацию (кнопки Back/Next)

### 3. Почему форма круизов (FORM-CRUISE) пустая?

**Причина:** Форма была создана как заглушка и не содержит блоков сбора данных.

**Решение:**
1. Добавить блоки для основной информации:
   - Дата круиза
   - Количество гостей
   - Тип круиза (ужин, вечерний, дневной)
   - Дополнительные услуги

2. Использовать структуру из других форм как шаблон

**Пример минимальной структуры:**
```
block: FORM-CRUISE-DATE-900
block: FORM-CRUISE-GUESTS-910
block: FORM-CRUISE-TYPE-920
block: FORM-CRUISE-REVIEW-930
```

### 5. Какие переменные использовать для новой формы?

**Стандартный набор переменных:**

1. **Основная информация:**
   - `{prefix}_date` - дата
   - `{prefix}_time` - время
   - `{prefix}_guests` - количество гостей

2. **Контактная информация:**
   - `{prefix}_name` - имя
   - `{prefix}_phone` - телефон
   - `{prefix}_hotel` - отель

3. **Дополнительно:**
   - `{prefix}_comments` - комментарии
   - `{prefix}_special` - особые пожелания

**Пример для новой формы SAFARI:**
```
safari_date
safari_time
safari_guests
safari_name
safari_phone
safari_hotel
safari_comments
```

### 6. Как добавить кнопку "Back" в форму?

**Базовая структура:**

```
buttons:
  - text: "🔙 Назад"
    screen: PREVIOUS-SCREEN-ID
  - text: "➡️ Далее"
    screen: NEXT-SCREEN-ID
```

**Где взять ID предыдущего экрана:**
1. Посмотреть на цифровой ID текущего блока (например, 850)
2. Найти блок с ID на 10 меньше (840)
3. Использовать его screen ID

**Пример:**
```
# Текущий блок: FORM-RENT-ABU-DHABI-850
# Предыдущий: FORM-RENT-EMIRATES-840

buttons:
  - text: "🔙 Назад"
    screen: FORM-RENT-EMIRATES-840
```

### 7. Почему не сохраняется ввод пользователя?

**Частые причины:**

1. **Отсутствует переменная `variable_name`:**
```
# Неправильно:
block: FORM-GT-DATE-350
  message: input

# Правильно:
block: FORM-GT-DATE-350
  message: input
  variable_name: gt_date
```

2. **Переменная не добавлена в список:**
Проверить наличие в разделе `variables:`

3. **Опечатка в имени переменной:**
Проверить консистентность использования.

if: special_request == "VIP"

### 9. Какой формат даты использовать в формах?

**Рекомендуемый формат:**
```
DD.MM.YYYY (например: 15.03.2024)
```

**Альтернативные форматы:**
- `DD/MM/YYYY` - 15/03/2024
- `YYYY-MM-DD` - 2024-03-15 (ISO стандарт)

**Валидация в коде:**
```javascript
// Проверка формата DD.MM.YYYY
const dateRegex = /^\d{2}\.\d{2}\.\d{4}$/;
if (!dateRegex.test(userInput)) {
  // Показать ошибку
}
```

**Подсказка для пользователя:**
```
message: text: |
  📅 Введите дату:
  Формат: ДД.ММ.ГГГГ (например: 25.12.2024)
```

### 10. Как добавить валидацию номера телефона?

**Базовая структура:**

```
block: FORM-GT-PHONE-380
  message:
    input: true
    text: |
      📱 Введите номер телефона:
      Формат: +971XXXXXXXXX
  variable_name: gt_phone
  validation:
    regex: "^\\+971[0-9]{9}$"
    error: "❌ Неверный формат. Используйте +971XXXXXXXXX"
```

**Принимаемые форматы:**
- `+971501234567` - с кодом страны
- `+971 50 123 4567` - с пробелами
- `050 123 4567` - без кода (автодополнение)

### 11. Как объединить данные из нескольких форм?

**Используйте системные переменные:**

```
# Сбор данных из GT формы
gt_date = "25.12.2024"
gt_guests = "4"

# Сбор данных из PT формы
pt_date = "26.12.2024"
pt_guests = "2"

# Итоговый отчет
total_guests = gt_guests + pt_guests  # 6
all_dates = [gt_date, pt_date]
```

**Вывод в Review блоке:**
```
message: text: |
  📊 Общая информация:

  Групповая экскурсия: {{gt_date}}, {{gt_guests}} чел.
  Приватная экскурсия: {{pt_date}}, {{pt_guests}} чел.

  Всего гостей: {{total_guests}}
```

### 12. Почему кнопки не работают?

**Частые причины:**

1. **Неверный `screen` ID:**
```
# Неправильно:
buttons:
  - text: "Далее"
    screen: NEXT_SCREEN  # такого блока нет

# Правильно:
buttons:
  - text: "Далее"
    screen: FORM-GT-TIME-360
```

2. **Отсутствует блок назначения:**
Проверить, что блок с указанным ID существует.

3. **Синтаксическая ошибка:**
```
# Неправильно:
buttons:
- text: "Далее"
  screen: NEXT

# Правильно (отступы важны):
buttons:
  - text: "Далее"
    screen: NEXT
```

### 13. Как добавить изображение в форму?

**Базовая структура:**

```
block: FORM-GT-BURJ-KHALIFA-355
  message:
    text: |
      🏙️ *Бурдж Халифа*
      Самое высокое здание в мире
    image: "https://example.com/burj-khalifa.jpg"
```

**Рекомендации:**
- Использовать HTTPS URL
- Формат: JPG, PNG (WebP для оптимизации)
- Размер: до 5MB
- Разрешение: 1200x800px оптимально

**Альтернатива - эмодзи:**
```
message: text: |
  🏙️🌆🌃 *Бурдж Халифа*
```

### 15. Как обработать отмену заполнения формы?

**Добавить кнопку "Отмена":**

```
block: FORM-GT-DATE-350
  message: text: "📅 Выберите дату:"
  buttons:
    - text: "❌ Отменить"
      screen: MAIN-MENU-100
    - text: "➡️ Далее"
      screen: FORM-GT-TIME-360
```

**Очистка данных:**
```
# При отмене - сбросить переменные
on_cancel:
  reset_variables:
    - gt_date
    - gt_time
    - gt_guests
    - gt_name
    - gt_phone
```

**Подтверждение отмены:**
```
block: CONFIRM-CANCEL-999
  message: text: |
    ⚠️ Вы уверены, что хотите отменить?
    Все введенные данные будут потеряны.
  buttons:
    - text: "Да, отменить"
      screen: MAIN-MENU-100
    - text: "Нет, продолжить"
      screen: FORM-GT-DATE-350
```

### 16. Какие есть готовые шаблоны форм?

**Базовые шаблоны:**

1. **Экскурсия (GT/PT):**
   - Дата → Время → Гости → Имя → Телефон → Отель → Обзор

2. **Аренда (RENT):**
   - Дата начала → Дата окончания → Эмират → Водитель → Обзор

3. **Активности (BUGGY/QUAD/JETSKI):**
   - Дата → Время → Участники → Имя → Телефон → Обзор

4. **Круиз (CRUISE):**
   - Дата → Тип → Гости → Имя → Телефон → Обзор

**Где найти:**
Папка `assets/templates/` в структуре скилла.

### 17. Как добавить комментарии в форму?

**Блок для комментариев:**

```
block: FORM-GT-COMMENTS-390
  message:
    input: true
    text: |
      💬 Дополнительные пожелания:
      (необязательно)

      Например:
      • Детские кресла
      • Особая диета
      • Предпочтения по маршруту
  variable_name: gt_comments
  optional: true
```

**Параметры:**
- `optional: true` - поле необязательное
- Можно пропустить кнопкой "Пропустить"

**Добавить кнопку "Пропустить":**
```
buttons:
  - text: "⏭️ Пропустить"
    screen: FORM-GT-REVIEW-400
  - text: "➡️ Далее"
    screen: FORM-GT-REVIEW-400
```

### 19. Как создать форму с выбором из списка?

**Inline кнопки:**

```
block: FORM-GT-TIME-360
  message: text: "🕒 Выберите время:"
  buttons:
    - text: "🌅 Утро (08:00-12:00)"
      action: set_variable
      variable: gt_time
      value: "morning"
    - text: "☀️ День (12:00-17:00)"
      action: set_variable
      variable: gt_time
      value: "afternoon"
    - text: "🌆 Вечер (17:00-21:00)"
      action: set_variable
      variable: gt_time
      value: "evening"
```

**Dropdown меню:**
```
block: FORM-GT-TIME-360
  message:
    select: true
    text: "🕒 Выберите время:"
    options:
      - "08:00"
      - "09:00"
      - "10:00"
      - "11:00"
      - "12:00"
  variable_name: gt_time
```

### 20. Как протестировать форму перед запуском?

**Чек-лист тестирования:**

- [ ] Все блоки имеют уникальные ID
- [ ] Каждая кнопка ведет на существующий блок
- [ ] Все переменные объявлены в `variables:`
- [ ] Добавлены кнопки "Назад" для навигации
- [ ] Валидация работает корректно
- [ ] Review блок показывает все данные
- [ ] Отправка админу работает
- [ ] Текст без опечаток
- [ ] Эмодзи отображаются корректно
- [ ] Форма проходится от начала до конца

**Тестовый сценарий:**
1. Запустить форму
2. Заполнить все поля
3. Проверить Review
4. Отправить
5. Проверить получение у админа
6. Попробовать вернуться назад на каждом шаге
7. Протестировать отмену

**Инструменты:**
- Локальный запуск бота
- Telegram Bot Emulator
- Логирование каждого шага
