## 1. Квиз "Какой тур вам подходит?"

**Источник:** Кейс Автошкола (конверсия 26%, ~1070 пользователей, 282 лида)

**Идея:** Заменить стандартное меню выбора туров на интерактивный квиз, который за 7 вопросов определит идеальный тип тура для туриста.

**Почему это работает:**
- Вовлечение через игрификацию (клик-клик-клик вместо чтения)
- Персонализация (клиент получает рекомендацию "для себя")
- Снижение когнитивной нагрузки (не нужно изучать 43 экскурсии)
- Психология: "меня поняли" → доверие → заявка

#### Блок 988: Обработка результата квиза

**ID:** 988

**Тип:** Технический блок (без отображения пользователю)

```javascript
// Матрица решений
const recommendations = {
  // Экономный бюджет + архитектура + короткая поездка + пара
  "economy-architecture-short-couple": [101, 102, 103], // Dubai Modern, Marina, Downtown

  // VIP бюджет + роскошь + средняя поездка + пара
  "vip-luxury-medium-couple": [109, 110, 112], // Yacht, Helicopter, Ferrari World

  // Семья + развлечения + активный
  "family-entertainment": [500, 501, 502], // IMG Worlds, Legoland, Aquaventure

  // Экстрим + друзья + активный
  "extreme-friends-active": [720, 721, 730], // Buggy, Quad, Jetski

  // Культура + первый раз + утро
  "culture-first_time-morning": [105, 200, 201], // Old Dubai, Sheikh Zayed Mosque, Louvre

  // ... (полная матрица — 50+ комбинаций)
};

// Упрощенный алгоритм подбора
function getRecommendations(answers) {
  // 1. Создаем ключ из ответов
  const key = `${answers.quiz_budget}-${answers.quiz_interests[0]}-${answers.quiz_days}-${answers.quiz_group}`;

  // 2. Ищем в матрице
  let result = recommendations[key];

  // 3. Если точного совпадения нет — берем по главным критериям
  if (!result) {
    result = recommendations[answers.quiz_interests[0]] || [101, 102, 103]; // Дефолт
  }

  // 4. Сохраняем результат
  quiz_result = result.join(','); // "101,102,103"

  return result;
}

const tours = getRecommendations(user_answers);
```

### Новая форма: FORM-QUIZ

**Название:** Бронирование пакета из квиза
**Префикс переменных:** `quiz_`

**Поля:**

| # | Поле | Переменная | Тип | Обязательно | Примечание |
|---|------|------------|-----|-------------|------------|
| 1 | Выбранные туры | `quiz_selected_tours` | CHOICE | Yes | Чекбоксы 1-3 тура |
| 2 | Дата первого тура | `quiz_date_1` | DATE | Yes | Календарь |
| 3 | Дата второго тура | `quiz_date_2` | DATE | Conditional | Если выбрано 2+ тура |
| 4 | Дата третьего тура | `quiz_date_3` | DATE | Conditional | Если выбрано 3 тура |
| 5 | Количество взрослых | `quiz_adults` | NUMBER | Yes | 1-20 |
| 6 | Количество детей | `quiz_children` | NUMBER | No | 0-10 |
| 7 | Имя | `quiz_name` | TEXT | Yes | 1-100 символов |
| 8 | Телефон | `quiz_phone` | PHONE | Yes | +971-XX-XXX-XXXX |
| 9 | Email | `quiz_email` | EMAIL | Yes | name@domain.ext |
| 10 | Отель | `quiz_hotel` | TEXT | No | Для трансфера |
| 11 | Промокод | `quiz_promo` | TEXT | No | Автозаполнение QUIZ10 |
| 12 | Комментарии | `quiz_comments` | TEXT | No | До 500 символов |

**Валидация:**
- Даты не должны совпадать
- Все даты в будущем
- Минимум 1 тур выбран
- Если выбрано 2+ тура → скидка 15%
- Если выбрано 3 тура → скидка 20%

**Исходящие действия:**
1. Сохранение данных в переменные `quiz_*`
2. Уведомление менеджеру с меткой "КВИЗ-ЗАЯВКА (приоритет)"
3. Отправка клиенту подтверждения
4. Переход в блок 970 (Thank You)
5. Интеграция с AmoCRM: статус "Горячий лид"

## 2. Автоматизация бронирования со статусами

**Источник:** Кейс Резиденции Villingston (полная автоматизация от заезда до выезда)

**Идея:** Заменить простую отправку формы на систему управления бронированиями с отслеживанием статусов и автоуведомлениями клиентам на каждом этапе.

**Почему это работает:**
- Прозрачность для клиента (видит статус заявки)
- Контроль для менеджеров (не теряются заявки)
- Автоматизация напоминаний (меньше ручной работы)
- Повышение доверия (профессиональный подход)

### Жизненный цикл бронирования (5 статусов)

#### Статус 1: Новая заявка

**Когда:** Сразу после отправки формы (любой FORM-GT/PT/BUGGY/RENT)

**Действия системы:**
1. Присвоение уникального номера заявки: `BOOK-{{timestamp}}-{{user_id}}`
2. Установка статуса: `booking_status = "new"`
3. Уведомление менеджеру (Telegram + Email)
4. Уведомление клиенту (блок 990)

**Блок 990: Подтверждение новой заявки**

**ID:** 990
**Название:** BOOKING-NEW-CONFIRMATION

**Контент:**
```markdown

📋 Что дальше?

1️⃣ Наш менеджер свяжется с вами в течение **1 часа** для подтверждения деталей
2️⃣ После подтверждения мы вышлем вам счет на оплату
3️⃣ После оплаты вы получите ваучер и детали встречи

📊 **Статус:** Новая заявка (ожидает обработки)
```

#### Статус 4: Оплачена

**Когда:** Платеж прошел успешно (webhook от платежной системы) или менеджер подтвердил наличные

**Действия системы:**
1. Установка статуса: `booking_status = "paid"`
2. Сохранение данных оплаты: `booking_payment_method`, `booking_payment_id`

4. Уведомление клиенту (блок 993)
5. Уведомление гиду/водителю (за 24 часа до тура)

## 3. Воронка для B2B-партнеров

**Источник:** Кейс HR-рекрутинг (конверсия 31%, закрытый канал + приветственный бот = в 2 раза больше подписчиков)

**Идея:** Создать отдельный путь в боте для турагентств, отелей и корпоративных клиентов с оптовыми условиями и персональной поддержкой.

**Почему это работает:**
- B2B-клиенты ценят другое (не цену, а сервис + комиссию)
- Отдельная воронка = меньше отвлечений на B2C-функции
- Закрытый контент повышает ценность
- Персонализация → доверие → долгосрочное сотрудничество

**Отличия от обычной формы:**

1. **Дополнительные поля:**
   - Имя туриста (если партнер бронирует для клиента)
   - Ваш номер заказа (внутренний reference партнера)
   - Способ оплаты: Счет/Кредитная линия/Постоплата
   - Комментарии для гида (особые пожелания клиента)

2. **Упрощенная валидация:**
   - Не требуется email туриста (только партнера)
   - Возможность отложенного подтверждения (до 48 часов)

3. **Автоматические скидки:**
   - Применение оптовой цены
   - Начисление комиссии партнеру

**Поля:**

| # | Поле | Переменная | Тип | Обязательно |
|---|------|------------|-----|-------------|
| 1 | Выбор тура | `b2b_booking_tour_id` | CHOICE | Yes |
| 2 | Дата тура | `b2b_booking_date` | DATE | Yes |

| 4 | Взрослых | `b2b_booking_adults` | NUMBER | Yes |

| 8 | Отель туриста | `b2b_booking_hotel` | TEXT | No |
| 9 | Ваш номер заказа | `b2b_booking_ref` | TEXT | No |
| 10 | Способ оплаты | `b2b_booking_payment` | CHOICE | Yes |
| 11 | Комментарии | `b2b_booking_comments` | TEXT | No |

**Варианты оплаты:**
- `Выставить счет` → Счет на email партнера, оплата в течение 3 дней
- `Кредитная линия` → Если есть кредитный лимит (для VIP-партнеров)

1. Создание заявки со статусом `b2b_booking`
2. Автоматический расчет:
   - Оптовая цена = розница × (1 - discount_rate)
   - Комиссия партнера = розница × commission_rate
3. Уведомление партнеру + туристу
4. Добавление в партнерскую статистику
5. Интеграция в CRM партнера (если настроена)

## Ожидаемые результаты

### 1. Квиз "Какой тур вам подходит?"

**Базовый сценарий (на основе кейса Автошкола):**

| Метрика | До квиза | После квиза | Источник |
|---------|----------|-------------|----------|
| Конверсия в заявку | 10-15% | 20-26% | Кейс Автошкола: 26% |
| Среднее время на сайте/боте | 2 мин | 5 мин | Квиз вовлекает |
| Процент отказов | 60% | 30% | Квиз удерживает |
| Качество лидов | Низкое | Высокое | Квалификация через ответы |

**Математика (при 1000 пользователей/месяц):**

**ДО квиза:**
- 1000 пользователей × 12% конверсия = 120 заявок/месяц
- 120 заявок × 40% конверсия в продажу = 48 туров/месяц
- 48 туров × 500 AED средний чек = 24,000 AED выручка

**ПОСЛЕ квиза:**
- 1000 пользователей × 70% начали квиз = 700 начали
- 700 начали × 80% завершили = 560 завершили
- 560 завершили × 26% конверсия = **146 заявок/месяц** (+21%)
- 146 заявок × 50% конверсия (выше, т.к. квалифицированы) = **73 тура/месяц** (+52%)
- 73 тура × 500 AED = **36,500 AED выручка** (+52%)

**Дополнительные эффекты:**
- Снижение нагрузки на менеджеров (лиды квалифицированы)
- База данных предпочтений клиентов (для таргетированных рассылок)
- Возможность A/B-тестирования предложений

**ROI квиза:**
- Разработка: ~40 часов × 50 AED/час = 2,000 AED
- Прирост выручки: 12,500 AED/месяц
- Окупаемость: 5 дней

| Повторные покупки | 5% | 30% | Кейс Компьютерный клуб |

**Математика (при 150 заявках/месяц):**

**ДО автоматизации:**
- 150 заявок × 40% конверсия = 60 оплаченных туров

- Время менеджеров: 150 × 20 мин = 50 часов/месяц

**ПОСЛЕ автоматизации:**
- 150 заявок × 60% конверсия = **90 оплаченных туров** (+50%)
- 90 туров × 500 AED = **45,000 AED выручка** (+50%)
- Время менеджеров: 150 × 5 мин = 12.5 часов/месяц (**-75% времени**)

**Дополнительные эффекты:**
- Снижение стресса менеджеров (нет потерянных заявок)
- Аналитика по воронке продаж (где теряются клиенты)

**ROI системы статусов:**

- Окупаемость: 9 дней

### Важные заметки

**Риски:**
1. **Квиз:** Если вопросы слишком сложные → пользователи бросают (решение: A/B-тестирование)
2. **Статусы:** Менеджеры забывают обновлять → клиенты видят неактуальный статус (решение: автообновление)
3. **B2B:** Партнеры требуют слишком высокие комиссии → низкая маржа (решение: гибкие условия)

**Критические факторы успеха:**
1. Квиз должен быть **быстрым** (< 3 минут)
2. Статусы должны обновляться **автоматически** (без ручного труда)
3. B2B-менеджер должен быть **проактивным** (активно искать партнеров)

**Метрики для мониторинга:**
- Конверсия на каждом шаге квиза (где отваливаются?)
- Время обработки заявок (растет или падает?)
- Количество активных партнеров (растет ли?)
- Средний чек (растет со временем?)
- Процент повторных покупок (работает ли лояльность?)
