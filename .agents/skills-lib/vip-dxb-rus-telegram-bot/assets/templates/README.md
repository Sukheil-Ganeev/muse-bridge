# VIP-DXB-RUS Bot Templates

Шаблоны для быстрого создания контента VIP-DXB-RUS Telegram бота.

## Структура папки

```
templates/
├── README.md                    # Этот файл
├── block-excursion.md           # Шаблон карточки экскурсии
├── block-menu.md                # Шаблон меню категории
├── block-service.md             # Шаблон карточки услуги
├── form-booking.md              # Шаблон формы бронирования
├── system-prompt-claude.txt     # Системный промпт для Claude API
└── button-navigation.md         # Шаблон навигационных кнопок
```

## Описание шаблонов

### 1. block-excursion.md
**Назначение:** Создание карточек экскурсий (блоки 101-113, 201-208, 301-313, 401-409)

**Содержит:**
- Полную структуру блока экскурсии
- Таблицы для кнопок (групповой/приватный тур)
- Входящие/исходящие пути
- Примеры emoji для разных типов экскурсий
- Checkpoint для проверки полноты документации

**Использование:**
1. Скопируйте шаблон
2. Замените плейсхолдеры `[...]` реальными данными
3. Добавьте описание экскурсии
4. Укажите ID блоков для форм FORM-GT и FORM-PT
5. Отметьте чекбоксы в Checkpoint

---

### 2. block-menu.md
**Назначение:** Создание меню категорий (главные меню, субменю)

**Содержит:**
- Структуру меню с переменными ({{FIRST_NAME_TEXT}})
- 4 паттерна кнопок (с emoji, с описанием, combo, навигация)
- Emoji стандарты по категориям и эмиратам
- Таблицы для документирования кнопок

**Использование:**
1. Определите тип меню (главное/категория/субменю)
2. Выберите подходящий паттерн кнопок
3. Заполните таблицу кнопок
4. Не забудьте кнопку "⬅ Назад"!

---

### 3. block-service.md
**Назначение:** Создание карточек услуг (парки, активности, SPA, рестораны)

**Содержит:**
- Шаблоны описания по 7 категориям:
  - Parks (парки)
  - Water Activities (водные активности)
  - Pools (infinity pools)
  - Beach Clubs (пляжные клубы)
  - Buggy/Safari (багги и сафари)
  - SPA (спа-услуги)
  - Restaurants (рестораны)
- Примеры emoji для каждой категории
- Структуру с кнопкой бронирования

**Использование:**
1. Выберите категорию услуги
2. Используйте соответствующий шаблон описания
3. Укажите форму бронирования (FORM-BUGGY, FORM-POOL и т.д.)
4. Добавьте детали (цена, время, что включено)

---

### 4. form-booking.md
**Назначение:** Создание и документирование форм бронирования

**Содержит:**
- Таблицу структуры полей формы
- Шаблоны для всех 10 типов форм:
  - FORM-GT/PT (экскурсии)
  - FORM-BUGGY (багги)
  - FORM-RENT (аренда авто)
  - FORM-POOL (бассейны)
  - FORM-BEACH (beach clubs)
  - FORM-SPA (спа)
  - FORM-TRANSFER (трансфер)
  - FORM-YACHT (яхты)
  - FORM-REST (рестораны)
- Правила валидации полей
- Типы данных (TEXT, PHONE, EMAIL, DATE, TIME и т.д.)
- Рекомендуемые лимиты (количество гостей, дней и т.д.)

**Использование:**
1. Определите тип услуги и выберите префикс переменных
2. Заполните таблицу полей
3. Опишите choice-поля с опциями
4. Укажите входящие блоки (откуда вызывается форма)
5. Опишите исходящие действия (уведомления, подтверждения)

---

### 5. system-prompt-claude.txt
**Назначение:** Системный промпт для интеграции Claude API с ботом

**Содержит:**
- Контекст бота (187 блоков, 11 форм, 113 переменных)
- Описание всех услуг по 4 эмиратам
- Детали всех 11 форм бронирования
- Примеры диалогов (4 сценария)
- Правила ответов
- Информацию о критических багах
- Emoji стандарты
- Диапазоны ID блоков

**Использование:**
1. Скопируйте весь текст в поле System Prompt Claude API
2. Или используйте как базу для создания кастомного промпта
3. Адаптируйте под конкретные нужды (добавьте/удалите секции)

**Примеры использования:**
- AI-ассистент внутри бота для ответов на вопросы
- Чат-поддержка для пользователей
- Автоматизация подбора услуг

---

### 6. button-navigation.md
**Назначение:** Документирование навигационных кнопок и путей

**Содержит:**
- 5 паттернов кнопок:
  1. С emoji (классический)
  2. С описанием
  3. Combo-кнопки (пакеты)
  4. Action buttons (бронирование)
  5. Back button (навигация назад)
- Таблицы входящих/исходящих путей
- Полный список emoji по категориям
- 3 примера полной документации
- Типичные ошибки и их решения
- Checkpoint для проверки навигации

**Использование:**
1. При создании любого блока используйте для документирования кнопок
2. Выберите подходящий паттерн
3. Заполните таблицы Incoming/Outgoing Paths
4. Обязательно добавьте кнопку "⬅ Назад"
5. Проверьте по чеклисту

## Плейсхолдеры (обозначения для замены)

Все шаблоны используют квадратные скобки для плейсхолдеров:

| Плейсхолдер | Пример замены | Описание |
|-------------|---------------|----------|
| `[ID]` | `101` | ID блока в боте |
| `[Название]` | `Современный Дубай` | Название услуги/меню/экскурсии |
| `[Эмират]` | `Dubai` / `Abu Dhabi` | Название эмирата |
| `[EMOJI]` | `🏙️` | Emoji из стандартов бота |
| `[DD.MM.YYYY]` | `01.02.2026` | Дата в русском формате |
| `[X]` | `5` / `250 AED` | Числовое значение |
| `[prefix]_[name]` | `gt_client_name` | Имя переменной формы |
| `[Type]` | `TEXT` / `PHONE` / `EMAIL` | Тип поля формы |
| `[Yes/No]` | `Yes` или `No` | Булево значение |

## Рабочий процесс

### Создание новой экскурсии:
```
1. Копируем block-excursion.md
2. Заменяем [ID] → реальный ID (например, 114)
3. Заполняем [Название экскурсии] и [Эмират]
4. Добавляем описание и детали
5. Указываем пути к формам FORM-GT и FORM-PT
6. Проверяем по Checkpoint
```

### Создание новой услуги:
```
1. Копируем block-service.md
2. Выбираем категорию (Parks/SPA/Beach и т.д.)
3. Используем соответствующий шаблон описания
4. Указываем форму бронирования
5. Добавляем кнопку "Забронировать"
6. Не забываем "⬅ Назад"!
```

### Создание новой формы:
```
1. Копируем form-booking.md
2. Выбираем префикс для переменных (например, newservice_)
3. Заполняем таблицу полей
4. Добавляем Required поля (name, phone, email, date)
5. Описываем choice-поля с опциями
6. Указываем входящие блоки
7. Тестируем валидацию
```

## Best Practices

### При создании контента:

1. **Всегда используйте шаблоны** — они гарантируют полноту документации
2. **Заполняйте все секции** — даже если "Notes" кажется необязательным
3. **Проверяйте Checkpoint** — это контроль качества
4. **Тестируйте навигацию** — убедитесь, что все пути работают
5. **Документируйте сразу** — не откладывайте на потом

### Обязательные элементы:

- ✅ Кнопка "⬅ Назад" на КАЖДОМ блоке
- ✅ Emoji из стандартов бота
- ✅ Таблицы Incoming/Outgoing Paths
- ✅ ID блоков в формате `[ID] — [Название]`
- ✅ Переменные с правильным префиксом

### Частые ошибки:

- ❌ Отсутствие кнопки "Назад" → пользователь застревает
- ❌ Неверный emoji → нарушение визуальной логики
- ❌ Пустые таблицы → невозможно проверить пути
- ❌ Забытые переменные → форма не работает
- ❌ Неуказанный эмират → непонятно, откуда доступна услуга
