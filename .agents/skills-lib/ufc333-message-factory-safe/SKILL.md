# UFC333 message factory

Создавай сообщение из актуальной проектной правды, а не из памяти общего билетного бизнеса.

## Сначала определить режим

1. `internal` — владелец: можно показывать закупку, источник, доказательства и статус решения.
2. `agent` — агент: показывать только нашу базовую цену и доступность. Не показывать закупку, источник, инвестора, нашу прибыль.
3. `client` — клиент: показывать только итоговую цену фиксированной клиентской ссылки. Не показывать базовую цену, процент надбавки или внутренний расчёт.

Если получатель очевиден из запроса, не задавай лишний вопрос. Если ошибка выбора режима раскроет внутренние данные — уточни получателя до выдачи.

## Источник правды

Перед ценовым сообщением читай [references/domain-contract.md](references/domain-contract.md). Для структуры сообщения читай только нужный раздел [references/message-modes.md](references/message-modes.md). Перед выдачей применяй [references/quality-gates.md](references/quality-gates.md).

## Главные правила

- `Category` определяется доказанной связкой Section + Row + Seat или явной категорией источника. Section или цена сами по себе недостаточны.
- `Official Platinum` — тип предложения Ticketmaster, не UFC Category.
- Aisle-правило применяется только при доказанном provider surcharge ровно 100 AED: official Aisle purchase +100 AED нашей маржи.
- Обычная owner price ladder по диапазонам закупки пока `OWNER_INPUT_REQUIRED_NOT_DONE`. Примерные числа владельца не превращать в правила.
- Внешние сообщения содержат только позиции с доказанной нашей базовой/итоговой ценой.
- `Продано` писать только при explicit sold. Исчезновение или молчание источника — `Сейчас нет в продаже`.
- Купленный/инвесторский билет показывать как наш билет по нашей цене; не упоминать инвестора.
- Наличие и цену всегда обозначать как подлежащие повторному подтверждению перед оплатой.
- Не создавать ложный ажиотаж. Подтверждённые sold-позиции можно показывать серыми/проданными; неизвестные нельзя.

## Формат

- Язык по умолчанию — русский. Английский/арабский использовать только по явному запросу владельца.
- WhatsApp: `*жирный*`, разделитель `───────────────`, обычные URL, короткие блоки.
- Telegram: Markdown Telegram; не переносить WhatsApp-звёздочки механически, если нужен MarkdownV2/HTML.
- По умолчанию сохранить готовое сообщение в `.txt`, если владелец просит материал для отправки.
- Полный прайс разбивать на понятные блоки; короткий ответ не раздувать до полного прайса.
- Сырые provider/category коды (`SECC4A`, source offer ID и подобные) разрешены только во внутреннем режиме.

## Перед отправкой наружу

Создание текста автономно. Реальная отправка, публикация или рассылка требует отдельного разрешения владельца.
