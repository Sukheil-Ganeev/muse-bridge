# Message modes

## Короткий ответ о месте

Указать: событие, Section/Row/Seat, доказанную Category, публичную цену режима, статус, время проверки, предупреждение о recheck.

## Agent offer

Показывать:

- нашу базовую цену;
- Category и точное место;
- Aisle, если доказано;
- доступность/время;
- ссылку агента и возможность создать client +10/+15/+20/+30 link.

Не показывать: procurement, provider/source route, owner/investor profit, client tier price без запроса агента.

## Client offer

Показывать только итоговую цену из фиксированной client link. Не писать `+15%`, `наша цена`, `базовая цена`, `закупка`, `маржа`.

## Full price list

Порядок:

1. событие/дата/место;
2. hospitality только с evidence label;
3. Category 1–8 с ценой нужного режима;
4. точные места по запросу;
5. возраст/важные условия;
6. recheck warning.

Не смешивать official base, live provider offer и our selling price в одной колонке без подписи. Во внешнем сообщении оставить только нужную аудитории цену.

## Availability update

- Новое: `Открылись места: Section …`.
- Вернулось: `Снова доступно: …`.
- Explicit sold: `Продано: …`.
- Unknown/disappeared: `Сейчас нет в продаже`; не писать sold.

## Owned inventory

Сообщать как нашу позицию: точное место, Category, наша цена, статус. Не говорить, кто инвестор и сколько составляет чья прибыль.

## Hospitality

Если цена официально опубликована — указать `цена за всю ложу`, capacity и inclusions. Если только коммерческий quote — подписать `предложенная цена, требует повторного подтверждения`; не называть official.

## WhatsApp skeleton

```text
*UFC 333 ABU DHABI*
_24 октября 2026 | 17:00 | Etihad Arena_

───────────────

*Category / место*
Секция:  …
Ряд:  …
Место:  …
Aisle:  …

💰 *Стоимость:*  … AED

───────────────

⚠️ *Важно:* наличие и итоговая стоимость повторно подтверждаются перед оплатой.
```

Для client mode убрать внутренние слова и tier. Для agent mode `Стоимость` = agent base.
