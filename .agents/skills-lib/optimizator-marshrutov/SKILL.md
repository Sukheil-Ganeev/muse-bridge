# ОПТИМИЗАТОР МАРШРУТОВ ОАЭ

## 🤖 Интеграция с VoiceTranscriptionBot (v5.4.0)

Маршрутизатор встроен в бот. Модуль: `D:/Downloads/VoiceTranscriptionBot/core/router.py`

| Команда | Что делает |
|---------|-----------|
| `/route` | Меню маршрутов (Telegram) |
| `/route JBR → Dubai Mall` | Маршрут между точками |
| `/route план: Safari Zoo, Burj Khalifa, Dubai Mall` | Оптимальный маршрут дня |
| `/route метро JBR → Dubai Mall` | Транзитный маршрут |
| WhatsApp: `маршрут` | Меню маршрутов |
| WhatsApp: `как добраться до Ferrari World` | AI-маршрут |
| WhatsApp: `на метро JBR → Dubai Mall` | Транзит |

**API:** Google Maps Directions + Distance Matrix + Geocoding
**Ключ:** GOOGLE_MAPS_API_KEY в .env
**Функции:**
- Маршрут между точками (расстояние, время, пробки, Салик, топливо)
- Оптимизация дня: TSP (Nearest Neighbor + 2-opt) + якорные точки
- Транзит: метро, автобус, nol card стоимость
- Салик: 8 ворот в Дубае, 5 AED каждые
- AI-маршрут через Gemini
**Тесты:** 35 тестов в `tests/test_router.py`

### Шаг 0.5: Transit Workflow (если запрос про общественный транспорт)

**Определи тип transit-запроса:**

| Тип | Пример | Действие |
|-----|--------|----------|
| СТАНЦИЯ | "какое метро до Dubai Mall?" | → Найди в `references/транспорт/станции-достопримечательности.md` |
| МАРШРУТ | "как доехать на метро от DXB до Marina?" | → Построй transit маршрут |
| СРАВНЕНИЕ | "метро или такси до Atlantis?" | → См. `references/транспорт/авто-vs-транспорт.md` |
| ОПЛАТА | "какую карту купить?" | → См. `references/транспорт/оплата-проездные.md` |
| ПРАВИЛА | "что нельзя в метро?" | → См. `references/транспорт/правила-советы.md` |

**Transit Decision Tree:**
```
1. Локация на линии Metro? → Metro (3-7.5 AED)
2. Нужна пересадка Metro+Tram? → Metro+Tram (5 AED, 1 nol tap)
3. Нет Metro? → Metro + автобус или Metro + такси "последняя миля"
4. Ночь (00:00-05:00)? → Только такси/Uber/Careem
5. Группа 3+? → Такси выгоднее
6. Межгород? → Автобус E-серии (12-25 AED)
```

**Критические transit-правила:**
- Metro: пн-сб 05:00-00:00, ПТ с 05:00, ВС с 08:00
- Daily Cap nol Silver: 14 AED (безлимит за день)
- Palm Monorail ПРИОСТАНОВЛЕН (с декабря 2025)
- E100 = Al Ghubaiba (НЕ Ibn Battuta!), E101 = Ibn Battuta
- Tap-in И tap-out обязательны (иначе макс. тариф)

### Шаг 1: Сбор данных (для ПОЛНОГО маршрута)
Получи от пользователя:
- Стартовая точка (отель/адрес) — ОБЯЗАТЕЛЬНО
- Список желаемых локаций — ОБЯЗАТЕЛЬНО
- Время выезда и возврата
- Тип транспорта (такси/авто/метро/общественный транспорт)
- Допустимость платных дорог Salik (если авто/такси)

### Шаг 2: Идентификация локаций
Для каждой локации определи:
- Координаты (район/эмират)
- Рекомендуемое время на посещение
- Часы работы (особенно пятница!)
- Оптимальное время визита (утро/день/вечер)

### Шаг 3: Оптимизация порядка
Применяй TSP-алгоритм:
1. Nearest Neighbor — построй начальный маршрут
2. 2-opt — улучши, устраняя пересечения
3. Учти якорные точки (временные привязки)

### Шаг 4: Учёт ограничений
- Жёсткие: часы работы, время бронирования
- Мягкие: лучшее время посещения, пробки

### Шаг 5: Формирование расписания
- Добавь буферы (+15% к времени в пути)
- Вставь перерыв на обед (12:00-14:00)
- Проверь реалистичность (не более 10-12 часов)

### Шаг 6: Вывод результата
Выбери формат в зависимости от канала:
- AI-чат: ASCII-таблицы
- WhatsApp: списковый с *жирным*
- Telegram: списковый с **жирным**

## 3. ПРАВИЛА ОПТИМИЗАЦИИ

### Критические точки — ЯКОРЯ МАРШРУТА

Эти локации ОБЯЗАТЕЛЬНО ставь в указанное время:

| Локация | Лучшее время | Причина | Приоритет |
|---------|--------------|---------|-----------|
| Safari Zoo Dubai | УТРО 9:00-11:00 | Животные активны, прохладнее | ВЫСОКИЙ |
| Burj Khalifa At The Top | ЗАКАТ 17:30-19:30 | День→ночь виды | ВЫСОКИЙ |
| Global Village | ВЕЧЕР после 16:00 | Открывается только вечером | ЖЁСТКИЙ |
| Desert Safari | ПОСЛЕ 15:00 | Программа привязана к закату | ЖЁСТКИЙ |
| Miracle Garden | УТРО 9:00-12:00 | Меньше людей, прохладнее | СРЕДНИЙ |
| Aquaventure | УТРО 10:00-11:00 | Меньше очередей | СРЕДНИЙ |
| Dubai Frame | ЗАКАТ 17:00-18:00 | Красивые виды | СРЕДНИЙ |
| Sheikh Zayed Mosque | УТРО или ЗАКАТ | Освещение, меньше людей | СРЕДНИЙ |

### Алгоритм построения маршрута

```
1. РАССТАВЬ ЯКОРЯ
   - Найди локации с жёстким временем (Global Village, Desert Safari)
   - Найди локации с оптимальным временем (Safari утром, Burj на закат)
   - Зафиксируй их в расписании

2. ЗАПОЛНИ ПРОМЕЖУТКИ
   - Между якорями вставляй ближайшие географически локации
   - Используй принцип "ближайший сосед"

3. ОПТИМИЗИРУЙ
   - Проверь на пересечения (2-opt)
   - Убери нелогичные переезды (А→С→А→В)

4. ДОБАВЬ СЕРВИС
   - Обед между 12:00-14:00 (~1 час)
   - Буферы +15% к каждому переезду
   - Время на парковку (+15 мин для авто)

5. ПРОВЕРЬ РЕАЛИСТИЧНОСТЬ
   - Общее время ≤ 12 часов
   - Локаций ≤ 6
   - Километраж ≤ 150 км
```

### ⭐ ПРИОРИТЕТ: Google Maps MCP

**Если доступен MCP `google-maps` — ВСЕГДА используй его:**

```
1. maps_distance_matrix — для матрицы расстояний между всеми точками
   origins: [отель, место1, место2, ...]
   destinations: [отель, место1, место2, ...]
   mode: "driving"

2. maps_directions — для построения финального маршрута
   origin: "Damac Smart Heights, Dubai"
   destination: "Ferrari World, Abu Dhabi"
   mode: "driving"

3. maps_geocode — если отель не из базы (получить координаты)
```

**Преимущества MCP:**
- Реальное время с учётом ТЕКУЩИХ пробок
- Точность ~95% вместо ~85%
- Автоматический расчёт платных дорог
- Актуальные данные

**В выводе указывай источник:**
```
📊 Данные: Google Maps (реальное время с учётом пробок)
```

### Формула расчёта времени в пути (FALLBACK если MCP недоступен)

```
Базовое_время = (расстояние_км × 2 минуты) + 10 минут

Коэффициенты:
- Час пик (7:00-9:00, 17:00-19:00): × 1.5
- Пятница утро: × 0.8 (меньше трафика)
- Пятница после обеда: × 1.3 (семейный трафик)
- Праздники/выходные: × 1.2

Итоговое_время = Базовое_время × Коэффициент + Буфер_15%
```

**В выводе указывай:**
```
📊 Данные: расчётные (~85% точность)
⚠️ Время может отличаться из-за пробок
```

### Правила пробелов — КРИТИЧНО!

| Символ | Правило | Пример правильно | Пример НЕПРАВИЛЬНО |
|--------|---------|------------------|-------------------|
| `\|` | ВСЕГДА с пробелами | `A \| B \| C` | `A\|B\|C` |
| `→` | ВСЕГДА с пробелами | `Dubai → Abu Dhabi` | `Dubai→Abu Dhabi` |
| `—` | ВСЕГДА с пробелами | `1 час — без пробок` | `1 час—без пробок` |
| `–` (время) | БЕЗ пробелов | `14:00–15:00` | `14:00 – 15:00` |

### Правило эмодзи

```
✅ ПРАВИЛЬНО: Эмодзи ПЕРЕД заголовком
   ⏱️ *ВРЕМЯ*
   📍 *РАССТОЯНИЕ*

   *⏱️ ВРЕМЯ*
```

| 1 | ❌ Циклические маршруты (A→C→A→B) | Лишние километры и время |
| 2 | ❌ Игнорировать пробки (7-9, 17-19) | Маршрут станет нереалистичным |
| 3 | ❌ Более 8 локаций в день | Физически невозможно |
| 4 | ❌ Пропускать обед (>8ч без еды) | Усталость, недовольство |
| 5 | ❌ Включать закрытые локации | Проверяй сезонность! |

| 7 | ❌ Global Village утром/днём | Закрыто до 16:00 |

| 9 | ❌ Дубай→Абу-Даби→Дубай за 4ч | Нереалистично |
| 10 | ❌ Burj Khalifa без брони | Билетов может не быть |

| # | Правило | Как выполнить |
|---|---------|---------------|
| 1 | ✅ Уточни транспорт | Влияет на время и Salik |
| 2 | ✅ Буфер +15% к времени | Умножь расчётное время на 1.15 |
| 3 | ✅ Проверь часы работы | Особенно пятница и праздники |

### ЛИМИТЫ

```
Максимум на 1 день:
├── Локаций: 5-6 (оптимально 4-5)
├── Километров: 150 км
├── Часов программы: 10-12 ч
├── Часов в пути: 3-4 ч
└── Проходов Salik: 6-8 (~30-40 AED)

Минимум времени на локацию:
├── Крупные (Safari, парки): 2-3 ч
├── Средние (Frame, музеи): 1.5-2 ч
├── Мелкие (фото-точки): 30-45 мин
└── Обед/перекус: 45-60 мин
```

```
🏨 Отель/старт      🦁 Зоопарки         🎡 Развлечения

🍽️ Еда/рестораны   🏜️ Пустыня          🚗 Переезд
⚠️ Важно            💰 Цены/Salik       ⏱️ Время
📍 Расстояние       🎫 Билеты           📸 Фото-точки
```

### Буферы времени

| Ситуация | Буфер |
|----------|-------|
| Стандартный переезд | +15% |
| Час пик (7-9, 17-19) | +50% |
| Парковка (личное авто) | +15 мин |
| Очередь (без брони) | +15-30 мин |
| Поиск входа (крупные моллы) | +10 мин |

### ⚠️ ВАЖНО: Перевод процентов в понятное время

**Для СОТРУДНИКА** — можно писать проценты: `+30–50%`

**Для КЛИЕНТА/АГЕНТА** — переводи в минуты!

| Базовое время | +30% | +50% | Что писать клиенту |
|---------------|------|------|-------------------|
| 30 мин | +9 мин | +15 мин | "на 10–15 минут дольше" |
| 1 час | +18 мин | +30 мин | "на 20–30 минут дольше" |
| 1.5 часа | +27 мин | +45 мин | "на 30–45 минут дольше" |

**Примеры правильного написания:**

```
❌ ДЛЯ КЛИЕНТА: "Час пик: +30–50%"
   (непонятно, технический язык)

✅ ДЛЯ КЛИЕНТА: "В час пик дорога займёт на 20–30 минут дольше"
   (понятно, конкретное время)
```

### Salik — платные дороги

```
Стоимость: 5 AED за проезд (дебетуется автоматически)

Основные точки Salik:
├── Sheikh Zayed Road (несколько точек)
├── Al Maktoum Bridge
├── Al Garhoud Bridge
├── Business Bay Crossing
└── Airport Tunnel

Совет: при расчёте закладывай 2-4 прохода = 10-20 AED
Дубай-Абу Даби: без Salik (федеральная трасса)
```

### Чеклист перед отправкой маршрута

```
Проверь перед выводом:
- [ ] Маршрут линейный (нет возвратов)
- [ ] Пробки учтены (7-9, 17-19 = +50%)
- [ ] Локаций ≤ 6 за день
- [ ] Обед включён (если > 6 часов)
- [ ] Часы работы проверены
- [ ] Сезонность учтена (лето, Рамадан)
- [ ] Якоря на месте (Safari утром, Burj на закат)
- [ ] Salik посчитан
- [ ] Предупреждения о брони добавлены
- [ ] Формат соответствует каналу
```

## 9. ОБРАБОТКА ОСОБЫХ СЛУЧАЕВ

### Слишком много локаций (> 6)

```
Ответь:
"Вы указали [N] локаций — это слишком много для одного дня.
Рекомендую разбить на 2 дня или выбрать приоритеты.

Какие места для вас важнее всего? Или предложить
оптимальное разделение на 2 дня?"
```

### Нереалистичные ожидания

```
Пример: "Хочу Safari, Burj Khalifa, Abu Dhabi и Global Village за день"

Ответь:
"Этот маршрут физически невозможен:
• Safari + Burj Khalifa = 6 часов минимум
• Abu Dhabi = 3 часа в одну сторону
• Global Village = открывается в 16:00

Предлагаю разбить:
День 1: Safari + Burj Khalifa
День 2: Abu Dhabi (целый день)
День 3: Global Village + [что-то рядом]"
```

### Неизвестная локация

```
Если локация не в базе:
1. Уточни у пользователя точное название/адрес
2. Определи район (для расчёта расстояний)
3. Запроси примерное время на посещение
4. Добавь в маршрут с пометкой "время приблизительное"
```

### Противоречивые требования

```
Пример: "Хочу Safari утром и Burj на рассвет"

Ответь:
"Есть конфликт времени:
• Safari оптимально 9:00-12:00
• Burj на рассвет = 5:30-6:30

Варианты:
1. Safari утром + Burj на закат (классика)
2. Burj на рассвет + Safari после (устанете)
3. Разнести на разные дни

Что предпочитаете?"
```
