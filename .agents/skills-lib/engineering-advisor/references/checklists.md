# Engineering Advisor v4.0 — Чек-листы

> Практические чек-листы для повседневной работы с кодом.
> Вынесены из SKILL.md для модульности. Ссылка: SKILL.md секция 7.

---

## 1. Перед вставкой сгенерированного кода

- [ ] Я понимаю что делает каждая функция? (если нет -- попроси объяснить)
- [ ] Код обрабатывает ошибки? (что если ввод неправильный, пустой, не того типа?)
- [ ] Код касается денег или безопасности? (если да -- тесты обязательны, без вариантов)
- [ ] Нет захардкоженных данных, которые должны быть переменными? (цены, URL, лимиты)
- [ ] Нет API-ключей и паролей в открытом виде? (должны быть в .env или переменных окружения)
- [ ] Код не дублирует то, что уже есть в проекте? (проверь существующие файлы)
- [ ] Если изменяется .env или конфиг -- убедись что секреты не попадут в git?

---

## 2. Перед тем как сказать "готово"

- [ ] Я реально запустил код? (не "должен работать", а фактически запустил)
- [ ] Тестировал с реальными данными? (не "test123", а настоящий пример из бизнеса)
- [ ] Проверил граничные случаи? (пусто, ноль, очень большое число, кириллица, спецсимволы)
- [ ] Если веб-страница -- открыл в браузере и проверил визуально?
- [ ] Если API -- отправил реальный запрос и получил ожидаемый ответ?
- [ ] Результат соответствует изначальному плану/запросу? (не "сделал что получилось", а "сделал что просили")

---

## 3. После третьего фикса одной проблемы

- [ ] **СТОП.** Отступи на шаг назад. Не правь ещё раз -- подумай.
- [ ] Подход вообще правильный? Или я латаю неправильный дизайн?
- [ ] Может, проблема глубже -- в архитектуре, а не в конкретной строке?
- [ ] Стоит ли переписать эту часть с нуля с чётким планом?
- [ ] Запросить superpowers:systematic-debugging для анализа корневой причины?
- [ ] Записать урок в experience, чтобы не наступать на те же грабли?

---

## 4. Перед деплоем на production

- [ ] Все тесты проходят? (`pytest` / `npm test` зелёный)
- [ ] .env.production содержит правильные значения? (не dev-ключи!)
- [ ] Секреты НЕ в git? (`git log --all -p -- .env` пустой?)
- [ ] requirements.txt / package.json актуален? (все зависимости записаны с версиями)
- [ ] Есть план отката? (что делать если деплой сломался)
- [ ] SSL / HTTPS настроен?
- [ ] Firewall / rate limiting включён?
- [ ] Логи настроены и пишутся в файл? (не только в stdout)
- [ ] systemd / pm2 / supervisor настроен для автозапуска?
- [ ] Мониторинг / алерты настроены? (хотя бы healthcheck endpoint)

---

## 5. Перед коммитом / пуш в репозиторий

- [ ] `git diff` просмотрен -- нет случайных изменений?
- [ ] Нет файлов с секретами в staged? (.env, credentials.json, *.pem)
- [ ] .gitignore актуален? (все секреты и артефакты исключены)
- [ ] Коммит-сообщение описывает ЧТО и ПОЧЕМУ, а не КАК?
- [ ] Все новые файлы добавлены? (нет забытых файлов)
- [ ] Тесты проходят после изменений?
- [ ] Если merge/rebase -- конфликты разрешены корректно?

---

## Как использовать

1. **Перед вставкой кода** → Чеклист #1
2. **Перед словом "готово"** → Чеклист #2
3. **Петля фиксов** → Чеклист #3
4. **Деплой** → Чеклист #4
5. **Git push** → Чеклист #5

Связанные скиллы:
- superpowers:verification-before-completion → автоматизирует чеклист #2
- superpowers:systematic-debugging → автоматизирует чеклист #3
- superpowers:writing-plans → создаёт план для чеклиста #4
