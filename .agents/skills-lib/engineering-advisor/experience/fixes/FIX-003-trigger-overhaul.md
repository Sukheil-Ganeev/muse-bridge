# FIX-003: Полная переработка триггеров

**Дата:** 2026-02-17
**Проблема:** Триггеры почти никогда не срабатывали

## Корневые причины

### 1. Исключения слишком широкие
- "текстовые задачи" — покрывало 90% запросов пользователя
- "форматирование WhatsApp/Telegram" — основной канал работы
- "работа с документами" — постоянная активность
- "презентации" — частые задачи

### 2. Приоритет исключений = безусловный блок
Правило "исключения ВСЕГДА важнее триггеров" блокировало даже явные запросы на код, если контекст содержал "WhatsApp" или "документы".

### 3. Триггеры для программиста, не для пользователя
- "Генерация кода > 50 строк" — пользователь не считает строки
- "Третья+ итерация фикса" — требует подсчёта
- Ключевые слова на английском (payment, token) — пользователь говорит по-русски

### 4. Отсутствие триггера на деплой
Целая категория работ (Oracle Cloud, systemd, nginx) не имела триггера.

## Решение

### Новые триггеры (9 вместо 8):
- Группа A: Работа с ФАЙЛАМИ КОДА (.py, .js, .ts, .html)
- Группа B: Безопасность (MANDATORY)
- Группа C: Деплой/Production (MANDATORY) — НОВЫЙ
- Группа D: Повторные ошибки
- Группа E: Сложные задачи
- Группа F: Завершение ("готово" без доказательств)
- Триггер 9: Новая фича в 3+ файлах — НОВЫЙ

### Переписанные исключения:
- Сужены: вместо "текстовые задачи" → "Markdown файлы (*.md)"
- Добавлено правило приоритета: если есть ФАЙЛ КОДА — активировать даже при наличии исключения
- Убрано: "форматирование WhatsApp" (слишком широко)

### Новый приоритет:
Если запрос содержит И триггер И исключение → проверить наличие файла кода:
- .py/.js/.ts → активировать
- Нет → не активировать

## Метрики
- Триггеров: 8 → 9
- Исключений: 7 → 6 (сужены)
- Ожидаемое улучшение: с ~5% срабатывания до ~60%+
