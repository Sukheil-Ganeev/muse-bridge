# EXP-053: aiogram 3 — порядок хэндлеров определяет работоспособность команд

**Тип:** fix
**Severity:** critical
**Проект:** VoiceTranscriptionBot
**Дата:** 2026-02-22

## Проблема

Команды `/calc`, `/rate`, `/route` не работали — бот молча игнорировал их. Тесты при этом проходили (67/67).

## Корневая причина

В aiogram 3.x хэндлеры проверяются **строго в порядке объявления декораторов** в файле. Catch-all хэндлер `@router.message(F.text)` был объявлен на строке ~3998, а `@router.message(Command("calc"))` — на строке ~5313 (ПОСЛЕ catch-all).

Что происходило:
1. Пользователь отправляет `/calc`
2. `F.text` на строке 3998 **ловит** сообщение (т.к. `/calc` — это текст)
3. Внутри хэндлера: `if text.startswith("/"): return` — молчаливый return
4. aiogram считает сообщение **обработанным** (return = handled)
5. `Command("calc")` на строке 5313 **никогда не вызывается**

## Почему тесты не поймали

Тесты вызывают `await cmd_calc(mock_message)` напрямую, минуя dispatcher routing. Порядок регистрации не тестировался.

## Решение

Переместить `Command("calc/rate/route")` хэндлеры **до** catch-all `F.text` хэндлера.

## Правило

**В aiogram 3: ВСЕГДА размещай `Command()` хэндлеры ВЫШЕ `F.text` catch-all.** Порядок декораторов в файле = порядок проверки = приоритет.

Мнемоника: «Конкретные фильтры — вверху, общие — внизу. Как воронка: узкое горлышко вверху.»

## Чек-лист для будущих хэндлеров

- [ ] Новый `Command()` хэндлер добавлен ПЕРЕД `F.text` catch-all
- [ ] Проверить что `F.text` catch-all — ПОСЛЕДНИЙ message-хэндлер в файле
- [ ] При добавлении нового catch-all — убедиться что все Command() уже зарегистрированы выше
- [ ] Рассмотреть интеграционный тест на порядок хэндлеров (dispatcher routing test)
