# EXP-069: split("_") возвращает строки — всегда int() для ID

- **Дата:** 2026-02-28
- **Severity:** high
- **Тип:** warning
- **Проект:** rassilka-bot (aiogram 3.x)
- **Триггер:** Нет прямого триггера (новый паттерн)

## Проблема
`call.data.split("_")` возвращает список строк. При передаче в БД-функции ожидающие int,
это работает в SQLite (неявное приведение), но ломается при:
- Сравнении: `if campaign_id == some_int` → False
- Форматировании: f-строки работают, но тип неправильный
- Других БД (PostgreSQL) — ошибка типа

11 мест в 3 файлах были исправлены.

## Правило
После КАЖДОГО split("_") для callback_data:
```python
parts = call.data.split("_")
campaign_id = int(parts[1])  # ← ВСЕГДА int()
```

## Grep-паттерн для аудита
`split\("_"\).*parts\[\d\]` без `int(` рядом
