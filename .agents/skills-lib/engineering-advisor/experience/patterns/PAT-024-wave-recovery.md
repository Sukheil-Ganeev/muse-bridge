# PAT-024: Восстановление после обрыва контекста через волновую стратегию

**Дата:** 2026-02-22
**Проект:** VoiceTranscriptionBot v5.5.0
**Severity:** high
**Категория:** pattern

## Ситуация

Сессия реализации 30 фич админ-бота прервалась на Волне 2 из-за `Context limit reached`.
Было выполнено: Волна 0 (БД), Волна 1 (5 модулей), Волна 2 (4 агента отчитались, но результат не верифицирован).
Не выполнено: Волны 3, 4, 5.

## Паттерн

**Волновая стратегия позволяет продолжить с любого места:**

1. **Экспорт сессии** — пользователь сохранил контекст в .txt файл
2. **Анализ субагентом** — новая сессия читает экспорт, определяет точку остановки
3. **Верификация** — субагент проверяет фактическое состояние файлов и тестов (что реально на диске vs что было заявлено)
4. **Планирование остатка** — создание плана только для незавершённых волн
5. **Выполнение** — продолжение с точки остановки, не с начала

## Ключевые уроки

- Каждая волна должна быть **автономной и верифицируемой** — можно проверить результат без контекста предыдущей сессии
- **Верификация > доверие** — даже если агенты отчитались об успехе, проверяй файлы на диске (в нашем случае 7/8 файлов были на месте, 1 отсутствовал)
- **Тесты = контрольная точка** — `pytest` показывает реальное состояние: 1671 passed (до) → 1725 passed (после)
- **Документация (CLAUDE.md)** — обновлённая документация позволяет следующей сессии понять контекст без экспорта

## Результат

- Подхватили с Волны 2, завершили за 3 новых волны (A, B, C)
- 30/30 фич реализовано, +221 тест, 0 failures
- Общее время восстановления: ~20 минут на анализ + планирование

## Применимость

Любой проект с 10+ задачами, где сессия может прерваться. Особенно актуально для:
- Командной работы с тиммейтами (контекст главного окна ограничен)
- Больших рефакторингов и миграций
- Реализации фич по дизайн-документу
