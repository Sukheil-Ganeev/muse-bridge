# PAT-031: Трёхфазный backward-compatible рефакторинг

- **ID:** PAT-031
- **Дата:** 2026-02-28
- **Источник:** VoiceTranscriptionBot v6.1.0 — AI Architecture Refactoring

## Контекст

Крупный рефакторинг AI-архитектуры: миграция моделей + консолидация клиентов + task routing. 15+ файлов, 2138 тестов. Риск сломать всё при одновременном изменении.

## Паттерн

Разделяй крупный рефакторинг на 3 фазы с нарастающей сложностью:

### Phase A: Quick Wins (минимальный риск)
- Простые string replacements (model ID)
- 8 строк в 6 файлах
- Время: ~1 час
- **Полный pytest между фазами**

### Phase B: Architecture (средний риск)
- Структурные изменения (консолидация клиентов → DI)
- Добавление новых методов в shared сервис
- Время: ~4 часа
- **Полный pytest между фазами**

### Phase C: Optimization (low risk, high value)
- Новая абстракция (TaskType enum)
- Оптимизация параметров по задачам
- Время: ~2 часа
- **Финальный pytest**

## Ключевой инсайт

**Начинай с самого маленького изменения, которое даёт ценность.** Phase A = 8 строковых замен. Если pytest зелёный — продолжай. Если красный — откат тривиален.

**НИКОГДА не пропускай pytest между фазами.** Каждая фаза — независимо тестируемая единица. Баг в Phase B не должен маскироваться за Phase A.

## Применение

Используй этот паттерн когда:
1. Рефакторинг затрагивает 10+ файлов
2. Есть хорошее тестовое покрытие (>100 тестов)
3. Изменения можно разделить по уровню риска
4. Система должна оставаться работоспособной после каждой фазы

## Анти-паттерн

**"Big Bang Refactoring"** — все изменения в одном коммите. При падении тестов непонятно какое изменение виновато. Откат = потеря всей работы.
