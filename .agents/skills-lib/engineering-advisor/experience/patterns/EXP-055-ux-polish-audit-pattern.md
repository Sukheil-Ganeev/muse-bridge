# EXP-055: UX-полировка — аудит+план+волны как масштабируемый паттерн

- **Severity:** high
- **Тип:** pattern
- **Проект:** ContentFactory (Telegram-бот, 134 .py файла, 20 хэндлеров)
- **Дата:** 2026-02-22
- **Применено:** 1 раз

## Контекст

ContentFactory — Telegram-бот на aiogram 3, 10 волн реализации, 1415 тестов. Задача: UX-полировка без новых фич, без поломки тестов. 20 хэндлеров, 14 core-модулей, 29 таблиц SQLite.

## Урок

**Трёхфазный паттерн масштабного аудита работает:**

### Фаза 1: Параллельный аудит (5 агентов)
- Разделить кодовую базу на непересекающиеся группы файлов
- Каждый агент получает чеклист + область ответственности
- Результат: структурированный отчёт P0/P1/P2/P3 по каждому файлу
- **Ключевое:** аудит-агенты ТОЛЬКО читают, НЕ правят файлы

### Фаза 2: Сводный отчёт + план
- Объединить находки всех агентов
- Приоритизировать: P0 Critical → P1 High → P2 Medium → P3 Low
- Показать пользователю план ДО начала правок
- **Ключевое:** план разбит на волны по 3-5 агентов

### Фаза 3: Исправления волнами (3 волны × 3-5 агентов)
- Каждый агент: бэкап → правка → pytest
- Волна 1: P0 Critical (мёртвые кнопки, XSS, краши)
- Волна 2: P1 High (двойное экранирование, даты, меню, навигация)
- Волна 3: P2 Medium (тон, дублирование, cleanup)
- **Ключевое:** pytest после КАЖДОЙ волны. 0 сломанных тестов = обязательно

## Критические находки (воспроизводимые паттерны)

### 1. nav:back мёртвая кнопка (aiogram 3)
- 13 хэндлеров создавали `callback_data="nav:back"` без глобального обработчика
- Решение: отдельный fallback-роутер, зарегистрированный ПОСЛЕДНИМ в main.py
- **Запомнить:** при добавлении новых callback_data — ВСЕГДА проверять наличие handler

### 2. Двойное экранирование _status_line
- `_status_line("X", _esc(val))` — двойной escape через _code() внутри _status_line
- 35 мест в 13 файлах. Видимый баг: `&amp;amp;` вместо `&amp;`
- **Запомнить:** если helper внутри уже вызывает _esc(), НЕ оборачивать снаружи

### 3. Unicode escape sequences в коде
- 130+ мест с `\U0001f516` вместо 🔖 — код нечитаем
- Особенно опасно в F.text == фильтрах — невозможно визуально проверить совпадение с кнопкой
- **Запомнить:** ВСЕГДА использовать читаемые символы в строковых литералах

### 4. Routing conflict в aiogram 3
- cabinet.py и planner.py оба слушали `F.text == "📅 Контент-план"`
- Первый зарегистрированный роутер побеждает — planner был недоступен
- **Запомнить:** при добавлении F.text фильтра — grep по всем хэндлерам на совпадение

### 5. Параллельные агенты на одних файлах
- Fix-4 и Fix-5 оба правили archive.py параллельно
- Решение: финальный pytest после ВСЕХ агентов волны + ручная проверка конфликтов
- **Запомнить:** при параллельной работе — минимизировать пересечение файлов
