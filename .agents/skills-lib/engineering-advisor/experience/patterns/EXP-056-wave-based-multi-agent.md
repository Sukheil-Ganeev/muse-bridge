# EXP-056: Wave-based Multi-Agent Implementation Pattern

**Дата:** 2026-02-27
**Тип:** pattern
**Severity:** medium
**Контекст:** VIP-DXB-CatalogBot Phase 12 — 4 крупные фичи параллельно (Mini App, крипто-платежи, AI Trip Planner, рекомендации)
**Применений:** 1

## Урок

При реализации 3+ независимых фич одновременно, **feature-based агенты** (1 агент = 1 фича целиком) эффективнее **layer-based** (1 агент = DB слой, другой = UI слой).

### Что работает:

1. **Feature-based агенты** — каждый агент владеет полным стеком фичи (DB + сервис + хэндлер + тесты). Минимум зависимостей между агентами, нет конфликтов файлов.

2. **Wave-based зависимости** — когда фича требует последовательных шагов:
   - Wave 1: независимые задачи параллельно (DB + refactor)
   - Wave 2: зависимые задачи после Wave 1 (UI + тесты)
   - Блокировки через TaskUpdate.addBlockedBy

3. **Worktree изоляция** — каждый агент в своём worktree для избежания конфликтов при параллельной работе на одних файлах.

4. **Shutdown после завершения** — освобождать ресурсы: shutdown_request сразу после получения отчёта.

### Что НЕ работает:

1. **Layer-based разделение** при 3+ фичах — db-dev пишет методы для всех фич, но не понимает контекст каждой. UI-dev зависит от всех DB-агентов → bottleneck.

2. **Слишком мелкие задачи** — 1 метод = 1 агент = overhead. Лучше: 1 фича = 1 агент с 3-4 подзадачами внутри.

### Метрики паттерна:

| Подход | Фичи | Агенты | Конфликты | Время |
|--------|:-----:|:------:|:---------:|-------|
| Layer-based (рекомендации) | 1 фича, 3 слоя | 3 агента в 2 волнах | 0 | ~15 мин |
| Feature-based (Phase 12) | 4 фичи | 4 агента параллельно | 0 | ~20 мин |

### Когда применять:

- 3+ независимых фич → feature-based агенты
- 1 фича с 3+ слоями → layer-based (wave) агенты
- Смешанный: feature-based для независимых + wave внутри сложной фичи

## Применение

При запуске команды для мульти-фичной разработки: назначать 1 агент = 1 полная фича (DB + сервис + хэндлер + тесты). Использовать layer-based только когда фича одна но сложная.
