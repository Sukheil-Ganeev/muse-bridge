# PAT-001: Паттерн приоритета исключений в триггерах

- **ID:** PAT-001
- **Дата:** 2026-02-17
- **Источник:** tester-report.md (MEDIUM #4)

## Контекст

YAML frontmatter скилла содержал позитивные триггеры (когда активировать) и негативные исключения (когда НЕ активировать). Но нигде не было явного правила: что происходит когда запрос попадает одновременно в оба списка?

Пример: "Напиши текст для Instagram поста" — содержит глагол "напиши" (триггер), но это текстовый контент (исключение).

## Паттерн

Добавил явное правило прямо в YAML frontmatter:

```
ПРИОРИТЕТ ИСКЛЮЧЕНИЙ: если запрос попадает одновременно
в триггер И в исключение — НЕ активировать.
Исключения ВСЕГДА важнее позитивных триггеров.
```

Это аналогично принципу "deny overrides allow" в системах безопасности.

## Применение

**В любом скилле с YAML frontmatter, где есть и triggers и exclusions — добавляй явное правило приоритета.** Без него поведение при конфликте неопределено. Лучше одна ложная деактивация, чем одна ложная активация — пользователь может вызвать скилл вручную, но не может его выключить если он уже активировался.
