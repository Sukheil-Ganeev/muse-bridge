# Промт для Codex — настройка Muse Bridge с нуля

> Скопируй текст ниже (всё, что в кавычках) и вставь его в Codex
> (CLI или Desktop). Codex сам всё установит и настроит. Тебе нужно
> будет только один раз войти в Muse своей подпиской (логин/пароль),
> потому что у каждого человека своя подписка — она не хранится в проекте.

```
Ты — системный инженер. Настрой мне проект "Muse Bridge" на этой машине.

ЦЕЛЬ: чтобы моя подписка Muse Code работала в любом приложении, которое
умеет подключать "OpenAI-совместимый" провайдер (например PI-Desktop,
или любой другой чат/IDE). Для этого мы поднимаем маленький локальный
сервер-мост, который переводит обычные chat-запросы в команды Muse.

ВАЖНО:
- У меня СВОЯ подписка Muse Code. Логин и пароль введу я сам. Ты их не
  запрашивай и никуда не сохраняй.
- Никаких секретов, токенов, ключей и паролей не записывай в файлы проекта
  и не выводи в отчёт. Это публичный репозиторий.
- Работай на той ОС, где ты запущен (Windows / Linux / macOS) — определи её сам.

ШАГИ (по порядку):

1. Определи ОС и архитектуру. Проверь, что установлен Python 3.9+.
   Если нет — установи его штатным способом этой ОС
   (Windows: python.org; Linux: apt/dnf; macOS: brew install python).

2. Установи Muse Code CLI официальным способом для этой ОС
   (официальный источник Meta/Muse, страница install — только она).
   Проверь командой `muse --version` (на Windows это может быть muse.exe
   или muse.cmd). Если `muse` не в PATH — найди, где он стоит, и запиши путь.

3. Попроси меня войти: запусти `muse login` (или `muse auth login`) и ДАЙ МНЕ
   ввести логин самому. Дождись, пока я подтвержу, что вошёл. Проверь вход
   безвредной командой (например `muse --version` ещё раз, или `muse auth`).

4. Прочитай файл `muse_bridge.py` из этого репозитория. Не меняй его без
   необходимости. Если команда `muse` определяется не автоматически —
   сообщи мне путь и задай переменную окружения MUSE_BRIDGE_EXE для моста.

5. Запусти мост и проверь, что он отвечает:
   - запусти `python3 muse_bridge.py` (или `python muse_bridge.py` на Windows);
   - проверь `http://127.0.0.1:11471/health` — должен вернуть {"ok": true};
   - проверь `http://127.0.0.1:11471/v1/models` — должен вернуть список моделей.

6. Сделай быстрый сквозной тест: отправь один запрос
   POST http://127.0.0.1:11471/v1/chat/completions
   с телом {"model":"muse-spark-1.2","messages":[{"role":"user","content":"Reply with exactly one word: ok"}]}
   и убедись, что вернулся ответ "ok". Если нет — прочитай ошибку, исправь
   и перепроверь. Не считай задачу выполненной, пока тест не пройден.

7. Настрой автозапуск моста, чтобы он стартовал после входа в систему:
   - Windows: файл install/windows-install.bat (или создай .bat в папке
     "Автозагрузка", запускающий pythonw muse_bridge.py);
   - Linux: install/linux-install.sh (freedesktop autostart);
   - macOS: install/macos-install.sh (launchd).
   После настройки перезапусти мост и ещё раз проверь /health.

8. Если я использую PI-Desktop: закрой приложение, запусти
   `python3 restore/restore_muse_provider.py`, снова открой PI-Desktop
   и выбери провайдера "Meta Muse". Если я использую другое приложение —
   дай мне готовую строку настроек: провайдер "OpenAI-совместимый",
   base URL http://127.0.0.1:11471/v1, API-ключ не нужен.

9. В конце дай мне короткий отчёт (по-русски, простыми словами):
   что установлено, работает ли тест, как проверять, и что делать, если
   после обновления приложения провайдер пропадёт (перезапустить
   restore/restore_muse_provider.py).

ПРАВИЛА КАЧЕСТВА:
- Не меняй и не удаляй существующие файлы проекта без причины.
- Не создавай лишних файлов. Действуй минимально и безопасно.
- Ничего не публикуй и не отправляй наружу без моей команды.
- Считай задачу готовой только когда сквозной тест (шаг 6) реально прошёл.
```
