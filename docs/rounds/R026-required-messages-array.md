# R026 — отклонять POST без массива messages

**Статус:** готово

## Цель

Не запускать Muse/Codex CLI для chat-completions-запросов без обязательного
поля `messages` в виде массива объектов.

## Проблема

Оба обработчика проверяют форму `messages` только когда значение не `null`.
Поэтому `{}` и `{"messages": null}` принимаются, а CLI вызывается с пустым
промптом вместо ответа `400` на некорректный запрос.

## Сделано

- Оба обработчика теперь отвечают `400`, если `messages` отсутствует, равно
  `null` или не является массивом объектов.
- Добавлены регрессионные тесты для отсутствующего и `null`-поля в обоих
  мостах.
- Старые проверки Content-Length приведены к валидному телу с `messages`;
  пустое тело без этого поля теперь ожидаемо получает `400`.

## Проверка

- До исправления: targeted unittest — 7 тестов, 4 провалены; каждый дефектный
  запрос получил `200` вместо `400`.
- После исправления: offline unittest — 32 теста, `OK`.
- `python3 -m py_compile muse_bridge.py codex_bridge.py tests/test_bridge.py` —
  успешно.
- `git diff --check` — успешно.
- Полный HTTP-набор с loopback-сокетами не запускался в этом раунде.
