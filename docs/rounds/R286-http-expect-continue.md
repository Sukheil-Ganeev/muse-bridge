# R286 — корректно обрабатывать HTTP Expect

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Не допускать тайм-аута штатных HTTP/1.1 клиентов, которые перед отправкой
тела POST ждут подтверждение `100 Continue`.

## Проблема

Оба моста начинают читать тело сразу после заголовков и игнорируют `Expect`.
Клиент с `Expect: 100-continue` ждёт промежуточный ответ, поэтому клиент и
сервер ждут друг друга до истечения срока чтения тела. Неизвестные ожидания
тоже нельзя молча принимать.

## Сделано

- Muse и Codex отвечают `100 Continue` до чтения тела для HTTP/1.1-запроса с
  единственным поддерживаемым ожиданием.
- Неизвестное ожидание получает HTTP 417 до чтения тела и запуска CLI.
- Добавлены четыре регрессионных теста на оба моста: правильный порядок ответа
  и чтения тела, а также отказ без запуска CLI.

## Проверка

- До исправления: `PYTHONPATH=tests python3 -B -m unittest
  test_bridge.RequestExpectationTests` — 4 FAIL: оба моста читали тело без
  промежуточного ответа и принимали неизвестное ожидание.
- После исправления: тот же запуск — 4 теста, `OK`.
- Офлайн-контракты моста без классов, которым нужен loopback-bind: 90 тестов,
  `OK`. Env-port, установщики и очередь раундов: 5 тестов, `OK`.
- `py_compile` для двух мостов и теста: 3 файла, `OK`; `git diff --check`:
  код возврата 0.
- Интеграционные классы `PostHandlerTests` и `HealthTests` не запускались:
  sandbox запрещает bind loopback; проверка по сокету здесь недоступна.
