# R246 — idle timeout при чтении HTTP-запроса

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Освобождать поток моста, если локальный клиент остановился до завершения
строки запроса или HTTP-заголовков.

## Проблема

`BaseHTTPRequestHandler` по умолчанию не задавал socket timeout. Поэтому
подключившийся клиент, который перестал присылать данные до завершения
заголовков, мог держать поток `ThreadingHTTPServer` без ограничения.

## Сделано

- Muse- и Codex-обработчики задают 30-секундный idle timeout при настройке
  соединения.
- Для тела POST остаётся отдельный абсолютный срок чтения R236; после тела
  исходный idle timeout соединения восстанавливается.
- Добавлены тесты setup обработчиков, подтверждающие применение тайм-аута к
  соединению обоих мостов.

## Проверка

- До исправления: два теста завершались FAIL — `setup()` не вызывал
  `settimeout`.
- После исправления: `PYTHONPATH=tests python3 -B -m unittest
  test_bridge.RequestHeaderTimeoutTests test_bridge.PostBodyDeadlineTests` —
  8 тестов, `OK`.
- Live socket-тест не запускался: sandbox запрещает bind loopback.

## Остаток

Это тайм-аут бездействия, не общий срок разбора заголовков: клиент, который
периодически присылает байты чаще чем раз в 30 секунд, может продолжать
удерживать соединение. Абсолютный срок заголовков этим раундом не добавлялся.
