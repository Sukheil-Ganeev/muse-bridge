# R036 — отклонять POST с неполным телом

**Статус:** готово · без commit/push

## Цель

Не запускать Muse или Codex для HTTP-запроса, в котором получено меньше байт,
чем заявлено в `Content-Length`.

## Проблема

Оба обработчика разбирают результат `rfile.read(length)`, не сверяя фактическую
длину. Если оборванное тело само является валидным JSON (например,
`{"messages":[]}`), запрос принимается и передаётся CLI.

## Сделано

- Добавлены регрессионные тесты для обоих обработчиков: валидный короткий JSON
  при завышенном `Content-Length` должен дать `400` и не запускать CLI.
- До исправления оба теста получили `200` и вызвали подменённый CLI.
- Оба обработчика теперь сверяют число прочитанных байт с заявленной длиной и
  отвечают `400`, не запуская CLI, если тело оборвано.

## Проверка

  — до исправления: 2 ошибки (`200 != 400`); после: 2 теста, `OK`.
- Offline-набор без HTTP-тестов, которым нужен loopback: 34 теста, `OK`.
- Полный `python3 -m unittest discover -s tests`: 47 тестов; 13 ошибок при

- `python3 -m py_compile muse_bridge.py codex_bridge.py tests/test_bridge.py`
  — успешно; `git diff --check` — успешно.
