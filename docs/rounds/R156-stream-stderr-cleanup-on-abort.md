# R156 — закрытие stderr temp-файла при обрыве клиента

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Закрывать временный файл `stderr` после аварийного выхода из потоковой выдачи.

## Проблема

Если `on_delta` выбрасывал исключение, например `BrokenPipeError` при закрытии
клиентом соединения, очистка процесса выполнялась, но управление покидало
`stream_muse` до блока, закрывающего временный файл `stderr`. Проверка выдавала
`ResourceWarning: unclosed file`.

## Сделано

- Добавлен регрессионный тест: при обрыве клиента он проверяет, что `stderr`
  temp-файл закрыт.
- Закрытие файла добавлено на аварийный выход после очистки процесса; успешные
  и штатно завершившиеся с ошибкой пути сохраняют прежнюю обработку.

## Проверка

- До исправления: новый тест — `Ran 1 test`, `FAILED (failures=1)`; поле
  `closed` было `False`, наблюдался `ResourceWarning`.
- После исправления: `StreamAbortTests` с `PYTHONWARNINGS=error::ResourceWarning`
  — `Ran 7 tests`, `OK`, без предупреждений.
- Проверены также после изменения: полный выбранный офлайн-набор, py_compile,
  очередь раундов и `git diff --check` (результаты в `OUT.md`).
