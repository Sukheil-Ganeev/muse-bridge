# R326 — закрывать соединение при раннем отказе

**Статус:** готово локально · без commit/push
**Начат:** 2026-10-05

## Цель

Не позволять непрочитанному телу отклонённого HTTP-запроса становиться строкой
следующего запроса в keep-alive соединении.

## Проблема

Оба моста могли ответить на запрос до чтения его тела (например, отказать по
чужому `Origin`) и оставить HTTP/1.1 соединение открытым. Остаток тела тогда
разбирался как новый запрос; его заголовки могли не содержать `Origin`, что
обходило проверку локального источника.

## Сделано

- Оба моста закрывают соединение при отказе до чтения тела, при неполном или
  просроченном чтении тела и при неизвестном маршруте. Это не даёт серверу
  принять остаток тела за следующий запрос.
- Регрессионные тесты проверяют отказ по чужому `Origin` при непрочитанном
  теле, неполное тело и неизвестный GET-маршрут.

## Проверка

  тест 404 также сначала упал на том же флаге.
- После исправления: офлайн-набор `test_bridge` без классов
  `PostHandlerTests` и `HealthTests` — 98 тестов, `OK`.
- `test_round_queue`, `test_install_scripts`, `test_env_port` — 5 тестов, `OK`;
  `py_compile` для двух мостов и тестов — код 0; `git diff --check` — код 0.
- Loopback-тесты не запускались: sandbox запрещает локальный bind.
- Commit и push не выполнялись.
