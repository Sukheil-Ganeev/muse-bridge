# R266 — защита локального API от чужих Origin и Host

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Не позволять посторонней веб-странице вызывать локальный CLI через Muse Bridge
или Codex Bridge и ограничить перепривязку DNS к чужому имени хоста.

## Проблема

Оба HTTP-моста слушают loopback, но принимали JSON-тело POST без проверки
`Origin` и `Host`. Браузер может отправить простой межсайтовый запрос с телом
JSON и `Content-Type: text/plain`; отсутствие доступа к ответу не мешает
побочному эффекту — запуску CLI. Чужой `Host` также не должен приниматься на
loopback-сокете.

## Сделано

- Добавлена общая проверка заголовков для обоих мостов. Если `Origin` указан,
  он должен быть HTTP-origin для `localhost` или `127.0.0.1` на порту моста.
  Указанный `Host` должен быть loopback-именем; явный порт должен совпадать.
- Чужие запросы к GET и POST получают HTTP 403 до обработки маршрута или тела.
- Отсутствующий `Origin` остаётся разрешён для локальных клиентов без
  браузерного заголовка; loopback `Host` без порта сохранён для старых клиентов.
- Добавлены регрессионные проверки чужого Origin/Host и разрешённых локальных
  запросов для Muse и Codex, включая неправильные и испорченные порты.

## Проверка

- До исправления: `PYTHONPATH=tests python3 -B -m unittest
  test_bridge.RequestOriginProtectionTests` — 5 тестов, 4 FAIL (чужие Origin и
  Host проходили как HTTP 200 и вызывали runner).
- После исправления: автономные контрактные тесты мостов без bind-портов —
  85 тестов, `OK`; env, установщики и очередь — ещё 5 тестов, `OK`.
- Проверка `HealthTests` не прошла запуск: sandbox запрещает bind loopback
  (`PermissionError: [Errno 1] Operation not permitted`); это ограничение среды,
  а не падение проверки поведения API.
- `py_compile` и `git diff --check` проверены отдельно в `OUT.md`.
