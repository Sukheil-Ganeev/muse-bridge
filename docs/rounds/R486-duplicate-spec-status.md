# R486 — отклонять противоречивые статусы в спеках

**Статус:** done
**PR:** #64

## Цель

Не считать очередь согласованной, если строки статуса одной спеки расходятся в
том, завершён раунд или нет.

## Проблема

Проверка брала только первое совпадение `**Статус:**`. Поэтому первая строка
«готово», за которой следовала строка «в работе», могла скрыть противоречие и
пропустить ложную отметку завершения в очереди.

## Сделано

- Регрессия воспроизводит завершённую запись очереди и две конфликтующие строки
  статуса в соответствующей спеке; отдельный тест проверяет, что пустая строка
  не поглощает следующую.
- Пустой статус — ошибка. Непустые строки статуса должны одинаково
  классифицировать раунд как завершённый или открытый. Повторные формулировки
  одного состояния допустимы; прежнее поведение для незавершённых старых
  записей без строки статуса сохраняется.
