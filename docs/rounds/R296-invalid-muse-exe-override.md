# R296 — не подменять неверный MUSE_BRIDGE_EXE найденным в PATH

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Если владелец явно указал `MUSE_BRIDGE_EXE`, не запускать вместо него другой
экземпляр Muse CLI при неверном пути.

## Проблема

`find_muse()` проверяет, существует ли заданный путь. Если он отсутствует,
функция продолжает поиск в `PATH` и стандартных каталогах так, будто
переменная не задана. В результате ошибочная настройка незаметно меняет
выбираемую команду.

## Сделано

- Если `MUSE_BRIDGE_EXE` задан, `find_muse()` возвращает указанный путь только
  когда он существует; иначе поднимает понятный `FileNotFoundError` вместо
  поиска другой команды.
- Добавлен регрессионный тест: неверный явный путь не должен переключать мост
  на бинарник, найденный в `PATH`.

## Проверка

- До исправления: `PYTHONPATH=tests python3 -B -m unittest
  test_bridge.FindMuseTests` — 1 FAIL: `FileNotFoundError not raised`.
- После исправления: тот же запуск — 1 тест, `OK`.
- Офлайн-набор тестов моста без классов, требующих loopback-bind, плюс проверки
  переменной порта, установщиков и очереди: 96 тестов, `OK`; после обновления
  очереди отдельная проверка `test_round_queue` также прошла: 1 тест, `OK`.
- `py_compile` для моста и теста: 2 файла, `OK`; `git diff --check`: код
  возврата 0, вывода нет.
- `PostHandlerTests` и `HealthTests` не выполнились: 13 ошибок при создании
  сокета `127.0.0.1:0`, sandbox вернул `PermissionError: [Errno 1] Operation
  not permitted`.
