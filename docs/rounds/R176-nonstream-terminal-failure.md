# R176 — отклонять terminal.failed в обычном ответе

**Статус:** готово локально · без commit/push
**Начат:** 2026-10-04

## Цель

Не выдавать обычный ответ Muse как успешный, если CLI сообщил `run.terminal.failed`.

## Проблема

`run_muse` запоминает причину `run.terminal.failed`, но проверяет её только когда
текста нет. Если перед ошибкой уже пришёл `run.terminal.completed` с текстом,
мост возвращает этот текст с HTTP 200. Потоковый путь, напротив, отклоняет
terminal failure независимо от уже выданных частей.

## Сделано

- Добавлен регрессионный тест для последовательности completed → failed.
- Проверка terminal failure перенесена перед возвратом любого текста.

## Проверка

- До исправления: новый тест падает, поскольку `run_muse` возвращает текст
  завершённого события вместо ошибки `quota exceeded`.
- До исправления: тест без поля `reason` также падал — terminal failure без
  описания не сохранялся.
- После исправления: оба регрессионных теста проходят; изолированный
  офлайн-набор — `Ran 50 tests`, `OK`. Остальные результаты и ограничение
  loopback-проверок указаны в `OUT.md`.
