# R106 — не маскировать ненулевой код выхода частичным текстом

**Статус:** готово локально · без commit/push  
**Дата:** 2026-10-03

## Цель

Не возвращать частичный вывод как успешный ответ, если процесс Muse CLI
завершился с ошибочным кодом.

## Проблема

`stream_muse` ждал завершения дочернего процесса, но игнорировал результат
`wait()`. Поэтому уже полученный текст delta возвращался как успех даже при
ненулевом коде выхода, если CLI не прислал отдельное `run.terminal.failed`.

## Сделано

- Добавлен регрессионный тест: CLI выдаёт частичный delta и завершается с кодом
  17; ожидается `RuntimeError` с кодом выхода.
- Код завершения процесса теперь проверяется вместе с текстом и terminal-failed
  событием; неизвестный код также не считается успешным.
- Проверено удаление временного файла промпта на ошибочном пути.

## Проверка

- До исправления: новый тест падал — `RuntimeError not raised`.
- После исправления: `python3 -m unittest test_bridge.StreamAbortTests` — 6
  тестов, `OK`; `python3 -m unittest test_round_queue` — 1 тест, `OK`.
- `python3 -m py_compile muse_bridge.py tests/test_bridge.py` и
  `git diff --check` завершились с кодом 0.
- Полный HTTP-набор не запускался: он требует loopback-сокеты, недоступные в
  этой sandbox-среде.
