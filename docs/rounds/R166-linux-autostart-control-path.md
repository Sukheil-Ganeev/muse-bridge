# R166 — Linux autostart: отклонять управляющие символы в пути

**Статус:** готово локально · без commit/push \
**Начат:** 2026-10-04

## Цель

Не создавать небезопасную или испорченную запись автозапуска, если путь к
репозиторию содержит управляющие символы.

## Проблема

Linux installer вставляет путь к `muse_bridge.py` в строку `Exec=` файла
`.desktop`. Символы вроде перевода строки нельзя вставлять в такую строку
буквально: они меняют структуру файла и могут превратить часть имени пути в
новые параметры или команды автозапуска.

## Сделано

- Добавлен регрессионный тест для пути репозитория с переводом строки.
- Установщик проверяет путь до создания автозапуска и отказывает с понятным
  сообщением, если в нём есть управляющий символ.
- Регрессионный тест подтверждает отказ без создания `.desktop`; существующий
  тест экранирования специальных символов продолжает проходить.

## Проверка

- До исправления: новый тест — `Ran 1 test`, `FAILED (failures=1)`; установщик
  завершился с кодом 0 и принял путь с переводом строки.
- После исправления: `test_install_scripts.py` — `Ran 3 tests`, `OK`;
  `test_round_queue.py` — `Ran 1 test`, `OK`.
- `bash -n install/linux-install.sh`, `python3 -m py_compile
  tests/test_install_scripts.py` и `git diff --check` прошли.
- Успешные прогоны использовали временный каталог внутри репозитория и удалили
  его после проверки; временный каталог красного прогона описан в `OUT.md`.
