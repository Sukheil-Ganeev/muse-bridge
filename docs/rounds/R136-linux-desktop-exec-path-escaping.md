# R136 — экранировать путь в Linux autostart Exec

**Статус:** готово локально · без commit/push  
**Дата:** 2026-10-04

## Цель

Сделать так, чтобы Linux autostart запускал мост из каталога, в имени которого
есть допустимые для файловой системы кавычки или обратные слеши.

## Проблема

`install/linux-install.sh` заключает путь к мосту в двойные кавычки, но не
экранирует символы внутри самого пути. В результате запись `Exec` разбирается
не в исходный путь, и автозапуск указывает на другой аргумент.

## Сделано

- Путь для Linux `.desktop` теперь экранирует кавычки, обратные слеши,
  `$`, обратные кавычки и `%` для формата команды автозапуска.
- Добавлен тест на путь с этими символами; он проверяет разобранные аргументы
  запуска и, если программа доступна, валидирует `.desktop` системным
  `desktop-file-validate`.

## Проверка

- До исправления: новый тест падал — кавычки исчезали из пути, а аргумент
  запуска отличался от реального пути к файлу.
- После исправления: Linux installer regression test — 1 тест, `OK`; системный
  `desktop-file-validate` в тесте также прошёл.
- Общий доступный офлайн-набор — 47 тестов, `OK`; полный набор — 60 тестов,
  13 проверок HTTP не смогли открыть loopback-сокет из-за `EPERM` sandbox.
- `bash -n install/linux-install.sh`, Python compile-check и `git diff --check`
  — успешно.
