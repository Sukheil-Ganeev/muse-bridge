# R536 — несовпадающий итог stream не должен превращаться в частичный успех

**Статус:** влито · PR #72

## Цель

Не возвращать как успешный ответ только часть текста, если финальное событие
`muse exec` содержит другой итоговый текст.

## Проблема

`stream_muse` добавляет финальный текст только когда он продолжает уже полученные
дельты. Если итог не начинается с отправленной части, финальное событие
игнорируется, а накопленный неполный текст возвращается с успешным статусом.

## Сделано

Добавлена регрессия на конфликт дельт и финального текста. Несовпадение теперь
завершает вызов контролируемой ошибкой; очистка процесса и временных файлов
осталась в общем блоке завершения.

## Проверка

- До исправления адресный тест упал: `RuntimeError not raised`, мост вернул
  частичный ответ как успешный.
- После исправления: `StreamAbortTests` — 11 тестов, `OK`; офлайн-набор
  `test_bridge.py` без двух классов с loopback-bind — 112 тестов, `OK`.
- `py_compile` затронутых Python-файлов и `git diff --check` — код 0.
- Проверка очереди обнаружила отдельную проблему с завершённым статусом
  `сделано`; она вынесена в R546.
