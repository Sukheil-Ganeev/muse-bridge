# R086 — отклонять неподдерживаемый Transfer-Encoding в POST

**Статус:** готово локально · без commit/push  
**Дата:** 2026-10-03

## Цель

Не запускать Muse/Codex по POST-запросу с неоднозначной или неподдерживаемой
разметкой тела.

## Проблема

Оба обработчика читали тело только по `Content-Length` и игнорировали
`Transfer-Encoding`. Запрос с обоими заголовками мог быть принят по длине и
передан CLI, хотя мост не декодирует chunked-тело. Это оставляло неоднозначное
HTTP framing на границе API.

## Сделано

- Добавлены контрактные тесты для обоих мостов: запрос с
  `Transfer-Encoding: chunked` и `Content-Length` должен вернуть 400 и не
  запускать CLI.
- Оба обработчика теперь отклоняют любой `Transfer-Encoding` ответом 400 до
  чтения тела и запуска CLI.

## Проверка

- До исправления: два новых теста падали; оба моста отвечали 200 вместо 400.
- После исправления: офлайн-набор контрактов — 41 тест, `OK`.
- `python3 -m py_compile` для изменённых Python-файлов и `git diff --check` —
  успешно.
- Полные HTTP-тесты не запускались: sandbox блокирует loopback-сокеты;
  `pytest` также отсутствует, зависимости не устанавливались.
