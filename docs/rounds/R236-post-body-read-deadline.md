# R236 — общий срок чтения тела POST

**Статус:** готово локально · без commit/push  
**Начат:** 2026-10-04

## Цель

Не позволять незавершённому POST-запросу бессрочно занимать поток локального
HTTP-моста.

## Проблема

Оба моста ограничивали размер тела через `Content-Length`, но затем выполняли
блокирующее `rfile.read(length)` без общего срока. Клиент мог объявить тело и
не прислать его полностью; `ThreadingHTTPServer` оставлял поток запроса ждать.

## Сделано

- Чтение тела Muse и Codex ограничено общим сроком 30 секунд; чтение идёт
  порциями, а до каждого чтения выставляется оставшееся время.
- Тайм-аут возвращает HTTP 408 с понятной ошибкой; прежний socket timeout
  восстанавливается после чтения.
- Добавлены тесты истечения срока, общего (не сбрасываемого на каждой порции)
  срока и успешного чтения для обоих мостов.

## Проверка

- До исправления: два регрессионных теста завершались FAIL — старый код
  отвечал `400 bad json`, а не `408`.
- После исправления: `PYTHONPATH=tests python3 -B -m unittest
  test_bridge.PostBodyDeadlineTests` — 6 тестов, `OK`.
- Сетевой тест намеренно не использовался: sandbox запрещает bind loopback
  (`PermissionError: [Errno 1] Operation not permitted`).
