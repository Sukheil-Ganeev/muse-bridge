# R126 — останавливать CLI после разрыва SSE-клиента

**Статус:** готово локально · без commit/push  
**Дата:** 2026-10-04

## Цель

Сразу останавливать запущенный Muse CLI, если отправка SSE keepalive клиенту
не удалась из-за разрыва соединения.

## Проблема

Основной цикл `stream_muse` может ждать следующую строку от CLI, пока отдельный
поток отправляет keepalive. Если запись keepalive завершается ошибкой, watchdog
сейчас прекращает только себя. Тихий CLI остаётся работать до своего вывода,
завершения или общего тайм-аута до 280 секунд.

## Сделано

- При исключении из keepalive callback watchdog теперь останавливает Muse
  CLI, чтобы разрыв соединения не оставлял его ждать общего тайм-аута.
- Добавлен регрессионный тест с тихим дочерним процессом и блокирующим stdout.

## Проверка

- До исправления: `test_bridge.StreamKeepaliveAbortTests` — 1 ошибка: CLI не был остановлен
  после ошибки записи keepalive.
- После исправления: потоковые тесты — 7 тестов, `OK`; полный доступный
  офлайн-набор — 46 тестов, `OK`.
- Полный `unittest discover` запустил 59 тестов, но 13 проверок с HTTP-сервером
  завершились `PermissionError: [Errno 1] Operation not permitted` при создании
  loopback-сокета в sandbox. Повторный узкий запуск без этих проверок прошёл.
- `pytest` для `tests/test_env_port.py` недоступен: модуль pytest не установлен;
  пакеты не устанавливались.
- `python3 -m py_compile muse_bridge.py tests/test_bridge.py` и
  `git diff --check` — успешно.
