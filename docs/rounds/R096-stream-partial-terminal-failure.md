# R096 — не считать частичный поток успешным после terminal-failed

**Статус:** готово локально · без commit/push  
**Дата:** 2026-10-03

## Цель

Если Muse сообщает об ошибке завершения после выдачи части текста, не
возвращать этот фрагмент как успешный ответ.

## Проблема

`stream_muse` сохранял причину из `run.terminal.failed`, но проверял её только
когда текста не было. При частичном выводе функция возвращала текст, из-за чего
HTTP-обработчик завершал SSE-поток с `finish_reason=stop` и `[DONE]` вместо
сообщения об ошибке.

## Сделано

- Добавлен регрессионный тест: после текстового delta приходит
  `run.terminal.failed`; ожидается `RuntimeError` с причиной ошибки.
- Проверено, что временный файл промпта удаляется и на этом пути.
- `stream_muse` теперь поднимает ошибку при terminal-failed независимо от того,
  успел ли CLI выдать часть текста.

## Проверка

- До исправления: регрессионный тест падал — `RuntimeError not raised`.
- После исправления: `python3 -m unittest test_bridge.StreamAbortTests` — 6
  тестов, `OK`; `python3 -m unittest test_round_queue` — 1 тест, `OK`.
- Полный HTTP-набор не запускался: он требует loopback-сокеты, недоступные в
  этой sandbox-среде.
- `python3 -m py_compile muse_bridge.py tests/test_bridge.py` и
  `git diff --check` завершились с кодом 0.
