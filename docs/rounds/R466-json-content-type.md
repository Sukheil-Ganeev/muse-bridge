# R466: POST требует однозначный JSON Content-Type

**Статус:** merged · PR #60

## Цель

До чтения тела и запуска CLI отклонять POST-запросы, которые не объявляют
единственный `Content-Type: application/json`.

## Проблема

Оба моста всегда разбирали POST-тело как JSON, даже если тип содержимого
отсутствовал, был `text/plain` или заголовок повторялся с разными значениями.
Из-за этого объявленный формат запроса не совпадал с тем, который реально
разбирает сервер.

## Сделано

- Muse Bridge и Codex Bridge теперь отвечают HTTP 415 до чтения тела, если
  `Content-Type` отсутствует, повторяется или его тип не `application/json`.
- Регистр типа и параметры вроде `charset=utf-8` не меняют распознавание
  допустимого JSON-запроса.
- Добавлены общие регрессии на отказ обоих мостов и приём JSON с параметром.

## Проверка

- До исправления: `JsonContentTypeTests` — 3 теста, 2 провала: оба моста
  приняли запрос без `Content-Type` и вернули 200 вместо 415.
- Полные адресные и офлайн-гейты записаны в корневом `OUT.md`.
- Commit и push не выполнялись.
